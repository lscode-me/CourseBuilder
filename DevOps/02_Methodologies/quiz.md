## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Agile Manifesto: "Готовность к изменениям важнее следования плану" |
| 2 | C | Product Owner — единственный владелец Product Backlog и его приоритизации |
| 3 | B | Scope спринта защищён после Planning; изменения только между спринтами |
| 4 | B | Daily Standup — синхронизация команды, не отчёт менеджеру |
| 5 | B | По закону Литтла: Lead Time = WIP / Throughput. Меньше WIP = меньше Lead Time |
| 6 | B | Lead Time включает всё время (и ожидание), Cycle Time — только время работы |
| 7 | B | Фиксированные итерации — это Scrum. Kanban — непрерывный поток |
| 8 | B | Planning → Daily Standups → Review → Retrospective |
| 9 | C | "Optimize and automate" напрямую соответствует DevOps автоматизации |
| 10 | B | Standard Change — преапproved, автоматизированное, низкорисковое изменение |
| 11 | B | Scrum использует спринты с фиксированной длительностью, Kanban — нет |
| 12 | B | DoD включает критерии готовности к deployment (тесты, review, staging) |
| 13 | B | ART — 50-125 человек, работающих синхронно в Program Increments |
| 14 | B | Incident Management: восстановить сервис. Problem Management: найти root cause |
| 15 | B | DevOps расширяет Agile на operations, обеспечивая continuous delivery |
| 16 | B | Ретроспектива фокусируется на улучшении процесса без blame |
| 17 | B | CFD показывает количество работы в каждом состоянии во времени |
| 18 | B | LeSS минималистичен: один backlog, минимум ролей, простая структура |
| 19 | B | Incident — нарушение сервиса; Problem — underlying cause инцидентов |
| 20 | B | Velocity = story points за спринт. Используется для планирования |
