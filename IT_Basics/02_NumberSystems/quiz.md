## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Байт всегда состоит из 8 бит. Это стандартная единица данных. |
| 2 | B | 8 бит = 2^8 = 256 возможных значений (от 0 до 255). |
| 3 | B | 101010 = 32 + 8 + 2 = 42 (позиции: 1×32 + 0×16 + 1×8 + 0×4 + 1×2 + 0×1). |
| 4 | B | 15 = 8 + 4 + 2 + 1 = 1111 в двоичной системе. |
| 5 | B | Hex использует 0-9 и A-F (всего 16 символов для основания 16). |
| 6 | C | 0xFF = 15×16 + 15 = 240 + 15 = 255. |
| 7 | B | Nibble — это 4 бита, половина байта, один hex-символ. |
| 8 | B | 7=rwx, 5=r-x, 5=r-x. Владелец всё, группа и остальные — чтение и выполнение. |
| 9 | B | Восьмеричная система имеет основание 8, использует цифры 0-7. |
| 10 | B | Big-Endian хранит старший байт первым: 12 34 56 78. |
| 11 | B | x86-64 (Intel/AMD) использует Little-Endian. |
| 12 | B | TCP/IP всегда использует Big-Endian (Network Byte Order). |
| 13 | B | `xxd` — стандартная утилита для hex dump в Linux. |
| 14 | C | `hex(42)` возвращает строку `'0x2a'` (42 в hex = 2a). |
| 15 | B | `bin(42)` возвращает `'0b101010'`. |
| 16 | B | Signed 8-bit: -128 до 127. Unsigned: 0 до 255. |
| 17 | B | -5 в two's complement: инвертировать 00000101 = 11111010, добавить 1 = 11111011. |
| 18 | B | IEEE 754 floating point имеет ограниченную точность, 0.1 — бесконечная дробь в binary. |
| 19 | B | 1 KiB (кибибайт по IEC) = 1024 байт. Производители часто используют 1000. |
| 20 | B | `xxd -r -p` — reverse plain hex dump, конвертирует hex в binary. |
