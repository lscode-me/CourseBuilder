## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Кодировка — таблица соответствия между символами и их числовыми представлениями. |
| 2 | B | ASCII — 7 бит, 128 символов (0-127). |
| 3 | C | 'A' = 65 (0x41). Строчная 'a' = 97 (0x61). |
| 4 | D | ASCII поддерживает только латиницу и базовые символы, не кириллицу. |
| 5 | A | Unicode — таблица символов. UTF-8/16/32 — способы кодирования Unicode в байты. |
| 6 | C | Code points записываются как U+XXXX, например U+0041 для 'A'. |
| 7 | C | Первые 128 символов UTF-8 идентичны ASCII — один байт, то же значение. |
| 8 | D | UTF-8: 1 байт (ASCII), 2 байта (кириллица), 3 байта (CJK), 4 байта (эмодзи). |
| 9 | A | Кириллица (U+0400-U+04FF) кодируется 2 байтами в UTF-8. |
| 10 | B | Эмодзи (U+1F600+) находятся за пределами BMP и требуют 4 байта в UTF-8. |
| 11 | C | Mojibake — искажённый текст при несовпадении кодировки записи и чтения. |
| 12 | D | UTF-8 байты интерпретированы как Latin-1 дают характерные "ÐŸÑ€Ð¸..." |
| 13 | A | `iconv` с флагами -f (from) и -t (to) конвертирует кодировки. |
| 14 | B | BOM — байты в начале файла для определения кодировки и endianness. |
| 15 | C | UTF-8 BOM = `EF BB BF`. `FF FE` = UTF-16 LE, `FE FF` = UTF-16 BE. |
| 16 | D | Всегда явно указывайте `encoding='utf-8'` при открытии файлов. |
| 17 | B | MySQL `utf8` = max 3 байта, не поддерживает символы за BMP (эмодзи). |
| 18 | A | В КОИ-8 русские буквы расположены так, что при обнулении 8-го бита получается похожая латиница. |
| 19 | C | `chardet` — библиотека для автоматического определения кодировки. |
| 20 | D | Один символ может иметь разные Unicode-представления; нормализация приводит их к единому виду. |
