## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Кодировка — таблица соответствия между символами и их числовыми представлениями. |
| 2 | B | ASCII — 7 бит, 128 символов (0-127). |
| 3 | B | 'A' = 65 (0x41). Строчная 'a' = 97 (0x61). |
| 4 | C | ASCII поддерживает только латиницу и базовые символы, не кириллицу. |
| 5 | B | Unicode — таблица символов. UTF-8/16/32 — способы кодирования Unicode в байты. |
| 6 | C | Code points записываются как U+XXXX, например U+0041 для 'A'. |
| 7 | B | Первые 128 символов UTF-8 идентичны ASCII — один байт, то же значение. |
| 8 | C | UTF-8: 1 байт (ASCII), 2 байта (кириллица), 3 байта (CJK), 4 байта (эмодзи). |
| 9 | B | Кириллица (U+0400-U+04FF) кодируется 2 байтами в UTF-8. |
| 10 | D | Эмодзи (U+1F600+) находятся за пределами BMP и требуют 4 байта в UTF-8. |
| 11 | B | Mojibake — искажённый текст при несовпадении кодировки записи и чтения. |
| 12 | B | UTF-8 байты интерпретированы как Latin-1 дают характерные "ÐŸÑ€Ð¸..." |
| 13 | B | `iconv` с флагами -f (from) и -t (to) конвертирует кодировки. |
| 14 | B | BOM — байты в начале файла для определения кодировки и endianness. |
| 15 | C | UTF-8 BOM = `EF BB BF`. `FF FE` = UTF-16 LE, `FE FF` = UTF-16 BE. |
| 16 | B | Всегда явно указывайте `encoding='utf-8'` при открытии файлов. |
| 17 | C | MySQL `utf8` = max 3 байта, не поддерживает символы за BMP (эмодзи). |
| 18 | B | В КОИ-8 русские буквы расположены так, что при обнулении 8-го бита получается похожая латиница. |
| 19 | B | `chardet` — библиотека для автоматического определения кодировки. |
| 20 | B | Один символ может иметь разные Unicode-представления; нормализация приводит их к единому виду. |
