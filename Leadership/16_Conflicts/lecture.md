## 1. Понимание конфликтов

### 1.1 Конфликт — не всегда плохо

> **💡 Key Insight:**  
> Здоровый конфликт (о идеях) = innovation. Нездоровый конфликт (о людях) = dysfunction.

**Constructive conflict:**
```
- Дебаты о технических решениях
- Оспаривание assumptions
- Разные perspectives на проблему
- Challenge статуса-кво
```

**Destructive conflict:**
```
- Личные атаки
- Blame и criticism
- Passive-aggressive behavior
- Избегание проблем
```

### 1.2 Типы конфликтов

**Task Conflict:**
```
О чём: Разногласия о работе, решениях, подходах
Пример: "Какую технологию использовать?"
Impact: Может быть полезен (better decisions)
```

**Relationship Conflict:**
```
О чём: Межличностные tensions
Пример: "Я не могу с ним работать"
Impact: Всегда негативен, нужно решать
```

**Process Conflict:**
```
О чём: Как делать работу
Пример: "Кто должен делать code review?"
Impact: Может быть полезен, нужна clarity
```

### 1.3 Sources конфликтов

```
Resource scarcity:
- Конкуренция за ресурсы
- Приоритизация проектов
- Headcount allocation

Communication:
- Misunderstandings
- Information gaps
- Different communication styles

Goals:
- Misaligned incentives
- Different priorities
- Individual vs team goals

Personalities:
- Working style differences
- Value differences
- Past history
```

## 2. Conflict Resolution Framework

### 2.1 Thomas-Kilmann Model

**Пять стилей:**

```
                    High
                     │
        Competing    │    Collaborating
        (Win-Lose)   │    (Win-Win)
                     │
     ─────────────── ┼ ───────────────────
                     │    
       Avoiding      │    Accommodating
       (Lose-Lose)   │    (Lose-Win)
                     │
                    Low
              ──────────────────────
              Low    Cooperativeness   High
```

**When to use each:**

| Style | When |
|-------|------|
| **Collaborating** | Important issues, time available, need commitment |
| **Competing** | Quick decision needed, unpopular action, critical |
| **Compromising** | Moderate importance, equal power |
| **Avoiding** | Trivial issue, need to cool down, no chance of winning |
| **Accommodating** | You're wrong, harmony important, building goodwill |

### 2.2 Interest-Based Resolution

**Positions vs Interests:**
```
Position: What someone says they want
Interest: Why they want it (underlying need)

Example:
Position A: "Я хочу использовать React"
Position B: "Я хочу использовать Vue"

Interest A: "Мне важна ecosystem и job market"
Interest B: "Мне важна простота для junior developers"

→ Explore: Can we meet both interests?
```

### 2.3 Resolution Process

```
1. Acknowledge
   "I see there's disagreement here"
   
2. Understand Each Side
   "Help me understand your perspective"
   "What's important to you about this?"
   
3. Find Common Ground
   "What do we both agree on?"
   "What's our shared goal?"
   
4. Generate Options
   "What are possible solutions?"
   "What if we tried...?"
   
5. Agree on Solution
   "Which option works for both?"
   "What can each side commit to?"
   
6. Follow Up
   "Let's check in next week"
```

## 3. Mediation

### 3.1 When to Mediate

**Вмешивайтесь когда:**
- Конфликт влияет на работу
- Стороны не могут решить сами
- Escalation продолжается
- Team morale страдает

**Не вмешивайтесь если:**
- Обычное disagreement
- Стороны могут решить сами
- Conflict is healthy debate

### 3.2 Mediation Process

```
Step 1: Preparation
─────────────────────
- Understand situation (talk to each separately)
- Assess if mediation needed
- Set up neutral meeting

Step 2: Opening
─────────────────────
- Ground rules (respectful, no interrupting)
- Goal: find solution, not assign blame
- Both sides will be heard

Step 3: Each Side's Story
─────────────────────
- Person A speaks uninterrupted
- Person B speaks uninterrupted
- Summarize each perspective

Step 4: Identify Issues
─────────────────────
- What are the key issues?
- What are underlying interests?
- Where is common ground?

Step 5: Generate Solutions
─────────────────────
- Brainstorm options
- Evaluate together
- Find mutually acceptable

Step 6: Agreement
─────────────────────
- Specific commitments
- Follow-up plan
- Document if needed

Step 7: Follow Up
─────────────────────
- Check in after 1-2 weeks
- Ensure agreement holding
```

### 3.3 Mediator Guidelines

```
✅ DO:
- Stay neutral
- Listen actively
- Ask clarifying questions
- Focus on behavior, not personality
- Look for common ground
- Redirect personal attacks

❌ DON'T:
- Take sides
- Impose solution
- Blame either party
- Share confidences
- Rush to judgment
- Allow disrespect
```

## 4. Difficult Conversations

### 4.1 Types of Difficult Conversations

```
Performance issues:
"Your work quality has declined"

Behavioral problems:
"Your attitude in meetings is disruptive"

Compensation:
"I can't approve the raise you requested"

Layoffs/terminations:
"Your position is being eliminated"

Personal issues:
"Your personal situation is affecting work"
```

### 4.2 Framework: DESC

**D**escribe: Объективно опишите ситуацию
**E**xpress: Выразите impact
**S**pecify: Укажите желаемое изменение
**C**onsequences: Объясните последствия

**Example:**
```
D: "В последних трёх code review ты оставил comments 
    типа 'это плохо' без объяснений"
    
E: "Это frustrating для junior developers 
    и замедляет их обучение"
    
S: "Я прошу добавлять одно предложение объяснения 
    к каждому critical comment"
    
C: "Это поможет команде учиться быстрее 
    и улучшит наш review process"
```

### 4.3 Handling Reactions

**Defensive:**
```
"I'm not criticizing you, 
I'm trying to solve a problem together.
Can you help me understand your perspective?"
```

**Emotional:**
```
"I can see this is upsetting.
Do you want to take a moment?
We can continue when you're ready."
```

**Denial:**
```
"I've documented [specific examples].
Let's look at them together.
Help me understand what you see differently."
```

**Blame:**
```
"I hear that you see other factors.
Right now I want to focus on what we can control.
What can you do differently?"
```

## 5. Specific Situations

### 5.1 Конфликт между двумя членами команды

**Scenario:** Два senior developers не могут работать вместе

**Approach:**
```
1. Speak to each privately
2. Understand each perspective
3. Identify if task or relationship conflict
4. Mediate if needed
5. Set clear expectations
6. Monitor and follow up
```

### 5.2 Конфликт с другой командой

**Scenario:** Ваша команда и Team B blame друг друга

**Approach:**
```
1. Talk to other team lead
2. Understand their perspective
3. Find common ground (shared goals)
4. Joint problem-solving session
5. Clear agreements on interactions
6. Regular check-ins
```

### 5.3 Конфликт с вашим руководителем

**Scenario:** Вы не согласны с решением вашего EM/Director

**Approach:**
```
1. Request 1-on-1 to discuss
2. Share your perspective (data, concerns)
3. Listen to their reasoning
4. Disagree and commit if needed
5. Document if significant
6. Escalate only if ethical issue
```

### 5.4 Toxic Team Member

**Scenario:** Один человек создаёт негатив для всей команды

**Approach:**
```
1. Document specific behaviors
2. Private conversation: feedback + expectations
3. Monitor for change
4. If no change: formal warning / PIP
5. If still no change: termination
6. Protect team throughout
```

## 6. Conflict Prevention

### 6.1 Proactive Measures

```
Clear expectations:
- Roles and responsibilities defined
- Decision-making process clear
- Communication norms established

Regular feedback:
- Issues addressed early
- No buildup of resentment
- Open dialogue encouraged

Team norms:
- How we disagree
- How we make decisions
- How we give feedback
```

### 6.2 Healthy Disagreement

**Encourage:**
```
- "Devil's advocate" role
- Pre-mortem exercises
- Diverse perspectives invited
- Debate ideas, not people
```

**Team agreement:**
```
"We commit to:
- Attack problems, not people
- Listen to understand, not respond
- Assume good intent
- Disagree openly, commit together"
```

## 7. Escalation

### 7.1 When to Escalate

```
Escalate to your manager / HR:
- Legal/ethical concerns
- Harassment / discrimination
- Safety issues
- You can't resolve it
- Pattern of behavior despite intervention
```

### 7.2 How to Escalate

```
1. Document everything first
2. Be factual, not emotional
3. Describe what you've tried
4. Be clear about what you need
5. Propose solutions if possible
```

## 8. Self-Management

### 8.1 Managing Your Emotions

**Before conflict conversation:**
```
- Take time to calm down
- Separate facts from interpretation
- Consider their perspective
- Plan your key points
- Anticipate reactions
```

**During:**
```
- Breathe
- Pause before responding
- Focus on issue, not person
- Ask questions
- Take breaks if needed
```

### 8.2 After Conflict

**Reflection:**
```
- What went well?
- What would I do differently?
- Did I listen enough?
- What did I learn about them? About myself?
```

## 💡 Key Takeaways

- **Not all conflict is bad:** Task conflict can improve decisions
- **Interests > Positions:** Understand underlying needs
- **Mediate carefully:** Stay neutral, focus on resolution
- **DESC framework:** Describe, Express, Specify, Consequences
- **Prevent proactively:** Clear expectations, regular feedback, team norms
