## 1. Continuous Performance Management

### 1.1 От Annual к Continuous

**Старый подход:**
```
Annual review:

- Раз в год
- Surprise feedback
- Ranking и rating
- Disconnect от реальности
```

**Современный подход:**
```
Continuous:

- Ongoing feedback
- Regular 1-on-1
- No surprises at review
- Real-time course correction
```

### 1.2 Cycle

```
         ┌─────────────────────────────────────────┐
         │           Performance Cycle             │
         └─────────────────────────────────────────┘
                           │
       ┌───────────────────┼───────────────────┐
       ▼                   ▼                   ▼
   ┌───────┐          ┌───────┐          ┌───────┐
   │ PLAN  │───────►  │DEVELOP│───────►  │REVIEW │
   │       │          │       │          │       │
   │Goals  │          │Ongoing│          │Assess │
   │Setup  │          │Feedback│         │Results│
   └───────┘          └───────┘          └───────┘
       │                                      │
       └──────────────────────────────────────┘
                    (repeat)
```

## 2. Goal Setting

### 2.1 OKR Framework

**Objectives and Key Results:**

```markdown
Objective: What you want to achieve (qualitative)
Key Results: How you measure progress (quantitative)

Example:
O: Improve customer onboarding experience
KR1: Reduce onboarding time from 7 days to 3 days
KR2: Increase onboarding completion rate from 60% to 85%
KR3: Achieve NPS of 50+ for onboarding flow
```

**OKR Best Practices:**
- 3-5 objectives per quarter
- 2-4 key results per objective
- 70% achievement is success (stretch goals)
- Transparent across organization

### 2.2 SMART Goals

```
S - Specific: Clear and well-defined
M - Measurable: Quantifiable progress
A - Achievable: Realistic but challenging
R - Relevant: Aligned with priorities
T - Time-bound: Clear deadline
```

**Example:**
```
❌ "Improve code quality"

✅ "Reduce bug escape rate from 5% to 2% 
    by implementing code review checklist 
    by end of Q2"
```

### 2.3 Individual vs Team Goals

**Balance:**
```
Individual goals:

- Personal development
- Specific deliverables
- Career growth

Team goals:

- Shared outcomes
- Collaboration incentives
- Collective success
```

**Ratio:** ~60% individual, ~40% team (varies by role)

## 3. Performance Review

### 3.1 Review Structure

**Typical cycle:**
- Mid-year review (informal)
- Annual review (formal)
- Quarterly check-ins (optional)

### 3.2 Self-Assessment

**Template for self-assessment:**
```markdown
## Self Assessment: [Name] - [Period]

### Goals Achievement
| Goal | Target | Actual | Comment |
|------|--------|--------|---------|
| [goal 1] | [metric] | [result] | [context] |

### Highlights
- [Key achievement 1]
- [Key achievement 2]

### Challenges
- [Challenge 1 and how addressed]
- [Challenge 2 and learnings]

### Growth Areas
- [Area where I improved]
- [Area to focus on next]

### Goals for Next Period
- [Goal 1]
- [Goal 2]
```

### 3.3 Manager Assessment

**Preparing:**
```
1. Review goals и OKRs
2. Gather feedback (peers, stakeholders)
3. Review 1-on-1 notes
4. Identify specific examples
5. Draft assessment
```

**Writing assessment:**
```markdown
## Performance Assessment: [Name]

### Overall Rating: [Rating]

### Goal Achievement: [%]
[Specific outcomes with examples]

### Strengths
- [Strength 1]: [Example]
- [Strength 2]: [Example]

### Growth Areas
- [Area 1]: [Specific feedback and path forward]
- [Area 2]: [Specific feedback and path forward]

### Recommendations
[Promotion / Development / Compensation]
```

### 3.4 Review Meeting

**Структура:**
```
1. Set context (5 min)
   - Purpose of meeting
   - Their self-assessment first

2. Discuss performance (30-40 min)
   - What went well
   - Areas for improvement
   - Specific examples

3. Career conversation (15-20 min)
   - Future goals
   - Development needs
   - Growth opportunities

4. Next steps (5-10 min)
   - Action items
   - Goals for next period
   - Follow-up plan
```

**Key principles:**
- No surprises (continuous feedback!)
- Balanced (strengths + areas for growth)
- Specific examples, not generalities
- Two-way conversation
- Forward-looking

## 4. Career Development

### 4.1 Career Conversations

**Frequency:** Quarterly, separate from performance review

**Questions:**
```
1. Where do you see yourself in 2-3 years?
2. What skills do you want to develop?
3. What type of work energizes you?
4. What's blocking your growth?
5. How can I support your development?
```

### 4.2 Development Plan

**Template:**
```markdown
## Development Plan: [Name]

### Current State
- Role: [current role]
- Level: [current level]
- Strengths: [list]
- Gaps: [list]

### Target State
- Desired role: [role]
- Timeline: [when]
- Required skills: [list]

### Development Actions

| Skill Gap | Action | Timeline | Support |
|-----------|--------|----------|---------|
| [gap 1] | [project/training] | Q1 | Mentor: X |
| [gap 2] | [stretch assignment] | Q2 | Training budget |

### Check-ins
- Monthly 1-on-1 review
- Quarterly formal review
```

### 4.3 Career Ladders

**Transparent expectations:**
```markdown
## Engineering Levels

### Junior Engineer (L1)
- Scope: Tasks with guidance
- Impact: Individual
- Technical: Basic skills
- Communication: Team

### Engineer (L2)
- Scope: Features independently
- Impact: Team
- Technical: Solid skills
- Communication: Cross-team

### Senior Engineer (L3)
- Scope: Projects, multi-feature
- Impact: Team/Area
- Technical: Expert in area
- Communication: Stakeholders

### Staff Engineer (L4)
- Scope: Strategic initiatives
- Impact: Org-wide
- Technical: Multiple domains
- Communication: Executive

[Continue for each level...]
```

## 5. Promotion Process

### 5.1 Promotion Criteria

**Typical criteria:**
```
1. Already performing at next level
   (не "готов к promotion", а "уже делает")

2. Consistent performance
   (не один раз, а pattern)

3. Business need
   (есть позиция, scope)

4. Demonstrates competencies
   (по ladder)
```

### 5.2 Promotion Packet

**Contents:**
```markdown
## Promotion Packet: [Name] to [Level]

### Summary
[1 paragraph: why this person, why now]

### Evidence by Competency

#### Technical Skills
- [Example 1]
- [Example 2]

#### Impact
- [Project A with results]
- [Project B with results]

#### Leadership
- [Mentorship]
- [Influence]

#### Communication
- [Examples]

### Stakeholder Feedback
- [Quote from peer]
- [Quote from partner]

### Recommendation
[Strong support for promotion]
```

### 5.3 Calibration

**Process:**
```
1. Managers submit nominations
2. Calibration meeting with peer managers
3. Compare candidates against ladder
4. Discuss edge cases
5. Final decisions
```

**Purpose:**
- Consistency across managers
- Fair application of standards
- Reduce bias

## 6. Managing Underperformance

### 6.1 Early Signals

```
🚨 Warning signs:

- Missed deadlines consistently
- Quality issues
- Negative peer feedback
- Disengagement
- Attitude changes
- Avoiding responsibility
```

### 6.2 Root Cause Analysis

**Before action, understand WHY:**

| Category | Examples | Solution |
|----------|----------|----------|
| Skill gap | New technology | Training, mentoring |
| Clarity | Unclear expectations | Better communication |
| Fit | Wrong role | Re-alignment |
| Personal | Life circumstances | Support, accommodation |
| Motivation | Disengagement | Address root cause |
| Culture | Team issues | Team intervention |

### 6.3 Performance Improvement Plan (PIP)

**When to use:**
- After informal feedback didn't work
- Clear underperformance vs expectations
- Documented issues
- Reasonable time given

**PIP Structure:**
```markdown
## Performance Improvement Plan

### Employee: [Name]
### Period: [Start - End, typically 30-90 days]
### Manager: [Name]

### Current Performance Issues
1. [Specific issue with examples]
2. [Specific issue with examples]

### Expected Performance
1. [Clear expectation with metric]
2. [Clear expectation with metric]

### Support Provided
- [Weekly 1-on-1]
- [Mentor assigned]
- [Training]

### Success Criteria
[What needs to be true to pass PIP]

### Check-in Schedule
- Week 1: [date]
- Week 2: [date]
- Week 4: [date]
- Final: [date]

### Consequences
If expectations not met by [date], 
[termination / role change / extended PIP]

Signatures:
Employee: _________ Date: _____
Manager: _________ Date: _____
HR: _________ Date: _____
```

### 6.4 PIP Best Practices

```
✅ DO:

- Be specific and measurable
- Provide real support
- Regular check-ins
- Document everything
- Give genuine chance to improve
- Involve HR

❌ DON'T:

- Use PIP as termination paperwork
- Set impossible goals
- Ignore during PIP period
- Skip documentation
- Make it punitive vs developmental
```

### 6.5 Exit Decisions

**When PIP fails:**
```
1. Documented failure to meet criteria
2. HR review
3. Legal review (если нужно)
4. Respectful exit conversation
5. Severance (per policy)
6. Transition plan
```

## 7. Compensation

### 7.1 Compensation Philosophy

**Components:**
```
Total Compensation:

- Base salary
- Bonus / Variable
- Equity / Stock
- Benefits
```

### 7.2 Performance и Compensation

**Link:**
```
High performer → Higher raises, bonus
Meets expectations → Standard raise
Below expectations → No raise / PIP
```

### 7.3 Conversations about Compensation

**When asked:**
```
1. Listen to their perspective
2. Explain factors (performance, market, budget)
3. Be honest about what you can/can't control
4. If unfair — advocate for them
5. Discuss non-monetary growth
```

**What you can say:**
```
"Based on your performance and our budget, 
your raise is X%. Here's how it compares to..."

"I've advocated for a higher increase. 
Let me share what's possible and timeline."
```

## 8. Rating Systems

### 8.1 Common Approaches

**Numeric (1-5):**
```
5 - Exceptional
4 - Exceeds
3 - Meets
2 - Below
1 - Unsatisfactory
```

**Forced distribution:**
```
Top 20% - High performers
Middle 70% - Meets expectations
Bottom 10% - Underperformers
```

**No ratings:**
```
Qualitative feedback only
Focus on development
No rankings
```

### 8.2 Pros and Cons

| System | Pros | Cons |
|--------|------|------|
| Numeric | Clear, comparable | Gaming, stress |
| Forced | Differentiation | Unfair if good team |
| No ratings | Development focus | Hard to make decisions |

## 💡 Key Takeaways

- **No surprises:** Continuous feedback, not annual surprise
- **Specific:** Examples and metrics, not generalities
- **Development focus:** Performance → Growth, not just rating
- **Early intervention:** Address issues before they escalate
- **Document:** Especially for underperformance
