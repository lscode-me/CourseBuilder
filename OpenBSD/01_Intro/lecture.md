## 1. Что такое OpenBSD

OpenBSD — это свободная Unix-подобная операционная система, основанная на 4.4BSD. Проект был основан в 1995 году Тео де Раадтом (Theo de Raadt) после его ухода из проекта NetBSD.

OpenBSD известна тремя главными качествами:
- **Безопасность** — проактивный подход к безопасности
- **Качество кода** — регулярные аудиты и чистый код  
- **Документация** — лучшие man-страницы в мире Unix

### 1.1 Краткая история

**1995** — Тео де Раадт форкнул NetBSD и создал OpenBSD

**1996** — Первый официальный релиз OpenBSD 2.0

**1997** — Начало регулярных аудитов кода на безопасность

**1999** — Создание OpenSSH — теперь стандарт для SSH

**2004** — Создание PF (Packet Filter) — мощный файрвол

**2006** — Появление LibreSSL (форк OpenSSL)

**2015** — Внедрение pledge() для ограничения системных вызовов

**2018** — Внедрение unveil() для ограничения доступа к файловой системе

**2023** — OpenBSD 7.4 с поддержкой vmm/vmd виртуализации

```sh
# Узнать версию OpenBSD
$ uname -a
OpenBSD puffy.my.domain 7.4 GENERIC.MP#0 amd64
```

**Output:**
```
OpenBSD puffy.my.domain 7.4 GENERIC.MP#0 amd64
```

### 1.2 Талисман — Puffy

Талисман OpenBSD — рыба Фугу (Puffy the Pufferfish). Фугу раздувается при опасности, что символизирует защитный характер OpenBSD. Каждый релиз сопровождается оригинальной песней и artwork с Puffy.

## 2. Философия OpenBSD

### 2.1 "Secure by Default"

Главный принцип OpenBSD — **безопасность по умолчанию**. Это означает:

- Минимум сервисов запущено после установки
- Все сетевые демоны выключены по умолчанию
- Консервативный подход к новым функциям
- Регулярные аудиты кода

**Сравнение с Linux:**

| Аспект | OpenBSD | Типичный Linux |
|--------|---------|----------------|
| SSH после установки | Включён, но только локально | Часто открыт для всех |
| Файрвол | PF выключен, но готов | Варьируется |
| Сервисы по умолчанию | Минимум | Много |
| X Window | Нужно включить | Часто автозапуск |

### 2.2 Код важнее функций

OpenBSD предпочитает:
- **Качество** над количеством функций
- **Простоту** над сложностью  
- **Безопасность** над производительностью
- **Корректность** над совместимостью

> **💡 Pro Tip:**  
> Если функция добавляет сложность и риски безопасности, OpenBSD скорее откажется от неё, чем включит "потому что все хотят".

### 2.3 Интегрированная система

В отличие от Linux, где ядро и userland разрабатываются отдельно, OpenBSD — это **интегрированная система**:

- Ядро и базовая система разрабатываются вместе
- Все компоненты тестируются как единое целое
- Релиз = полная система, не только ядро
- Обновления системы атомарны

```sh
# Базовая система OpenBSD включает:
$ ls /bin /sbin /usr/bin /usr/sbin | head -20
```

## 3. Ключевые инновации OpenBSD

OpenBSD создала множество технологий, которые сейчас используются повсеместно.

### 3.1 OpenSSH

**OpenSSH** — стандарт де-факто для безопасного удалённого доступа. Создан в OpenBSD в 1999 году.

```sh
# OpenSSH используется на ~90% серверов в интернете
$ ssh -V
OpenSSH_9.5, LibreSSL 3.8.2
```

**Output:**
```
OpenSSH_9.5, LibreSSL 3.8.2
```

Возможности OpenSSH:
- Шифрованные соединения
- Аутентификация по ключам
- Проброс портов (port forwarding)
- SFTP для передачи файлов
- Мультиплексирование соединений

### 3.2 PF (Packet Filter)

**PF** — мощный, но простой в настройке файрвол. Заменил IPFilter в 2001 году.

```sh
# Пример простого правила PF
$ cat /etc/pf.conf
# Разрешить весь исходящий трафик
pass out all

# Блокировать весь входящий по умолчанию
block in all

# Разрешить SSH
pass in on egress proto tcp to port 22
```

Особенности PF:
- Читаемый синтаксис
- Stateful filtering
- NAT и редирект
- Балансировка нагрузки
- Защита от DDoS

### 3.3 LibreSSL

**LibreSSL** — форк OpenSSL, созданный после уязвимости Heartbleed (2014).

```sh
# LibreSSL — версия по умолчанию в OpenBSD
$ openssl version
LibreSSL 3.8.2
```

**Output:**
```
LibreSSL 3.8.2
```

Улучшения в LibreSSL:
- Удалён устаревший код
- Улучшенный API
- Лучшая переносимость
- Современные алгоритмы

### 3.4 pledge() и unveil()

Уникальные механизмы безопасности OpenBSD.

**pledge()** — ограничивает системные вызовы процесса:

```c
// Программа обещает использовать только stdio и rpath
#include <unistd.h>

int main() {
    // После этого вызова программа не сможет
    // открывать сетевые соединения, форкаться и т.д.
    pledge("stdio rpath", NULL);
    
    // Безопасная работа с файлами
    // ...
}
```

**unveil()** — ограничивает видимость файловой системы:

```c
#include <unistd.h>

int main() {
    // Программа видит только /etc и /var/log
    unveil("/etc", "r");      // только чтение
    unveil("/var/log", "rw"); // чтение и запись
    unveil(NULL, NULL);       // заблокировать добавление путей
    
    // Теперь доступ к /home вызовет ошибку
}
```

> **🔒 Security:**  
> Даже если злоумышленник получит контроль над программой с pledge/unveil, его возможности будут сильно ограничены.

### 3.5 ASLR, W^X, и другие митигации

OpenBSD пионер в технологиях защиты памяти:

| Технология | Описание | Когда добавлена |
|------------|----------|-----------------|
| W^X | Память либо исполняемая, либо записываемая | 2003 |
| ASLR | Рандомизация адресного пространства | 2003 |
| ProPolice | Защита стека | 2002 |
| KARL | Рандомизация ядра при загрузке | 2017 |
| RETGUARD | Защита возврата из функций | 2018 |

## 4. Сравнение с другими ОС

### 4.1 OpenBSD vs FreeBSD

| Аспект | OpenBSD | FreeBSD |
|--------|---------|---------|
| Фокус | Безопасность | Производительность |
| Документация | Лучшая | Хорошая |
| Пакеты | ~11,000 | ~40,000 |
| ZFS | Нет | Да |
| Виртуализация | vmm (простая) | bhyve (мощная) |
| Релизы | 2 раза в год | ~1 раз в год |

### 4.2 OpenBSD vs Linux

| Аспект | OpenBSD | Linux |
|--------|---------|-------|
| Лицензия | BSD | GPL |
| Ядро | Монолитное, интегрированное | Отдельное от userland |
| Init система | rc.d (простая) | systemd/openrc/etc |
| Драйверы | Меньше, но стабильные | Больше |
| Целевая аудитория | Серверы, файрволы | Всё |
| Desktop | Минималистичный | Полноценный |

### 4.3 Когда выбрать OpenBSD

✅ **Выбирайте OpenBSD когда:**
- Нужен надёжный файрвол/роутер
- Безопасность критически важна
- Хотите простую, понятную систему
- Цените качественную документацию
- Строите VPN-сервер
- Нужна стабильная почтовая система

❌ **OpenBSD не лучший выбор когда:**
- Нужна максимальная производительность
- Требуется специфическое железо
- Нужен Desktop с играми
- Требуется ZFS
- Нужно много пакетов

## 5. Архитектура системы

### 5.1 Структура каталогов

```sh
# Стандартная иерархия OpenBSD
/           # Корень
├── bin/    # Базовые утилиты пользователя
├── sbin/   # Базовые утилиты администратора
├── etc/    # Конфигурационные файлы
├── dev/    # Устройства
├── home/   # Домашние каталоги пользователей
├── root/   # Домашний каталог root
├── tmp/    # Временные файлы
├── usr/    # Вторичная иерархия
│   ├── bin/     # Пользовательские утилиты
│   ├── sbin/    # Административные утилиты
│   ├── lib/     # Библиотеки
│   ├── include/ # Заголовочные файлы
│   ├── share/   # Архитектурно-независимые данные
│   ├── local/   # Локально установленное ПО (пакеты)
│   └── src/     # Исходный код системы
├── var/    # Изменяемые данные
│   ├── log/     # Логи
│   ├── mail/    # Почта
│   └── run/     # PID файлы
└── altroot/ # Альтернативный root (для восстановления)
```

### 5.2 Особенности файловой системы

OpenBSD использует **FFS2** (Fast File System) с расширениями:

```sh
# Просмотр смонтированных файловых систем
$ mount
/dev/sd0a on / type ffs (local)
/dev/sd0d on /home type ffs (local, nodev, nosuid)
/dev/sd0e on /tmp type ffs (local, nodev, nosuid)
/dev/sd0f on /usr type ffs (local, nodev)
/dev/sd0g on /var type ffs (local, nodev, nosuid)
```

**Output:**
```
/dev/sd0a on / type ffs (local)
/dev/sd0d on /home type ffs (local, nodev, nosuid)
/dev/sd0e on /tmp type ffs (local, nodev, nosuid)
/dev/sd0f on /usr type ffs (local, nodev)
/dev/sd0g on /var type ffs (local, nodev, nosuid)
```

Особенности:
- **Soft Updates** — целостность без журнала
- **nodev, nosuid** — защита разделов
- **Шифрование** — встроенная поддержка через softraid

### 5.3 Загрузка системы

Процесс загрузки OpenBSD:

1. **BIOS/UEFI** → находит загрузчик
2. **biosboot/boot** → загружает ядро
3. **Ядро (bsd)** → инициализирует железо
4. **init** → запускает /etc/rc
5. **/etc/rc** → запускает службы из /etc/rc.conf.local

```sh
# Просмотр процесса загрузки
$ dmesg | head -30
```

## 6. Релизный цикл

### 6.1 График релизов

OpenBSD выпускает новые версии **дважды в год**:
- **1 мая** — весенний релиз
- **1 ноября** — осенний релиз

```sh
# Текущая версия и дата
$ uname -r
7.4

$ cat /etc/motd
OpenBSD 7.4 (GENERIC.MP) #0: Mon Oct  9 13:57:11 MDT 2023
```

### 6.2 Поддержка версий

Каждая версия поддерживается **1 год** (два релизных цикла):

| Версия | Релиз | Окончание поддержки |
|--------|-------|---------------------|
| 7.4 | Окт 2023 | Окт 2024 |
| 7.3 | Апр 2023 | Апр 2024 |
| 7.2 | Окт 2022 | ❌ Не поддерживается |

> **⚠️ Warning:**  
> Всегда используйте поддерживаемую версию. Обновление между релизами — обязательная процедура.

### 6.3 Stable vs Current

**-stable** — текущий релиз с патчами безопасности
**-current** — разработческая ветка (для разработчиков)

```sh
# Проверить, какую ветку используете
$ sysctl kern.version
kern.version=OpenBSD 7.4 (GENERIC.MP) #0: Mon Oct  9 13:57:11 MDT 2023
```

## 8. Практическое применение

### 8.1 Типичные сценарии использования

**Файрвол/Роутер:**
```
┌─────────┐     ┌──────────────┐     ┌─────────┐
│ Internet│────▶│   OpenBSD    │────▶│   LAN   │
└─────────┘     │   (PF/NAT)   │     └─────────┘
                └──────────────┘
```

**VPN-сервер:**
```sh
# OpenBSD включает WireGuard в базовой системе
$ ifconfig wg0 create
$ cat /etc/hostname.wg0
wgkey <private_key>
wgpeer <public_key> wgendpoint 1.2.3.4 51820 wgaip 10.0.0.2/32
inet 10.0.0.1/24
```

**Почтовый сервер:**
```sh
# OpenSMTPD — почтовый сервер из OpenBSD
$ cat /etc/mail/smtpd.conf
listen on egress
action "local" mbox
match from any for local action "local"
```

**Web-сервер:**
```sh
# httpd — встроенный веб-сервер
$ cat /etc/httpd.conf
server "example.com" {
    listen on * port 80
    root "/htdocs/example.com"
}
```
