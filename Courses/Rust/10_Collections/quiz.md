## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Все варианты правильны: Vec::new() создаёт пустой, vec![] с начальными значениями, with_capacity с ёмкостью |
| 2 | A | Выход за границы вызывает панику во время выполнения |
| 3 | B | insert() добавляет или обновляет элемент в HashMap |
| 4 | B | String владеет данными и может расти, &str — неизменяемая ссылка на строковые данные |
| 5 | D | collect() собирает итератор в коллекцию (Vec, HashMap и т.д.) |
| 6 | A | push() добавляет один символ (char), push_str() добавляет строковый срез (&str) |
| 7 | A | entry() возвращает Entry для условной вставки или обновления значения |
| 8 | A | capacity — выделенная память, может быть больше текущего размера для эффективности |
| 9 | A | Итерация по HashMap: `for (key, value) in &map` |
| 10 | B | String хранит UTF-8, где символы могут занимать разное количество байтов |
| 11 | C | get() возвращает Option<&T>, [] паникует при выходе за границы |
| 12 | A | Итераторы ленивы — вычисления происходят только при вызове методов потребления (collect, next) |
| 13 | C | Цепочка map().filter().collect() преобразует, фильтрует и собирает в коллекцию |
| 14 | B | or_insert() вставляет значение, если ключа нет в HashMap |
| 15 | A | Срез строки получается через `&s[0..5]`, но нужно быть осторожным с границами UTF-8 |
| 16 | C | with_capacity предварительно выделяет память, избегая перераспределений |
| 17 | A | Ownership зависит от типа итерации: & — заимствование, &mut — изменяемое заимствование, into_iter — владение |
| 18 | B | Ключи получаются через метод keys(), возвращающий итератор |
| 19 | B | format! форматирует строку и возвращает String без владения исходными данными |
| 20 | B | fold() накапливает значение через функцию, применяя её к каждому элементу |
