## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Trait определяет общее поведение, которое могут реализовывать разные типы |
| 2 | B | Generics позволяют писать код, работающий с разными типами |
| 3 | A | Trait bounds — это ограничения на generic типы, гарантирующие наличие нужного поведения |
| 4 | B | derive(Debug) автоматически генерирует реализацию Debug trait |
| 5 | A | Методы в trait могут иметь реализацию по умолчанию, которую можно переопределить |
| 6 | D | Generic структура создаётся с указанием generic параметра: `struct Point<T> { x: T, y: T }` |
| 7 | A | Множественные trait bounds указываются через `+`: `T: Trait1 + Trait2` |
| 8 | B | where clause упрощает синтаксис для множественных bounds, особенно в сложных случаях |
| 9 | C | Copy — автоматическое копирование (побитовое), Clone — явное копирование через метод |
| 10 | B | PartialEq позволяет сравнивать значения на равенство (== и !=) |
| 11 | A | Associated types — типы, связанные с trait, определяются в определении trait |
| 12 | B | Trait objects обеспечивают динамическую диспетчеризацию через указатели (dyn Trait) |
| 13 | B | impl Trait в возвращаемом типе возвращает любой тип, реализующий указанный trait |
| 14 | C | Generic функция создаётся с указанием generic параметра: `fn func<T>() {}` |
| 15 | C | Trait bounds в impl блоках позволяют условно реализовывать методы для типов с определёнными traits |
| 16 | D | Реализацию по умолчанию можно переопределить в impl блоке для конкретного типа |
| 17 | A | Ord обеспечивает полное упорядочивание (всегда можно сравнить), PartialOrd — частичное |
| 18 | B | Display trait используется для форматирования для пользователя ({} в println!) |
| 19 | C | From и Into traits обеспечивают преобразование между типами |
| 20 | A | Можно иметь generic методы в impl блоке, независимо от того, generic структура или нет |
