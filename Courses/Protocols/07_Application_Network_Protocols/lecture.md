## 1. Введение: прикладные протоколы

**Прикладные протоколы** работают на верхнем уровне сетевого стека и определяют взаимодействие между приложениями. Они используют транспортные протоколы (TCP/UDP) для передачи данных, но определяют семантику — что означают сообщения и как на них реагировать.

В этом модуле мы рассмотрим:

1. **HTTP** — протокол передачи гипертекста для веба
2. **SMTP** — протокол передачи почты
3. **FTP** — протокол передачи файлов
4. **WebSocket** — протокол двусторонней коммуникации
5. **Текстовые vs бинарные** — компромиссы в дизайне протоколов

## 2. HTTP (HyperText Transfer Protocol)

### 2.1 Назначение

HTTP — основа веба, обеспечивает передачу гипертекста и других данных.

**Характеристики:**

- Текстовый протокол
- Клиент-серверная модель
- Без состояния (stateless)
- Основан на TCP

### 2.2 Структура HTTP запроса

```
GET /api/users/123 HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: application/json
Authorization: Bearer token123
```

**Компоненты:**

- **Строка запроса**: метод, путь, версия

- **Заголовки**: метаданные (Host, User-Agent, Accept, и т.д.)

- **Пустая строка**: разделитель

- **Тело**: данные (для POST, PUT)

### 2.3 Структура HTTP ответа

```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 85
Date: Mon, 15 Jan 2024 10:00:00 GMT

{"id": 123, "name": "John Doe", "email": "john@example.com"}
```

**Компоненты:**

- **Строка статуса**: версия, статус-код, описание

- **Заголовки**: метаданные (Content-Type, Content-Length, и т.д.)

- **Пустая строка**: разделитель

- **Тело**: данные ответа

### 2.4 HTTP методы

| Метод | Назначение | Идемпотентность | Безопасность |
|-------|------------|-----------------|--------------|
| GET | Получить ресурс | Да | Да |
| POST | Создать ресурс | Нет | Нет |
| PUT | Обновить ресурс | Да | Нет |
| DELETE | Удалить ресурс | Да | Нет |
| PATCH | Частично обновить | Нет | Нет |
| HEAD | Получить заголовки | Да | Да |

### 2.5 HTTP статус-коды

**2xx — Успех:**

- 200 OK — запрос выполнен
- 201 Created — ресурс создан
- 204 No Content — успех без тела ответа

**3xx — Перенаправление:**

- 301 Moved Permanently — постоянное перенаправление
- 302 Found — временное перенаправление

**4xx — Ошибка клиента:**

- 400 Bad Request — некорректный запрос
- 401 Unauthorized — требуется авторизация
- 404 Not Found — ресурс не найден

**5xx — Ошибка сервера:**

- 500 Internal Server Error — ошибка сервера
- 503 Service Unavailable — сервис недоступен

### 2.6 HTTP/2 и HTTP/3

**HTTP/2:**

- Бинарный протокол (не текстовый)
- Мультиплексирование: несколько запросов в одном TCP соединении
- Сжатие заголовков
- Server push

**HTTP/3:**

- Основан на QUIC (UDP)
- Быстрее установление соединения
- Лучше работает при потере пакетов

## 3. SMTP (Simple Mail Transfer Protocol)

### 3.1 Назначение

SMTP обеспечивает передачу электронной почты между серверами.

**Характеристики:**

- Текстовый протокол
- Основан на TCP (порт 25, 587)
- Последовательность команд и ответов

### 3.2 Структура SMTP взаимодействия

```
Клиент: HELO client.example.com
Сервер: 250 Hello client.example.com

Клиент: MAIL FROM:<sender@example.com>
Сервер: 250 OK

Клиент: RCPT TO:<recipient@example.com>
Сервер: 250 OK

Клиент: DATA
Сервер: 354 Start mail input; end with <CRLF>.<CRLF>

Клиент: From: sender@example.com
        To: recipient@example.com
        Subject: Test
        
        Hello, this is a test email.
        .
Сервер: 250 OK: queued as 12345

Клиент: QUIT
Сервер: 221 Bye
```

**Команды:**

- **HELO/EHLO**: идентификация клиента

- **MAIL FROM**: адрес отправителя

- **RCPT TO**: адрес получателя

- **DATA**: начало передачи сообщения

- **QUIT**: завершение сессии

### 3.3 Коды ответов SMTP

**2xx — Успех:**

- 220 Service ready
- 250 OK

**3xx — Промежуточный успех:**

- 354 Start mail input

**4xx — Временная ошибка:**

- 421 Service not available
- 450 Mailbox unavailable

**5xx — Постоянная ошибка:**

- 550 Mailbox not found
- 552 Mailbox full

## 4. FTP (File Transfer Protocol)

### 4.1 Назначение

FTP обеспечивает передачу файлов между клиентом и сервером.

**Характеристики:**

- Текстовый протокол
- Два соединения: control (команды) и data (файлы)
- Основан на TCP (порт 21 для control)

### 4.2 Два соединения FTP

**Control connection:**

- Порт 21
- Передача команд и ответов
- Постоянное соединение

**Data connection:**

- Порт 20 (активный режим) или случайный (пассивный режим)
- Передача файлов и листингов
- Устанавливается для каждой операции

### 4.3 Пример FTP сессии

```
Клиент: USER username
Сервер: 331 Password required

Клиент: PASS password
Сервер: 230 User logged in

Клиент: PWD
Сервер: 257 "/home/user"

Клиент: LIST
Сервер: 150 Opening data connection
        [передача листинга через data connection]
        226 Transfer complete

Клиент: RETR file.txt
Сервер: 150 Opening data connection
        [передача файла через data connection]
        226 Transfer complete

Клиент: QUIT
Сервер: 221 Goodbye
```

### 4.4 Активный vs пассивный режим

**Активный режим:**

- Клиент открывает порт для data connection
- Сервер подключается к клиенту
- Проблемы с NAT и firewall

**Пассивный режим (PASV):**

- Сервер открывает порт для data connection
- Клиент подключается к серверу
- Решает проблемы с NAT и firewall

## 5. WebSocket

### 5.1 Назначение

WebSocket обеспечивает двустороннюю коммуникацию между клиентом и сервером в реальном времени.

**Характеристики:**

- Полнодуплексный протокол
- Основан на TCP
- Начинается как HTTP, затем upgrade
- Эффективнее HTTP для частых обновлений

### 5.2 Установление WebSocket соединения

**HTTP Upgrade запрос:**
```
GET /chat HTTP/1.1
Host: example.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: x3JJHMbDL1EzLkh9GBhXDw==
Sec-WebSocket-Version: 13
```

**HTTP Upgrade ответ:**
```
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: HSmrc0sMlYUkAGmm5OPpG2HaGWk=
```

**После handshake:**

- Соединение остаётся открытым
- Обе стороны могут отправлять сообщения в любое время
- Низкий overhead (не нужно повторять заголовки HTTP)

### 5.3 Применение WebSocket

**Use cases:**

- Чаты и мессенджеры
- Live обновления (биржи, мониторинг)
- Онлайн игры
- Коллаборативные редакторы

**Сравнение с HTTP:**

- HTTP: запрос → ответ (цикл повторяется)
- WebSocket: установление → постоянное двустороннее общение

## 6. Текстовые vs бинарные протоколы

### 6.1 Текстовые протоколы

**Примеры:** HTTP/1.1, SMTP, FTP

**Преимущества:**

- **Читаемость**: можно читать и отлаживать в текстовом редакторе

- **Простота реализации**: легко парсить и генерировать

- **Совместимость**: работают в различных системах без проблем с endianness

- **Расширяемость**: легко добавлять новые поля

**Недостатки:**

- **Размер**: текстовое представление больше бинарного

- **Производительность**: парсинг текста медленнее бинарного формата

- **Overhead**: избыточность (ключи, разделители)

### 6.2 Бинарные протоколы

**Примеры:** HTTP/2, HTTP/3, протоколы баз данных

**Преимущества:**

- **Компактность**: меньший размер сообщений

- **Производительность**: быстрый парсинг

- **Эффективность**: меньше overhead

**Недостатки:**

- **Нечитаемость**: нужны специальные инструменты для отладки

- **Сложность**: сложнее реализовать и поддерживать

- **Совместимость**: нужно учитывать endianness, выравнивание

### 6.3 Компромиссы

**Когда использовать текстовые:**

- Простота и отладка важнее производительности
- Совместимость с различными системами
- Протокол используется редко (overhead незначителен)

**Когда использовать бинарные:**

- Производительность критична
- Большой объём данных
- Ограниченная пропускная способность

**Гибридный подход:**

- HTTP/2: бинарные кадры, но заголовки сжимаются (не чисто бинарный)
- gRPC: бинарный (Protocol Buffers), но с текстовыми метаданными

## 7. Сравнение протоколов

| Протокол | Тип | Транспорт | Соединение | Use case |
|----------|-----|-----------|------------|----------|
| HTTP | Текст | TCP | Без состояния | Веб, API |
| SMTP | Текст | TCP | С состоянием | Email |
| FTP | Текст | TCP (2 соед.) | С состоянием | Файлы |
| WebSocket | Бинарный | TCP | Постоянное | Real-time |
| HTTP/2 | Бинарный | TCP | Без состояния | Веб |
| HTTP/3 | Бинарный | UDP (QUIC) | Без состояния | Веб |

---

## 💡 Key Takeaways

- **HTTP — основа веба**: Текстовый, без состояния, основан на запрос-ответ модели. HTTP/2 и HTTP/3 улучшают производительность через бинарный формат и мультиплексирование.

- **SMTP и FTP — специализированные протоколы**: SMTP для email, FTP для файлов. Оба текстовые, основаны на командах и ответах, но FTP использует два соединения.

- **WebSocket для real-time**: Полнодуплексный, постоянное соединение, низкий overhead. Идеален для чатов, live updates, игр.

- **Текстовые vs бинарные — компромисс**: Текстовые просты и отлаживаемы, бинарные эффективны и быстры. Выбор зависит от требований к производительности и сложности.

- **Прикладные протоколы строятся на транспортных**: Все рассмотренные протоколы используют TCP (или UDP для HTTP/3), фокусируясь на семантике приложений, а не на надёжности передачи.
