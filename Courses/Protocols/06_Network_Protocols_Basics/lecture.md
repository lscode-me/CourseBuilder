## 1. Введение: сетевой стек

Сетевые протоколы организованы в **стек** — иерархию протоколов, где каждый слой использует услуги слоя ниже и предоставляет услуги слою выше. Это позволяет разделить ответственность: нижние слои отвечают за физическую передачу, верхние — за семантику приложений.

В этом модуле мы рассмотрим основные протоколы сетевого стека:

1. **Ethernet** — канальный уровень, передача между соседними узлами
2. **IP** — сетевой уровень, маршрутизация пакетов
3. **TCP vs UDP** — транспортный уровень, надёжность vs скорость

---

## 2. Модель слоёв

### 2.1 Модель OSI (7 слоёв)

**7. Прикладной (Application)**: HTTP, SMTP, FTP
**6. Представления (Presentation)**: шифрование, сжатие
**5. Сеансовый (Session)**: управление сессиями
**4. Транспортный (Transport)**: TCP, UDP
**3. Сетевой (Network)**: IP
**2. Канальный (Data Link)**: Ethernet
**1. Физический (Physical)**: кабели, сигналы

### 2.2 Модель TCP/IP (4 слоя)

**Прикладной (Application)**: HTTP, SMTP, FTP
**Транспортный (Transport)**: TCP, UDP
**Сетевой (Internet)**: IP
**Канальный (Link)**: Ethernet

**Принцип:** Каждый слой добавляет заголовок к данным, формируя инкапсуляцию.

## 3. Ethernet (канальный уровень)

### 3.1 Назначение

Ethernet обеспечивает передачу данных между узлами в одной локальной сети (LAN).

**Роль:**

- Определяет формат кадров (frames)
- Контролирует доступ к среде (CSMA/CD)
- Обеспечивает обнаружение ошибок (CRC)

### 3.2 Структура Ethernet кадра

```
[Preamble] [Destination MAC] [Source MAC] [Type] [Data] [CRC]
    8           6 байт          6 байт      2     46-1500  4
```

**Поля:**

- **Destination MAC**: адрес получателя (48 бит)

- **Source MAC**: адрес отправителя (48 бит)

- **Type**: тип данных (например, 0x0800 для IP)

- **Data**: полезная нагрузка (46-1500 байт)

- **CRC**: проверка целостности

### 3.3 MAC адреса

**MAC (Media Access Control)** адрес — уникальный идентификатор сетевого интерфейса.

**Формат:** 6 байт, записывается как `AA:BB:CC:DD:EE:FF`

**Использование:** Ethernet использует MAC адреса для доставки кадров в локальной сети.

## 4. IP (сетевой уровень)

### 4.1 Назначение

IP (Internet Protocol) обеспечивает маршрутизацию пакетов между разными сетями.

**Роль:**

- Определяет формат IP пакетов
- Обеспечивает маршрутизацию через сети
- Не гарантирует доставку (best effort)

### 4.2 Структура IP пакета

```
[Version] [IHL] [Type] [Length] [ID] [Flags] [Fragment] [TTL] [Protocol] [Checksum] [Source IP] [Dest IP] [Data]
   4         4      8      16     16     3        13       8       8         16         32        32     вариативно
```

**Ключевые поля:**

- **Source IP**: IP адрес отправителя (32 бит для IPv4)

- **Dest IP**: IP адрес получателя (32 бит для IPv4)

- **TTL (Time To Live)**: максимальное количество хопов (предотвращает бесконечные циклы)

- **Protocol**: тип данных (6 для TCP, 17 для UDP)

### 4.3 IP адреса

**IPv4:** 32 бита, записывается как `192.168.1.1`
**IPv6:** 128 бит, записывается как `2001:0db8::1`

**Маршрутизация:** IP пакеты маршрутизируются от источника к назначению через промежуточные узлы (роутеры).

## 5. TCP (Transmission Control Protocol)

### 5.1 Назначение

TCP обеспечивает **надёжную** передачу данных между приложениями.

**Характеристики:**

- **Надёжность**: гарантирует доставку и порядок

- **Соединение-ориентированный**: требует установления соединения

- **Полнодуплексный**: одновременная передача в обе стороны

- **Потоковый**: передаёт поток байтов, не границы сообщений

### 5.2 Установление соединения (3-way handshake)

```
Клиент: SYN (seq=x)
Сервер: SYN-ACK (seq=y, ack=x+1)
Клиент: ACK (seq=x+1, ack=y+1)
        [соединение установлено]
```

### 5.3 Структура TCP сегмента

```
[Source Port] [Dest Port] [Seq Number] [Ack Number] [Flags] [Window] [Checksum] [Data]
    16           16          32           32          6       16        16      вариативно
```

**Ключевые поля:**

- **Ports**: идентифицируют приложения (16 бит каждый)

- **Seq Number**: порядковый номер байта

- **Ack Number**: подтверждение получения

- **Flags**: SYN, ACK, FIN, RST

- **Window**: размер окна для flow control

### 5.4 Надёжность TCP

**Механизмы:**

- **Последовательные номера**: порядок байтов

- **Подтверждения**: ACK для полученных данных

- **Повторная отправка**: при отсутствии ACK

- **Таймауты**: определение потерянных пакетов

- **Контроль потока**: window size для предотвращения переполнения

---

## 6. UDP (User Datagram Protocol)

### 6.1 Назначение

UDP обеспечивает **быструю** передачу данных без гарантий.

**Характеристики:**

- **Ненадёжный**: не гарантирует доставку и порядок

- **Без соединения**: отправка без установления соединения

- **Простой**: минимальный overhead

- **Датаграмный**: передаёт отдельные сообщения

### 6.2 Структура UDP датаграммы

```
[Source Port] [Dest Port] [Length] [Checksum] [Data]
    16           16         16        16      вариативно
```

**Минимальный overhead:** только порты, длина и checksum.

### 6.3 Когда использовать UDP

**Применение:**

- **DNS**: быстрые запросы, не критична потеря

- **Видео/аудио стриминг**: лучше потерять пакет, чем задержка

- **Игры**: низкая задержка важнее надёжности

- **Мониторинг**: периодические метрики, потеря допустима

---

## 7. TCP vs UDP

### 7.1 Сравнение

| Характеристика | TCP | UDP |
|----------------|-----|-----|
| Надёжность | Гарантирует доставку | Не гарантирует |
| Порядок | Гарантирует порядок | Не гарантирует |
| Соединение | Требует установления | Без соединения |
| Overhead | Высокий (заголовки, ACK) | Низкий |
| Скорость | Медленнее (из-за надёжности) | Быстрее |
| Использование | HTTP, SMTP, FTP | DNS, видео, игры |

### 7.2 Выбор протокола

**Используйте TCP, когда:**

- Нужна гарантия доставки (файлы, веб-страницы)
- Важен порядок данных
- Можно жертвовать скоростью ради надёжности

**Используйте UDP, когда:**

- Скорость важнее надёжности (видео, игры)
- Потеря данных допустима
- Нужна минимальная задержка

## 8. Инкапсуляция пакетов

### 8.1 Процесс инкапсуляции

Данные приложения проходят через слои, каждый добавляет свой заголовок:

```
Приложение: "Hello"
    ↓
TCP:  [TCP заголовок] "Hello"
    ↓
IP:   [IP заголовок] [TCP заголовок] "Hello"
    ↓
Ethernet: [Ethernet заголовок] [IP заголовок] [TCP заголовок] "Hello"
```

### 8.2 Декодирование

При получении каждый слой:

1. Проверяет свой заголовок
2. Извлекает данные для следующего слоя
3. Передаёт выше

**Пример:**
```
Ethernet: проверяет MAC, извлекает IP пакет
    ↓
IP: проверяет IP адрес, извлекает TCP сегмент
    ↓
TCP: проверяет порт, извлекает данные
    ↓
Приложение: получает "Hello"
```

## 💡 Key Takeaways

- **Сетевой стек — иерархия протоколов**: Каждый слой (Ethernet, IP, TCP/UDP) решает свою задачу и использует услуги слоя ниже.

- **Ethernet для локальной сети, IP для интернета**: Ethernet обеспечивает передачу в LAN через MAC адреса, IP обеспечивает маршрутизацию между сетями через IP адреса.

- **TCP для надёжности, UDP для скорости**: TCP гарантирует доставку и порядок, но медленнее; UDP быстрее, но не гарантирует доставку. Выбор зависит от требований.

- **Инкапсуляция создаёт слои**: Каждый протокол добавляет заголовок, создавая вложенную структуру. Это позволяет разделить ответственность и упростить реализацию.

- **Порты идентифицируют приложения**: TCP и UDP используют порты для идентификации приложений на одном хосте, позволяя множеству приложений работать одновременно.
