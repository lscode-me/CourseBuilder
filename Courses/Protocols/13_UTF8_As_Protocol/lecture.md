## 1. Введение: кодировки как протоколы

**Кодировка** — это протокол интерпретации байтов как текста.

**Без протокола:**
```
Байты: 0x48 0x65 0x6C 0x6C 0x6F
Что это? Текст? Число? Команда?
```

**С протоколом (UTF-8):**
```
Байты: 0x48 0x65 0x6C 0x6C 0x6F
UTF-8: "Hello"
```

**Кодировка — это договорённость** между producer (кто создаёт байты) и consumer (кто читает байты) о том, как интерпретировать данные.

## 2. UTF-8 как протокол

### 2.1 Что кодирует UTF-8

**Unicode** определяет набор символов (codepoints):
- U+0041 = 'A'
- U+0420 = 'Р' (русская)
- U+1F600 = '😀' (emoji)

**UTF-8** кодирует Unicode codepoints в байты.

### 2.2 Структура UTF-8

**1 байт (ASCII, U+0000 — U+007F):**
```
0xxxxxxx
```
Пример: 'A' = U+0041 = 0x41 = 01000001

**2 байта (U+0080 — U+07FF):**
```
110xxxxx 10xxxxxx
```
Пример: 'Ф' = U+0424 = 11010000 10100100

**3 байта (U+0800 — U+FFFF):**
```
1110xxxx 10xxxxxx 10xxxxxx
```

**4 байта (U+10000 — U+10FFFF):**
```
11110xxx 10xxxxxx 10xxxxxx 10xxxxxx
```

### 2.3 Самосинхронизация

**Ключевая особенность UTF-8:** можно определить границы символов, начав с любого байта.

**Правила:**

- Если байт начинается с `0`: это 1-байтовый символ
- Если байт начинается с `110`, `1110`, `11110`: начало многобайтового символа
- Если байт начинается с `10`: продолжение символа

**Пример:**
```
Байты: ... 0x91 0xD0 0xA4 0x48 ...
         ↑    ↑    ↑    ↑
         ?    начало  продолжение  начало
                2-байт            1-байт

UTF-8: ... [invalid] 'Ф' 'H' ...
```

Можно восстановиться после ошибки, найдя следующий валидный старт-байт.

## 3. Producer и Consumer

### 3.1 Роли

**Producer (производитель):**

- Создаёт текст
- Кодирует в UTF-8 байты
- Ответственность: создать валидный UTF-8

**Consumer (потребитель):**

- Читает байты
- Декодирует UTF-8 в Unicode
- Ответственность: правильно интерпретировать или обработать ошибки

### 3.2 Пример: Producer

```python
text = "Привет, мир! 😀"
utf8_bytes = text.encode('utf-8')
print(utf8_bytes)
print(f"Length: {len(utf8_bytes)} bytes")
```

**Output:**
```
b'\xd0\x9f\xd1\x80\xd0\xb8\xd0\xb2\xd0\xb5\xd1\x82, \xd0\xbc\xd0\xb8\xd1\x80! \xf0\x9f\x98\x80'
Length: 26 bytes
```

### 3.3 Пример: Consumer

```python
utf8_bytes = b'\xd0\x9f\xd1\x80\xd0\xb8\xd0\xb2\xd0\xb5\xd1\x82'
text = utf8_bytes.decode('utf-8')
print(text)
print(f"Length: {len(text)} characters")
```

**Output:**
```
Привет
Length: 6 characters
```

### 3.4 Контракт

**Producer обещает:**

- Байты соответствуют UTF-8 спецификации
- Нет invalid sequences

**Consumer обещает:**

- Правильно декодировать валидный UTF-8
- Обработать или сообщить об ошибках для invalid sequences

## 4. Ошибки кодировки

### 4.1 Типы ошибок

**Invalid start byte:**
```
Байты: 0x80 (10000000)
       ↑
    Ожидается 0xxxxxxx или 11xxxxxx
```

**Missing continuation bytes:**
```
Байты: 0xD0 (11010000) [конец данных]
       ↑
    Ожидается продолжение 10xxxxxx
```

**Invalid continuation bytes:**
```
Байты: 0xD0 0x20
       ↑    ↑
    11010000 00100000 (ожидается 10xxxxxx)
```

**Overlong encoding:**
```
Байты: 0xC0 0x80
UTF-8: декодируется как U+0000
Ошибка: должно быть закодировано как 0x00 (1 байт)
```

### 4.2 Обработка ошибок

**Strict (по умолчанию):**
```python
invalid_utf8 = b'\xff\xfe'
try:
    text = invalid_utf8.decode('utf-8')
except UnicodeDecodeError as e:
    print(f"Error: {e}")
```

**Output:**
```
Error: 'utf-8' codec can't decode byte 0xff in position 0: invalid start byte
```

**Replace (замена на �):**
```python
invalid_utf8 = b'Hello \xff World'
text = invalid_utf8.decode('utf-8', errors='replace')
print(text)
```

**Output:**
```
Hello � World
```

**Ignore (пропуск):**
```python
invalid_utf8 = b'Hello \xff World'
text = invalid_utf8.decode('utf-8', errors='ignore')
print(text)
```

**Output:**
```
Hello  World
```

### 4.3 Причины ошибок

1. **Неправильная кодировка**: данные не в UTF-8 (например, Windows-1251)
2. **Коррупция данных**: битые биты при передаче
3. **Несовпадение кодировок**: producer использует одну, consumer — другую
4. **Бинарные данные**: попытка декодировать не-текст как текст

## 5. Почему UTF-8 — хороший протокол

### 5.1 Обратная совместимость с ASCII

**ASCII (1 байт, 0-127):**
```
'A' = 0x41 (01000001)
```

**UTF-8:**
```
'A' = 0x41 (01000001)  — то же самое!
```

Любой валидный ASCII — валидный UTF-8. Это обеспечило плавный переход.

### 5.2 Самосинхронизация

Можно найти границы символов, начав с любого места:

```python
utf8_bytes = "Привет".encode('utf-8')
print(utf8_bytes)

# Начнём с середины

for i in range(len(utf8_bytes)):
    try:
        text = utf8_bytes[i:].decode('utf-8')
        print(f"From byte {i}: {text}")
    except UnicodeDecodeError:
        print(f"From byte {i}: [invalid start]")
```

**Output:**
```
b'\xd0\x9f\xd1\x80\xd0\xb8\xd0\xb2\xd0\xb5\xd1\x82'
From byte 0: Привет
From byte 1: [invalid start]
From byte 2: ривет
From byte 3: [invalid start]
...
```

### 5.3 Эффективность

**Для ASCII:** 1 байт/символ (эффективно для английского)
**Для кириллицы:** 2 байта/символ (компактнее, чем UTF-16 для ASCII)
**Для emoji:** 4 байта/символ

**Сравнение с UTF-16:**
```
Текст: "Hello мир 😀"
UTF-8:  5 + 6*2 + 1 + 4 = 22 байта
UTF-16: 5*2 + 3*2 + 1*2 + 2*2 = 24 байта
```

UTF-8 компактнее для текста с преобладанием ASCII.

### 5.4 Нет BOM (Byte Order Mark)

**UTF-16:** требует BOM для определения endianness (0xFEFF или 0xFFFE)
**UTF-8:** не требует BOM (порядок байтов фиксирован)

Хотя BOM может использоваться (0xEF 0xBB 0xBF), он опционален.

### 5.5 Устойчивость к ошибкам

**Ошибка в 1 байте:**
```
UTF-8:  повреждён 1 символ
UTF-16: может повредить несколько символов (если surrogates)
```

## 6. Примеры использования

### 6.1 Чтение файла

```python
# Правильно: указываем кодировку

with open('file.txt', 'r', encoding='utf-8') as f:
    text = f.read()
    print(text)

# Неправильно: используется system default (может быть не UTF-8)

with open('file.txt', 'r') as f:  # Опасно!
    text = f.read()
```

### 6.2 HTTP

**Правильный заголовок:**
```
Content-Type: text/html; charset=UTF-8
```

Это сообщает consumer, что данные в UTF-8.

### 6.3 База данных

```sql
CREATE DATABASE mydb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

`utf8mb4` в MySQL — полный UTF-8 (4 байта), `utf8` — ограниченный (3 байта, нет emoji).

## 7. Альтернативы UTF-8

### 7.1 UTF-16

**Характеристики:**

- 2 или 4 байта на символ
- BOM для определения endianness
- Используется в Windows, Java, JavaScript internally

**Когда лучше:**

- Много non-ASCII символов (китайский, японский)
- Internal representation (не для передачи)

### 7.2 UTF-32

**Характеристики:**

- Всегда 4 байта на символ
- Простой доступ по индексу

**Когда лучше:**

- Нужен быстрый доступ по индексу символа
- Внутренние структуры данных

### 7.3 Сравнение

| Кодировка | Байт/символ | ASCII совместимость | Endianness | Use case |
|-----------|-------------|---------------------|------------|----------|
| UTF-8 | 1-4 | Да | Нет | Текст, веб, файлы |
| UTF-16 | 2-4 | Нет | Да | Windows, Java |
| UTF-32 | 4 | Нет | Да | Internal |

## 💡 Key Takeaways

- **UTF-8 — протокол интерпретации байтов**: Это договорённость между producer и consumer о том, как кодировать Unicode в байты и обратно.

- **Самосинхронизация — ключевая особенность**: Структура UTF-8 позволяет найти границы символов с любой позиции, обеспечивая восстановление после ошибок.

- **Обратная совместимость с ASCII**: Любой валидный ASCII — валидный UTF-8, обеспечивая плавный переход от ASCII к Unicode.

- **Обработка ошибок критична**: Consumer должен обрабатывать invalid sequences (strict, replace, ignore), а producer — создавать валидный UTF-8.

- **UTF-8 — стандарт де-факто**: Эффективность, самосинхронизация, совместимость с ASCII сделали UTF-8 доминирующей кодировкой для веба и файлов.
