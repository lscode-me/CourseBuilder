## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | REST — это архитектурный стиль для проектирования распределённых систем, а не протокол или стандарт. |
| 2 | A | REST не требует обязательного использования JSON. REST может использовать JSON, XML или другие форматы. |
| 3 | A | В REST ресурсы идентифицируются через URI (Uniform Resource Identifier). |
| 4 | A | SOAP (Simple Object Access Protocol) — это протокол для обмена структурированными сообщениями в распределённых системах. |
| 5 | D | WSDL (Web Services Description Language) — это язык описания веб-сервисов, формальное описание SOAP API через XML. |
| 6 | D | GraphQL — это язык запросов и runtime для выполнения запросов к API, позволяющий клиентам запрашивать только нужные данные. |
| 7 | D | GraphQL решает проблему over-fetching (получение лишних данных) и under-fetching (недостаточно данных). |
| 8 | B | REST имеет фиксированные endpoints, GraphQL позволяет гибкие запросы, где клиент определяет нужные поля. |
| 9 | C | SOAP имеет встроенные стандарты безопасности WS-Security, что делает его подходящим для enterprise интеграций. |
| 10 | B | GraphQL Schema определяет типы данных и операции (queries для чтения, mutations для изменения данных). |
| 11 | D | REST хорошо подходит для кэширования, так как использует стандартные HTTP механизмы кэширования (Cache-Control, ETag). |
| 12 | C | SOAP следует использовать для enterprise интеграций с формальными контрактами (WSDL) и требованиями безопасности. |
| 13 | B | GraphQL позволяет клиенту определять, какие поля нужны в запросе, избегая over-fetching. |
| 14 | D | "Stateless" в REST означает, что сервер не хранит состояние клиента между запросами. Каждый запрос самодостаточен. |
| 15 | C | WSDL обеспечивает формальное описание API: операции, типы данных, формат запросов и ответов. |
| 16 | C | GraphQL эффективен, так как клиент получает только запрошенные данные, избегая over-fetching лишней информации. |
| 17 | A | REST использует стандартные HTTP методы: GET (чтение), POST (создание), PUT (обновление), DELETE (удаление) и другие. |
| 18 | B | SOAP подходит для enterprise интеграций с распределёнными транзакциями благодаря формальным контрактам и стандартам. |
| 19 | B | "Единая точка входа" в GraphQL означает один endpoint для всех запросов, в отличие от REST с множеством endpoints. |
| 20 | C | REST лучше для простого CRUD API, так как простой, понятный и использует стандартные HTTP методы. |
| 21 | B | "Layered System" в REST означает многоуровневую архитектуру с прокси, балансировщиками, кэшами между клиентом и сервером. |
| 22 | D | SOAP использует XML формат для всех сообщений (запросов и ответов). |
| 23 | A | GraphQL обеспечивает сильную типизацию через Schema, что помогает предотвращать ошибки и обеспечивает валидацию. |
| 24 | B | "Uniform Interface" в REST означает единообразный интерфейс для всех операций через стандартные HTTP методы и форматы. |
| 25 | D | GraphQL предпочтительнее REST, когда нужна гибкость запросов, эффективность данных и работа со сложными связанными данными. |
