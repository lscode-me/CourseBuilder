# Проектирование баз данных

## Что нужно знать для интервью

Тема баз данных на Python-интервью обычно включает нормальные формы, связи между таблицами и базовый SQL. Классическая задача — спроектировать схему для "библиотеки" или "интернет-магазина".

---

## 🔑 Ключевые понятия

### Нормальные формы (кратко)

| Форма | Правило | Пример нарушения |
|-------|---------|------------------|
| **1NF** | Атомарные значения, нет повторяющихся групп | Колонка `phones = "123, 456"` |
| **2NF** | 1NF + нет частичных зависимостей | Зависимость от части составного ключа |
| **3NF** | 2NF + нет транзитивных зависимостей | `city → country` в таблице заказов |

**Ответ на интервью:**
> "Нормализация — это процесс организации данных для минимизации избыточности. 1NF требует атомарных значений, 2NF устраняет частичные зависимости, 3NF устраняет транзитивные зависимости."

### Типы связей

| Связь | Описание | Реализация |
|-------|----------|------------|
| **One-to-One** | Один к одному | FK в любой таблице |
| **One-to-Many** | Один ко многим | FK на стороне "многих" |
| **Many-to-Many** | Многие ко многим | **Junction table** (связующая таблица) |

## 💻 Классическая задача: Библиотека

### Условие

> База данных содержит таблицы books и authors. Где хранить информацию о том, кто написал какую книгу? Учтите: автор может написать много книг, книга может иметь несколько авторов.

### Неправильные решения

```sql
-- ❌ Добавить author_id в books
-- Не работает: книга может иметь несколько авторов

-- ❌ Добавить book_id в authors  
-- Не работает: автор может написать несколько книг

-- ❌ Хранить список авторов в строке
-- books.authors = "Пушкин, Лермонтов"
-- Нарушает 1NF, невозможен JOIN
```

### Правильное решение

```sql
CREATE TABLE authors (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    birth_date DATE
);

CREATE TABLE books (
    id SERIAL PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    publication_date DATE,
    genre VARCHAR(100)
);

-- Junction table (связующая таблица)
CREATE TABLE book_authors (
    book_id INTEGER REFERENCES books(id),
    author_id INTEGER REFERENCES authors(id),
    PRIMARY KEY (book_id, author_id)
);
```

**Ответ на интервью:**
> "Это связь many-to-many, поэтому нужна junction table (связующая таблица) с FK на обе таблицы. Это позволяет одному автору иметь много книг и одной книге — много авторов."

## 💻 SQL запросы, которые могут попросить написать

### Найти все книги автора

```sql
SELECT b.title, b.publication_date
FROM books b
JOIN book_authors ba ON b.id = ba.book_id
JOIN authors a ON a.id = ba.author_id
WHERE a.name = 'Пушкин';
```

### Найти авторов книги

```sql
SELECT a.name
FROM authors a
JOIN book_authors ba ON a.id = ba.author_id
JOIN books b ON b.id = ba.book_id
WHERE b.title = 'Война и мир';
```

### Посчитать количество книг каждого автора

```sql
SELECT a.name, COUNT(ba.book_id) as book_count
FROM authors a
LEFT JOIN book_authors ba ON a.id = ba.author_id
GROUP BY a.id, a.name
ORDER BY book_count DESC;
```

## ❓ Типичные вопросы на интервью

### Q: Почему не хранить всё в одной таблице?

**A:** 
- **Избыточность данных** — информация об авторе дублируется для каждой книги
- **Аномалии обновления** — при изменении имени автора нужно менять во всех записях
- **Аномалии удаления** — удаляя последнюю книгу автора, теряем информацию об авторе
- **Сложность поиска** — нельзя эффективно искать по авторам

### Q: Что такое денормализация и когда она нужна?

**A:** 
> "Денормализация — намеренное нарушение нормальных форм для оптимизации производительности. Используется когда JOIN-ы становятся слишком дорогими на чтение. Trade-off: быстрее читаем, сложнее обновляем."

### Q: Разница между INNER JOIN и LEFT JOIN?

**A:**
- **INNER JOIN** — возвращает только совпадающие записи из обеих таблиц
- **LEFT JOIN** — возвращает все записи из левой таблицы + совпадающие из правой (NULL если нет совпадения)
