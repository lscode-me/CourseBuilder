## 1. Почему feedback важен

### 1.1 Feedback как подарок

> **💡 Key Insight:**  
> Feedback — это подарок. Люди, которые дают честный feedback, инвестируют в ваш рост.

**Без feedback:**

- Люди не знают, что делают хорошо
- Проблемы накапливаются до кризиса
- Performance reviews становятся сюрпризом
- Таланты уходят, не понимая причин

**С регулярным feedback:**

- Быстрая коррекция курса
- Признание достижений
- Развитие и рост
- Доверие в команде

### 1.2 Feedback Loop

```

       ┌──────────────────────────────────────┐
       │                                      │
       ▼                                      │
  ┌─────────┐     ┌─────────┐     ┌─────────┐
  │ Действие│────►│ Feedback│────►│ Обучение│
  └─────────┘     └─────────┘     └─────────┘
       │                                      │
       │                                      │
       └──────────────────────────────────────┘

```

Чем короче цикл — тем быстрее рост.

### 1.3 Типы feedback

| Тип | Цель | Когда |
|-----|------|-------|
| **Positive** | Признание, reinforcement | Сразу после успеха |
| **Constructive** | Улучшение, коррекция | Как можно раньше |
| **Directive** | Срочное изменение | При критичных проблемах |

## 2. Radical Candor Framework

### 2.1 Две оси

Kim Scott предложила framework из двух измерений:

**Care Personally** — насколько вы показываете заботу о человеке как о личности

**Challenge Directly** — насколько вы готовы говорить неприятную правду

```

                    Challenge Directly
                          ▲
                          │
         ┌────────────────┼────────────────┐
         │                │                │
         │  Obnoxious     │    Radical     │
         │  Aggression    │    Candor      │
         │                │      ★         │
─────────┼────────────────┼────────────────┼─────► Care
         │                │                │      Personally
         │  Manipulative  │    Ruinous     │
         │  Insincerity   │    Empathy     │
         │                │                │
         └────────────────┼────────────────┘
                          │

```

### 2.2 Четыре квадранта

**Radical Candor (Care + Challenge):**

- Говорите правду с заботой
- "Я говорю это, потому что хочу, чтобы ты рос"
- ✅ Идеал

**Obnoxious Aggression (Challenge без Care):**

- Критика без эмпатии
- "Просто факты, без обёрток"
- ❌ Ранит и демотивирует

**Ruinous Empathy (Care без Challenge):**

- Избегание сложных разговоров
- "Не хочу расстраивать"
- ❌ Не помогает расти

**Manipulative Insincerity (ни Care, ни Challenge):**

- Фальшивые комплименты или критика за спиной
- "Всё отлично" в лицо, критика другим
- ❌ Разрушает доверие

### 2.3 Как практиковать Radical Candor

**Показать Care:**

- Узнайте человека как личность
- Помните детали их жизни
- Будьте доступны
- Признавайте их успехи публично

**Challenge Directly:**

- Говорите конкретно и сразу
- Фокусируйтесь на поведении, не на личности
- Предлагайте путь улучшения
- Follow up

## 3. SBI Model

### 3.1 Структура

**SBI** — простая модель для структурирования feedback:

- **S**ituation — контекст, когда это произошло

- **B**ehavior — что конкретно человек сделал

- **I**mpact — какой эффект это имело

### 3.2 Примеры SBI

**Positive feedback:**
```

Situation: "На demo вчера..."
Behavior:  "...ты очень чётко объяснил архитектуру, 
           использовал понятные диаграммы и отвечал на вопросы спокойно..."
Impact:    "...благодаря этому stakeholders одобрили проект, 
           и команда получила green light на разработку."

```

**Constructive feedback:**
```

Situation: "На code review на этой неделе..."
Behavior:  "...твои комментарии были очень короткими и без объяснений, 
           например 'это неправильно' без указания почему..."
Impact:    "...это расстроило junior developer, и он не понял, 
           как исправить, потратив лишние 2 часа."

```

### 3.3 SBI-BI для запроса изменений

Расширенная версия добавляет **BI** — альтернативное Behavior и его Impact:

```

SBI:   [Situation + Behavior + Impact текущего поведения]
BI:    [альтернативное Behavior + его положительный Impact]

"На code review твои комментарии были без объяснений, 
что расстроило junior developer.

В следующий раз, если добавишь одно предложение 'почему',
это поможет ему учиться быстрее и экономить время."

```

## 4. Давать Feedback эффективно

### 4.1 Timing

**Правило:** Чем раньше — тем лучше.

- **Positive feedback:** Сразу, публично (если уместно)

- **Constructive feedback:** В течение 24-48 часов, приватно

- **Срочные issues:** Немедленно

> **⚠️ Warning:**  
> Не накапливайте feedback до performance review. К тому времени он потеряет impact.

### 4.2 Setting

**Для constructive feedback:**

- Приватно (1-on-1, закрытая комната)
- Достаточно времени для разговора
- Без спешки и отвлечений

**Для positive feedback:**

- Публично — если человеку комфортно
- Приватно — если человек интроверт

**Спросите:** "Тебе комфортно, если я поблагодарю тебя на standup?"

### 4.3 Delivery

**Начните с разрешения:**
```

"Можно дать тебе feedback по вчерашней презентации?"

```

**Будьте конкретны:**
```

❌ "Ты был неорганизован"
✅ "Слайды шли не по порядку, и ты дважды возвращался назад"

```

**Фокус на поведении, не на личности:**
```

❌ "Ты невнимательный"
✅ "В этом PR пропущены юнит-тесты для двух методов"

```

**Используйте "Я" высказывания:**
```

❌ "Ты сделал плохо"
✅ "Я заметил, что..." / "Мне показалось, что..."

```

### 4.4 Сложный feedback

**Структура разговора:**

```

1. Подготовка
   - Соберите факты
   - Определите желаемый outcome
   - Выберите время и место

2. Открытие
   - "Есть важная тема, которую хочу обсудить"
   - Покажите intent помочь

3. SBI
   - Конкретная ситуация
   - Наблюдаемое поведение
   - Impact

4. Пауза
   - Дайте человеку отреагировать
   - Слушайте их perspective

5. Диалог
   - Обсудите причины
   - Поймите контекст
   
6. Путь вперёд
   - Договоритесь о конкретных изменениях
   - Определите support, который нужен
   
7. Follow-up
   - Запланируйте check-in

```

## 5. Получать Feedback

### 5.1 Почему это сложно

**Triggers (по книге "Thanks for the Feedback"):**

- **Truth triggers:** "Это неправда!"

- **Relationship triggers:** "Кто ты такой, чтобы мне говорить?"

- **Identity triggers:** "Значит, я плохой человек?"

### 5.2 Как принимать feedback

**В момент получения:**

```

1. Слушайте полностью
   - Не перебивайте
   - Не защищайтесь сразу
   
2. Поблагодарите
   - "Спасибо, что сказал"
   - Даже если не согласны
   
3. Уточните
   - "Можешь привести пример?"
   - "Что бы ты рекомендовал?"
   
4. Возьмите паузу
   - "Мне нужно подумать об этом"
   - Не обязаны реагировать сразу

```

**После получения:**

```

1. Рефлексия
   - Что правда в этом feedback?
   - Что я могу применить?
   
2. Отделите зёрна от плевел
   - Не весь feedback полезен
   - Ищите patterns (если слышите одно и то же от разных людей)
   
3. Action
   - Выберите 1-2 вещи для изменения
   - Сообщите человеку о вашем плане

```

### 5.3 Запрашивать feedback

**Регулярно спрашивайте:**
```

- "Что я мог бы сделать лучше?"
- "Есть ли что-то, что мешает команде?"
- "Какой feedback у тебя для меня?"

```

**Конкретные вопросы работают лучше:**
```

❌ "Есть feedback?"
✅ "Как прошла вчерашняя презентация? Что я мог бы улучшить?"

```

## 6. Feedback Culture в команде

### 6.1 Создание безопасности

**Psychological Safety необходима:**

- Люди должны чувствовать, что feedback безопасен
- Mistakes не наказываются
- Vulnerability приветствуется

**Как создать:**

- Сами моделируйте получение feedback
- Благодарите за честность
- Никогда не наказывайте за feedback

### 6.2 Нормализация feedback

**Встройте в процессы:**

- Retro с регулярным feedback
- Peer feedback после проектов
- 360 reviews периодически

**Практики:**
```

"Feedback Fridays" — выделенное время для feedback
"Start/Stop/Continue" — простой формат для команды
"Kudos channel" — публичное признание в Slack

```

### 6.3 Моделирование поведения

**Вы как лидер:**

- Открыто просите feedback о себе
- Публично благодарите за критику
- Показываете, как вы применяете feedback
- Признаёте свои ошибки

```

Пример: "На прошлой неделе Маша сказала мне, что я слишком много 
перебиваю на митингах. Я постарался это исправить. 
Маша, ты заметила изменения?"

```

## 7. Особые случаи

### 7.1 Feedback senior сотруднику

**Вызовы:**

- Они опытнее вас (возможно)
- Могут защищаться
- "Я знаю лучше"

**Подход:**

- Больше вопросов, меньше директив
- Апеллируйте к их expertise
- Фокус на impact, не на правильности

```

"Ты опытнее меня в архитектуре, поэтому хочу понять твоё мнение.
Я заметил, что решение X привело к проблемам Y.
Как ты думаешь, что можно было сделать иначе?"

```

### 7.2 Feedback underperformer

**Принципы:**

- Конкретно и документировано
- Частота выше обычной
- Чёткие expectations и сроки
- Поддержка, но и accountability

**Структура разговора:**
```

1. "Я наблюдаю [конкретные проблемы]"
2. "Это влияет на [команду/проект]"
3. "Я ожидаю [конкретные изменения]"
4. "Давай договоримся о плане"
5. "Я буду проверять прогресс [когда]"
6. "Я хочу тебе помочь. Что тебе нужно?"

```

### 7.3 Feedback через культурные различия

**Учитывайте:**

- В некоторых культурах прямой feedback — табу
- Power distance влияет на восприятие
- "Сохранение лица" важно

**Адаптируйте:**

- Узнайте культурный контекст
- Будьте готовы к более indirect подходу
- Дайте время на обработку

### 7.4 Feedback от подчинённого руководителю

**Для менеджеров — создайте возможность:**

- Регулярно спрашивайте feedback о себе
- Анонимные surveys
- Skip-level 1-on-1

**Для сотрудников — как давать:**
```

1. Попросите разрешения
2. Будьте конкретны (SBI)
3. Фокусируйтесь на impact на команду
4. Предложите решения

```

## 8. Инструменты и практики

### 8.1 Регулярные практики

**Weekly:**

- Kudos на standup
- Informal feedback в течение недели

**Monthly:**

- 1-on-1 с фокусом на feedback
- Peer recognition program

**Quarterly:**

- 360 feedback (формальный или informal)
- Team retro с personal feedback

**Annually:**

- Performance review (не сюрприз!)
- Career discussion

### 8.2 360 Feedback

**Что это:** Сбор feedback от коллег, подчинённых, руководителя.

**Как делать:**
```

1. Определите респондентов (3-5 человек)
2. Стандартизированные вопросы
3. Анонимность (или нет — зависит от культуры)
4. Агрегация и delivery результатов
5. Action planning

```

**Пример вопросов:**
```

- Какие сильные стороны [Имя]?
- Что [Имя] стоит улучшить?
- Один совет для [Имя] для роста?

```

### 8.3 Kudos и Recognition

**Каналы:**

- #kudos в Slack
- Shoutouts на all-hands
- Peer bonuses (если есть)

**Формат:**
```

"Kudos to @Maria за помощь с debugging вчера. 
Она потратила 2 часа помогая мне разобраться с проблемой,
и мы успели к дедлайну."

```

## 💡 Key Takeaways

- **Radical Candor**: Care Personally + Challenge Directly — говорите правду с заботой

- **SBI Model**: Situation + Behavior + Impact — структура конкретного feedback

- **Timing**: Давайте feedback сразу, не копите до review

- **Получение**: Слушайте, благодарите, уточняйте, берите паузу

- **Культура**: Моделируйте сами — просите и принимайте feedback публично
