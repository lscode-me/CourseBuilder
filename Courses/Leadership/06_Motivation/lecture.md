## 1. Основы мотивации

### 1.1 Почему люди работают

**Базовые вопросы:**

- Почему люди приходят на работу каждый день?
- Почему одни горят, а другие "отбывают номер"?
- Что заставляет людей оставаться или уходить?

> **💡 Key Insight:**  
> Деньги важны, но не являются главным мотиватором для knowledge workers.

### 1.2 Внешняя vs Внутренняя мотивация

**Внешняя (Extrinsic):**

- Зарплата, бонусы
- Повышение, статус
- Награды, признание
- Избегание наказания

**Внутренняя (Intrinsic):**

- Интерес к работе
- Чувство достижения
- Желание расти
- Смысл и цель

**Исследования показывают:**

- Для creative work внутренняя мотивация важнее
- Внешние мотиваторы могут подавлять внутренние (overjustification effect)
- Деньги работают до определённого уровня (covering needs)

### 1.3 Two-Factor Theory (Herzberg)

```

Гигиенические факторы          Мотивационные факторы
(если плохо — демотивируют)    (создают мотивацию)
─────────────────────────      ─────────────────────────
• Зарплата                     • Достижения
• Условия работы               • Признание
• Политика компании            • Интересная работа
• Отношения с коллегами        • Ответственность
• Безопасность работы          • Рост и развитие

```

**Вывод:** Устранение демотиваторов не создаёт мотивацию. Нужны оба.

## 2. Модель Drive (Daniel Pink)

### 2.1 Три столпа мотивации

Daniel Pink в книге "Drive" выделяет три компонента внутренней мотивации:

```

        ┌─────────────────────────────────────┐
        │           МОТИВАЦИЯ                 │
        └─────────────────────────────────────┘
                        │
         ┌──────────────┼──────────────┐
         ▼              ▼              ▼
    ┌─────────┐    ┌─────────┐    ┌─────────┐
    │AUTONOMY │    │ MASTERY │    │ PURPOSE │
    │         │    │         │    │         │
    │Контроль │    │ Желание │    │  Смысл  │
    │над своей│    │  стать  │    │  работы │
    │работой  │    │ лучше   │    │         │
    └─────────┘    └─────────┘    └─────────┘

```

### 2.2 Autonomy (Автономия)

**Что это:** Контроль над тем, КАК, КОГДА, ГДЕ и С КЕМ работать.

**Четыре измерения автономии:**

| Измерение | Описание | Пример |
|-----------|----------|--------|
| Task | Что делать | Выбор проектов, backlog grooming |
| Time | Когда делать | Гибкий график, async work |
| Technique | Как делать | Выбор инструментов, подходов |
| Team | С кем делать | Выбор коллег для проекта |

**Как давать автономию:**
```

✅ "Вот цель. Как достичь — решаешь ты"
✅ "Работай откуда удобно"
✅ "Выбери инструменты, которые подходят"

❌ "Делай точно так, как я сказал"
❌ "Будь в офисе с 9 до 6"
❌ "Используй только утверждённый стек"

```

> **⚠️ Warning:**  
> Автономия без компетенции — хаос. Постепенно увеличивайте автономию с ростом навыков.

### 2.3 Mastery (Мастерство)

**Что это:** Желание становиться лучше в чём-то важном.

**Три закона Mastery (по Pink):**

1. **Mastery is a Mindset**
   - Growth mindset vs Fixed mindset
   - "Я могу научиться" vs "Я не способен"

2. **Mastery is Pain**
   - Рост требует усилий за пределами комфорта
   - Deliberate practice — осознанная практика

3. **Mastery is Asymptote**
   - Никогда полностью не достигается
   - Процесс важнее результата

**Как поддерживать Mastery:**
```

✅ Challenging задачи (не слишком лёгкие, не слишком сложные)
✅ Время на обучение (learning budget, conference days)
✅ Менторство и feedback
✅ Возможность работать с экспертами

❌ Только рутинные задачи
❌ "Нет времени на обучение"
❌ Отсутствие feedback о прогрессе

```

### 2.4 Purpose (Цель/Смысл)

**Что это:** Понимание, ЗАЧЕМ мы делаем эту работу.

**Уровни Purpose:**

```

Большая миссия:    "Мы меняем образование в мире"
                         ↓
Продуктовая цель:  "Наш продукт помогает учителям"
                         ↓
Командная цель:    "Наша команда делает платформу доступной"
                         ↓
Личная связь:      "Моя работа влияет на тысячи студентов"

```

**Как создавать Purpose:**
```

✅ Связывайте задачи с impact на пользователей
✅ Рассказывайте истории успеха клиентов
✅ Показывайте метрики impact
✅ Приглашайте пользователей на демо

❌ "Просто сделай эту задачу"
❌ Изоляция от конечных пользователей
❌ Фокус только на технических метриках

```

## 3. Определение мотиваторов

### 3.1 Индивидуальные различия

> **💡 Key Insight:**  
> Нет универсальной мотивации. Что мотивирует одного — может демотивировать другого.

**Примеры различий:**

- Для одного важнее деньги, для другого — интересные задачи
- Один хочет публичное признание, другой — тихую благодарность
- Кто-то хочет стабильность, кто-то — новые вызовы

### 3.2 Вопросы для понимания мотиваторов

**На 1-on-1 спрашивайте:**

```

О прошлом опыте:

- "Расскажи о работе/проекте, где ты был максимально мотивирован. Что делало это особенным?"
- "Когда ты чувствовал себя демотивированным? Что происходило?"

О текущей работе:

- "Какая часть работы приносит тебе больше всего удовлетворения?"
- "Что бы ты хотел делать больше?"
- "Что истощает твою энергию?"

О будущем:

- "Каким ты видишь идеальный день работы?"
- "Какие навыки хочешь развить?"
- "К чему стремишься через 2-3 года?"

```

### 3.3 Карта мотиваторов

Создайте "карту мотиваторов" для каждого члена команды:

```markdown
## Карта мотиваторов: [Имя]

### Топ-3 мотиватора:

1. [мотиватор 1] — пример проявления
2. [мотиватор 2] — пример проявления
3. [мотиватор 3] — пример проявления

### Демотиваторы (избегать):

- [демотиватор 1]
- [демотиватор 2]

### Тип recognition:

- Публичный / Приватный
- Устный / Письменный

### Карьерные цели:

- Short-term: [цель]
- Long-term: [цель]

```

## 4. Engagement и Flow

### 4.1 Engagement Model

**Engaged сотрудник:**

- Эмоционально привязан к работе
- Готов прикладывать дополнительные усилия
- Рекомендует компанию другим
- Остаётся в компании

**Три уровня:**
```

Engaged        — "Я люблю свою работу"
Not Engaged    — "Я просто делаю работу"
Disengaged     — "Я ненавижу эту работу"

```

**Gallup Q12** — 12 вопросов для измерения engagement:

1. Я знаю, что от меня ожидают на работе
2. У меня есть материалы и инструменты для работы
3. Я могу делать то, что умею лучше всего, каждый день
4. Я получил признание за хорошую работу за последние 7 дней
5. Мой руководитель заботится обо мне как о человеке
6. Кто-то на работе способствует моему развитию
7. Моё мнение учитывается на работе
8. Миссия компании делает мою работу важной
9. Мои коллеги привержены качественной работе
10. У меня есть лучший друг на работе
11. За последние 6 месяцев кто-то говорил о моём прогрессе
12. За последний год у меня были возможности учиться и расти

### 4.2 Flow State

**Flow** (по Csikszentmihalyi) — состояние полной погружённости в задачу.

**Условия для Flow:**
```

                    High
                     │
         Anxiety     │     FLOW
                     │
     ─────────────────────────────
                     │
         Boredom     │     Relaxation
                     │
        Low ─────────┴───────────── High
                   SKILLS

```

**Как создавать условия для Flow:**

1. **Clear Goals**
   - Ясные цели и ожидания
   - Понимание "готово"

2. **Immediate Feedback**
   - Быстрая обратная связь о результатах
   - Тесты, CI/CD, review

3. **Challenge-Skill Balance**
   - Задачи чуть сложнее текущих навыков
   - Не слишком легко (скука), не слишком сложно (тревога)

4. **Uninterrupted Time**
   - Защита от прерываний
   - Минимум митингов во время deep work

## 5. Развитие людей

### 5.1 Модель развития 70-20-10

```

┌─────────────────────────────────────────────────┐
│                  РАЗВИТИЕ                        │
├─────────────────────────────────────────────────┤
│ 70% │ On-the-job Experience                     │
│     │ Реальные проекты, stretch assignments      │
├─────────────────────────────────────────────────┤
│ 20% │ Social Learning                           │
│     │ Менторство, feedback, наблюдение          │
├─────────────────────────────────────────────────┤
│ 10% │ Formal Learning                           │
│     │ Курсы, книги, тренинги                    │
└─────────────────────────────────────────────────┘

```

**Вывод:** Большинство развития происходит через работу, не через курсы.

### 5.2 Stretch Assignments

**Что это:** Задачи, которые немного выходят за пределы текущих навыков.

**Типы stretch:**

- Новая технология
- Больший scope
- Новая роль (например, tech lead на проекте)
- Cross-functional проект
- Высокая visibility

**Как давать stretch assignments:**
```

1. Оцените readiness человека
2. Объясните, почему это stretch и зачем
3. Обеспечьте поддержку (mentor, check-ins)
4. Примите, что будут ошибки
5. Celebrate learning, не только результат

```

### 5.3 Individual Development Plan (IDP)

**Структура IDP:**

```markdown
## Individual Development Plan: [Имя]
## Период: [Q1-Q2 2024]

### Текущий уровень
- Роль: Senior Developer
- Сильные стороны: [список]
- Области роста: [список]

### Цель развития
- Short-term (3-6 мес): [цель]
- Long-term (1-2 года): [цель]

### План действий

| Навык | Действия | Timeline | Support |
|-------|----------|----------|---------|
| [навык 1] | [проект/активность] | Q1 | Ментор: X |
| [навык 2] | [курс/книга] | Q1-Q2 | Бюджет: $Y |

### Check-ins
- Monthly 1-on-1: обзор прогресса
- [Дата]: mid-period review
- [Дата]: end-of-period review

```

### 5.4 Career Conversations

**Регулярность:** Минимум раз в квартал отдельный разговор о карьере.

**Вопросы для career conversation:**
```

- Каким ты видишь свой рост в следующие 1-2 года?
- Какие навыки хочешь развить?
- Есть ли роли в компании, которые тебя интересуют?
- Что я могу сделать, чтобы помочь твоему росту?
- Чувствуешь ли ты прогресс за последние месяцы?

```

## 6. Признание и награды

### 6.1 Виды признания

| Тип | Когда | Как |
|-----|-------|-----|
| **Informal** | Постоянно | "Отличная работа над X!" |
| **Formal** | Milestones | Kudos на all-hands, номинации |
| **Monetary** | Результаты | Бонусы, spot bonuses |
| **Experiential** | Achievements | Conference, off-site, gifts |

### 6.2 Effective Recognition

**Принципы:**

- **Timely**: Сразу, не через месяц

- **Specific**: За что конкретно

- **Sincere**: Искренне, не формально

- **Personalized**: Учитывает preferences человека

**Примеры:**
```

❌ Плохо: "Молодец, хорошая работа"

✅ Хорошо: "Хочу отметить твою работу над migration. 
Особенно впечатлило, как ты организовал rollback plan — 
это позволило нам запуститься без даунтайма."

```

### 6.3 Peer Recognition

**Программы:**

- Kudos channel в Slack
- Peer bonuses (если есть бюджет)
- "Shoutouts" на standup
- Monthly awards с голосованием

## 7. Демотивация и Burnout

### 7.1 Признаки демотивации

**Behaviour changes:**

- Снижение качества работы
- Меньше участия в обсуждениях
- Избегание новых задач
- Cynicism и негатив
- Абсентеизм

**В разговоре:**

- "Какой смысл?"
- "Это не мой уровень"
- "Мне всё равно"

### 7.2 Причины демотивации

```

Personal           Work              Organizational
─────────────────  ────────────────  ─────────────────
• Проблемы дома    • Boring tasks    • Bad management
• Здоровье         • No growth       • Unclear direction
• Burnout          • No recognition  • Toxic culture
• Life events      • Unfair pay      • Layoffs/instability

```

### 7.3 Burnout

**Признаки burnout:**

- Хроническая усталость
- Cynicism и отстранённость
- Ощущение неэффективности
- Физические симптомы

**Три измерения (Maslach):**

1. **Exhaustion**: Эмоциональное и физическое истощение
2. **Cynicism**: Отстранённость от работы
3. **Inefficacy**: Ощущение бесполезности

**Как помочь:**
```

1. Заметьте и начните разговор
2. Снизьте нагрузку реально (не на словах)
3. Дайте отдых (PTO, sabbatical)
4. Устраните root cause (если возможно)
5. Поддержите professional help

```

### 7.4 Re-engagement

**Стратегии:**

- Найти новый challenge
- Сменить проект/команду
- Роль ментора для других
- Повышение ответственности
- Обучение новому

## 8. Мотивация на разных уровнях

### 8.1 Junior Developers

**Мотиваторы:**

- Learning и growth
- Mentorship
- Clear feedback
- Small wins

**Подход:**

- Частый feedback
- Challenging но achievable задачи
- Доступность для вопросов
- Celebrate прогресс

### 8.2 Senior Developers

**Мотиваторы:**

- Autonomy
- Technical challenges
- Influence на решения
- Recognition expertise

**Подход:**

- Больше автономии
- Stretch assignments
- Участие в architecture decisions
- Leadership opportunities

### 8.3 Staff+ Engineers

**Мотиваторы:**

- Strategic impact
- Org-wide influence
- Solving ambiguous problems
- Building legacy

**Подход:**

- Alignment с strategy
- Visibility работы
- Cross-org projects
- External representation

## 💡 Key Takeaways

- **Drive модель**: Autonomy, Mastery, Purpose — три столпа внутренней мотивации

- **Индивидуальный подход**: Нет универсальной мотивации, узнавайте каждого

- **70-20-10**: Большинство развития — через реальный опыт

- **Recognition matters**: Timely, Specific, Sincere, Personalized

- **Watch for burnout**: Замечайте признаки и действуйте
