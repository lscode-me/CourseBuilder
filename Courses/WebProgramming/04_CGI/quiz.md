## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | CGI создаёт новый процесс (fork+exec) для каждого запроса |
| 2 | A | QUERY_STRING содержит часть URL после знака вопроса |
| 3 | D | CGI скрипт выводит заголовки и тело в stdout, веб-сервер читает и отправляет клиенту |
| 4 | B | FastCGI процессы персистентны — не перезапускаются на каждый запрос |
| 5 | B | HTTP заголовки преобразуются в переменные окружения HTTP_* (например, HTTP_USER_AGENT) |
| 6 | C | Тело POST запроса передаётся через stdin; CONTENT_LENGTH указывает размер |
| 7 | C | PHP-FPM = FastCGI Process Manager — менеджер FastCGI процессов для PHP |
| 8 | B | FastCGI использует бинарный формат с фиксированными заголовками записей |
| 9 | C | Отсутствие Content-Type обычно вызывает ошибку 500 или malformed header |
| 10 | B | SCGI использует простой текстовый netstring-формат вместо бинарного |
| 11 | C | Nginx не имеет встроенной поддержки CGI, требуется fcgiwrap или spawn-fcgi |
| 12 | B | REQUEST_METHOD может содержать любой HTTP метод: GET, POST, PUT, DELETE, PATCH, HEAD и др. |
| 13 | B | Основные накладные расходы — fork(), exec(), загрузка интерпретатора и библиотек |
| 14 | C | FastCGI использует Unix sockets (/var/run/php-fpm.sock) или TCP (127.0.0.1:9000) |
| 15 | B | Первыми должны идти HTTP заголовки, затем пустая строка, затем тело |
