## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | CGI создаёт новый процесс (fork+exec) для каждого запроса |
| 2 | B | QUERY_STRING содержит часть URL после знака вопроса |
| 3 | A | CGI скрипт выводит заголовки и тело в stdout, веб-сервер читает и отправляет клиенту |
| 4 | B | FastCGI процессы персистентны — не перезапускаются на каждый запрос |
| 5 | B | HTTP заголовки преобразуются в переменные окружения HTTP_* (например, HTTP_USER_AGENT) |
| 6 | B | Тело POST запроса передаётся через stdin; CONTENT_LENGTH указывает размер |
| 7 | B | PHP-FPM = FastCGI Process Manager — менеджер FastCGI процессов для PHP |
| 8 | D | FastCGI использует бинарный формат с фиксированными заголовками записей |
| 9 | D | Отсутствие Content-Type обычно вызывает ошибку 500 или malformed header |
| 10 | D | SCGI использует простой текстовый netstring-формат вместо бинарного |
| 11 | B | Nginx не имеет встроенной поддержки CGI, требуется fcgiwrap или spawn-fcgi |
| 12 | B | REQUEST_METHOD может содержать любой HTTP метод: GET, POST, PUT, DELETE, PATCH, HEAD и др. |
| 13 | A | Основные накладные расходы — fork(), exec(), загрузка интерпретатора и библиотек |
| 14 | D | FastCGI использует Unix sockets (/var/run/php-fpm.sock) или TCP (127.0.0.1:9000) |
| 15 | C | Первыми должны идти HTTP заголовки, затем пустая строка, затем тело |
| 16 | D | CONTENT_LENGTH указывает размер тела POST запроса для чтения из stdin |
| 17 | D | PATH_INFO содержит дополнительный путь после имени CGI скрипта |
| 18 | B | FastCGI поддерживает пул процессов, которые переиспользуются между запросами |
| 19 | B | SERVER_NAME содержит имя хоста (hostname) сервера |
| 20 | B | spawn-fcgi запускает и управляет FastCGI процессами |
