## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | HTTP/1.1 (RFC 2616) сделал заголовок Host обязательным для поддержки виртуальных хостов |
| 2 | A | 301 Moved Permanently — постоянный редирект, 302 — временный |
| 3 | C | DELETE идемпотентен (повторный вызов даёт тот же результат), но не безопасен (изменяет состояние) |
| 4 | B | В HTTP/1.0 соединение закрывается после каждого запроса, Keep-Alive появился как расширение |
| 5 | B | Chunked encoding позволяет передавать данные порциями, когда общий размер неизвестен заранее |
| 6 | D | Корректный формат: METHOD PATH VERSION, затем заголовки, пустая строка в конце |
| 7 | B | По умолчанию HTML формы отправляют данные как application/x-www-form-urlencoded |
| 8 | C | If-None-Match используется для условного запроса с проверкой ETag |
| 9 | B | HTTP/2 решил HoL blocking через мультиплексирование потоков в одном соединении |
| 10 | B | HTTP/3 использует QUIC, который работает поверх UDP |
| 11 | A | 5xx — ошибки сервера, 503 означает "сервис временно недоступен" |
| 12 | A | HSTS (Strict-Transport-Security) принуждает браузер использовать только HTTPS |
| 13 | C | Заголовок Host позволяет различать сайты на одном IP (виртуальный хостинг) |
| 14 | C | 304 означает, что ресурс не изменился с момента последнего запроса |
| 15 | B | no-store запрещает любое кэширование; no-cache разрешает с проверкой |
| 16 | C | HEAD возвращает те же заголовки, что и GET, но без тела ответа |
| 17 | B | HTTPS использует порт 443, HTTP — порт 80 |
| 18 | C | HTTP/2 работает поверх TCP; HTTP/3 использует QUIC (UDP) |
| 19 | A | Accept указывает предпочтительные MIME-типы; Accept-Encoding — сжатие |
| 20 | A | 401 — "кто вы?", 403 — "я знаю кто вы, но вам нельзя" |
