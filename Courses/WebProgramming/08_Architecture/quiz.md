## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Монолит прост в разработке, тестировании и деплое — один артефакт |
| 2 | D | Микросервисы добавляют сложность: network latency, distributed transactions, debugging |
| 3 | B | IP Hash направляет запросы от одного IP на один сервер (sticky sessions) |
| 4 | C | CDN кэширует статику на edge серверах ближе к пользователям, снижая latency |
| 5 | D | Cache-aside загружает данные в кэш только при промахе (ленивая загрузка) |
| 6 | B | Message Queue используются для async задач (email, notifications) и decoupling сервисов |
| 7 | C | Replica серверы обрабатывают чтение, разгружая Primary |
| 8 | A | Шардирование — разделение данных по ключу между серверами (horizontal scaling) |
| 9 | C | PATCH — частичное обновление; PUT — полная замена ресурса |
| 10 | D | GraphQL позволяет клиенту запросить только нужные поля, избегая over-fetching |
| 11 | A | gRPC использует бинарный Protocol Buffers для эффективной сериализации |
| 12 | C | Reverse proxy не работает с БД напрямую; это задача application server |
| 13 | D | Redis используется как кэш, хранилище сессий и брокер очередей |
| 14 | A | Celery — distributed task queue для Python, выполняет фоновые задачи |
| 15 | D | Prometheus собирает метрики; Grafana визуализирует их |
