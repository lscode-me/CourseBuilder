## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Монолит прост в разработке, тестировании и деплое — один артефакт |
| 2 | D | Микросервисы добавляют сложность: network latency, distributed transactions, debugging |
| 3 | B | IP Hash направляет запросы от одного IP на один сервер (sticky sessions) |
| 4 | C | CDN кэширует статику на edge серверах ближе к пользователям, снижая latency |
| 5 | D | Cache-aside загружает данные в кэш только при промахе (ленивая загрузка) |
| 6 | D | Message Queue используются для async задач (email, notifications) и decoupling сервисов |
| 7 | C | Replica серверы обрабатывают чтение, разгружая Primary |
| 8 | C | Шардирование — разделение данных по ключу между серверами (horizontal scaling) |
| 9 | D | PATCH — частичное обновление; PUT — полная замена ресурса |
| 10 | D | GraphQL позволяет клиенту запросить только нужные поля, избегая over-fetching |
| 11 | C | gRPC использует бинарный Protocol Buffers для эффективной сериализации |
| 12 | B | Reverse proxy не работает с БД напрямую; это задача application server |
| 13 | D | Redis используется как кэш, хранилище сессий и брокер очередей |
| 14 | C | Celery — distributed task queue для Python, выполняет фоновые задачи |
| 15 | D | Prometheus собирает метрики; Grafana визуализирует их |
| 16 | A | Grafana создаёт дашборды и визуализирует данные из Prometheus и других источников |
| 17 | A | 12-Factor рекомендует хранить конфигурацию в environment variables |
| 18 | B | Write-through пишет и в кэш, и в БД синхронно |
| 19 | B | CAP: можно гарантировать только 2 из 3 (Consistency, Availability, Partition tolerance) |
| 20 | B | Health check endpoint (/health) позволяет проверить работоспособность сервиса |
