## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Все аспекты (Validation, Completeness, Freshness, Consistency) входят в качество данных. |
| 2 | B | Data validation проверяет соответствие данных ожидаемой схеме и бизнес-правилам. |
| 3 | A | Schema validation проверяет соответствие схеме, типы данных и наличие обязательных полей. |
| 4 | D | Business rules validation проверяет бизнес-логику, ограничения значений и связи между полями. |
| 5 | D | Data completeness измеряет, какая часть данных присутствует и не является NULL (field и record level). |
| 6 | A | Field completeness — это процент не-NULL значений в конкретном поле данных. |
| 7 | C | Data freshness измеряет, насколько актуальны данные, сравнивая время последнего обновления с текущим. |
| 8 | C | Data consistency обеспечивает согласованность данных между различными системами и источниками. |
| 9 | C | Referential integrity обеспечивает корректность связей между таблицами через foreign keys и каскадные операции. |
| 10 | D | Cross-system consistency обеспечивает согласованность данных между различными системами (например, между OLTP и OLAP). |
| 11 | D | Data quality framework включает validation layer, monitoring layer и alerting для комплексного подхода. |
| 12 | A | Валидацию следует выполнять на всех этапах: при ingestion, трансформации и перед загрузкой. |
| 13 | C | Все метрики (Completeness, Freshness, Consistency) важны для оценки качества данных. |
| 14 | C | Алерты следует отправлять при падении метрик качества ниже определённого порога для раннего обнаружения проблем. |
| 15 | B | Автоматизация обеспечивает постоянный мониторинг качества данных и раннее обнаружение проблем без ручного вмешательства. |
