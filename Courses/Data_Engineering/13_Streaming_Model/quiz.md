## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | Streaming processing обрабатывает данные в реальном времени по мере их поступления, в отличие от batch. |
| 2 | A | Event-driven система реагирует на события в реальном времени, обрабатывая их по мере поступления. |
| 3 | C | Event — это действие или изменение состояния, представленное как неизменяемая запись с временной меткой. |
| 4 | B | Все различия (накопленные vs по мере поступления, задержка, расписание vs непрерывно) относятся к streams vs batches. |
| 5 | D | At-least-once гарантирует, что событие обработано минимум один раз, но возможны дубликаты. |
| 6 | C | Exactly-once гарантирует, что событие обработано ровно один раз, без дубликатов. |
| 7 | B | At-least-once требует идемпотентности обработки, чтобы дубликаты не вызывали проблем. |
| 8 | C | Exactly-once требует транзакций и координации для гарантии обработки ровно один раз. |
| 9 | D | Windowing — это агрегация потоковых данных по временным окнам для вычисления метрик. |
| 10 | B | Tumbling windows — это непересекающиеся окна фиксированного размера (например, каждые 5 минут). |
| 11 | C | Sliding windows — это пересекающиеся скользящие окна (например, последние 5 минут каждую минуту). |
| 12 | D | Session windows — это окна по активности с динамическим размером (например, сессия пользователя). |
| 13 | B | Все use cases (real-time аналитика, мониторинг, fraud detection) подходят для streaming благодаря низкой задержке. |
| 14 | B | Streaming processing имеет низкую задержку (секунды-миллисекунды) благодаря обработке в реальном времени. |
| 15 | B | Batch processing имеет высокую задержку (минуты-дни) из-за обработки накопленных данных порциями. |
