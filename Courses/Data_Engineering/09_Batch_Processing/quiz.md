## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | C | Batch processing — это обработка данных порциями (батчами) по расписанию, в отличие от real-time обработки. |
| 2 | A | Все компоненты (Extract, Transform, Load) входят в batch pipeline для полного цикла обработки данных. |
| 3 | D | ETL означает Extract (извлечение), Transform (трансформация), Load (загрузка) в указанном порядке. |
| 4 | B | ELT означает Extract (извлечение), Load (загрузка), Transform (трансформация) — другой порядок операций. |
| 5 | C | ETL трансформирует данные до загрузки в промежуточной системе, ELT загружает сырые данные и трансформирует в хранилище. |
| 7 | C | Идемпотентность означает, что повторное выполнение pipeline даёт тот же результат, что и первое выполнение. |
| 8 | B | Идемпотентность обеспечивает безопасный перезапуск, отсутствие дубликатов и предсказуемость результатов. |
| 9 | D | Upsert — это стратегия, которая обновляет существующие записи и вставляет новые, обеспечивая идемпотентность. |
| 10 | B | Best practices включают модульность, обработку ошибок с retry, мониторинг и метрики для надёжных pipelines. |
| 11 | B | ELT обеспечивает гибкость (можно трансформировать по-разному) и сохраняет сырые данные для будущего использования. |
| 12 | D | Time-based расписание использует cron expressions, например "0 2 * * *" для ежедневного запуска в 2:00. |
| 13 | D | Event-based расписание запускает job по событию, например после завершения другого job или появления файла. |
| 14 | A | Обработка ошибок включает retry механизмы, логирование для отладки и alerting для уведомления о проблемах. |
| 15 | A | Все метрики (время выполнения, объём данных, успешность запусков) важны для мониторинга batch pipelines. |
