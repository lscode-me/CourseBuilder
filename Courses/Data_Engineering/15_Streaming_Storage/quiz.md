## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | Log — это append-only структура данных, где записи добавляются только в конец, обеспечивая упорядоченность и простоту. |
| 2 | D | Append-only структура обеспечивает быструю запись, простоту реализации и эффективный последовательный доступ. |
| 3 | D | Offset — это позиция записи в log, используемая для навигации и чтения данных с определённой точки. |
| 4 | D | Retention — это политика хранения, определяющая как долго хранятся данные в log (по времени или размеру). |
| 5 | D | Time-based retention хранит данные по времени (например, 7 дней, 30 дней) и автоматически удаляет старые данные. |
| 6 | D | Size-based retention хранит данные по размеру (например, 10GB, 100GB) и удаляет старые данные при превышении лимита. |
| 7 | C | Log compaction удаляет старые версии записей, оставляя только последние значения для каждого ключа, оптимизируя хранение. |
| 8 | B | Compaction следует использовать для key-value данных, состояния системы, когда важны последние значения, а не вся история. |
| 9 | A | Replay — это переобработка данных из log, начиная с определённого offset, для отладки, восстановления или тестирования. |
| 10 | B | Replay используется для отладки, восстановления после ошибок, тестирования исправлений и восстановления состояния. |
| 11 | C | Все преимущества (простота, durability, replay capability) относятся к log структуре данных. |
| 12 | B | Выбор retention policy должен балансировать между хранением и стоимостью, учитывать требования к replay и compliance. |
| 13 | B | Retention удаляет старые данные по времени или размеру, compaction удаляет старые версии записей по ключу, оставляя последние значения. |
| 14 | D | Replay можно начать с любого offset в log, что позволяет переобработать данные с любой точки. |
| 15 | C | Best practices включают правильный выбор retention, использование compaction для key-value данных и настройку replay capability. |
