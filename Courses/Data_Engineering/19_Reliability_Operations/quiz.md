## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | Fault tolerance — это способность системы продолжать работу при сбоях компонентов через redundancy и failover. |
| 2 | B | Redundancy — это дублирование компонентов (серверы, данные) для обеспечения отказоустойчивости. |
| 3 | C | Failover — это автоматическое переключение на резервный компонент при сбое основного для обеспечения непрерывности работы. |
| 4 | C | Monitoring — это непрерывное наблюдение за состоянием системы через сбор метрик и их анализ. |
| 5 | A | Все типы метрик (System, Application, Business) важны для полного понимания состояния системы. |
| 6 | D | Alerting — это автоматические уведомления о проблемах в системе для раннего обнаружения и реагирования. |
| 7 | B | Threshold-based alerting генерирует алерты при превышении определённых порогов (например, CPU > 80%). |
| 8 | A | Anomaly detection использует ML подходы для обнаружения аномалий в поведении системы, не только пороговые значения. |
| 9 | B | SLA (Service Level Agreement) — это соглашение с клиентами о качестве сервиса, включая последствия нарушения. |
| 10 | A | SLO (Service Level Objective) — это внутренние цели производительности, метрики для команды. |
| 11 | A | SLO — внутренние цели для команды, SLA — соглашение с клиентами, включающее последствия нарушения SLA. |
| 12 | D | Graceful degradation позволяет системе продолжать работу при частичных сбоях, ухудшая функциональность вместо полного отказа. |
| 13 | A | Replication дублирует данные на нескольких узлах для отказоустойчивости и обеспечения доступности при сбоях. |
| 14 | A | Uptime — это процент времени, когда система доступна и работает корректно (например, 99.9% uptime). |
| 15 | A | Все компоненты (Fault Tolerance, Monitoring, Alerting) входят в комплексный подход к надёжности системы. |
