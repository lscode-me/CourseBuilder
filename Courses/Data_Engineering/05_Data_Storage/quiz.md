## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Реляционные базы данных хранят структурированные данные в таблицах с поддержкой ACID транзакций и SQL запросов. |
| 2 | B | Все перечисленные типы (Document, Key-Value, Column-family, Graph) являются типами NoSQL баз данных. |
| 3 | D | Data Warehouses оптимизированы для аналитических запросов, отчётов и Business Intelligence, а не для операций. |
| 4 | B | Columnar storage ускоряет агрегации и аналитические запросы, так как данные организованы по колонкам, а не по строкам. |
| 5 | B | Data Lake использует schema-on-read подход, где схема применяется при чтении данных, а не при записи. |
| 6 | B | Data Lake может хранить любые форматы данных: структурированные (CSV, JSON, Parquet) и неструктурированные (изображения, видео). |
| 7 | B | Lakehouse — это гибридный подход, объединяющий гибкость Data Lake с управлением и производительностью Data Warehouse. |
| 8 | C | Lakehouse объединяет преимущества: ACID транзакции, schema enforcement, открытые форматы и единое хранилище. |
| 9 | B | Data Lakes используют schema-on-read, в то время как Databases и Data Warehouses используют schema-on-write. |
| 10 | B | Databases используются для операционных транзакций и real-time доступа, в отличие от Data Warehouses для аналитики. |
| 12 | D | Все перечисленные (AWS S3, Azure Data Lake Storage, Google Cloud Storage) являются примерами Data Lakes. |
| 13 | B | Многослойная архитектура может включать все три слоя: Operational (Database), Analytical (Warehouse), Raw (Lake). |
| 14 | D | Lakehouse архитектура обычно включает все три слоя: Bronze (сырые), Silver (очищенные), Gold (готовые для потребления). |
| 15 | D | Databases оптимизированы для операционных транзакций и быстрого доступа к отдельным записям, а не для аналитики. |
