## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Data Engineering как system design означает принятие решений на основе компромиссов, понимая что нет универсальных решений. |
| 2 | B | OLTP хранилища (PostgreSQL, MySQL) следует использовать для транзакционных данных с ACID требованиями и низкой задержкой записи. |
| 3 | A | OLAP хранилища (Snowflake, BigQuery) следует использовать для аналитических запросов на больших объёмах данных. |

| 5 | D | Column-based форматы (Parquet, ORC) следует использовать для аналитических запросов с агрегациями на больших объёмах. |
| 6 | A | B-tree индекс следует использовать для range queries и упорядоченного поиска благодаря структуре сбалансированного дерева. |
| 7 | D | Hash индекс следует использовать для точного поиска со сложностью O(1) в среднем. |
| 8 | D | Компромисс consistency vs availability означает выбор между strong consistency и high availability, описывается CAP theorem. |
| 9 | C | Компромисс latency vs throughput означает выбор между низкой задержкой и высокой пропускной способностью, зависит от use case. |
