## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | Entity — это объект или концепция, о которой хранятся данные, представляемая таблицей в БД. |
| 2 | B | One-to-Many связь: один пользователь может иметь много заказов. Реализуется через FK в таблице Orders. |
| 3 | D | Many-to-Many связь реализуется через junction table (связующую таблицу) с foreign keys на обе таблицы. |
| 4 | C | 1NF требует атомарных значений (одно значение в ячейке) и отсутствия повторяющихся групп. |
| 5 | B | 2NF требует 1NF + отсутствие частичных зависимостей (все неключевые атрибуты зависят от всего первичного ключа). |
| 6 | C | 3NF требует 2NF + отсутствие транзитивных зависимостей (неключевые атрибуты не зависят от других неключевых). |
| 7 | B | Все перечисленные проблемы (избыточность, update anomaly, delete anomaly) возникают при отсутствии нормализации. |
| 8 | B | Денормализация оправдана для оптимизации операций чтения в OLAP системах, где чтение преобладает над записью. |
| 9 | D | Нормализация минимизирует избыточность и обеспечивает высокую целостность данных, но требует JOIN для запросов. |
| 10 | A | Денормализация ускоряет чтение (нет JOIN), но усложняет обновления (нужно обновлять данные в нескольких местах). |
| 11 | D | OLTP системы обычно используют нормализацию (3NF) для обеспечения целостности и эффективности обновлений. |
| 12 | A | OLAP системы используют денормализацию для оптимизации аналитических запросов, где чтение преобладает. |
| 13 | A | Hybrid подход использует нормализованные данные для операций (OLTP) и денормализованные для аналитики (OLAP). |
| 14 | C | Вычисляемые поля — это предварительно вычисленные значения (например, total_amount), сохранённые для ускорения запросов. |
| 15 | B | Сводные таблицы содержат агрегированные данные (например, daily_sales) для быстрого доступа без повторных вычислений. |
