## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | Все типы ошибок (Transient, Permanent, System) могут возникать в data pipelines и требуют разных подходов к обработке. |
| 2 | D | Retry механизмы используются для автоматического повторения операций при временных ошибках (сеть, таймауты). |
| 3 | B | Exponential backoff увеличивает задержку между попытками экспоненциально (1s, 2s, 4s, 8s) для эффективности. |
| 4 | A | Ограничение количества retry попыток предотвращает бесконечные циклы и контролирует использование ресурсов. |
| 5 | C | Backfill — это переобработка исторических данных, обычно после исправления ошибок или изменений в логике. |
| 6 | B | Full backfill используется для критических исправлений, когда нужно переобработать все данные. |
| 7 | C | Incremental backfill переобрабатывает только изменённые периоды, что более эффективно по времени и ресурсам. |
| 8 | C | Версионирование данных позволяет отслеживать изменения и восстанавливать предыдущие версии при необходимости. |
| 9 | C | Snapshot versioning создаёт полные снимки данных на момент времени, просто, но требует больше места. |
| 10 | A | Delta versioning хранит только изменения между версиями, что эффективнее по объёму, но сложнее в реализации. |
| 11 | D | Воспроизводимость означает, что pipeline даёт одинаковый результат при повторном выполнении с теми же входными данными и параметрами. |
| 12 | D | Детерминированные операции дают одинаковый результат для одинаковых входных данных, без случайности. |
| 13 | B | Fail fast стратегия быстро обнаруживает ошибки и немедленно останавливает выполнение при критических ошибках. |
| 14 | A | Dead letter queue — это очередь для необработанных записей, позволяющая вручную обработать проблемные данные. |
| 15 | D | Best practices включают фиксированные версии зависимостей, детерминированные операции и документацию параметров. |
