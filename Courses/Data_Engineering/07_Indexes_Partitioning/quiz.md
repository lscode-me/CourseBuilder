## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Индекс — это дополнительная структура данных (B-tree, Hash), которая ускоряет поиск записей в таблице. |
| 2 | A | B-tree индекс поддерживает range queries и упорядоченный поиск благодаря структуре сбалансированного дерева. |
| 3 | A | Hash индекс оптимизирован для точного поиска со сложностью O(1) в среднем, но не поддерживает range queries. |
| 4 | C | Индексы ускоряют чтение, но замедляют запись (нужно обновлять индекс) и требуют дополнительного места. |
| 5 | D | Партиционирование — это разделение таблицы на меньшие части (партиции) в рамках одного сервера для оптимизации запросов. |
| 6 | A | Все перечисленные типы (Range, Hash, List) являются типами партиционирования. |
| 7 | A | Партиционирование позволяет сканировать только нужные партиции вместо всей таблицы, ускоряя запросы. |
| 8 | D | Sharding — это горизонтальное разделение данных по нескольким узлам (шардам) для масштабирования. |
| 9 | D | Partitioning разделяет данные в рамках одного сервера, sharding распределяет данные по нескольким серверам. |
| 10 | B | Индексы следует создавать для часто используемых колонок в WHERE, foreign keys и колонок для JOIN. |
| 11 | A | Индексы НЕ следует создавать для колонок с низкой селективностью, write-heavy таблиц и маленьких таблиц. |
| 12 | A | Ключ партиционирования должен быть колонкой, часто используемой в WHERE, с равномерным распределением значений. |
| 13 | B | Партиционирование следует использовать для больших таблиц (>10GB) с запросами, фильтрующими по партиционному ключу. |
| 14 | A | Sharding следует использовать когда нужно горизонтальное масштабирование и один сервер не справляется с нагрузкой. |
| 15 | B | В реальных системах часто используются все три техники вместе: индексы на партициях, sharding с партиционированием. |
