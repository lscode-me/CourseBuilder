## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Vertical scaling увеличивает ресурсы одного сервера (CPU, RAM, storage) для обработки большей нагрузки. |
| 2 | D | Horizontal scaling добавляет новые серверы и распределяет нагрузку между ними для масштабирования. |
| 3 | A | Horizontal scaling имеет преимущества: безграничное масштабирование и высокая отказоустойчивость. |
| 4 | C | Throughput — это количество операций в единицу времени (например, запросов в секунду). |
| 5 | A | Latency — это время выполнения одной операции (например, миллисекунды на запрос). |
| 6 | D | Trade-off между throughput и latency: увеличение одного может повлиять на другое, зависит от use case. |
| 7 | B | Bottlenecks — это узкие места в системе, которые ограничивают общую производительность. |
| 8 | D | CPU bound bottleneck означает ограничение по CPU, решение — добавить больше CPU cores или оптимизировать код. |
| 9 | D | I/O bound bottleneck означает ограничение по I/O, решение — улучшить storage или network. |
| 10 | B | Cost-aware design — это проектирование с учётом стоимости, включая right-sizing и выбор типа ресурсов. |
| 11 | A | Right-sizing — это выбор правильного размера ресурсов, не переплачивая за избыточные ресурсы. |
| 12 | A | Reserved instances дешевле для долгосрочного использования, on-demand гибче для переменных нагрузок. |
| 13 | A | Все преимущества (безграничное масштабирование, отказоустойчивость, стоимость) относятся к horizontal scaling. |
| 14 | B | Vertical scaling ограничен физическими пределами сервера (максимальные CPU, RAM, которые можно установить). |
| 15 | C | Оптимальная производительность требует баланса между масштабированием, производительностью и стоимостью. |
