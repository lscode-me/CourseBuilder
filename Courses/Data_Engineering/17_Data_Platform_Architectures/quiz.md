## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | Lambda архитектура разделяет обработку на batch layer (точные результаты) и speed layer (низкая задержка). |
| 2 | C | Все компоненты (Batch Layer, Speed Layer, Serving Layer) входят в Lambda архитектуру. |
| 3 | B | Batch layer обрабатывает все данные с точными результатами, но с высокой задержкой. |
| 4 | B | Speed layer обрабатывает новые данные с приблизительными результатами, но с низкой задержкой. |
| 5 | D | Все недостатки (дублирование логики, сложность поддержки, два кода) относятся к Lambda архитектуре. |
| 6 | B | Kappa архитектура использует единый streaming слой для всех данных вместо разделения на batch и speed. |
| 7 | B | Все преимущества (единая кодовая база, простота поддержки, replay) относятся к Kappa архитектуре. |
| 8 | D | Replay в Kappa архитектуре позволяет переобработать данные для исправления ошибок или обновления логики. |
| 9 | D | Modern Data Stack использует облачные управляемые сервисы и современные инструменты для построения data-платформы. |
| 10 | C | Все компоненты (Cloud Data Warehouses, ELT Tools, Orchestration) входят в Modern Data Stack. |
| 11 | A | Все преимущества (управляемые сервисы, SQL-first, интеграция) относятся к Modern Data Stack. |
| 12 | B | Lambda архитектура подходит когда требуется высокая точность из batch layer и низкая задержка из speed layer. |
| 13 | A | Kappa архитектура подходит для streaming-first подходов, где важна простота поддержки единого кода. |
| 14 | A | Modern Data Stack подходит для облачных решений с SQL-first подходом и управляемыми сервисами. |
| 15 | A | Архитектуры эволюционируют, и Modern Data Stack становится стандартом благодаря простоте и управляемости. |
