## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | C | Data Governance — это управление доступностью, целостностью и безопасностью данных через политики, процессы, роли и мониторинг для обеспечения правильного использования данных. |
| 2 | D | Data Governance включает политики (правила работы с данными), процессы (процедуры управления), роли и ответственность (кто за что отвечает) и мониторинг (отслеживание использования). |
| 3 | D | Классификация данных по чувствительности необходима для применения соответствующих мер безопасности (контроль доступа, шифрование) в зависимости от уровня чувствительности данных. |
| 4 | C | GDPR (General Data Protection Regulation) — это европейское регулирование защиты персональных данных, устанавливающее требования к обработке персональных данных граждан ЕС. |
| 5 | D | GDPR требует явного согласия субъекта данных на обработку его персональных данных для конкретной цели, что является основным принципом защиты данных. |
| 6 | D | Право доступа по GDPR означает право субъекта данных получить информацию о том, какие персональные данные о нём обрабатываются, для каких целей и как долго. |
| 7 | D | Право на удаление (right to be forgotten) по GDPR означает право субъекта данных требовать удаления своих персональных данных при определённых условиях. |
| 8 | A | HIPAA (Health Insurance Portability and Accountability Act) — это регулирование защиты медицинских данных в США, устанавливающее требования к защите PHI. |
| 9 | A | PHI (Protected Health Information) — это персональная медицинская информация, которая идентифицирует пациента и защищается требованиями HIPAA. |
| 10 | D | HIPAA включает требования защиты PHI (физическая и техническая защита), контроль доступа (только авторизованные пользователи), аудит логов (отслеживание доступа) и шифрование данных. |
| 11 | C | RBAC (Role-Based Access Control) — это контроль доступа на основе ролей пользователей, где разрешения назначаются ролям, а пользователи получают роли. |
| 12 | D | ABAC (Attribute-Based Access Control) — это контроль доступа на основе атрибутов пользователя (проект, отдел) и ресурса (чувствительность, владелец), что более гибко чем RBAC. |
| 13 | D | Аудит логи необходимы для отслеживания доступа к данным (кто, когда, что), обеспечения compliance (GDPR, HIPAA требуют аудит) и выявления нарушений безопасности. |
| 14 | A | Data lineage — это отслеживание происхождения данных и их трансформаций через pipeline, что важно для понимания, откуда взялись данные и как они были обработаны. |
| 15 | C | Encryption at rest означает защиту данных на диске через шифрование, что защищает данные даже если физический носитель будет скомпрометирован. |
| 16 | C | Encryption in transit означает защиту данных при передаче по сети через шифрование (TLS/SSL), что защищает данные от перехвата при передаче. |
| 17 | D | Безопасное управление ключами критично, потому что компрометация ключей шифрования означает компрометацию всех зашифрованных данных, поэтому ключи должны храниться безопасно. |
| 18 | A | Принцип минимизации данных в GDPR означает сбор и обработку только тех данных, которые необходимы для конкретной законной цели, избегая избыточного сбора данных. |
| 19 | C | Data retention policy — это политика определения сроков хранения данных, которая определяет, как долго данные должны храниться и когда должны быть удалены или архивированы. |
| 20 | A | Data Steward — это роль в Data Governance, ответственная за управление качеством данных, обеспечение соответствия политикам и поддержание метаданных. |
| 21 | A | Анонимизация данных позволяет использовать данные в исследованиях без нарушения privacy требований, удаляя или маскируя идентифицирующую информацию. |
| 22 | B | Псевдонимизация — это замена прямых идентификаторов (имя, ID) на псевдонимы, что защищает privacy, но позволяет связать данные при необходимости через ключ. |
| 23 | C | Регулярные compliance проверки необходимы для обеспечения постоянного соответствия требованиям (GDPR, HIPAA), выявления нарушений и принятия корректирующих мер. |
| 24 | A | Инциденты безопасности данных следует обрабатывать через немедленное реагирование, расследование причины, уведомление затронутых сторон (если требуется) и принятие мер по предотвращению повторения. |
| 25 | A | Трассируемость данных важна для compliance, потому что позволяет продемонстрировать происхождение данных, их обработку и соответствие требованиям при аудитах и проверках. |
