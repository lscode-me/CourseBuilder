## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Архитектура scientific data platform включает data ingestion (приём данных), storage (хранение), processing (обработка), analysis (анализ) и metadata management (управление метаданными). |
| 2 | D | Data Lake характеризуется хранением любых данных в исходном формате, schema-on-read подходом (схема применяется при чтении) и высокой масштабируемостью для больших объёмов данных. |
| 3 | C | Data Warehouse — это структурированное хранилище с schema-on-write подходом (схема определяется при записи), оптимизированное для быстрых запросов и анализа структурированных данных. |
| 4 | A | Schema-on-read означает, что схема применяется при чтении данных (Data Lake), что даёт гибкость. Schema-on-write означает, что схема определяется при записи (Data Warehouse), что обеспечивает структурированность. |
| 5 | C | Data Lake следует использовать, когда данные в разных форматах (структурированные, неструктурированные) и нужна гибкость для исследования данных без предопределённой схемы. |
| 6 | B | On-premise развёртывание даёт полный контроль над инфраструктурой и данными, обеспечивает безопасность данных и отсутствие зависимости от внешнего провайдера. |
| 7 | C | Cloud развёртывание обеспечивает масштабируемость (автоматическое масштабирование), оплату по использованию (pay-as-you-go) и управляемые сервисы, требующие минимального администрирования. |
| 8 | D | Hybrid архитектура — это комбинация on-premise и cloud, которая позволяет оптимизировать безопасность (чувствительные данные on-premise) и масштабируемость (cloud для пиковых нагрузок). |
| 9 | B | HPC (High-Performance Computing) — это высокопроизводительные вычисления для сложных задач, требующих параллельной обработки на кластерах с множеством процессоров и высокой скоростью сети. |
| 10 | C | HPC система включает compute nodes (вычислительные узлы), высокоскоростную сеть (InfiniBand), параллельную файловую систему (Lustre, GPFS) и job scheduler (SLURM, PBS) для управления задачами. |
| 11 | C | Job scheduler в HPC нужен для планирования задач, управления ресурсами кластера (CPU, память), обеспечения справедливого распределения ресурсов и оптимизации использования кластера. |
| 12 | D | Lambda Architecture — это архитектурный паттерн, комбинирующий batch слой (обработка исторических данных) и speed слой (обработка в реальном времени) для полного покрытия данных. |
| 13 | D | Data ingestion включает приём данных из различных источников: экспериментов, научных инструментов, симуляций и внешних источников, что является первым шагом в data pipeline. |
| 14 | B | Управление метаданными критично для отслеживания происхождения данных, версионирования, поиска данных, обеспечения воспроизводимости и понимания контекста данных. |
| 15 | D | Масштабируемость архитектуры означает способность обрабатывать растущие объёмы данных и нагрузку без значительного снижения производительности, что критично для научных проектов. |
| 16 | A | Модель оплаты в cloud работает по принципу оплаты по использованию (pay-as-you-go), что позволяет платить только за используемые ресурсы и оптимизировать затраты. |
| 17 | D | Безопасность данных зависит от требований: on-premise даёт максимальный контроль, но cloud с правильной настройкой безопасности (шифрование, контроль доступа) также может быть безопасным. |
| 18 | A | Параллельная файловая система (Lustre, GPFS) нужна в HPC для высокопроизводительного доступа к данным из множества узлов кластера одновременно, что критично для параллельных вычислений. |
| 19 | D | При выборе архитектуры важно учитывать объём данных, тип данных (структурированные/неструктурированные), требования к производительности, бюджет, безопасность и масштабируемость. |
| 20 | A | Managed services в cloud — это сервисы, управляемые провайдером (базы данных, хранилища, аналитика), которые требуют минимального администрирования и автоматически масштабируются. |
| 21 | B | Data catalog — это каталог данных с метаданными (описания, схемы, версии), который позволяет находить и понимать доступные данные в data lake, что критично для больших хранилищ. |
| 22 | C | Data lineage — это отслеживание происхождения данных и их трансформаций через pipeline, что важно для понимания, откуда взялись данные и как они были обработаны. |
| 23 | C | Звёздная схема в data warehouse — это архитектура с fact таблицами (измерения, события) в центре и dimension таблицами (метаданные, категории) вокруг, оптимизированная для запросов. |
| 24 | D | HPC следует использовать для compute-intensive задач (молекулярное моделирование, климатические симуляции), требующих высокой производительности и параллельной обработки на множестве ядер. |
| 25 | D | При миграции scientific data в cloud важно учитывать безопасность данных (шифрование, контроль доступа), соответствие требованиям (GDPR, HIPAA), стоимость передачи данных и производительность. |
