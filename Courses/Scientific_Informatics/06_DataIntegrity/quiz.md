## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | C | Качество данных определяется полнотой (нет пропусков), точностью (соответствие реальности), согласованностью (логическая корректность), валидностью (формат) и актуальностью (время). |
| 2 | B | Полнота данных означает отсутствие пропущенных значений (NaN, None) в наборе данных. |
| 3 | C | Согласованность данных означает логическую корректность и соответствие ограничениям (диапазоны, правила). |
| 4 | A | Checksum (контрольная сумма) используется для проверки целостности данных и обнаружения изменений или повреждений. |
| 5 | D | Версионирование данных должно использовать семантическое версионирование (MAJOR.MINOR.PATCH), неизменяемость старых версий и метаданные об изменениях. |
| 6 | B | Валидация данных включает структурную (формат, типы), семантическую (логика) и проверку бизнес-правил (доменные ограничения). |
| 7 | B | Метод IQR использует границы Q1 - 1.5×IQR и Q3 + 1.5×IQR для определения выбросов, где IQR = Q3 - Q1. |
| 8 | D | Контроль доступа основан на принципах минимальных привилегий (доступ только к необходимому), аутентификации (проверка личности) и авторизации (проверка прав). |
| 9 | B | Шифрование данных включает at rest (хранимые данные), in transit (при передаче) и end-to-end (от источника до получателя). |
| 10 | B | Аудит данных обеспечивает трассируемость доступа и действий с данными, что важно для безопасности и соответствия требованиям. |
| 11 | A | Семантическое версионирование: MAJOR - несовместимые изменения API, MINOR - новые функции с обратной совместимостью, PATCH - исправления ошибок. |
| 12 | A | Структурная валидация проверяет формат данных и типы (например, является ли значение числом, строкой, соответствует ли структуре). |
| 13 | B | Семантическая валидация проверяет логическую корректность данных (например, температура не может быть отрицательной в определённом контексте). |
| 14 | A | Z-score метод вычисляет стандартизированное отклонение: значения с |Z| > threshold (обычно 3) считаются выбросами. |
| 15 | C | Принцип минимальных привилегий означает предоставление пользователю доступа только к необходимым данным и операциям для выполнения его задач. |
| 16 | B | Аутентификация — проверка личности пользователя (кто вы), авторизация — проверка прав доступа (что вы можете делать). |
| 17 | B | Логирование изменений позволяет отслеживать историю изменений, восстанавливать предыдущие версии и проводить аудит. |
| 18 | B | Проверка целостности выполняется сравнением вычисленного checksum файла с сохранённым checksum — если совпадают, данные не изменены. |
| 19 | C | Бизнес-правила валидации — это доменные ограничения и правила предметной области (например, реакция не может быть отрицательной). |
| 20 | D | Шифрование "at rest" означает шифрование данных, хранящихся на диске или в базе данных, в отличие от "in transit" (при передаче). |
| 21 | A | Трассируемость через аудит обеспечивает возможность отследить кто (пользователь), когда (время) и что (действие) делал с данными. |
| 22 | C | Для обнаружения выбросов используются различные статистические методы: IQR, Z-score, и другие, в зависимости от типа данных. |
| 23 | C | Правила валидации добавляются через систему правил (not_null, range, type и др.), что позволяет гибко настраивать проверки. |
| 24 | B | Уровни доступа обычно включают read (чтение), write (запись) и admin (администрирование) с разными привилегиями. |
| 25 | C | Чеклист качества данных включает проверку полноты (нет пропусков), точности (соответствие), согласованности (логика), валидности (формат) и целостности (checksum). |
