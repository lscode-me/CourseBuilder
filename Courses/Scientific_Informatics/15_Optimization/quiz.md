## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Оптимизация производительности начинается с профилирования для выявления узких мест (bottlenecks), а не с преждевременной оптимизации кода. |
| 2 | C | Performance bottleneck — это часть кода, которая занимает непропорционально много времени выполнения, что замедляет весь pipeline и требует оптимизации. |
| 3 | C | Выбор алгоритма критически важен, потому что разные алгоритмы имеют разную временную сложность (O(n) vs O(log n)), что значительно влияет на скорость при больших данных. |
| 4 | D | Параллельная обработка ускоряет обработку данных через использование нескольких процессоров или ядер одновременно, что особенно эффективно для независимых операций. |
| 5 | B | Параллельные вычисления происходят на одной машине (несколько ядер), а распределённые вычисления — на нескольких машинах в сети, что позволяет обрабатывать ещё большие объёмы данных. |
| 6 | C | Горизонтальное масштабирование — это добавление большего количества машин для обработки данных, что позволяет масштабировать систему без ограничений одной машины. |
| 7 | C | Стоимость вычислений в cloud можно оптимизировать через spot instances (прерываемые по низкой цене), reserved instances (долгосрочная аренда), right-sizing (правильный размер) и auto-scaling. |
| 8 | B | Spot instances — это прерываемые инстансы по сниженной цене (до 90% дешевле), подходящие для задач, которые могут терпеть прерывания и перезапуск. |
| 9 | A | Retry логика нужна для автоматического повторения операций при временных сбоях (сетевые ошибки, временная недоступность сервисов), что повышает надёжность pipeline. |
| 10 | B | Checkpointing — это сохранение промежуточных результатов pipeline, что позволяет возобновить выполнение после сбоя без перезапуска с начала, экономя время и ресурсы. |
| 11 | D | Отказоустойчивость pipeline означает способность продолжать работу или восстанавливаться после сбоев отдельных компонентов, что критично для production систем. |
| 12 | A | Кэширование результатов вычислений позволяет избежать повторных вычислений для тех же входных данных, что значительно ускоряет выполнение при повторных запросах. |
| 13 | C | Оптимизация I/O включает использование буферизации (большие буферы), batch операции (групповые чтения/записи), бинарные форматы (быстрее текстовых) и сжатие данных. |
| 14 | B | Профилирование кода показывает время выполнения каждой функции или метода, что позволяет выявить узкие места и сфокусировать оптимизацию на самых медленных частях. |
| 15 | A | Exponential backoff — это стратегия retry, где задержка между попытками увеличивается экспоненциально (1s, 2s, 4s, 8s...), что снижает нагрузку на систему при повторных попытках. |
| 16 | D | Вертикальное масштабирование — это увеличение мощности существующей машины (больше CPU, больше памяти), в отличие от горизонтального (добавление машин). |
| 17 | C | Load balancing нужен для равномерного распределения нагрузки между узлами в распределённой системе, что предотвращает перегрузку отдельных узлов и оптимизирует использование ресурсов. |
| 18 | A | Fault tolerance означает способность системы продолжать работу при сбоях отдельных компонентов через избыточность, retry логику и graceful degradation. |
| 19 | A | Оптимизация памяти включает использование правильных типов данных (int32 вместо int64), удаление неиспользуемых данных и использование генераторов вместо списков для больших данных. |
| 20 | B | Мониторинг производительности нужен для выявления проблем (узкие места, ошибки), оптимизации использования ресурсов и планирования масштабирования pipeline. |
| 21 | B | Стоимость хранения данных можно оптимизировать через использование разных классов хранения (hot/cold/archive), сжатие данных и архивирование старых данных в более дешёвое хранилище. |
| 22 | D | Auto-scaling — это автоматическое увеличение или уменьшение ресурсов (вычислительных, памяти) на основе текущей нагрузки, что оптимизирует стоимость и производительность. |
| 23 | D | Оптимизация запросов включает использование индексов для быстрого поиска, оптимизацию структуры запросов и кэширование результатов частых запросов. |
| 24 | B | Баланс между ресурсами и производительностью достигается через оптимизацию использования ресурсов для достижения требуемой производительности без избыточных затрат на ненужные ресурсы. |
| 25 | C | Production-ready pipeline означает надёжный (обработка ошибок, retry), масштабируемый (может обрабатывать растущие объёмы), мониторируемый (логи, метрики) pipeline с правильной обработкой ошибок. |

## Scoring Guide

Подсчитайте количество правильных ответов:

| Результат | Оценка | Рекомендации |
|-----------|--------|--------------|
| **23-25 правильных (90-100%)** | 🏆 Отлично! | Вы отлично усвоили материал. Переходите к следующему модулю. |
| **18-22 правильных (70-89%)** | ✅ Хорошо | Хороший результат! Повторите темы, в которых ошиблись. |
| **13-17 правильных (50-69%)** | ⚠️ Удовлетворительно | Рекомендуется перечитать соответствующие разделы лекции. |
| **Менее 13 правильных (<50%)** | 📚 Нужно повторить | Внимательно перечитайте лекцию и попробуйте ещё раз. |
