## 1. Введение: важность правильного выбора

Выбор структуры данных — это одно из самых важных решений при проектировании системы. Правильный выбор может сделать систему в разы быстрее и эффективнее, а неправильный — привести к проблемам с производительностью и масштабируемостью.

**Цель этого модуля:** Научиться систематически подходить к выбору структуры данных, задавая правильные вопросы и анализируя компромиссы.

## 2. Инженерные вопросы для анализа

### 2.1 Какие операции критичны?

**Вопрос:** Какие операции выполняются чаще всего и должны быть максимально быстрыми?

**Анализ:**

- Определите частоту каждой операции
- Выделите критические операции (80/20 правило)
- Выберите структуру, оптимизированную для этих операций

**Example: Анализ операций**

```python

class OperationAnalyzer:
    """Анализатор операций для выбора структуры данных."""
    def __init__(self):
        self.operations = {}
    
    def log_operation(self, op_type, count=1):
        """Зарегистрировать операцию."""
        self.operations[op_type] = self.operations.get(op_type, 0) + count
    
    def get_critical_operations(self, threshold=0.8):
        """Получить критические операции (80% нагрузки)."""
        total = sum(self.operations.values())
        sorted_ops = sorted(self.operations.items(), key=lambda x: x[1], reverse=True)
        
        critical = []
        cumulative = 0
        for op, count in sorted_ops:
            critical.append(op)
            cumulative += count / total
            if cumulative >= threshold:
                break
        
        return critical
    
    def recommend_structure(self):
        """Рекомендовать структуру данных."""
        critical = self.get_critical_operations()
        
        if 'search' in critical and 'range_query' in critical:
            return "Отсортированный массив или B+ дерево"
        elif 'search' in critical:
            return "Хеш-таблица"
        elif 'insert_beginning' in critical:
            return "Связанный список"
        elif 'priority_access' in critical:
            return "Куча (Heap)"
        else:
            return "Массив или список"

# Пример анализа
analyzer = OperationAnalyzer()
analyzer.log_operation('search', 1000)
analyzer.log_operation('insert', 100)
analyzer.log_operation('delete', 50)

critical = analyzer.get_critical_operations()
recommendation = analyzer.recommend_structure()

print(f"Критические операции: {critical}")
print(f"Рекомендация: {recommendation}")
```

**Output:**
```

Критические операции: ['search']
Рекомендация: Хеш-таблица
```

### 2.2 Объём данных

**Вопрос:** Какой объём данных ожидается? Будет ли он расти?

**Анализ:**

- Оцените текущий и будущий объём
- Учтите ограничения памяти
- Выберите структуру, которая масштабируется

**Example: Анализ объёма данных**

```python

def choose_structure_by_volume(current_size, expected_growth, memory_limit):
    """Выбрать структуру данных на основе объёма."""
    future_size = current_size * expected_growth
    
    if future_size < 1000:
        return "Массив или список (небольшой объём)"
    elif future_size < 100000:
        return "Хеш-таблица или дерево (средний объём)"
    elif future_size < 10000000:
        if memory_limit < future_size * 100:  # Примерная оценка памяти
            return "Вероятностные структуры (Bloom Filter, Count-Min Sketch)"
        else:
            return "B+ дерево или индексированная структура"
    else:
        return "Распределённые структуры или вероятностные структуры"

# Примеры

print(f"Маленький объём: {choose_structure_by_volume(100, 2, 1000000)}")
print(f"Большой объём: {choose_structure_by_volume(1000000, 10, 100000000)}")
```

**Output:**
```

Маленький объём: Массив или список (небольшой объём)
Большой объём: Вероятностные структуры (Bloom Filter, Count-Min Sketch)
```

### 2.3 Ограничения по памяти

**Вопрос:** Сколько памяти доступно? Есть ли жёсткие ограничения?

**Анализ:**

- Определите доступную память
- Оцените использование памяти каждой структурой
- Выберите структуру, которая укладывается в ограничения

**Example: Анализ памяти**

```python

import sys

def estimate_memory_usage(structure_type, num_elements):
    """Оценить использование памяти."""
    estimates = {
        'array': num_elements * 8,  # 8 байт на элемент (int)
        'hash_table': num_elements * 24,  # ~24 байта на элемент
        'tree': num_elements * 40,  # ~40 байт на узел
        'bloom_filter': num_elements * 1.2,  # ~1.2 байта на элемент (при 1% ошибке)
    }
    return estimates.get(structure_type, 0)

def choose_by_memory(num_elements, memory_limit):
    """Выбрать структуру на основе ограничений памяти."""
    options = ['array', 'hash_table', 'tree', 'bloom_filter']
    
    for option in options:
        memory = estimate_memory_usage(option, num_elements)
        if memory <= memory_limit:
            return f"{option} (использует ~{memory/1024/1024:.2f} MB)"
    
    return "Нужна вероятностная структура или распределённое решение"

# Пример
num_elements = 1000000
memory_limit = 10 * 1024 * 1024  # 10 MB

result = choose_by_memory(num_elements, memory_limit)
print(f"Для {num_elements} элементов с лимитом {memory_limit/1024/1024} MB:")
print(f"Рекомендация: {result}")
```

**Output:**
```

Для 1000000 элементов с лимитом 10.0 MB:
Рекомендация: bloom_filter (использует ~1.14 MB)
```

### 2.4 Latency vs Throughput

**Вопрос:** Что важнее — низкая задержка (latency) или высокая пропускная способность (throughput)?

**Анализ:**

- **Latency:** время отклика на один запрос

- **Throughput:** количество обработанных запросов в секунду
- Выберите структуру, оптимизированную для нужной метрики

**Example: Анализ latency vs throughput**

```python

def choose_by_performance_goal(goal, operations):
    """Выбрать структуру на основе цели производительности."""
    if goal == 'low_latency':
        # Низкая задержка: быстрый доступ к одному элементу
        if 'random_access' in operations:
            return "Массив или хеш-таблица (O(1) доступ)"
        elif 'sorted_access' in operations:
            return "Отсортированный массив с бинарным поиском"
        else:
            return "Структура с минимальным overhead"
    
    elif goal == 'high_throughput':
        # Высокая пропускная способность: обработка множества операций
        if 'batch_operations' in operations:
            return "Массив (хорошая кэш-локальность)"
        elif 'stream_processing' in operations:
            return "Вероятностные структуры (Count-Min Sketch, Bloom Filter)"
        else:
            return "Структура с хорошей кэш-локальностью"
    
    else:
        return "Сбалансированная структура"

# Примеры
print(f"Низкая задержка: {choose_by_performance_goal('low_latency', ['random_access'])}")
print(f"Высокая пропускная способность: {choose_by_performance_goal('high_throughput', ['stream_processing'])}")
```

**Output:**
```

Низкая задержка: Массив или хеш-таблица (O(1) доступ)
Высокая пропускная способность: Вероятностные структуры (Count-Min Sketch, Bloom Filter)
```

### 2.5 Детерминированность vs Приближение

**Вопрос:** Нужна ли гарантированная точность или можно допустить приближённые ответы?

**Анализ:**

- **Детерминированные:** гарантированная точность, больше памяти

- **Вероятностные:** приближённые ответы, меньше памяти
- Выберите в зависимости от требований

**Example: Анализ точности**

```python

def choose_by_accuracy_requirement(need_exact, can_afford_memory, volume):
    """Выбрать структуру на основе требований к точности."""
    if need_exact:
        if can_afford_memory:
            return "Детерминированная структура (хеш-таблица, дерево)"
        else:
            return "Нужно найти компромисс или использовать распределённое решение"
    else:
        if volume > 1000000:
            return "Вероятностная структура (Bloom Filter, Count-Min Sketch)"
        else:
            return "Можно использовать детерминированную структуру"

# Примеры
print(f"Точность + память: {choose_by_accuracy_requirement(True, True, 100000)}")
print(f"Приближение + большой объём: {choose_by_accuracy_requirement(False, False, 10000000)}")
```

**Output:**
```

Точность + память: Детерминированная структура (хеш-таблица, дерево)
Приближение + большой объём: Вероятностная структура (Bloom Filter, Count-Min Sketch)
```

**Example: Полный анализ**

```python

class StructureSelector:
    """Систематический выбор структуры данных."""
    def __init__(self):
        self.requirements = {}
    
    def analyze(self, operations, data_volume, memory_limit, 
                latency_important, need_exact):
        """Провести полный анализ."""
        self.requirements = {
            'operations': operations,
            'data_volume': data_volume,
            'memory_limit': memory_limit,
            'latency_important': latency_important,
            'need_exact': need_exact
        }
        return self._select_structure()
    
    def _select_structure(self):
        """Выбрать структуру на основе требований."""
        ops = self.requirements['operations']
        volume = self.requirements['data_volume']
        memory = self.requirements['memory_limit']
        latency = self.requirements['latency_important']
        exact = self.requirements['need_exact']
        
        # Анализ операций
        if 'search' in ops and 'range_query' in ops:
            if volume > 1000000:
                return "B+ дерево (для БД) или отсортированный массив"
            else:
                return "Отсортированный массив с бинарным поиском"
        
        elif 'search' in ops:
            if not exact and volume > 1000000:
                return "Bloom Filter (для предварительной проверки)"
            elif latency:
                return "Хеш-таблица (O(1) поиск)"
            else:
                return "Дерево поиска (BST или сбалансированное)"
        
        elif 'priority_access' in ops:
            return "Куча (Heap) или приоритетная очередь"
        
        elif 'frequent_insert_delete' in ops:
            if 'beginning' in ops:
                return "Связанный список"
            else:
                return "Хеш-таблица или дерево"
        
        else:
            return "Массив или список (базовая структура)"

# Пример использования
selector = StructureSelector()
result = selector.analyze(
    operations=['search', 'insert'],
    data_volume=100000,
    memory_limit=10000000,
    latency_important=True,
    need_exact=True
)

print(f"Рекомендуемая структура: {result}")
```

**Output:**
```

Рекомендуемая структура: Хеш-таблица (O(1) поиск)
```

## 4. Практические примеры

### 4.1 Пример 1: Система кэширования

**Требования:**

- Быстрый поиск по ключу
- Ограниченная память
- Нужно удалять старые элементы

**Анализ:**

- Операция: поиск (критична), вставка, удаление
- Объём: средний, но ограниченная память
- Latency важна
- Точность нужна

**Выбор:** LRU Cache (хеш-таблица + двусвязный список)

### 4.2 Пример 2: Потоковая аналитика

**Требования:**

- Обработка миллионов событий в секунду
- Оценка частоты элементов
- Ограниченная память

**Анализ:**

- Операция: добавление, оценка частоты
- Объём: очень большой
- Throughput важна
- Точность не критична (приближённая оценка)

**Выбор:** Count-Min Sketch

### 4.3 Пример 3: База данных

**Требования:**

- Быстрый поиск по ключу
- Диапазонные запросы
- Данные на диске

**Анализ:**

- Операция: поиск, диапазонные запросы
- Объём: большой, на диске
- Latency важна
- Точность нужна

**Выбор:** B+ дерево

## 5. Компромиссы и trade-offs

### 5.1 Таблица компромиссов

| Требование | Структура A | Структура B | Компромисс |
|------------|-------------|-------------|------------|
| **Память vs Скорость** | Меньше памяти | Быстрее | Вероятностные vs Детерминированные |
| **Вставка vs Поиск** | Быстрая вставка | Быстрый поиск | Связанный список vs Хеш-таблица |
| **Порядок vs Скорость** | Сохраняет порядок | Быстрый поиск | Отсортированный массив vs Хеш-таблица |
| **Точность vs Память** | Точность | Меньше памяти | Детерминированные vs Вероятностные |

### 5.2 Принятие решений

**Правило:** Нет идеальной структуры для всех задач. Выбор — это компромисс.

**Подход:**

1. Определите критичные требования
2. Оцените компромиссы
3. Выберите структуру, которая лучше всего соответствует критичным требованиям
4. Будьте готовы пересмотреть выбор при изменении требований
