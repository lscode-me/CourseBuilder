## 1. Введение: проблема внешней памяти

Когда данные не помещаются в оперативную память и хранятся на диске, операции ввода-вывода становятся узким местом. Обычные сбалансированные деревья (AVL, красно-чёрные) не оптимальны для дисковых операций, так как:

- Каждый узел может быть на отдельной странице диска
- Чтение с диска намного медленнее, чем из памяти
- Нужно минимизировать количество обращений к диску

**B-деревья и B+ деревья** решают эту проблему, храня больше данных в каждом узле и минимизируя количество дисковых операций.

## 2. B-деревья

### 2.1 Определение B-дерева

**B-дерево** — это самобалансирующееся дерево поиска, где:
- Каждый узел может содержать более одного ключа
- Каждый узел (кроме корня) имеет минимум t-1 и максимум 2t-1 ключей (t — минимальная степень)
- Все листья на одном уровне
- Ключи в узле отсортированы

**Преимущества:**

- Меньше обращений к диску (больше данных в узле)
- Высота дерева меньше
- Оптимизировано для внешней памяти

**Example: Концептуальная структура B-дерева**

```python
class BTreeNode:
    """Узел B-дерева (упрощённая версия)."""
    def __init__(self, is_leaf=False):
        self.keys = []  # Ключи в узле
        self.children = []  # Дочерние узлы
        self.is_leaf = is_leaf
    
    def __str__(self):
        return f"Keys: {self.keys}, Leaf: {self.is_leaf}"

# Концептуальный пример B-дерева степени 3
# Корень: [10, 20]
#   Дети: [5], [15], [25, 30]

root = BTreeNode(is_leaf=False)
root.keys = [10, 20]

child1 = BTreeNode(is_leaf=True)
child1.keys = [5]

child2 = BTreeNode(is_leaf=True)
child2.keys = [15]

child3 = BTreeNode(is_leaf=True)
child3.keys = [25, 30]

root.children = [child1, child2, child3]

print(f"Корень: {root}")
for i, child in enumerate(root.children):
    print(f"  Ребёнок {i+1}: {child}")
```

**Output:**
```
Корень: Keys: [10, 20], Leaf: False
  Ребёнок 1: Keys: [5], Leaf: True
  Ребёнок 2: Keys: [15], Leaf: True
  Ребёнок 3: Keys: [25, 30], Leaf: True
```

### 2.2 Свойства B-дерева

**Ключевые свойства:**

- **Минимальная степень t:** определяет минимальное и максимальное количество ключей

- **Все листья на одном уровне:** дерево всегда сбалансировано

- **Высота:** O(log_t n), где t обычно велико (сотни или тысячи)

**Example: Высота B-дерева**

```python
import math

def btree_height(n, t):
    """Вычислить высоту B-дерева."""
    # Максимальное количество ключей в B-дереве степени t с высотой h
    # примерно: n <= (2t)^h
    # h >= log_{2t}(n)
    return math.ceil(math.log(n, 2 * t))

# Сравнение высот

n = 1000000  # 1 миллион ключей
t_btree = 100  # B-дерево степени 100
t_bst = 2  # Обычное BST (бинарное)

height_btree = btree_height(n, t_btree)
height_bst = btree_height(n, t_bst)

print(f"Высота B-дерева (t={t_btree}): {height_btree}")
print(f"Высота BST (бинарное): {height_bst}")
print(f"B-дерево ниже в {height_bst / height_btree:.1f} раз")
```

**Output:**
```
Высота B-дерева (t=100): 3
Высота BST (бинарное): 20
B-дерево ниже в 6.7 раз
```

**Вывод:** B-дерево имеет намного меньшую высоту, что означает меньше дисковых операций.

## 3. B+ деревья

### 3.1 Определение B+ дерева

**B+ дерево** — это вариант B-дерева, где:
- Все ключи хранятся только в листьях
- Внутренние узлы содержат только ключи для навигации
- Листья связаны в список для последовательного доступа
- Данные хранятся только в листьях

**Преимущества B+ перед B-деревом:**

- Более эффективный последовательный доступ (листья связаны)
- Больше ключей во внутренних узлах (только ключи, без данных)
- Оптимально для диапазонных запросов

**Example: Концептуальная структура B+ дерева**

```python
class BPlusTreeNode:
    """Узел B+ дерева (упрощённая версия)."""
    def __init__(self, is_leaf=False):
        self.keys = []
        self.children = []
        self.is_leaf = is_leaf
        self.next_leaf = None  # Ссылка на следующий лист (только для листьев)
        self.data = []  # Данные (только для листьев)

# Концептуальный пример
# Внутренний узел: [10, 20] (только ключи для навигации)
# Листья: [5:data5], [15:data15], [25:data25, 30:data30] (ключи + данные)

internal = BPlusTreeNode(is_leaf=False)
internal.keys = [10, 20]

leaf1 = BPlusTreeNode(is_leaf=True)
leaf1.keys = [5]
leaf1.data = ['data5']

leaf2 = BPlusTreeNode(is_leaf=True)
leaf2.keys = [15]
leaf2.data = ['data15']

leaf3 = BPlusTreeNode(is_leaf=True)
leaf3.keys = [25, 30]
leaf3.data = ['data25', 'data30']

# Связываем листья

leaf1.next_leaf = leaf2
leaf2.next_leaf = leaf3

internal.children = [leaf1, leaf2, leaf3]

print("B+ дерево:")
print(f"Внутренний узел: {internal.keys}")
for i, leaf in enumerate(internal.children):
    print(f"  Лист {i+1}: ключи={leaf.keys}, данные={leaf.data}")
```

**Output:**
```
B+ дерево:
Внутренний узел: [10, 20]
  Лист 1: ключи=[5], данные=['data5']
  Лист 2: ключи=[15], данные=['data15']
  Лист 3: ключи=[25, 30], данные=['data25', 'data30']
```

## 4. Применение в базах данных

### 4.1 Индексы в базах данных

Базы данных используют B+ деревья для индексации, что позволяет:

- Быстро находить записи по ключу
- Эффективно выполнять диапазонные запросы
- Минимизировать дисковые операции

**Example: Концептуальный индекс БД**

```python
class DatabaseIndex:
    """Концептуальный индекс базы данных на основе B+ дерева."""
    def __init__(self):
        # В реальности используется B+ дерево
        # Упрощённо: словарь для демонстрации концепции
        self.index = {}
    
    def insert(self, key, record_id):
        """Добавить индекс."""
        self.index[key] = record_id
    
    def search(self, key):
        """Поиск по ключу."""
        return self.index.get(key)
    
    def range_search(self, start_key, end_key):
        """Диапазонный поиск (B+ дерево оптимизировано для этого)."""
        result = []
        for key, record_id in self.index.items():
            if start_key <= key <= end_key:
                result.append((key, record_id))
        return sorted(result)

# Использование

db_index = DatabaseIndex()
db_index.insert(100, "record_1")
db_index.insert(200, "record_2")
db_index.insert(150, "record_3")
db_index.insert(250, "record_4")

# Поиск

result = db_index.search(150)
print(f"Поиск 150: {result}")

# Диапазонный поиск

range_result = db_index.range_search(120, 220)
print(f"Диапазон [120, 220]: {range_result}")
```

**Output:**
```
Поиск 150: record_3
Диапазон [120, 220]: [(150, 'record_3'), (200, 'record_2')]
```

### 4.2 Преимущества для БД

**B+ деревья идеальны для БД, потому что:**

- Минимизируют дисковые операции (меньше высота)
- Эффективны для диапазонных запросов (связанные листья)
- Поддерживают быстрый поиск, вставку, удаление

## 5. Сравнение структур

### 5.1 Таблица сравнения

| Характеристика | AVL/Красно-чёрное | B-дерево | B+ дерево |
|----------------|-------------------|----------|------------|
| **Высота** | O(log n) | O(log_t n) | O(log_t n) |
| **Ключи в узле** | 1 | Много | Много |
| **Данные в узле** | Да | Да | Только в листьях |
| **Последовательный доступ** | Медленный | Медленный | Быстрый |
| **Диапазонные запросы** | Медленные | Медленные | Быстрые |
| **Лучше для** | Память | Внешняя память | БД индексы |

### 5.2 Когда что использовать

**Используй AVL/красно-чёрное дерево, когда:**

- Данные в оперативной памяти
- Нужен быстрый поиск
- Не нужны диапазонные запросы

**Используй B-дерево, когда:**

- Данные на диске
- Нужно минимизировать дисковые операции
- Данные хранятся в узлах

**Используй B+ дерево, когда:**

- Данные на диске
- Нужны диапазонные запросы
- Данные хранятся только в листьях
- Нужен последовательный доступ

## 6. Практические примеры

### 6.1 Пример: Индекс первичного ключа

**Example: Индекс в таблице пользователей**

```python
# Концептуально: БД использует B+ дерево для индексации

class UserTableIndex:
    """Индекс таблицы пользователей."""
    def __init__(self):
        # В реальности: B+ дерево
        self.index = {}  # user_id -> (page_id, offset)
    
    def insert(self, user_id, page_id, offset):
        """Добавить индекс."""
        self.index[user_id] = (page_id, offset)
    
    def find(self, user_id):
        """Найти запись по ID."""
        return self.index.get(user_id)

# Использование

user_index = UserTableIndex()
user_index.insert(1001, page_id=5, offset=1024)
user_index.insert(1002, page_id=5, offset=2048)
user_index.insert(1003, page_id=6, offset=512)

location = user_index.find(1002)
print(f"Запись 1002 находится: страница {location[0]}, смещение {location[1]}")
```

**Output:**
```
Запись 1002 находится: страница 5, смещение 2048
```

### 6.2 Пример: Диапазонный запрос

**Example: Поиск пользователей в диапазоне ID**

```python
def range_query(self, start_id, end_id):
    """Диапазонный запрос (B+ дерево оптимизировано)."""
    result = []
    for user_id, location in self.index.items():
        if start_id <= user_id <= end_id:
            result.append((user_id, location))
    return sorted(result)

# Добавляем метод

UserTableIndex.range_query = range_query

result = user_index.range_query(1001, 1003)
print(f"Пользователи в диапазоне [1001, 1003]: {result}")
```

**Output:**
```
Пользователи в диапазоне [1001, 1003]: [(1001, (5, 1024)), (1002, (5, 2048)), (1003, (6, 512))]
```

## 7. Операции с B-деревьями

### 7.1 Поиск

Поиск в B-дереве похож на поиск в BST, но в каждом узле может быть несколько ключей.

**Сложность:** O(log_t n), где t — степень дерева.

### 7.2 Вставка

Вставка в B-дерево:

1. Найти лист для вставки
2. Вставить ключ в лист
3. Если лист переполнен, разделить и поднять ключ в родителя

**Сложность:** O(log_t n)

### 7.3 Удаление

Удаление из B-дерева сложнее, так как нужно поддерживать минимальное количество ключей в узлах.

**Сложность:** O(log_t n)

---

## 💡 Key Takeaways

- **B-деревья и B+ деревья** оптимизированы для внешней памяти (дисков)

- **B-дерево** хранит данные в узлах, имеет меньшую высоту за счёт большего количества ключей в узле

- **B+ дерево** хранит данные только в листьях, связанных в список, оптимально для диапазонных запросов

- **Высота** O(log_t n) вместо O(log n), где t может быть сотнями или тысячами

- **Применение:** индексы баз данных, файловые системы, системы хранения данных
