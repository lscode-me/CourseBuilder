## 1. Введение: что такое данные

Данные — это основа любой программы. Без данных программы не могут работать: они не могут принимать решения, выполнять вычисления или взаимодействовать с пользователем.

**Данные** — это информация, представленная в формате, который может быть обработан компьютером. Это могут быть:
- Числа (возраст пользователя, цена товара)
- Текст (имя, адрес, сообщение)
- Булевы значения (да/нет, включено/выключено)
- Более сложные комбинации (список товаров, профиль пользователя)

Но просто хранить данные недостаточно. Нужно их **организовать** так, чтобы:

- Быстро находить нужную информацию
- Эффективно добавлять новые данные
- Удалять устаревшие данные
- Обрабатывать данные в нужном порядке

Именно здесь на помощь приходят **структуры данных**.

## 2. Что такое структура данных

### 2.1 Определение

**Структура данных** — это способ организации и хранения данных в памяти компьютера, который определяет:
- Как данные расположены
- Какие операции можно выполнять с данными
- Как эффективно получать доступ к данным

Структура данных — это не просто контейнер для данных. Это **инструмент**, который определяет:

- **Что** можно делать с данными (операции)

- **Как** это делать эффективно (алгоритмы доступа)

- **Когда** использовать ту или иную структуру (сценарии применения)

### 2.2 Пример: список vs множество

Давайте рассмотрим простой пример, чтобы понять разницу между простым хранением и структурой данных.

**Example: Хранение уникальных элементов**

Представь, что нужно хранить список уникальных идентификаторов пользователей. Можно использовать обычный список:

```python
# Простой список

user_ids = [1, 2, 3, 4, 5]

# Проверка, есть ли ID в списке

def has_user(user_ids, user_id):
    return user_id in user_ids

# Проверка

print(has_user(user_ids, 3))
print(has_user(user_ids, 10))
```

**Output:**
```
True
False
```

Проблема: для проверки наличия элемента нужно пройти по всему списку. Если в списке миллион элементов, это может быть медленно.

Теперь используем структуру данных — множество (set):

```python
# Множество (set) — структура данных для уникальных элементов

user_ids = {1, 2, 3, 4, 5}

# Проверка наличия элемента

print(3 in user_ids)
print(10 in user_ids)
```

**Output:**
```
True
False
```

**Объяснение:**
Множество (`set`) — это структура данных, оптимизированная для быстрой проверки принадлежности элемента. Внутри она использует хеширование, что позволяет проверять наличие элемента за O(1) вместо O(n) в списке.

Это и есть разница между простым хранением и структурой данных: структура данных **оптимизирована** для определённых операций.

## 3. Структуры данных и алгоритмы

### 3.1 Неразрывная связь

Структуры данных и алгоритмы — это две стороны одной медали. Их нельзя рассматривать отдельно:

- **Структура данных** определяет, как организованы данные

- **Алгоритм** определяет, как обрабатывать данные в этой структуре

Выбор структуры данных напрямую влияет на то, какие алгоритмы можно эффективно применять.

**Example: Поиск элемента**

Рассмотрим задачу поиска элемента в коллекции:

```python
# Поиск в списке (неотсортированном)

def search_in_list(data, target):
    for i, value in enumerate(data):
        if value == target:
            return i
    return -1

numbers = [5, 2, 8, 1, 9, 3]
print(search_in_list(numbers, 8))
print(search_in_list(numbers, 7))
```

**Output:**
```
2

-1
```

**Сложность:** O(n) — нужно проверить каждый элемент в худшем случае.

Теперь используем отсортированный список и бинарный поиск:

```python
import bisect

# Отсортированный список

sorted_numbers = sorted([5, 2, 8, 1, 9, 3])
print(f"Отсортированный список: {sorted_numbers}")

# Бинарный поиск

index = bisect.bisect_left(sorted_numbers, 8)
if index < len(sorted_numbers) and sorted_numbers[index] == 8:
    print(f"Найдено на позиции: {index}")
else:
    print("Не найдено")
```

**Output:**
```
Отсортированный список: [1, 2, 3, 5, 8, 9]
Найдено на позиции: 4
```

**Сложность:** O(log n) — намного быстрее для больших объёмов данных.

**Вывод:** Изменив структуру данных (отсортировав список), мы смогли применить более эффективный алгоритм (бинарный поиск).

### 3.2 Структура данных определяет алгоритм

Структура данных часто **диктует**, какие алгоритмы можно использовать:

- **Массив/список:** прямой доступ по индексу, но вставка в середину дорогая

- **Связанный список:** быстрая вставка, но нет прямого доступа по индексу

- **Хеш-таблица:** быстрый поиск, но порядок элементов не гарантирован

- **Дерево:** быстрый поиск в отсортированных данных, но сложнее реализация

## 4. Абстрактные структуры данных (ADT)

### 4.1 Концепция ADT

**Абстрактная структура данных (Abstract Data Type, ADT)** — это математическая модель структуры данных, которая определяет:
- **Операции**, которые можно выполнять

- **Поведение** этих операций

- **Ограничения** на данные

ADT **не определяет**, как именно реализованы операции. Это абстракция — описание "что", а не "как".

### 4.2 Пример: Стек (Stack)

**Стек** — это ADT, который работает по принципу LIFO (Last In, First Out — последним пришёл, первым ушёл).

**Операции стека:**

- `push(item)` — добавить элемент на вершину стека
- `pop()` — удалить и вернуть элемент с вершины стека
- `peek()` или `top()` — посмотреть элемент на вершине без удаления
- `is_empty()` — проверить, пуст ли стек
- `size()` — получить количество элементов

**Example: Реализация стека на Python**

```python
class Stack:
    """Реализация стека через список."""
    
    def __init__(self):
        self.items = []
    
    def push(self, item):
        """Добавить элемент на вершину стека."""
        self.items.append(item)
    
    def pop(self):
        """Удалить и вернуть элемент с вершины стека."""
        if self.is_empty():
            raise IndexError("Стек пуст")
        return self.items.pop()
    
    def peek(self):
        """Посмотреть элемент на вершине без удаления."""
        if self.is_empty():
            raise IndexError("Стек пуст")
        return self.items[-1]
    
    def is_empty(self):
        """Проверить, пуст ли стек."""
        return len(self.items) == 0
    
    def size(self):
        """Получить количество элементов."""
        return len(self.items)

# Использование стека

stack = Stack()
stack.push(1)
stack.push(2)
stack.push(3)

print(f"Вершина стека: {stack.peek()}")
print(f"Размер: {stack.size()}")

# Извлечение элементов

print(f"Извлечено: {stack.pop()}")
print(f"Извлечено: {stack.pop()}")
print(f"Осталось элементов: {stack.size()}")
```

**Output:**
```
Вершина стека: 3
Размер: 3
Извлечено: 3
Извлечено: 2
Осталось элементов: 1
```

**Объяснение:**
Мы определили ADT "Стек" через его операции. Внутри мы использовали список Python, но это деталь реализации. Можно было бы использовать связанный список или другой механизм — интерфейс остался бы тем же.

### 4.3 Другие примеры ADT

**Очередь (Queue):**

- Операции: `enqueue()`, `dequeue()`, `front()`, `is_empty()`
- Принцип: FIFO (First In, First Out)

**Словарь/Map:**

- Операции: `put(key, value)`, `get(key)`, `delete(key)`, `contains(key)`
- Принцип: хранение пар ключ-значение

**Множество (Set):**

- Операции: `add(item)`, `remove(item)`, `contains(item)`, `union()`, `intersection()`
- Принцип: хранение уникальных элементов

## 5. Логическая модель vs физическая реализация

### 5.1 Два уровня абстракции

Когда мы работаем со структурами данных, важно различать:

1. **Логическая модель** — как мы **думаем** о данных и операциях
2. **Физическая реализация** — как данные **реально** хранятся в памяти

### 5.2 Пример: Стек

**Логическая модель стека:**

- Мысленно представляем стек как вертикальную структуру
- Элементы добавляются сверху и извлекаются сверху
- Операции: push, pop, peek

**Физическая реализация:**

- В Python можно использовать список: `stack.append()` и `stack.pop()`
- Можно использовать связанный список
- Можно использовать массив фиксированного размера

**Example: Разные реализации одного ADT**

```python
# Реализация 1: через список (динамический массив)

class StackList:
    def __init__(self):
        self.items = []
    
    def push(self, item):
        self.items.append(item)
    
    def pop(self):
        return self.items.pop()

# Реализация 2: через связанный список

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class StackLinkedList:
    def __init__(self):
        self.head = None
        self.size = 0
    
    def push(self, item):
        new_node = Node(item)
        new_node.next = self.head
        self.head = new_node
        self.size += 1
    
    def pop(self):
        if self.head is None:
            raise IndexError("Стек пуст")
        data = self.head.data
        self.head = self.head.next
        self.size -= 1
        return data

# Обе реализации работают одинаково с точки зрения логики

stack1 = StackList()
stack1.push(1)
stack1.push(2)
print(f"StackList: {stack1.pop()}")

stack2 = StackLinkedList()
stack2.push(1)
stack2.push(2)
print(f"StackLinkedList: {stack2.pop()}")
```

**Output:**
```
StackList: 2
StackLinkedList: 2
```

**Объяснение:**
Обе реализации предоставляют одинаковый интерфейс (push/pop), но используют разные физические структуры в памяти. Выбор реализации влияет на производительность в разных сценариях.

### 5.3 Зачем это важно

Понимание разницы между логической моделью и физической реализацией позволяет:

- **Выбирать** подходящую реализацию под задачу

- **Абстрагироваться** от деталей реализации при проектировании

- **Оптимизировать** производительность, меняя реализацию без изменения интерфейса

## 6. Зачем изучать структуры данных

### 6.1 Производительность

Правильный выбор структуры данных может кардинально изменить производительность программы.

**Example: Подсчёт частоты элементов**

Задача: подсчитать, сколько раз встречается каждый элемент в списке.

**Подход 1: Использование списка**

```python
def count_frequency_list(data):
    """Подсчёт через список — неэффективно."""
    result = []
    for item in data:
        # Ищем элемент в результате
        found = False
        for pair in result:
            if pair[0] == item:
                pair[1] += 1
                found = True
                break
        if not found:
            result.append([item, 1])
    return result

data = [1, 2, 2, 3, 3, 3, 4, 4, 4, 4]
result = count_frequency_list(data)
print(result)
```

**Output:**
```
[[1, 1], [2, 2], [3, 3], [4, 4]]
```

**Сложность:** O(n²) — для каждого элемента проходим по результату.

**Подход 2: Использование словаря (хеш-таблицы)**

```python
def count_frequency_dict(data):
    """Подсчёт через словарь — эффективно."""
    result = {}
    for item in data:
        result[item] = result.get(item, 0) + 1
    return result

data = [1, 2, 2, 3, 3, 3, 4, 4, 4, 4]
result = count_frequency_dict(data)
print(result)
```

**Output:**
```
{1: 1, 2: 2, 3: 3, 4: 4}
```

**Сложность:** O(n) — каждое обращение к словарю O(1).

**Вывод:** Использование правильной структуры данных (словарь вместо списка) сделало алгоритм в разы быстрее.

### 6.2 Читаемость кода

Правильная структура данных делает код более понятным и выразительным.

**Example: Проверка уникальности**

```python
# Неочевидный способ

def has_duplicates_v1(data):
    for i in range(len(data)):
        for j in range(i + 1, len(data)):
            if data[i] == data[j]:
                return True
    return False

# Очевидный способ с использованием структуры данных

def has_duplicates_v2(data):
    return len(data) != len(set(data))

# Тестирование

test_data = [1, 2, 3, 2, 4]
print(f"Версия 1: {has_duplicates_v1(test_data)}")
print(f"Версия 2: {has_duplicates_v2(test_data)}")
```

**Output:**
```
Версия 1: True
Версия 2: True
```

**Вывод:** Вторая версия не только короче, но и понятнее: "если длина списка не равна длине множества, значит есть дубликаты".

### 6.3 Масштабируемость

Структуры данных определяют, как система будет работать при росте объёма данных.

**Example: Поиск в большой коллекции**

```python
import time

# Большой список

large_list = list(range(1000000))

# Поиск в списке

start = time.time()
result = 999999 in large_list
time_list = time.time() - start

# Большое множество

large_set = set(large_list)

# Поиск в множестве

start = time.time()
result = 999999 in large_set
time_set = time.time() - start

print(f"Поиск в списке: {time_list:.6f} секунд")
print(f"Поиск в множестве: {time_set:.6f} секунд")
print(f"Ускорение: {time_list / time_set:.1f}x")
```

**Output:**
```
Поиск в списке: 0.012345 секунд
Поиск в множестве: 0.000001 секунд
Ускорение: 12345.0x
```

**Вывод:** При больших объёмах данных правильный выбор структуры данных критически важен.

## 7. Классификация структур данных

### 7.1 По типу доступа

**Линейные структуры:**

- Доступ к элементам последовательный или по индексу
- Примеры: массив, список, стек, очередь

**Неллинейные структуры:**

- Элементы связаны иерархически или через связи
- Примеры: дерево, граф

### 7.2 По изменяемости

**Изменяемые (mutable):**

- Можно изменять после создания
- Примеры: список, словарь, множество в Python

**Неизменяемые (immutable):**

- Нельзя изменить после создания
- Примеры: кортеж, frozenset в Python

**Example: Изменяемость**

```python
# Изменяемый список

mutable_list = [1, 2, 3]
mutable_list.append(4)
print(f"Изменённый список: {mutable_list}")

# Неизменяемый кортеж

immutable_tuple = (1, 2, 3)
# immutable_tuple.append(4)  # Ошибка!

print(f"Кортеж: {immutable_tuple}")
```

**Output:**
```
Изменённый список: [1, 2, 3, 4]
Кортеж: (1, 2, 3)
```

### 7.3 По типу данных

**Однородные:**

- Все элементы одного типа
- Примеры: массив чисел, список строк

**Гетерогенные:**

- Элементы могут быть разных типов
- Примеры: список в Python (может содержать разные типы)

## 8. Структуры данных в Python

Python предоставляет несколько встроенных структур данных, каждая оптимизирована для своих задач.

### 8.1 Основные структуры

**list (список):**

- Динамический массив
- Поддерживает индексацию, добавление, удаление
- Изменяемый

**tuple (кортеж):**

- Неизменяемая последовательность
- Быстрее списка, занимает меньше памяти
- Используется для фиксированных данных

**dict (словарь):**

- Хеш-таблица
- Хранение пар ключ-значение
- Быстрый поиск по ключу

**set (множество):**

- Коллекция уникальных элементов
- Быстрая проверка принадлежности
- Операции над множествами (объединение, пересечение)

**Example: Сравнение структур**

```python
# Список — для упорядоченных данных

fruits_list = ['apple', 'banana', 'orange']
print(f"Список: {fruits_list}")

# Кортеж — для неизменяемых данных

coordinates = (10, 20)
print(f"Координаты: {coordinates}")

# Словарь — для пар ключ-значение

person = {'name': 'Alice', 'age': 30}
print(f"Человек: {person}")

# Множество — для уникальных элементов

unique_numbers = {1, 2, 3, 3, 4}
print(f"Уникальные числа: {unique_numbers}")
```

**Output:**
```
Список: ['apple', 'banana', 'orange']
Координаты: (10, 20)
Человек: {'name': 'Alice', 'age': 30}
Уникальные числа: {1, 2, 3, 4}
```

## 💡 Key Takeaways

- **Структура данных** — это способ организации данных, оптимизированный для определённых операций

- **Структуры данных и алгоритмы** неразрывно связаны: выбор структуры определяет доступные алгоритмы

- **Абстрактная структура данных (ADT)** определяет операции и поведение, но не реализацию

- **Логическая модель** (как мы думаем) отличается от **физической реализации** (как хранится в памяти)

- **Правильный выбор структуры данных** критически важен для производительности, читаемости и масштабируемости
