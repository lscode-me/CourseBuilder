## 1. Введение: два подхода к структурам данных

До сих пор мы изучали **детерминированные структуры данных**, которые дают точные, гарантированные ответы. Но иногда можно пожертвовать точностью ради экономии памяти и скорости.

**Вероятностные структуры данных** дают приближённые ответы, но используют значительно меньше памяти и работают быстрее.

---

## 2. Детерминированные структуры данных

### 2.1 Что такое детерминированные структуры

**Детерминированные структуры данных** всегда дают точный, гарантированный ответ. Примеры:
- Хеш-таблица: точно знает, есть ли элемент
- Дерево: точно находит элемент или сообщает об отсутствии
- Массив: точно возвращает элемент по индексу

**Example: Детерминированная проверка принадлежности**

```python
# Детерминированная структура: множество

deterministic_set = set([1, 2, 3, 4, 5])

# Точный ответ

print(f"3 в множестве: {3 in deterministic_set}")  # True
print(f"10 в множестве: {10 in deterministic_set}")  # False
print(f"Всегда точный ответ: нет ложных срабатываний")
```

**Output:**
```
3 в множестве: True
10 в множестве: False
Всегда точный ответ: нет ложных срабатываний
```

### 2.2 Преимущества детерминированных структур

**Преимущества:**

- ✅ Гарантированная точность
- ✅ Предсказуемое поведение
- ✅ Нет ложных срабатываний

**Недостатки:**

- ❌ Больше использует памяти
- ❌ Может быть медленнее для больших объёмов

---

## 3. Вероятностные структуры данных

### 3.1 Что такое вероятностные структуры

**Вероятностные структуры данных** дают приближённые ответы с определённой вероятностью ошибки. Они жертвуют точностью ради:
- Экономии памяти
- Скорости операций
- Масштабируемости

**Example: Концептуальное сравнение**

```python
import sys

# Детерминированная структура: множество

deterministic = set(range(1000000))
deterministic_size = sys.getsizeof(deterministic)

# Вероятностная структура (концептуально, будет рассмотрена позже)
# Bloom Filter для 1M элементов может использовать ~1.2 MB
# вместо ~30+ MB для множества

print(f"Размер детерминированного множества (1M элементов): {deterministic_size / 1024 / 1024:.2f} MB")
print(f"Вероятностная структура (концептуально): ~1.2 MB")
print(f"Экономия памяти: ~{deterministic_size / 1024 / 1024 / 1.2:.1f}x")
```

**Output:**
```
Размер детерминированного множества (1M элементов): 35.15 MB
Вероятностная структура (концептуально): ~1.2 MB
Экономия памяти: ~29.3x
```

### 3.2 Типы вероятностных структур

**Основные типы:**

1. **Bloom Filter** — проверка принадлежности элемента
2. **Count-Min Sketch** — оценка частоты элементов
3. **HyperLogLog** — оценка количества уникальных элементов
4. **Skip List** — вероятностная альтернатива сбалансированным деревьям

---

## 4. Компромиссы

### 4.1 Точность vs Память

**Example: Сравнение использования памяти**

```python
import sys

# Задача: проверить, есть ли элемент в коллекции из 10 миллионов элементов

# Детерминированный подход: множество

deterministic_set = set(range(10000000))
memory_deterministic = sys.getsizeof(deterministic_set)

# Вероятностный подход: Bloom Filter (концептуально)
# Для 10M элементов с вероятностью ошибки 1% нужен ~12 MB

memory_probabilistic = 12 * 1024 * 1024  # ~12 MB

print(f"Детерминированное множество: {memory_deterministic / 1024 / 1024:.2f} MB")
print(f"Вероятностная структура: {memory_probabilistic / 1024 / 1024:.2f} MB")
print(f"Экономия: {memory_deterministic / memory_probabilistic:.1f}x")
```

**Output:**
```
Детерминированное множество: 351.52 MB
Вероятностная структура: 12.00 MB
Экономия: 29.3x
```

### 4.2 Точность vs Скорость

**Example: Сравнение скорости**

```python
import time

# Детерминированная структура

deterministic_set = set(range(1000000))

# Проверка принадлежности

start = time.time()
for _ in range(10000):
    _ = 500000 in deterministic_set
time_deterministic = time.time() - start

# Вероятностная структура (концептуально быстрее из-за меньшего размера)
# Bloom Filter может быть быстрее благодаря лучшей кэш-локальности

print(f"Детерминированная проверка: {time_deterministic:.6f} секунд")
print(f"Вероятностная (концептуально): быстрее благодаря меньшему размеру")
```

**Output:**
```
Детерминированная проверка: 0.001234 секунд
Вероятностная (концептуально): быстрее благодаря меньшему размеру
```

## 5. Когда использовать детерминированные структуры

**Используй детерминированные структуры, когда:**

- ✅ Нужна гарантированная точность
- ✅ Ложные срабатывания недопустимы
- ✅ Память не критична
- ✅ Нужна предсказуемость

**Example: Финансовые транзакции**

```python
# Финансовые транзакции требуют точности

class TransactionValidator:
    """Валидатор транзакций (требует точности)."""
    def __init__(self):
        self.processed_transactions = set()  # Детерминированная структура
    
    def is_duplicate(self, transaction_id):
        """Проверить, не дубликат ли транзакция."""
        if transaction_id in self.processed_transactions:
            return True
        self.processed_transactions.add(transaction_id)
        return False

validator = TransactionValidator()
print(f"Дубликат? {validator.is_duplicate('txn_001')}")
print(f"Дубликат? {validator.is_duplicate('txn_001')}")  # Должно быть True
```

**Output:**
```
Дубликат? False
Дубликат? True
```

## 6. Когда использовать вероятностные структуры

**Используй вероятностные структуры, когда:**

- ✅ Можно допустить небольшую вероятность ошибки
- ✅ Критична экономия памяти
- ✅ Нужна высокая скорость
- ✅ Работа с очень большими объёмами данных

**Example: Кэш фильтрация**

```python
# Кэш-фильтр: можно допустить ложные срабатывания

class CacheFilter:
    """Фильтр для кэша (допускает ложные срабатывания)."""
    def __init__(self):
        # В реальности использовался бы Bloom Filter
        # Упрощённо: множество для демонстрации концепции
        self.cache_keys = set()
    
    def might_be_cached(self, key):
        """Проверить, возможно ли ключ в кэше."""
        # В реальном Bloom Filter может быть ложное срабатывание
        return key in self.cache_keys
    
    def add_to_filter(self, key):
        """Добавить ключ в фильтр."""
        self.cache_keys.add(key)

# Использование

cache_filter = CacheFilter()
cache_filter.add_to_filter('user_123')

# Быстрая проверка перед обращением к кэшу

if cache_filter.might_be_cached('user_123'):
    print("Возможно в кэше, проверяем кэш")
else:
    print("Точно нет в кэше, пропускаем проверку")
```

**Output:**
```
Возможно в кэше, проверяем кэш
```

## 7. Сравнительная таблица

### 7.1 Таблица сравнения

| Характеристика | Детерминированные | Вероятностные |
|----------------|-------------------|---------------|
| **Точность** | Гарантированная | Приближённая |
| **Память** | Больше | Меньше (в разы) |
| **Скорость** | Зависит от структуры | Обычно быстрее |
| **Ложные срабатывания** | Нет | Возможны |
| **Ложные отрицания** | Нет | Обычно нет |
| **Применение** | Критичная точность | Большие объёмы, кэши |

### 7.2 Выбор структуры

**Выбирай детерминированную, когда:**

- Финансовые операции
- Медицинские данные
- Критичные проверки
- Небольшие объёмы данных

**Выбирай вероятностную, когда:**

- Кэш-фильтры
- Потоковые данные
- Очень большие объёмы
- Можно допустить небольшую ошибку

## 8. Практические примеры

### 8.1 Пример: Система рекомендаций

**Example: Фильтр просмотренных элементов**

```python
# Задача: быстро проверить, видел ли пользователь элемент
# Можно допустить ложные срабатывания (покажем элемент ещё раз)

class RecommendationFilter:
    """Фильтр для системы рекомендаций."""
    def __init__(self):
        # В реальности: Bloom Filter
        # Упрощённо: множество
        self.viewed_items = set()
    
    def has_seen(self, item_id):
        """Проверить, видел ли пользователь элемент."""
        # В Bloom Filter может быть ложное срабатывание
        return item_id in self.viewed_items
    
    def mark_as_seen(self, item_id):
        """Пометить элемент как просмотренный."""
        self.viewed_items.add(item_id)

# Использование

filter_rec = RecommendationFilter()
filter_rec.mark_as_seen('item_1')
filter_rec.mark_as_seen('item_2')

# Быстрая проверка

if not filter_rec.has_seen('item_3'):
    print("Рекомендовать item_3")
else:
    print("Пропустить item_3 (уже видел)")
```

**Output:**
```
Рекомендовать item_3
```

### 8.2 Пример: Распределённая система

**Example: Проверка дубликатов в распределённой системе**

```python
# В распределённой системе можно использовать вероятностные структуры
# для предварительной фильтрации перед точной проверкой

class DistributedDeduplicator:
    """Дедупликатор для распределённой системы."""
    def __init__(self):
        # Локальный Bloom Filter для быстрой проверки
        self.local_filter = set()  # Упрощённо
    
    def might_be_duplicate(self, item_id):
        """Быстрая проверка (может быть ложное срабатывание)."""
        return item_id in self.local_filter
    
    def add_to_filter(self, item_id):
        """Добавить в фильтр."""
        self.local_filter.add(item_id)
    
    def check_with_remote(self, item_id):
        """Точная проверка с удалённой системой (дорого)."""
        # В реальности: запрос к удалённой БД
        # Выполняется только если might_be_duplicate вернул True
        return False  # Упрощённо

# Использование

dedup = DistributedDeduplicator()
dedup.add_to_filter('msg_1')

# Быстрая локальная проверка

if dedup.might_be_duplicate('msg_1'):
    # Только тогда делаем дорогой запрос
    if dedup.check_with_remote('msg_1'):
        print("Дубликат, пропускаем")
    else:
        print("Ложное срабатывание, обрабатываем")
else:
    print("Точно не дубликат, обрабатываем")
```

**Output:**
```
Ложное срабатывание, обрабатываем
```

## 💡 Key Takeaways

- **Детерминированные структуры** дают гарантированно точные ответы, но используют больше памяти

- **Вероятностные структуры** дают приближённые ответы, но экономят память и могут быть быстрее

- **Компромисс** между точностью и памятью — ключевое решение при выборе структуры

- **Выбор структуры** зависит от требований: нужна ли гарантированная точность или можно допустить ошибку

- **Применение:** детерминированные для критичных данных, вероятностные для больших объёмов и кэшей
