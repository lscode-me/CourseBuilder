## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | C | Каждая программа имеет 3 стандартных потока: stdin (0), stdout (1), stderr (2) |
| 2 | D | Дескриптор 2 соответствует stderr (standard error) |
| 3 | D | Символ `>` перезаписывает файл, если он существует |
| 4 | B | Символ `>>` добавляет вывод в конец файла, не перезаписывая его |
| 5 | C | Дескриптор `2>` перенаправляет только stderr |
| 6 | D | `2>&1` означает "перенаправить stderr туда же, куда и stdout" |
| 7 | C | Символ `|` создаёт pipe, передавая stdout одной команды в stdin другой |
| 8 | D | Here document (`<<`) передаёт многострочный текст в stdin команды |
| 9 | D | Here string (`<<<`) передаёт строку в stdin, `cat` выводит её |
| 10 | D | Символ `&` в конце команды запускает её в фоновом режиме |
| 11 | D | Команда `jobs` показывает фоновые задачи текущей shell сессии |
| 12 | B | Команда `fg` (foreground) переводит задачу в передний план |
| 13 | A | `nohup` позволяет процессу продолжить работу после закрытия терминала |
| 14 | A | Цепочка: echo создаёт "1\n2\n3", grep фильтрует "2", wc считает 1 строку |
| 15 | A | Pipe передаёт вывод ls в grep, результат grep сохраняется в result.txt |
| 16 | C | `<()` — это process substitution, создаёт именованный pipe с выводом команды |
| 17 | B | `<` перенаправляет stdin из file.txt, `wc -l` подсчитывает строки |
| 18 | A | `&>` — сокращение для перенаправления обоих потоков (stdout и stderr) |
| 19 | D | Coprocess — это процесс с двусторонней коммуникацией через pipes |
| 20 | C | `sort` сортирует, `tac` (cat наоборот) переворачивает: c b a |
| 21 | A | Можно, но с ограничениями — перенаправление работает на уровне shell |
| 22 | C | `fg %2` переводит задачу номер 2 в передний план (символ % обязателен) |
| 23 | A | `<&-` закрывает stdin, `>-` закрывает stdout, `2>-` закрывает stderr |
| 24 | A | `/dev/null` — это "чёрная дыра", `> /dev/null 2>&1` отбрасывает весь вывод |
| 25 | D | Pipe передаёт вывод command1 в command2, результат command2 (включая ошибки) сохраняется |
