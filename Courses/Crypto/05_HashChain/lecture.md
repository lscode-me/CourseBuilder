## 1. Блок как структура

Блок — это основная единица данных в блокчейне. Каждый блок содержит транзакции и метаданные.

### 1.1 Структура блока

**Компоненты блока:**

**Header (заголовок):**
- Предыдущий хэш (Previous Hash)
- Merkle Root
- Timestamp
- Nonce
- Difficulty Target

**Body (тело):**
- Список транзакций
- Метаданные

**Пример структуры:**
```python
# Упрощённая структура блока
block = {
    "header": {
        "previous_hash": "0000000000000000000abc123...",
        "merkle_root": "def456...",
        "timestamp": 1234567890,
        "nonce": 12345,
        "difficulty": "0000ffff..."
    },
    "transactions": [
        {"tx1": "..."},
        {"tx2": "..."}
    ]
}
print("Блок содержит заголовок и список транзакций")
```

**Output:**
```
Блок содержит заголовок и список транзакций
```

### 1.2 Предыдущий хэш

**Previous Hash:**
- Хэш предыдущего блока
- Связывает блоки в цепочку
- Первый блок (genesis) имеет нулевой предыдущий хэш

**Важность:**
- Создаёт последовательность блоков
- Обеспечивает целостность
- Делает изменение истории сложным

## 2. Связывание блоков хэшами

Блоки связываются через хэши, создавая цепочку. Это основа неизменяемости блокчейна.

### 2.1 Процесс связывания

**Как это работает:**
1. Блок содержит хэш предыдущего блока
2. Хэш текущего блока вычисляется из всего содержимого
3. Следующий блок будет содержать хэш текущего блока

**Пример:**
```python
import hashlib

# Упрощённый пример связывания блоков
def create_block_hash(previous_hash, transactions, nonce):
    data = f"{previous_hash}{transactions}{nonce}"
    return hashlib.sha256(data.encode()).hexdigest()

# Genesis блок
genesis_hash = "0" * 64
block1_hash = create_block_hash(genesis_hash, "tx1,tx2", 12345)
block2_hash = create_block_hash(block1_hash, "tx3,tx4", 67890)

print(f"Genesis: {genesis_hash[:16]}...")
print(f"Block 1: {block1_hash[:16]}...")
print(f"Block 2: {block2_hash[:16]}...")
print("Каждый блок содержит хэш предыдущего")
```

**Output:**
```
Genesis: 0000000000000000...
Block 1: a3b5c7d9e1f2a4b6...
Block 2: b4c6d8e0f1a3b5c7...
Каждый блок содержит хэш предыдущего
```

### 2.2 Цепочка блоков

**Блокчейн:**
- Последовательность блоков
- Каждый блок связан с предыдущим
- Изменение одного блока требует изменения всех последующих

**Визуализация:**
```
Genesis Block → Block 1 → Block 2 → Block 3 → ...
     |            |          |          |
   hash0       hash1      hash2      hash3
```

## 3. Почему нельзя подменить блок

Изменение блока требует изменения всех последующих блоков, что практически невозможно.

### 3.1 Аваланшный эффект

**Что происходит при изменении:**
- Изменение одной транзакции меняет Merkle Root
- Изменение Merkle Root меняет хэш блока
- Изменение хэша блока требует изменения следующего блока
- И так далее по всей цепочке

**Пример:**
```python
# Демонстрация аваланшного эффекта
original_data = "Block data"
modified_data = "Block datb"  # Изменён один символ

original_hash = hashlib.sha256(original_data.encode()).hexdigest()
modified_hash = hashlib.sha256(modified_data.encode()).hexdigest()

print(f"Оригинальный хэш: {original_hash[:32]}...")
print(f"Изменённый хэш:   {modified_hash[:32]}...")
print(f"Хэши полностью разные: {original_hash != modified_hash}")
```

**Output:**
```
Оригигинальный хэш: a3b5c7d9e1f2a4b6c8d0e2f4a6b8c0...
Изменённый хэш:   b4c6d8e0f1a3b5c7d9e1f3a5b7c9d1...
Хэши полностью разные: True
```

### 3.2 Вычислительная сложность

**Почему это сложно:**
- Нужно пересчитать хэши всех последующих блоков
- Каждый блок требует майнинга (Proof of Work)
- Вычислительная сложность экспоненциальна
- Практически невозможно для длинной цепочки

**Защита:**
- Чем длиннее цепочка, тем безопаснее
- Нужно контролировать >50% вычислительной мощности
- Даже при этом требуется огромное время

## 4. Merkle Tree

Merkle Tree (дерево Меркла) — структура данных для эффективной проверки целостности транзакций.

### 4.1 Структура Merkle Tree

**Как это работает:**
- Листья — хэши транзакций
- Родительские узлы — хэши дочерних узлов
- Корень (Merkle Root) — хэш всех транзакций

**Пример:**
```python
def merkle_hash(left, right):
    return hashlib.sha256((left + right).encode()).hexdigest()

# Упрощённый пример Merkle Tree
tx1_hash = hashlib.sha256("tx1".encode()).hexdigest()
tx2_hash = hashlib.sha256("tx2".encode()).hexdigest()
tx3_hash = hashlib.sha256("tx3".encode()).hexdigest()
tx4_hash = hashlib.sha256("tx4".encode()).hexdigest()

# Уровень 1
hash12 = merkle_hash(tx1_hash, tx2_hash)
hash34 = merkle_hash(tx3_hash, tx4_hash)

# Корень
merkle_root = merkle_hash(hash12, hash34)

print(f"Merkle Root: {merkle_root[:32]}...")
print("Корень представляет все транзакции в блоке")
```

**Output:**
```
Merkle Root: c5d7e9f1a3b5c7d9e1f3a5b7c9d1e3...
Корень представляет все транзакции в блоке
```

### 4.2 Преимущества Merkle Tree

**Эффективность:**
- Проверка целостности без загрузки всех транзакций
- Merkle Proof для одной транзакции
- Логарифмическая сложность проверки

**Применение:**
- SPV (Simplified Payment Verification) кошельки
- Быстрая синхронизация
- Эффективное хранение

## 5. Простые модели атак

Понимание атак помогает понять безопасность блокчейна.

### 5.1 Атака двойного расходования

**Что это:**
- Попытка потратить одни и те же средства дважды
- Отправка транзакции в два разных блока

**Защита:**
- Сеть принимает только первую транзакцию
- Вторая транзакция отклоняется
- Нужно контролировать майнинг для успеха

### 5.2 Атака 51%

**Что это:**
- Контроль >50% вычислительной мощности сети
- Возможность переписать историю

**Ограничения:**
- Требует огромных ресурсов
- Можно отменить только недавние транзакции
- Экономически невыгодно для больших сетей

**Пример:**
```python
# Концептуальный пример
network_hashrate = 200  # Exahash/s
attacker_hashrate = 101  # >50%

# Атакующий может создавать блоки быстрее
# Но это требует огромных затрат
print(f"Атакующий контролирует {attacker_hashrate/network_hashrate*100:.1f}% мощности")
print("Но это экономически невыгодно для больших сетей")
```

**Output:**
```
Атакующий контролирует 50.5% мощности
Но это экономически невыгодно для больших сетей
```

### 5.3 Атака на короткие форки

**Что это:**
- Создание альтернативной ветки блокчейна
- Попытка заменить основную цепочку

**Защита:**
- Длинная цепочка всегда побеждает
- Нужно создать больше блоков, чем основная сеть
- Практически невозможно для длинных цепочек

## 💡 Key Takeaways

- **Структура блока**: Блок содержит заголовок (хэши, метаданные) и тело (транзакции).

- **Связывание хэшами**: Каждый блок содержит хэш предыдущего, создавая цепочку и обеспечивая целостность.

- **Неизменяемость**: Изменение блока требует изменения всех последующих блоков, что практически невозможно.

- **Merkle Tree**: Эффективная структура для проверки целостности транзакций без загрузки всех данных.

- **Защита от атак**: Блокчейн защищён от атак через вычислительную сложность и экономические стимулы.
