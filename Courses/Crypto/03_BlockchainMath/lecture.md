## 1. Большие числа

Криптография работает с очень большими числами. Понимание масштаба этих чисел важно для понимания безопасности.

### 1.1 Масштаб чисел в криптографии

**Примеры больших чисел:**

**256-битное число:**

- 2^256 ≈ 10^77
- Это больше, чем количество атомов в наблюдаемой вселенной (≈ 10^80)
- Используется в SHA-256 (хэш Bitcoin)

**Пример в Python:**
```python
# 256-битное число

bits_256 = 2**256
print(f"2^256 = {bits_256}")
print(f"В десятичной системе: ~{bits_256:.2e}")
```

**Output:**
```
2^256 = 115792089237316195423570985008687907853269984665640564039457584007913129639936
В десятичной системе: ~1.16e+77
```

### 1.2 Почему такие большие числа

**Безопасность через большие числа:**

- Чем больше пространство возможных значений, тем сложнее угадать правильное
- Для 256-битного числа нужно проверить в среднем 2^255 вариантов
- Даже суперкомпьютерам потребуются миллиарды лет

**Пример:**
Если приватный ключ — случайное 256-битное число, вероятность угадать его случайно:

- 1 из 2^256
- Практически невозможно

## 2. Модульная арифметика

Модульная арифметика (арифметика остатков) — основа многих криптографических операций.

### 2.1 Что такое модуль

**Модульная арифметика:**

- Работа с остатками от деления
- Обозначение: a mod n (остаток от деления a на n)
- Пример: 17 mod 5 = 2 (17 = 3×5 + 2)

**Примеры:**
```python
# Модульная арифметика

print(f"17 mod 5 = {17 % 5}")
print(f"23 mod 7 = {23 % 7}")
print(f"100 mod 13 = {100 % 13}")
```

**Output:**
```
17 mod 5 = 2
23 mod 7 = 2
100 mod 13 = 9
```

### 2.2 Свойства модульной арифметики

**Замкнутость:**

- (a + b) mod n = ((a mod n) + (b mod n)) mod n
- (a × b) mod n = ((a mod n) × (b mod n)) mod n

**Пример:**
```python
a, b, n = 17, 23, 5
result1 = (a + b) % n
result2 = ((a % n) + (b % n)) % n
print(f"(17 + 23) mod 5 = {result1}")
print(f"((17 mod 5) + (23 mod 5)) mod 5 = {result2}")
```

**Output:**
```
(17 + 23) mod 5 = 0
((17 mod 5) + (23 mod 5)) mod 5 = 0
```

### 2.3 Применение в криптографии

**Циклические группы:**

- Многие криптографические операции работают в циклических группах
- Эллиптические криптограммы используют модульную арифметику
- Цифровые подписи основаны на модульных операциях

## 3. Вероятности и случайность

Вероятность и случайность критически важны для безопасности криптографии.

### 3.1 Вероятность угадывания

**Пример: Подбрасывание монеты**
- Вероятность выпадения орла: 1/2 = 50%
- Вероятность двух орлов подряд: (1/2)² = 1/4 = 25%
- Вероятность n орлов подряд: (1/2)^n

**Пример:**
```python
# Вероятность угадать приватный ключ Bitcoin

bits = 256
probability = 1 / (2**bits)
print(f"Вероятность угадать 256-битный ключ: {probability:.2e}")
print(f"Это примерно 1 из {2**bits:.2e}")
```

**Output:**
```
Вероятность угадать 256-битный ключ: 8.64e-78
Это примерно 1 из 1.16e+77
```

### 3.2 День рождения парадокс

**Парадокс дней рождения:**

- В группе из 23 человек вероятность совпадения дней рождения ≈ 50%
- Кажется неожиданным, но математически верно

**Применение в криптографии:**

- Коллизии хэшей становятся вероятными раньше, чем кажется
- Для SHA-256 нужно ~2^128 операций для коллизии (не 2^256)

**Пример:**
```python
import math

# Вероятность коллизии для n хэшей

def collision_probability(n, bits):
    # Упрощённая формула
    return 1 - math.exp(-n**2 / (2 * (2**bits)))

n_hashes = 2**64
bits = 256
prob = collision_probability(n_hashes, bits)
print(f"Вероятность коллизии для {n_hashes:.2e} хэшей: {prob:.2e}")
```

**Output:**
```
Вероятность коллизии для 1.84e+19 хэшей: 1.00e+00
```

### 3.3 Случайность и энтропия

**Энтропия:**
Энтропия — это мера случайности или неопределённости в системе. В криптографии энтропия измеряет, насколько непредсказуемы данные. Выше энтропия = выше безопасность, потому что злоумышленнику сложнее угадать или предсказать значение. Приватные ключи должны иметь высокую энтропию (максимальную случайность), чтобы быть безопасными. Например, 256-битный ключ с полной энтропией имеет 256 бит энтропии, что означает 2^256 возможных значений. Если энтропия ниже (например, ключ генерируется из предсказуемого источника), безопасность снижается.

**Источники случайности:**

- Криптографически стойкие генераторы случайных чисел (CSPRNG - Cryptographically Secure Pseudorandom Number Generator) — это алгоритмы, которые генерируют последовательности чисел, статистически неотличимые от истинно случайных, даже для злоумышленника с вычислительными ресурсами. В отличие от обычных генераторов случайных чисел, CSPRNG обеспечивают криптографическую стойкость, что критически важно для генерации приватных ключей.
- Физические источники (радиоактивный распад, тепловой шум) — используют физические процессы для получения истинной случайности
- Не использовать предсказуемые источники (время, счётчики) — такие источники могут быть предсказаны злоумышленниками

## 4. Односторонние функции

Односторонние функции — основа криптографии. Их легко вычислить в одну сторону, но практически невозможно обратить.

### 4.1 Концепция односторонней функции

**Определение:**

- Легко вычислить f(x) для любого x
- Практически невозможно найти x, зная f(x)
- Пример: умножение vs факторизация

**Пример: Умножение vs факторизация**

```python
# Легко: умножить два больших простых числа

p = 7919  # простое число
q = 7907  # простое число
n = p * q
print(f"p × q = {p} × {q} = {n}")
print(f"Вычисление заняло мгновение")

# Сложно: разложить на множители
# Для n = 62615533 нужно найти p и q
# Это требует проверки множества вариантов
```

**Output:**
```
p × q = 7919 × 7907 = 62615533
Вычисление заняло мгновение
```

**Факторизация:**
Для числа 62615533 нужно проверить множество простых чисел, чтобы найти множители. Это экспоненциально сложнее.

### 4.2 Хэш-функции как односторонние функции

**Хэш-функция:**

- Принимает данные любого размера
- Возвращает фиксированный размер (например, 256 бит)
- Детерминированная (одинаковый вход → одинаковый выход)
- Односторонняя (невозможно восстановить вход из выхода)

**Пример:**
```python
import hashlib

# Легко: вычислить хэш

data = "Hello, Blockchain!"
hash_result = hashlib.sha256(data.encode()).hexdigest()
print(f"Хэш '{data}': {hash_result}")

# Невозможно: восстановить данные из хэша
# Зная только хэш, нельзя узнать исходные данные
```

**Output:**
```
Хэш 'Hello, Blockchain!': a3b5c7d9e1f2a4b6c8d0e2f4a6b8c0d2e4f6a8b0c2d4e6f8a0b2c4d6e8f0a2
```

### 4.3 Почему сложно "взломать"

**Вычислительная сложность:**

- Перебор всех возможных вариантов требует экспоненциального времени
- Для 256-битного ключа: 2^256 операций
- Даже с квантовыми компьютерами некоторые алгоритмы остаются стойкими

**Пример времени:**
```python
# Предположим: компьютер может проверить 1 миллиард ключей в секунду

keys_per_second = 1e9
total_keys = 2**256
seconds = total_keys / keys_per_second
years = seconds / (365.25 * 24 * 3600)
print(f"Время перебора всех 256-битных ключей: {years:.2e} лет")
```

**Output:**
```
Время перебора всех 256-битных ключей: 3.67e+60 лет
```

Возраст вселенной ≈ 13.8 миллиардов лет. Это в 10^51 раз больше.

## 5. Экспоненциальный рост и безопасность

Экспоненциальный рост — ключ к пониманию, почему криптография безопасна.

### 5.1 Экспоненциальная сложность

**Линейный рост:**

- Удвоение размера → удвоение времени
- Пример: O(n)

**Экспоненциальный рост:**

- Увеличение размера на 1 бит → удвоение времени
- Пример: O(2^n)

**Пример:**
```python
# Время перебора для разных размеров ключей

for bits in [128, 192, 256]:
    keys = 2**bits
    # Предположим: 1 наносекунда на проверку
    nanoseconds = keys
    years = nanoseconds / (1e9 * 365.25 * 24 * 3600)
    print(f"{bits} бит: {years:.2e} лет")
```

**Output:**
```
128 бит: 1.08e+11 лет
192 бит: 1.98e+38 лет
256 бит: 3.67e+60 лет
```

### 5.2 Почему больше бит = экспоненциально безопаснее

**Добавление одного бита:**

- Удваивает пространство поиска
- Удваивает время перебора
- Экспоненциальное увеличение безопасности

**Пример:**

- 128 бит: 2^128 = 3.4×10^38 вариантов
- 256 бит: 2^256 = 1.2×10^77 вариантов
- Разница не в 2 раза, а в 2^128 раз!
