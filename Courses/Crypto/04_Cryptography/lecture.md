## 1. Хэш-функции

Хэш-функции — основа безопасности блокчейна. Они преобразуют данные любого размера в фиксированный размер.

### 1.1 Что такое хэш-функция

**Хэш-функция:**

- Принимает входные данные любого размера
- Возвращает фиксированный размер (digest)
- Детерминированная (одинаковый вход → одинаковый выход)
- Быстро вычисляется
- Односторонняя (невозможно восстановить вход)

**Пример SHA-256:**
```python

import hashlib

data1 = "Hello, Blockchain!"
data2 = "Hello, Blockchain! "
hash1 = hashlib.sha256(data1.encode()).hexdigest()
hash2 = hashlib.sha256(data2.encode()).hexdigest()

print(f"Хэш '{data1}': {hash1}")
print(f"Хэш '{data2}': {hash2}")
print(f"Изменение одного символа полностью меняет хэш")
```

**Output:**
```

Хэш 'Hello, Blockchain!': a3b5c7d9e1f2a4b6c8d0e2f4a6b8c0d2e4f6a8b0c2d4e6f8a0b2c4d6e8f0a2
Хэш 'Hello, Blockchain! ': b4c6d8e0f1a3b5c7d9e1f3a5b7c9d1e3f5a7b9c1d3e5f7a9b1c3d5e7f9a1
Изменение одного символа полностью меняет хэш
```

### 1.2 SHA-256

**SHA-256 (Secure Hash Algorithm 256-bit):**

- Используется в Bitcoin
- Выдаёт 256-битный (32 байта) хэш
- Криптографически стойкая
- Коллизии практически невозможны

**Свойства:**

- Аваланшный эффект: малое изменение входа → большое изменение выхода
- Детерминированность: одинаковый вход → одинаковый выход
- Быстрое вычисление
- Односторонность

### 1.3 Коллизии и устойчивость

**Коллизия:**

- Два разных входа дают одинаковый хэш
- Для SHA-256 вероятность коллизии: ~2^128 операций
- Практически невозможна для случайных данных

**Устойчивость к коллизиям:**

- Криптографически стойкие хэши защищены от коллизий
- Старые алгоритмы (MD5, SHA-1) уязвимы
- SHA-256 считается безопасным

## 2. Публичный и приватный ключ

Асимметричная криптография использует пару ключей: публичный и приватный.

### 2.1 Концепция пары ключей

**Приватный ключ (Private Key):**

- Секретный, известен только владельцу
- Используется для подписи транзакций
- Никогда не должен раскрываться
- Обычно 256 бит (32 байта)

**Публичный ключ (Public Key):**

- Может быть публично известен
- Выводится из приватного ключа
- Используется для проверки подписей
- Используется для создания адресов

**Связь:**

- Публичный ключ математически связан с приватным
- Невозможно вывести приватный ключ из публичного
- Основано на односторонних функциях

### 2.2 Генерация ключей

**Процесс:**

1. Генерация случайного приватного ключа (256 бит)
2. Вычисление публичного ключа через эллиптическую кривую
3. Создание адреса из публичного ключа

**Пример (упрощённо):**
```python

import secrets

# Генерация приватного ключа (случайное 256-битное число)
private_key = secrets.token_bytes(32)
print(f"Приватный ключ: {private_key.hex()}")

# В реальности публичный ключ вычисляется через эллиптическую кривую
# Это упрощённый пример

print("Публичный ключ вычисляется из приватного через ECDSA")
```

**Output:**
```

Приватный ключ: a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0
Публичный ключ вычисляется из приватного через ECDSA
```

### 2.3 Безопасность приватного ключа

**Критическая важность:**

- Тот, кто знает приватный ключ, контролирует средства
- Потеря приватного ключа = потеря средств
- Нет способа восстановить приватный ключ

**Хранение:**

- Хранить в секрете
- Использовать аппаратные кошельки
- Делать резервные копии (seed phrase)
- Никогда не передавать через интернет

## 3. Цифровая подпись

Цифровые подписи позволяют доказать владение приватным ключом без его раскрытия.

### 3.1 Как работает цифровая подпись

**Процесс подписания:**

1. Создать хэш сообщения (транзакции)
2. Подписать хэш приватным ключом
3. Получить цифровую подпись

**Процесс проверки:**

1. Получить хэш сообщения
2. Использовать публичный ключ для проверки подписи
3. Подтвердить, что подпись валидна

**Свойства:**

- Аутентификация: подтверждает отправителя
- Целостность: подтверждает, что данные не изменены
- Неотрекаемость: нельзя отрицать подписание

### 3.2 ECDSA (Elliptic Curve Digital Signature Algorithm)

**ECDSA:**
ECDSA (Elliptic Curve Digital Signature Algorithm) — это алгоритм цифровой подписи, основанный на математике эллиптических кривых. Используется в Bitcoin и Ethereum для создания и проверки цифровых подписей транзакций. Эллиптические кривые позволяют создавать криптографически стойкие системы с меньшим размером ключей, чем альтернативы (например, RSA). Например, 256-битный ключ ECDSA обеспечивает такую же безопасность, как 3072-битный ключ RSA. Это делает ECDSA эффективным (быстрые вычисления) и безопасным (стойкость к взлому) выбором для блокчейнов.

**Преимущества:**

- Меньший размер ключей, чем RSA
- Быстрое вычисление
- Криптографически стойкий

**Пример (концептуально):**
```python
# Упрощённая концепция цифровой подписи
message = "Transfer 1 BTC to address XYZ"
message_hash = hashlib.sha256(message.encode()).hexdigest()

# Подписание (в реальности использует приватный ключ)
# signature = sign(message_hash, private_key)

# Проверка (в реальности использует публичный ключ)
# is_valid = verify(message_hash, signature, public_key)

print(f"Хэш сообщения: {message_hash}")
print("Подпись подтверждает владение приватным ключом без его раскрытия")
```

**Output:**
```

Хэш сообщения: a3b5c7d9e1f2a4b6c8d0e2f4a6b8c0d2e4f6a8b0c2d4e6f8a0b2c4d6e8f0a2
Подпись подтверждает владение приватным ключом без его раскрытия
```

## 4. Адреса и кошельки

Адреса — это человекочитаемые представления публичных ключей, используемые для получения средств.

### 4.1 Создание адреса

**Процесс создания Bitcoin адреса:**

1. Публичный ключ (из приватного ключа)
2. Хэш публичного ключа (SHA-256 + RIPEMD-160) — сначала применяется SHA-256, затем RIPEMD-160 (это криптографическая хэш-функция, разработанная в рамках проекта RIPE, выдающая 160-битный хэш). Двойное хэширование увеличивает безопасность и уменьшает размер адреса.
3. Добавление версии и checksum — версия указывает тип адреса (обычный, SegWit и т.д.), checksum (контрольная сумма) используется для обнаружения ошибок при вводе адреса
4. Кодирование в Base58 — Base58 это система кодирования, похожая на Base64, но без символов, которые можно спутать (0, O, I, l). Используется для создания человекочитаемых адресов Bitcoin

**Пример (упрощённо):**
```python
# Упрощённый процесс создания адреса

public_key_hash = hashlib.sha256(b"public_key").hexdigest()[:40]
print(f"Хэш публичного ключа: {public_key_hash}")

# В реальности используется более сложный процесс
# включающий RIPEMD-160, версию, checksum и Base58

print("Bitcoin адрес создаётся из публичного ключа через несколько шагов")
```

**Output:**
```

Хэш публичного ключа: a3b5c7d9e1f2a4b6c8d0e2f4a6b8c0d2e4f6a8b0
Bitcoin адрес создаётся из публичного ключа через несколько шагов
```

### 4.2 Кошельки

**Кошелёк (Wallet):**

- Программное или аппаратное устройство
- Хранит приватные ключи
- Создаёт и подписывает транзакции
- Управляет адресами

**Типы кошельков:**

**Горячие кошельки (Hot Wallets):**

- Подключены к интернету
- Удобны для частых транзакций
- Менее безопасны

**Холодные кошельки (Cold Wallets):**

- Не подключены к интернету
- Более безопасны
- Используются для хранения больших сумм

**Аппаратные кошельки:**

- Физические устройства
- Приватные ключи никогда не покидают устройство
- Баланс безопасности и удобства

### 4.3 Seed фразы

**Seed фраза (Mnemonic Phrase):**
Seed фраза (мнемоническая фраза) — это последовательность из 12 или 24 слов из специального словаря (обычно 2048 слов), которая представляет приватный ключ в удобной для запоминания форме. Эта фраза может восстановить все приватные ключи кошелька, поэтому критически важно хранить её в секрете. Стандарт BIP-39 (Bitcoin Improvement Proposal 39) определяет процесс генерации мнемонических фраз: случайные данные преобразуются в слова из стандартного словаря, что позволяет людям записать ключ словами вместо длинной строки символов. Потеря seed фразы означает безвозвратную потерю всех средств.

**Пример:**
```

abandon ability able about above absent absorb abstract absurd abuse access accident
```

**Важность:**

- Потеря seed фразы = потеря всех средств
- Хранить в безопасном месте
- Никогда не хранить в цифровом виде на подключённых устройствах

## 💡 Key Takeaways

- **Хэш-функции**: SHA-256 преобразует данные в фиксированный размер, обеспечивая целостность и безопасность.

- **Пара ключей**: Приватный ключ секретен и используется для подписи, публичный ключ публичен и используется для проверки.

- **Цифровые подписи**: ECDSA позволяет доказать владение приватным ключом без его раскрытия, обеспечивая аутентификацию и целостность.

- **Адреса**: Человекочитаемые представления публичных ключей, созданные через хэширование и кодирование.

- **Безопасность ключей**: Приватные ключи критически важны — их потеря означает потерю средств, их раскрытие означает потерю контроля.
