## 1. Ограничения Bitcoin

Bitcoin решает проблему цифровых денег, но имеет ограничения для более сложных приложений.

### 1.1 Ограничения

**Ограниченная программируемость:**
- Простые скрипты
- Нельзя создавать сложные приложения
- Нет состояния и циклов

**Медленные транзакции:**
- ~10 минут на блок
- Низкая пропускная способность
- Высокие комиссии при нагрузке

**Модель UTXO:**
- Сложна для некоторых приложений
- Нет глобального состояния
- Ограниченная функциональность

### 1.2 Что нужно было

**Программируемый блокчейн:**
- Возможность создавать приложения
- Сложная логика
- Состояние и вычисления

**Быстрые транзакции:**
- Более высокая пропускная способность
- Низкие комиссии
- Масштабируемость

## 2. Виртуальная машина (EVM)

EVM — это вычислительная среда Ethereum, где выполняются смарт-контракты.

### 2.1 Что такое EVM

**Ethereum Virtual Machine:**
- Виртуальная машина для выполнения кода
- Детерминированная среда
- Изоляция от основной системы

**Свойства:**
- Тьюринг-полная (может выполнять любой код)
- Детерминированная (одинаковый вход → одинаковый выход)
- Изолированная (не может влиять на систему)

**Пример:**
```python
# Концептуальный пример EVM
# Смарт-контракт на Solidity компилируется в bytecode
# Bytecode выполняется в EVM

contract_code = """
contract SimpleStorage {
    uint256 public value;
    
    function setValue(uint256 _value) public {
        value = _value;
    }
}
"""

print("EVM выполняет bytecode смарт-контрактов")
print("Каждая операция стоит Gas")
```

**Output:**
```
EVM выполняет bytecode смарт-контрактов
Каждая операция стоит Gas
```

### 2.2 Архитектура EVM

**Компоненты:**
- Стек: для вычислений
- Память: временное хранение
- Хранилище: постоянное состояние
- Баланс: эфир на аккаунте

## 3. Аккаунтная модель

Ethereum использует аккаунтную модель вместо UTXO.

### 3.1 Типы аккаунтов

**EOA (Externally Owned Account):**
- Контролируется приватным ключом
- Может отправлять транзакции
- Имеет баланс эфира

**Contract Account:**
- Контролируется кодом
- Выполняет смарт-контракты
- Имеет баланс и код

**Пример:**
```python
# Упрощённая модель аккаунта
account = {
    "address": "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb",
    "balance": 1.5,  # ETH
    "nonce": 42,  # Счётчик транзакций
    "code": None  # Для EOA
}

contract_account = {
    "address": "0xContract...",
    "balance": 0.1,
    "nonce": 0,
    "code": "0x6080604052..."  # Bytecode контракта
}

print("Ethereum использует аккаунтную модель вместо UTXO")
```

**Output:**
```
Ethereum использует аккаунтную модель вместо UTXO
```

### 3.2 Преимущества аккаунтной модели

**Простота:**
- Понятные балансы
- Легче для разработчиков
- Глобальное состояние

**Гибкость:**
- Сложные приложения
- Взаимодействие контрактов
- Состояние и вычисления

## 4. Gas и комиссии

Gas — единица измерения вычислительной работы в Ethereum.

### 4.1 Что такое Gas

**Gas:**
- Единица измерения работы
- Каждая операция стоит Gas
- Ограничивает сложность вычислений

**Gas Price:**
- Цена за единицу Gas (в Gwei)
- Устанавливается пользователем
- Влияет на скорость обработки

**Gas Limit:**
- Максимум Gas для транзакции
- Защита от бесконечных циклов
- Устанавливается пользователем

**Пример:**
```python
# Расчёт комиссии
gas_used = 21000  # Базовая транзакция
gas_price = 20  # Gwei (1 Gwei = 10^-9 ETH)
eth_price = 2000  # USD

fee_eth = gas_used * gas_price / 1e9
fee_usd = fee_eth * eth_price

print(f"Комиссия: {fee_eth:.6f} ETH (${fee_usd:.2f})")
print(f"Gas used: {gas_used}, Gas price: {gas_price} Gwei")
```

**Output:**
```
Комиссия: 0.000420 ETH ($0.84)
Gas used: 21000, Gas price: 20 Gwei
```

### 4.2 Динамика комиссий

**Факторы:**
- Загрузка сети
- Сложность операции
- Срочность транзакции

**Проблемы:**
- Высокие комиссии при нагрузке
- Непредсказуемость
- Барьер для использования

## 5. Ethereum 2.0 и PoS

Ethereum перешёл на Proof of Stake для решения проблем масштабируемости и энергопотребления.

### 5.1 Переход на PoS

**The Merge (2022):**
- Объединение Beacon Chain и Mainnet
- Переход с PoW на PoS
- Снижение энергопотребления на 99%

**Преимущества:**
- Низкое энергопотребление
- Более быстрая финализация
- Экономическая безопасность

**Механизм:**
- Валидаторы блокируют ETH
- Выбор валидаторов случайный
- Награды за валидацию
- Штрафы за злонамеренное поведение

### 5.2 Будущие обновления

**Sharding:**
- Разделение сети на шарды
- Параллельная обработка
- Увеличение пропускной способности

**Layer 2:**
- Решения поверх Ethereum
- Низкие комиссии
- Быстрые транзакции

## 💡 Key Takeaways

- **Ограничения Bitcoin**: Ограниченная программируемость и медленные транзакции создали запрос на программируемый блокчейн.

- **EVM**: Виртуальная машина для выполнения смарт-контрактов, обеспечивающая программируемость блокчейна.

- **Аккаунтная модель**: Проще UTXO для разработчиков, позволяет создавать сложные приложения с состоянием.

- **Gas**: Система оплаты за вычисления, защищающая сеть от злоупотреблений и ограничивающая сложность.

- **Ethereum 2.0**: Переход на PoS решает проблемы энергопотребления и открывает путь к масштабированию.
