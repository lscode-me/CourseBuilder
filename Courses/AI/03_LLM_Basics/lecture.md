## 1. Токенизация

### 1.1 Что такое токены

LLM не работают с текстом напрямую — они работают с **токенами**. Токен — это единица текста, на которую модель разбивает входные данные.

```python
# Токенизация — преобразование текста в последовательность чисел

text = "Hello, world!"

# Возможная токенизация:
tokens = ["Hello", ",", " world", "!"]
token_ids = [15496, 11, 995, 0]

# Модель видит только числа, не текст!
```

**Виды токенизации:**

| Метод | Описание | Пример |
|-------|----------|--------|
| Word-level | Каждое слово — токен | ["Hello", "world"] |
| Character-level | Каждый символ — токен | ["H", "e", "l", "l", "o"] |
| Subword (BPE) | Частые подстроки | ["Hel", "lo", " wor", "ld"] |

### 1.2 BPE (Byte Pair Encoding)

Большинство современных LLM используют BPE или его варианты:

```python
# Концептуально: BPE находит частые пары символов
# и объединяет их в новые токены

# Шаг 1: Начинаем с отдельных символов
vocab = ["a", "b", "c", "d", ...]

# Шаг 2: Находим самую частую пару, объединяем
# "t" + "h" → "th" (очень часто в английском)

# Шаг 3: Повторяем
# "th" + "e" → "the"
# "in" + "g" → "ing"

# Результат: словарь из ~50,000 токенов
# Баланс между размером словаря и длиной последовательности
```

**Пример токенизации OpenAI (tiktoken):**

```python
import tiktoken

enc = tiktoken.encoding_for_model("gpt-4")

text = "Artificial Intelligence is transforming the world"
tokens = enc.encode(text)
print(f"Tokens: {tokens}")
print(f"Count: {len(tokens)}")

# Декодируем обратно
for token_id in tokens:
    print(f"{token_id} → '{enc.decode([token_id])}'")
```

**Output:**
```
Tokens: [9470, 16895, 22107, 374, 46890, 279, 1917]
Count: 7

9470 → 'Art'
16895 → 'ificial'
22107 → ' Intelligence'
374 → ' is'
46890 → ' transforming'
279 → ' the'
1917 → ' world'
```

### 1.3 Особенности токенизации

```
┌─────────────────────────────────────────────────────────────┐
│               Важные особенности токенизации                 │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  1. Пробелы включаются в токены                             │
│     " the" ≠ "the"                                          │
│                                                              │
│  2. Регистр имеет значение                                  │
│     "Hello" ≠ "hello" → разные токены                       │
│                                                              │
│  3. Языки токенизируются по-разному                         │
│     English: "hello" → 1 токен                              │
│     Русский: "привет" → 2-3 токена                          │
│                                                              │

│     "123456789" → ["123", "456", "789"]                     │
│                                                              │
│  5. Редкие слова требуют больше токенов                     │
│     "ChatGPT" → 1 токен (частое)                            │

```

## 2. Генерация текста: предсказание следующего токена

### 2.1 Основной принцип

LLM — это статистическая модель, предсказывающая **следующий токен** на основе предыдущих:

```
┌─────────────────────────────────────────────────────────────┐
│          Как LLM генерирует текст                            │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Input: "The quick brown"                                   │
│                                                              │
│  Модель предсказывает распределение вероятностей:           │
│                                                              │
│  P("fox")    = 0.35  ←── наиболее вероятно                  │
│  P("dog")    = 0.15                                         │
│  P("cat")    = 0.10                                         │
│  P("rabbit") = 0.05                                         │
│  P("bear")   = 0.03                                         │
│  ...         = 0.32  (все остальные токены)                 │
│                                                              │
│  Модель выбирает токен и добавляет к последовательности:    │
│  "The quick brown fox"                                      │
│                                                              │
│  Повторяем для следующего токена...                         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 Autoregressive генерация

LLM генерирует текст **авторегрессивно** — каждый новый токен зависит от всех предыдущих:

```python
# Концептуальный алгоритм генерации

def generate(model, prompt, max_tokens=100):
    tokens = tokenize(prompt)
    
    for _ in range(max_tokens):
        # Получаем вероятности следующего токена
        probabilities = model.forward(tokens)
        
        # Выбираем следующий токен
        next_token = sample(probabilities)
        
        # Добавляем к последовательности
        tokens.append(next_token)
        
        # Проверяем условие остановки
        if next_token == END_OF_TEXT:
            break
    
    return detokenize(tokens)
```

**Важно понимать:** модель не "думает" о всём ответе сразу. Она генерирует текст токен за токеном, и каждый токен влияет на следующие.

### 2.3 Нет "понимания" — есть статистика

```python
# LLM не "понимает" текст в человеческом смысле
# Она находит статистические паттерны

# Пример: модель "знает", что после "The capital of France is"
# с высокой вероятностью следует "Paris"

# Но это не потому, что модель "понимает" географию
# Это потому, что в обучающих данных этот паттерн встречался часто

# Следствие: модель может уверенно генерировать неправду,
# если паттерн кажется "правильным"

# "The capital of Australia is Sydney" 
# Может показаться модели более "естественным", чем "Canberra"
```

## 3. Параметры генерации

### 3.1 Temperature

Temperature контролирует "случайность" генерации:

```python
# Temperature: 0.0 - 2.0 (типично)

temperature_effects = {
    0.0: "Детерминированный выбор (greedy). Всегда самый вероятный токен",
    0.3: "Низкая случайность. Предсказуемый, консервативный текст",
    0.7: "Сбалансированно. Хорошо для большинства задач",
    1.0: "Стандартное распределение вероятностей",
    1.5: "Высокая случайность. Креативный, но менее связный текст",
    2.0: "Очень случайный. Может быть бессмысленным"
}
```

**Математически:**

```python
import numpy as np

def apply_temperature(logits, temperature):
    """Temperature scaling для вероятностей"""
    if temperature == 0:
        # Greedy: выбираем максимум
        return np.argmax(logits)
    
    # Делим logits на temperature
    scaled = logits / temperature
    
    # Применяем softmax
    probs = np.exp(scaled) / np.sum(np.exp(scaled))
    
    # Сэмплируем
    return np.random.choice(len(probs), p=probs)

# При temperature → 0: распределение становится "острым"
# При temperature → ∞: распределение становится равномерным
```

**Рекомендации по temperature:**

| Задача | Temperature |
|--------|-------------|
| Код, факты, JSON | 0.0 - 0.3 |
| Общие вопросы | 0.5 - 0.7 |
| Креативное письмо | 0.7 - 1.0 |
| Brainstorming | 1.0 - 1.5 |

### 3.2 Top-p (Nucleus Sampling)

Top-p ограничивает выборку токенами, составляющими определённый процент вероятности:

```python
# Top-p = 0.9 означает: рассматривать только токены,
# которые в сумме дают 90% вероятности

def top_p_sampling(probs, p=0.9):
    """Nucleus sampling"""
    # Сортируем по убыванию вероятности
    sorted_indices = np.argsort(probs)[::-1]
    sorted_probs = probs[sorted_indices]
    
    # Находим минимальное количество токенов для p
    cumsum = np.cumsum(sorted_probs)
    cutoff_index = np.searchsorted(cumsum, p) + 1
    
    # Оставляем только top токены
    top_indices = sorted_indices[:cutoff_index]
    top_probs = sorted_probs[:cutoff_index]
    
    # Перенормируем и сэмплируем
    top_probs /= top_probs.sum()
    return np.random.choice(top_indices, p=top_probs)
```

**Пример:**

```
Вероятности: {"the": 0.5, "a": 0.3, "an": 0.1, "that": 0.05, ...}

Top-p = 0.9:
- "the" (0.5) → cumsum = 0.5
- "a" (0.3)   → cumsum = 0.8
- "an" (0.1)  → cumsum = 0.9 ✓ (достигли порога)

Выбираем только из: {"the", "a", "an"}
```

### 3.3 Top-k

Top-k ограничивает выборку k наиболее вероятными токенами:

```python
def top_k_sampling(probs, k=50):
    """Top-k sampling"""
    # Находим k наиболее вероятных токенов
    top_k_indices = np.argsort(probs)[-k:]
    top_k_probs = probs[top_k_indices]
    
    # Перенормируем и сэмплируем
    top_k_probs /= top_k_probs.sum()
    return np.random.choice(top_k_indices, p=top_k_probs)

# Top-k = 40: рассматриваем только 40 самых вероятных токенов
```

### 3.4 Комбинирование параметров

На практике часто используют комбинацию:

```python
# Типичные комбинации

# Для кода/фактов (консервативно)
params_conservative = {
    "temperature": 0.2,
    "top_p": 0.95,
    "top_k": None  # не используется
}

# Для общих задач (сбалансированно)
params_balanced = {
    "temperature": 0.7,
    "top_p": 0.9,
    "top_k": 50
}

# Для креатива (разнообразно)
params_creative = {
    "temperature": 1.0,
    "top_p": 0.95,
    "top_k": None
}
```

> **⚠️ Warning:**  
> Не используйте одновременно высокий temperature (>1) и широкий top_p (>0.95). Это может привести к бессмысленному тексту.

## 4. Контекстное окно

### 4.1 Что такое контекстное окно

Контекстное окно — максимальное количество токенов, которое модель может обработать за один запрос (вход + выход):

```
┌─────────────────────────────────────────────────────────────┐
│                   Контекстное окно                           │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ◄─────────────── Context Window ───────────────►           │
│                                                              │
│  [System] [User Prompt] [Context/Documents] [Response]      │
│  ↑                                           ↑              │
│  input tokens                         output tokens         │
│                                                              │
│  Всё должно умещаться в лимит!                              │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**Размеры контекстных окон (2024):**

| Модель | Контекстное окно |
|--------|-----------------|
| GPT-3.5 | 16K токенов |
| GPT-4 | 8K / 128K токенов |
| GPT-4o | 128K токенов |
| Claude 3 | 200K токенов |
| Gemini 1.5 | 1M / 2M токенов |

### 4.2 Практические ограничения

```python
# Контекстное окно — это не "магический" лимит

context_window_reality = {
    "Лимит": "Технический предел",
    "Производительность": "Качество падает на длинных контекстах",
    "Latency": "Больше токенов = дольше ответ",
    "Стоимость": "Больше токенов = дороже",
    "Attention": "Модель хуже 'помнит' середину длинного контекста"
}

# "Lost in the middle" — феномен, когда модель хуже работает
# с информацией в середине длинного контекста
```

### 4.3 Как работать с длинным контекстом

```python
# Стратегии работы с длинным контекстом

strategies = {
    "Chunking": "Разбить документ на части, обработать по очереди",
    "Summarization": "Сначала суммаризировать, потом работать",
    "RAG": "Извлекать только релевантные части",
    "Prioritization": "Важную информацию — в начало и конец",
}

# Пример: вместо одного промпта с 50К токенов
# разбить на несколько запросов с обработкой частей
```

### 4.4 Вычисление использования контекста

```python
import tiktoken

def estimate_tokens(text, model="gpt-4"):
    """Оценка количества токенов в тексте"""
    enc = tiktoken.encoding_for_model(model)
    return len(enc.encode(text))

# Пример расчёта
system_prompt = "You are a helpful assistant..."  # ~10 tokens
user_prompt = "Summarize this article..."  # ~5 tokens
article = "..." * 10000  # допустим, 15000 tokens

total_input = (
    estimate_tokens(system_prompt) +
    estimate_tokens(user_prompt) +
    estimate_tokens(article)
)

max_output = 128000 - total_input  # для GPT-4 128K

print(f"Input: {total_input} tokens")
print(f"Available for output: {max_output} tokens")
```

## 5. Галлюцинации

### 5.1 Что такое галлюцинации

Галлюцинации — это уверенная генерация фактически неверной информации:

```
┌─────────────────────────────────────────────────────────────┐
│                    Типы галлюцинаций                         │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  1. Фактические ошибки                                      │
│     "Эйфелева башня была построена в 1920 году"             │
│     (на самом деле 1889)                                    │
│                                                              │
│  2. Выдуманные факты                                        │
│     "Согласно исследованию Гарварда 2023 года..."           │
│     (исследования не существует)                            │
│                                                              │
│  3. Логические противоречия                                 │
│     "X одновременно больше и меньше Y"                      │
│                                                              │
│  4. Ложные ссылки                                           │
│     "Как сказано в книге <несуществующий автор>..."         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 Почему галлюцинации возникают

```python
# Причины галлюцинаций

causes = {
    "Training objective": """
        Модель обучена предсказывать "правдоподобный" текст,
        а не "правдивый". Правдоподобный ≠ правдивый.
    """,
    
    "No grounding": """
        Модель не имеет доступа к источнику истины.
        Она "помнит" паттерны, но не может проверить факты.
    """,
    
    "Confidence calibration": """
        Модель не умеет правильно оценивать уверенность.
        Она может быть очень уверена в неверном ответе.
    """,
    
    "Distribution shift": """
        Вопрос может быть вне области обучающих данных.
        Модель всё равно сгенерирует ответ.
    """,
    
    "Pressure to answer": """
        RLHF обучает модель "помогать".
        Она может предпочесть неверный ответ отказу отвечать.
    """
}
```

### 5.3 Примеры галлюцинаций

```python
# Пример 1: Выдуманные ссылки

prompt = "Приведи ссылки на научные статьи о влиянии X на Y"

# Модель может сгенерировать:
# "Smith, J. et al. (2021). 'Impact of X on Y'. Nature, 589, 42-48."
# При этом такой статьи не существует!

# Пример 2: Уверенные неверные факты

prompt = "Когда родился Барак Обама?"

# Модель ответит: "4 августа 1961 года" (правильно)
# Но на более редких фактах может ошибиться с той же уверенностью

# Пример 3: Логические ошибки

prompt = "Сколько будет 17 × 24?"

# Модель может ответить "398" (правильно 408)
# с полной уверенностью
```

### 5.4 Как минимизировать галлюцинации


## 6. Attention и "память" модели

### 6.1 Как модель "помнит" контекст

LLM не имеет "памяти" в традиционном смысле. Вместо этого она использует **attention** для связывания информации в контексте:

```
┌─────────────────────────────────────────────────────────────┐
│            Attention как "память" в контексте                │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Контекст: "The cat sat on the mat. It was very soft."      │
│                                                              │
│  При генерации слова после "It was very":                   │
│                                                              │
│  Attention weights:                                         │
│  "The"   → 0.02                                             │
│  "cat"   → 0.05                                             │
│  "sat"   → 0.01                                             │
│  "mat"   → 0.40  ← высокий вес! "soft" относится к "mat"    │
│  "It"    → 0.20                                             │
│  "was"   → 0.15                                             │
│  "very"  → 0.17                                             │
│                                                              │
│  Модель "смотрит" на "mat", чтобы понять контекст "soft"    │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 Lost in the Middle

При длинных контекстах модель хуже "помнит" информацию в середине:

```python
# Исследование "Lost in the Middle" (Liu et al., 2023)

# Тест: ключевая информация размещена в разных позициях контекста

position_accuracy = {
    "В начале контекста": "Высокая точность",
    "В середине контекста": "Низкая точность",  # Проблема!
```

### 7.2 Типичные ошибки

```python
# Ошибка 1: Игнорирование токенизации
# ❌ "Модель может обработать 100 000 слов"
# ✅ "Модель может обработать 128 000 токенов (≈90 000 английских слов)"

# Ошибка 2: Использование высокого temperature для фактов
# ❌ temperature=1.0 для "Какова столица Франции?"
# ✅ temperature=0.0 для фактических вопросов

# Ошибка 3: Доверие без проверки
# ❌ "Модель дала ссылку, значит она существует"
# ✅ "Модель может выдумать ссылку, нужно проверить"

# Ошибка 4: Информация в середине длинного контекста
# ❌ [много текста] [важная инструкция] [много текста]
# ✅ [важная инструкция] [текст] [напоминание инструкции]
```

## 💡 Key Takeaways

- **Токены ≠ слова** — модель работает с токенами (subwords). Русский текст требует больше токенов, чем английский. Токены влияют на стоимость и лимиты

- **Генерация авторегрессивна** — модель предсказывает следующий токен на основе предыдущих. Нет "планирования" всего ответа заранее

- **Temperature контролирует случайность** — низкая (0-0.3) для фактов и кода, средняя (0.5-0.7) для общих задач, высокая (0.8-1.0) для креатива

- **Контекстное окно конечно** — важно умещаться в лимит. Информация в середине длинного контекста теряется (lost in the middle)

- **Галлюцинации неизбежны** — модель не "знает" факты, она генерирует правдоподобный текст. Верификация обязательна
