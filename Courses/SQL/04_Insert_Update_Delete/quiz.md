## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Правильный синтаксис: INSERT INTO table_name (columns) VALUES (values). INTO обязательно, столбцы лучше указывать явно |
| 2 | D | Можно указать несколько наборов значений: VALUES (val1, val2), (val3, val4), (val5, val6) |
| 3 | B | UPDATE без WHERE обновит ВСЕ строки в таблице. Это очень опасно! |
| 4 | D | DELETE без WHERE удалит ВСЕ строки в таблице. Всегда используйте WHERE! |
| 5 | A | BEGIN начинает новую транзакцию. Все последующие команды будут частью этой транзакции до COMMIT или ROLLBACK |
| 6 | B | COMMIT сохраняет все изменения в транзакции и завершает транзакцию |
| 7 | C | ROLLBACK откатывает все изменения в текущей транзакции и завершает транзакцию |
| 8 | A | A в ACID означает Atomicity (Атомарность) — все операции выполняются или ни одна |
| 9 | D | Можно не указывать столбец в списке (если у него есть DEFAULT) или явно указать DEFAULT |
| 10 | C | Можно указать несколько SET через запятую: SET col1 = val1, col2 = val2, col3 = val3 |
| 11 | C | INSERT ... SELECT вставляет данные из результата SELECT запроса в таблицу |
| 12 | B | Подзапросы можно использовать и в SET (для значений), и в WHERE (для условий) |
| 13 | B | Подзапросы можно использовать в WHERE условии DELETE для фильтрации удаляемых строк |
| 14 | D | RETURNING возвращает изменённые (вставленные, обновлённые или удалённые) данные. Доступно в PostgreSQL |
| 15 | A | UPSERT (UPDATE + INSERT) — вставка новой записи или обновление существующей, если она уже есть |
| 16 | D | ON CONFLICT в PostgreSQL позволяет обработать конфликт (например, по первичному ключу) и выполнить UPDATE вместо INSERT |
| 17 | C | Автокоммит означает, что каждая команда автоматически становится отдельной транзакцией и коммитится |
| 18 | A | Атомарность означает "всё или ничего" — либо все операции транзакции выполняются, либо ни одна |
| 19 | B | В SET можно использовать выражения: SET age = age + 1, price = price * 1.1 и т.д. |
| 20 | A | При каскадном удалении (ON DELETE CASCADE) удаление записи автоматически удаляет связанные записи в других таблицах |
| 21 | C | INSERT без указания столбцов хрупкий — при изменении структуры таблицы (добавлении/удалении столбцов) запрос может сломаться |
| 22 | D | Изоляция означает, что транзакции изолированы друг от друга и не видят незакоммиченные изменения других транзакций |
| 23 | D | Самый безопасный подход — сначала выполнить SELECT с теми же условиями, чтобы увидеть, какие строки будут затронуты |
| 24 | B | Самый безопасный подход: сначала SELECT с условиями, проверить результат, затем DELETE с теми же условиями |
| 25 | C | Долговечность означает, что после COMMIT изменения сохраняются навсегда, даже при сбое системы |
