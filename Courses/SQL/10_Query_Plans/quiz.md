| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | EXPLAIN показывает план выполнения без реального выполнения запроса |

| 3 | A | Seq Scan (Sequential Scan) — полное сканирование таблицы, строка за строкой |
| 4 | B | Index Scan использует индекс для быстрого поиска нужных строк |
| 5 | B | Seq Scan используется, когда нет подходящего индекса или нужно прочитать большую часть таблицы |
| 6 | B | Index Only Scan читает только индекс, не обращаясь к таблице (самый быстрый вариант) |

| 8 | A | Статистика таблиц нужна оптимизатору для оценки стоимости и выбора оптимального плана |
| 9 | D | ANALYZE обновляет статистику таблицы для оптимизатора запросов |
| 10 | C | cost — оценка стоимости операции (startup..total), используется оптимизатором |
| 11 | C | Planning Time — время, потраченное оптимизатором на планирование запроса |
| 12 | A | Execution Time — реальное время выполнения запроса |
| 13 | B | EXPLAIN поддерживает несколько форматов: TEXT, JSON, XML, YAML |
| 14 | D | EXPLAIN ANALYZE реально выполняет запрос и показывает фактические метрики, EXPLAIN только план |
| 15 | A | EXPLAIN ANALYZE стоит использовать, когда нужно узнать реальное время выполнения |
| 16 | B | Bitmap Scan — комбинация индекса и таблицы, создаёт битовую карту строк для эффективного чтения |

| 24 | B | pg_stat_statements — расширение для статистики выполнения запросов, помогает найти медленные запросы |

| 28 | B | Оптимизация JOIN: создание индексов на ключах JOIN для ускорения операций |
