## 1. Что такое база данных

**База данных (БД)** — это организованная коллекция данных, хранящаяся и доступная в электронном виде. Данные структурированы таким образом, чтобы их можно было эффективно хранить, извлекать и изменять.

### 1.1 Зачем нужны базы данных

Представьте, что вы храните информацию о пользователях в текстовом файле:

```
users.txt:
Иван, ivan@example.com, 25
Мария, maria@example.com, 30
Петр, petr@example.com, 28
```

**Проблемы такого подхода:**

- ❌ Сложно найти конкретного пользователя
- ❌ Нет гарантии уникальности email
- ❌ Нет связей между данными (например, заказы пользователя)
- ❌ Нет контроля доступа
- ❌ Нет транзакций (атомарность операций)

**База данных решает эти проблемы:**

- ✅ Эффективный поиск по индексам
- ✅ Ограничения целостности данных
- ✅ Связи между таблицами
- ✅ Контроль доступа и безопасность
- ✅ Транзакции для надёжности

### 1.2 Система управления базами данных (СУБД)

**СУБД (DBMS — Database Management System)** — это программное обеспечение, которое управляет базой данных.

**Популярные СУБД:**

| СУБД | Тип | Особенности |
|------|-----|-------------|
| PostgreSQL | Реляционная | Открытая, мощная, стандарт SQL |
| MySQL | Реляционная | Популярная, быстрая, веб-приложения |
| SQLite | Реляционная | Встраиваемая, файловая, для разработки |
| MongoDB | Документная | NoSQL, гибкая схема |
| Redis | Ключ-значение | In-memory, кэширование |

В этом курсе мы фокусируемся на **реляционных СУБД** и **SQL**.

## 2. Реляционная модель данных

**Реляционная модель** — это математическая модель данных, основанная на теории множеств и логике первого порядка. Она была предложена Эдгаром Коддом в 1970 году.

### 2.1 Основные концепции

**Таблица (отношение)** — это набор строк (кортежей) с одинаковой структурой.

**Пример таблицы `users`:**

| id | name  | email              | age |
|----|-------|--------------------|-----|
| 1  | Иван  | ivan@example.com   | 25  |
| 2  | Мария | maria@example.com  | 30  |
| 3  | Петр  | petr@example.com   | 28  |

**Терминология:**

- **Таблица (Table/Relation)** — структура для хранения данных

- **Строка (Row/Tuple)** — одна запись в таблице

- **Столбец (Column/Attribute)** — поле данных

- **Первичный ключ (Primary Key)** — уникальный идентификатор строки (например, `id`)

- **Схема (Schema)** — структура таблицы (названия и типы столбцов)

### 2.2 Связи между таблицами

Реляционная модель позволяет создавать связи между таблицами через **внешние ключи (Foreign Keys)**.

**Пример: таблицы `users` и `orders`**

```sql
-- Таблица пользователей
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100)
);

-- Таблица заказов
CREATE TABLE orders (
    id INT PRIMARY KEY,
    user_id INT,
    amount DECIMAL(10, 2),
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**Связь:** Каждый заказ принадлежит пользователю через `user_id`.

**Типы связей:**

- **Один-к-одному (1:1)** — один пользователь имеет один профиль

- **Один-ко-многим (1:N)** — один пользователь имеет много заказов

- **Многие-ко-многим (M:N)** — студенты и курсы (через промежуточную таблицу)

## 3. Что такое SQL

**SQL (Structured Query Language)** — это декларативный язык программирования, предназначенный для работы с реляционными базами данных.

### 3.1 История SQL

- **1970** — Эдгар Кодд публикует статью о реляционной модели

- **1974** — Разработка языка SEQUEL (Structured English Query Language)

- **1979** — Oracle выпускает первую коммерческую СУБД с SQL

- **1986** — SQL становится стандартом ANSI

- **1992** — SQL-92 (основной стандарт, используемый до сих пор)

- **Сейчас** — SQL используется во всех реляционных СУБД

### 3.2 Декларативный vs Императивный

**SQL — декларативный язык:** вы описываете **ЧТО** хотите получить, а не **КАК** это получить.

**Пример: найти всех пользователей старше 25 лет**

**Декларативный подход (SQL):**
```sql
SELECT name, age
FROM users
WHERE age > 25;
```

Вы говорите: "Дай мне имена и возраст пользователей, у которых возраст больше 25".

**Императивный подход (Python):**
```python
result = []
for user in users:
    if user.age > 25:
        result.append({'name': user.name, 'age': user.age})
```

Вы описываете шаги: "Пройдись по всем пользователям, проверь возраст, добавь в результат".

**Преимущества декларативного подхода:**

- ✅ Проще писать и читать
- ✅ СУБД сама выбирает оптимальный способ выполнения
- ✅ Не нужно думать о деталях реализации

## 4. Типы операций в SQL

SQL операции делятся на несколько категорий:

### 4.1 DDL — Data Definition Language

**DDL** — язык определения данных. Используется для создания и изменения структуры базы данных.

**Основные команды:**

```sql
-- Создание таблицы
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100)
);

-- Изменение таблицы
ALTER TABLE users ADD COLUMN age INT;

-- Удаление таблицы
DROP TABLE users;
```

### 4.2 DML — Data Manipulation Language

**DML** — язык манипуляции данными. Используется для работы с данными в таблицах.

**Основные команды:**

```sql
-- Вставка данных
INSERT INTO users (name, email) VALUES ('Иван', 'ivan@example.com');

-- Обновление данных
UPDATE users SET age = 26 WHERE id = 1;

-- Удаление данных
DELETE FROM users WHERE id = 1;

-- Выборка данных
SELECT name, email FROM users WHERE age > 25;
```

### 4.3 DQL — Data Query Language

**DQL** — язык запросов. Хотя `SELECT` технически относится к DML, его часто выделяют отдельно.

```sql
-- Простой запрос
SELECT * FROM users;

-- Запрос с условиями
SELECT name, email 
FROM users 
WHERE age > 25 
ORDER BY name;
```

### 4.4 DCL — Data Control Language

**DCL** — язык управления доступом. Используется для управления правами доступа.

```sql
-- Предоставление прав
GRANT SELECT ON users TO analyst;

-- Отзыв прав
REVOKE SELECT ON users FROM analyst;
```

### 4.5 TCL — Transaction Control Language

**TCL** — язык управления транзакциями. Используется для управления транзакциями.

```sql
-- Начало транзакции
BEGIN;

-- Подтверждение изменений
COMMIT;

-- Откат изменений
ROLLBACK;
```

## 5. Популярные СУБД и их особенности

### 5.1 PostgreSQL

**Особенности:**

- ✅ Полная поддержка стандарта SQL
- ✅ Расширенные типы данных (JSON, массивы, геоданные)
- ✅ Мощные индексы (GIN, GiST, BRIN)
- ✅ Открытый исходный код
- ✅ Отличная производительность

**Пример использования:**
```sql
-- PostgreSQL поддерживает JSON
SELECT 
    id,
    name,
    metadata->>'city' AS city
FROM users
WHERE metadata @> '{"country": "Russia"}';
```

### 5.2 MySQL

**Особенности:**

- ✅ Очень популярна в веб-разработке
- ✅ Быстрая для простых запросов
- ✅ Хорошая интеграция с PHP
- ⚠️ Некоторые ограничения по сравнению с PostgreSQL

**Пример использования:**
```sql
-- MySQL синтаксис
SELECT name, email
FROM users
WHERE age > 25
LIMIT 10;
```

### 5.3 SQLite

**Особенности:**

- ✅ Встраиваемая (один файл)
- ✅ Не требует сервера
- ✅ Идеальна для разработки и тестирования
- ✅ Используется в мобильных приложениях

**Пример использования:**
```sql
-- SQLite синтаксис (очень похож на стандартный SQL)
SELECT * FROM users WHERE age > 25;
```

### 5.4 Выбор СУБД

**Когда использовать PostgreSQL:**

- Нужна полная поддержка SQL
- Сложные запросы и аналитика
- Требуется надёжность и консистентность

**Когда использовать MySQL:**

- Веб-приложения с простыми запросами
- Нужна высокая скорость чтения
- Команда уже знакома с MySQL

**Когда использовать SQLite:**

- Разработка и тестирование
- Мобильные приложения
- Небольшие проекты без множественных подключений

## 6. Первый SQL-запрос

Давайте выполним первый запрос. Предположим, у нас есть таблица `users`:

```sql
-- Создадим таблицу
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100),
    age INT
);

-- Вставим данные
INSERT INTO users VALUES 
    (1, 'Иван', 'ivan@example.com', 25),
    (2, 'Мария', 'maria@example.com', 30),
    (3, 'Петр', 'petr@example.com', 28),
    (4, 'Анна', 'anna@example.com', 22);
```

**Простой запрос: получить всех пользователей**

```sql
SELECT * FROM users;
```

**Output:**
```
id | name  | email              | age
---+-------+--------------------+-----
1  | Иван  | ivan@example.com   | 25
2  | Мария | maria@example.com  | 30
3  | Петр  | petr@example.com   | 28
4  | Анна  | anna@example.com   | 22
```

**Запрос с условием: пользователи старше 25**

```sql
SELECT name, email
FROM users
WHERE age > 25
ORDER BY age DESC;
```

**Output:**
```
name  | email

------+--------------------
Мария | maria@example.com
Петр  | petr@example.com
```

## 7. Зачем изучать SQL

### 7.1 SQL везде

SQL используется в:

- **Backend разработке** — работа с базами данных

- **Data Engineering** — обработка и трансформация данных

- **Data Analytics** — анализ данных и отчёты

- **Business Intelligence** — дашборды и визуализации

- **System Design** — проектирование систем с данными

### 7.2 SQL — фундаментальный навык

**Почему SQL важен:**

- ✅ **Стандартизирован** — один язык для всех реляционных БД
- ✅ **Долговечен** — SQL существует 50+ лет и не устаревает
- ✅ **Универсален** — используется во всех областях работы с данными
- ✅ **Мощен** — позволяет решать сложные задачи простыми запросами

### 7.3 SQL vs NoSQL

**Когда использовать SQL (реляционные БД):**

- ✅ Структурированные данные
- ✅ Нужны связи между данными
- ✅ Требуется ACID (транзакции)
- ✅ Сложные запросы и аналитика

**Когда использовать NoSQL:**

- ✅ Неструктурированные данные
- ✅ Горизонтальное масштабирование
- ✅ Высокая скорость записи
- ✅ Гибкая схема данных

**Важно:** SQL и NoSQL не исключают друг друга. Многие системы используют оба подхода.
