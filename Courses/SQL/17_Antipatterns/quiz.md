## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | SELECT * возвращает все столбцы (медленнее), скрывает реальные зависимости, ломается при изменении структуры |
| 2 | A | N+1 queries — выполнение множества запросов (1 для списка + N для каждого элемента) вместо одного запроса с JOIN |
| 3 | A | Решение N+1 — использовать один запрос с JOIN вместо множества отдельных запросов |
| 4 | B | Без индексов используется Seq Scan (полное сканирование), что медленно на больших таблицах |

| 18 | C | DISTINCT с GROUP BY избыточен, так как GROUP BY уже обеспечивает уникальность групп |
| 19 | A | Неявные JOIN (старый синтаксис) менее читаемы и легко забыть условие, что приведёт к CROSS JOIN |
| 20 | B | Индексы на внешних ключах нужны для ускорения JOIN операций |
| 21 | A | Избыточные вычисления повторяются для каждой строки, замедляют запрос, нужно вынести в подзапрос |
| 22 | A | Форматирование SQL улучшает читаемость и упрощает поддержку кода |
| 23 | D | Понятные алиасы (user_id вместо a) улучшают читаемость и понятность кода |
