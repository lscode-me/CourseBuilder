## 1. TCP/IP

### 1.1 Стек протоколов TCP/IP

**TCP/IP** — набор протоколов, лежащих в основе интернета.

**Уровни:**

- **Application** — приложения (HTTP, FTP, SMTP)

- **Transport** — TCP, UDP

- **Internet** — IP

- **Link** — Ethernet, Wi-Fi

**Принцип:**
Каждый уровень решает свои задачи, не зная деталей других уровней.

### 1.2 IP (Internet Protocol)

**IP адресация:**

- Уникальный адрес для каждого устройства
- IPv4: 32 бита (4 миллиарда адресов)
- IPv6: 128 бит (практически неограниченное количество)

**Маршрутизация:**

- Пакеты направляются от источника к получателю
- Каждый узел решает, куда направить пакет дальше

### 1.3 TCP (Transmission Control Protocol)

**Особенности:**

- Надёжная доставка данных
- Установление соединения
- Контроль потока
- Упорядочивание пакетов

**UDP (User Datagram Protocol):**

- Ненадёжная доставка
- Быстрее TCP
- Для приложений, где скорость важнее надёжности

## 2. DNS

### 2.1 Система доменных имён

**DNS (Domain Name System)** — система преобразования доменных имён в IP адреса.

**Проблема:**
Людям легче запомнить `google.com`, чем `142.250.185.14`.

**Решение:**
DNS преобразует доменные имена в IP адреса.

### 2.2 Иерархия DNS

**Структура:**
```

. (корень)
├── com
│   └── google
│       └── www
├── org
└── ru
```

**Процесс запроса:**

1. Запрос к локальному DNS серверу
2. Если нет — запрос к корневому серверу
3. Направление к соответствующему домену
4. Получение IP адреса

### 2.3 Важность DNS

**Критичность:**

- Без DNS интернет практически не работает
- Атаки на DNS могут парализовать сеть
- Распределённая система для надёжности

## 3. HTTP

### 3.1 Протокол HTTP

**HTTP (HyperText Transfer Protocol)** — протокол для передачи веб-страниц.

**Принцип:**

- Клиент отправляет запрос
- Сервер отправляет ответ
- Статус-коды (200 OK, 404 Not Found, etc.)

### 3.2 Эволюция HTTP

**HTTP/1.0:**

- Одно соединение на запрос
- Медленно для современных сайтов

**HTTP/1.1:**

- Постоянные соединения
- Кеширование
- Сжатие

**HTTP/2:**

- Мультиплексирование
- Приоритизация
- Сжатие заголовков

**HTTP/3:**

- На основе UDP (QUIC)
- Быстрое установление соединения
- Лучшая работа при потере пакетов

## 4. Интернет как платформа

### 4.1 Эволюция использования

**Ранний интернет:**

- Обмен информацией
- Электронная почта
- Файловые архивы

**Веб:**

- Гипертекстовые документы
- Связь между документами
- Доступ через браузер

**Современный интернет:**

- Платформа для приложений
- Облачные сервисы
- Социальные сети

### 4.2 Влияние на вычисления

**Изменения:**

- Вычисления переместились в сеть
- Данные хранятся в облаке
- Приложения работают в браузере
- Мобильные устройства подключены постоянно

---

## 5. Как сети изменили вычисления

### 5.1 Распределённые вычисления

**Возможности:**

- Вычисления на удалённых серверах
- Доступ к данным из любого места
- Совместная работа

### 5.2 Облачные вычисления

**Модели:**

- **IaaS** — инфраструктура как услуга

- **PaaS** — платформа как услуга

- **SaaS** — программное обеспечение как услуга

**Преимущества:**

- Масштабируемость
- Гибкость
- Снижение затрат

### 5.3 Новые парадигмы

**Изменения:**

- От локальных приложений к веб-приложениям
- От покупки ПО к подписке
- От локального хранения к облачному

---

## 💡 Key Takeaways

- **TCP/IP** обеспечивает надёжную передачу данных в интернете через многоуровневую архитектуру

- **DNS** критически важен для работы интернета, преобразуя доменные имена в IP адреса

- **HTTP** эволюционировал от простого протокола к сложной системе, оптимизированной для современных веб-приложений

- **Интернет стал платформой** для вычислений, изменив способ разработки и использования приложений

- **Сети изменили вычисления** — от локальных к распределённым, от покупки к подписке, от локального хранения к облачному
