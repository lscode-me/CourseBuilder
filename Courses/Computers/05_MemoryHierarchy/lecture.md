## 1. Проблема памяти: скорость vs объём

### 1.1 Фундаментальный конфликт

В идеальном мире процессору нужна память, которая:
- **Бесконечно быстрая** — доступ за 0 циклов
- **Бесконечно большая** — любой объём данных
- **Бесконечно дешёвая** — не влияет на стоимость системы

Реальность: это физически невозможно. Быстрая память — дорогая и маленькая. Большая память — медленная и дешёвая.

**Фундаментальная проблема:** разрыв между скоростью процессора и скоростью памяти (Memory Wall).

### 1.2 Историческая перспектива

**1970-е:** Процессоры и память работали примерно с одинаковой скоростью.

**1980-е:** Процессоры начали обгонять память. Появились первые кэши.

**1990-е - 2000-е:** Разрыв увеличился в сотни раз. Многоуровневые кэши стали критичны.

**Современность:** Процессор за время доступа к RAM может выполнить сотни инструкций.

## 2. Иерархия памяти

### 2.1 Пирамида памяти

От самой быстрой к самой медленной:

```
          [Регистры]           ← 0-1 цикл, ~1 KB
             |
        [L1 Cache]             ← 1-4 цикла, ~32-128 KB
             |
        [L2 Cache]             ← 10-20 циклов, ~256 KB - 1 MB
             |
        [L3 Cache]             ← 40-75 циклов, ~4-32 MB
             |
           [RAM]               ← ~200 циклов, 8-128 GB
             |
          [SSD]                ← ~50,000 циклов, 256 GB - 4 TB
             |
          [HDD]                ← ~10,000,000 циклов, 1-20 TB
             |
      [Tape/Cloud]             ← секунды/минуты, практически ∞
```

### 2.2 Принцип работы иерархии

**Ключевая идея:** Данные автоматически мигрируют между уровнями в зависимости от использования.

**Locality of Reference** — два фундаментальных принципа:

1. **Temporal Locality:** Если данные использовались недавно, они вероятно понадобятся снова скоро
2. **Spatial Locality:** Если использовались данные по адресу X, вероятно понадобятся данные рядом (X+1, X+2...)

Эти принципы работают в ~90% программ, делая кэши эффективными.

## 3. Кэш-память

### 3.1 Что такое кэш

**Cache** — быстрая промежуточная память между процессором и RAM.

Кэш хранит копии наиболее часто используемых данных из RAM. Процессор сначала проверяет кэш:
- **Cache Hit:** данные найдены в кэше → быстрый доступ
- **Cache Miss:** данных нет → загрузка из RAM

**Cache Hit Rate** — процент обращений, которые находят данные в кэше. Типично 95-99%.

### 3.2 Многоуровневые кэши

**L1 Cache (Level 1):**
- Самый быстрый, самый маленький
- Обычно разделён на I-cache (инструкции) и D-cache (данные)
- 32-128 KB на ядро
- Доступ: 1-4 цикла

**L2 Cache (Level 2):**
- Больше L1, медленнее L1
- 256 KB - 1 MB на ядро
- Доступ: 10-20 циклов
- Унифицированный (и инструкции, и данные)

**L3 Cache (Level 3):**
- Shared между всеми ядрами процессора
- 4-32 MB (весь чип)
- Доступ: 40-75 циклов
- Критичен для многоядерных систем

### 3.3 Организация кэша

**Cache Line** — минимальная единица кэша, обычно 64 байта.

При промахе загружается не один байт, а целая cache line (spatial locality!).

**Типы организации:**

1. **Direct-Mapped Cache:** Каждый адрес RAM может находиться только в одной позиции кэша
   - Просто, быстро
   - Много конфликтов

2. **Fully Associative Cache:** Данные могут быть в любой позиции
   - Нет конфликтов
   - Сложно, медленно искать

3. **Set-Associative Cache:** Компромисс
   - N-way: данные могут быть в одном из N мест
   - Типично: 4-way, 8-way, 16-way

### 3.4 Cache Coherency

**Проблема:** В многоядерной системе каждое ядро имеет свой L1/L2 кэш. Что если два ядра модифицируют одни данные?

**Решение:** Протоколы когерентности кэша

**MESI Protocol** (Modified, Exclusive, Shared, Invalid):
- Modified: данные изменены только в этом кэше
- Exclusive: данные только в этом кэше, не изменены
- Shared: данные есть в нескольких кэшах
- Invalid: данные устарели

Процессор отслеживает состояние каждой cache line и синхронизирует изменения между ядрами.

## 4. Оперативная память (RAM)

### 4.1 DRAM vs SRAM

**SRAM (Static RAM):**
- Используется в кэшах
- Очень быстрая (~1 ns)
- Дорогая
- Сложная (6 транзисторов на бит)
- Не требует refresh

**DRAM (Dynamic RAM):**
- Используется как основная память
- Медленнее (~50 ns)
- Дешёвая
- Простая (1 транзистор + конденсатор на бит)
- Требует refresh (конденсаторы разряжаются)

### 4.2 Типы DRAM

**SDR SDRAM (Single Data Rate):**
- 1990-е годы
- Один transfer на такт

**DDR (Double Data Rate):**
- DDR, DDR2, DDR3, DDR4, DDR5
- Два transfer на такт
- Каждое поколение: выше частота, ниже напряжение

**DDR5 (современность):**
- 4800-6400 MT/s (transfers per second)
- 1.1V
- On-die ECC
- Два независимых канала на модуль

### 4.3 Timing и Latency

**CAS Latency (CL)** — задержка между запросом и получением данных

Типичная спецификация: **DDR4-3200 CL16**
- 3200: частота в MHz
- CL16: 16 циклов задержки

**Trade-off:** Выше частота ≠ меньше реальная задержка
- DDR4-3200 CL16: ~10 ns
- DDR4-2400 CL12: ~10 ns (то же самое!)

## 5. Виртуальная память

### 5.1 Зачем нужна виртуальная память

**Проблемы без виртуальной памяти:**
1. Каждая программа видит всю физическую память — конфликты
2. Невозможна изоляция программ — безопасность
3. Фрагментация памяти
4. Невозможно использовать больше физической RAM

**Решение:** Каждая программа получает своё виртуальное адресное пространство.

### 5.2 Концепция виртуальной памяти

**Virtual Address** → **Physical Address**

Процессор работает с виртуальными адресами. Memory Management Unit (MMU) транслирует их в физические.

**Преимущества:**
- Изоляция процессов
- Защита памяти
- Возможность использовать disk как расширение RAM (swap)
- Упрощение разработки (программа всегда видит одинаковое адресное пространство)

### 5.3 Страничная организация

Память делится на **Pages** (обычно 4 KB).

**Page Table** — таблица соответствия виртуальных страниц физическим:

```
Virtual Page → Physical Frame
0x00001000 → 0x00123000
0x00002000 → 0x00456000
0x00003000 → [Not Mapped - Page Fault]
```

**Page Fault** — обращение к странице, которой нет в RAM:
1. OS находит страницу на диске
2. Загружает её в RAM
3. Обновляет Page Table
4. Возобновляет выполнение программы

Прозрачно для программы!

### 5.4 Translation Lookaside Buffer (TLB)

**Проблема:** Каждый доступ к памяти требует чтения Page Table (тоже в памяти!) → удвоение обращений.

**Решение:** TLB — кэш для Page Table.

TLB хранит последние использованные трансляции виртуальных адресов. Типично 64-512 записей, hit rate ~99%.

Без TLB виртуальная память была бы неприемлемо медленной.

### 5.5 Размеры страниц

**Стандартные:** 4 KB
**Большие (Huge Pages):** 2 MB, 1 GB

**Большие страницы:**
- Меньше записей в TLB → меньше TLB misses
- Меньше overhead на управление
- Используются для баз данных, виртуализации

## 6. Неволатильная память

### 6.1 ROM (Read-Only Memory)

**Использование:** BIOS/UEFI firmware, встроенные системы

**Типы:**
- **ROM:** Записывается при производстве
- **PROM:** Программируется один раз
- **EPROM:** Стирается UV светом
- **EEPROM:** Электрически перезаписываемая

### 6.2 Flash память

**NAND Flash** — основа современных SSD и USB флешек.

**Принцип:** Floating gate transistors — электроны задерживаются в изолированном слое.

**Характеристики:**
- Неволатильная (сохраняет данные без питания)
- Ограниченное число циклов записи (~3000-100,000)
- Необходима "стирка" блоков перед записью

**SLC vs MLC vs TLC vs QLC:**
- SLC (Single-Level Cell): 1 бит на ячейку — быстро, надёжно, дорого
- MLC (Multi-Level Cell): 2 бита — баланс
- TLC (Triple-Level Cell): 3 бита — медленнее, дешевле
- QLC (Quad-Level Cell): 4 бита — самое медленное, самое дешёвое

### 6.3 SSD vs HDD

**SSD (Solid State Drive):**
- Нет движущихся частей
- Latency: ~50-100 μs
- Throughput: 3-7 GB/s (NVMe)
- Ограниченный ресурс записи
- Дорого за GB

**HDD (Hard Disk Drive):**
- Механический (диски, головки)
- Latency: ~5-10 ms (в 100 раз медленнее!)
- Throughput: 100-200 MB/s
- Практически неограниченный ресурс записи
- Дешёво за GB

**Применение:**
- SSD: OS, приложения, база данных
- HDD: архивы, backup, большие данные

## 7. Практические соображения

### 7.1 Cache-Friendly код

**Плохо (cache miss на каждом обращении):**
```c
// Обход двумерного массива не по порядку хранения
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += matrix[j][i];  // column-major обход row-major массива
```

**Хорошо (spatial locality):**
```c
// Обход по порядку хранения
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += matrix[i][j];  // последовательный доступ
```

Разница в производительности может быть 10x!

### 7.2 False Sharing

**Проблема:** Два потока модифицируют разные переменные, но они находятся в одной cache line.

```c
struct Counter {
    int count1;  // поток 1 модифицирует
    int count2;  // поток 2 модифицирует
};  // count1 и count2 в одной cache line → конфликт!
```

**Решение:** Cache line padding
```c
struct Counter {
    int count1;
    char padding[60];  // отделяем count1 и count2
    int count2;
};
```

### 7.3 Memory Alignment

Процессоры предпочитают данные, выровненные по своему размеру:
- 4-байтовый int → адрес кратен 4
- 8-байтовый double → адрес кратен 8

Невыровненный доступ:
- Медленнее (может требовать два обращения)
- На некоторых архитектурах — ошибка

Компиляторы автоматически выравнивают, но важно понимать при работе с низкоуровневым кодом.

## 💡 Key Takeaways

- **Иерархия памяти** существует из-за невозможности создать идеальную память — быструю, большую и дешёвую одновременно
- **Locality of Reference** (temporal и spatial) — фундаментальный принцип, позволяющий кэшам быть эффективными
- **Кэши** критичны для производительности — разница между L1 hit и RAM access — это сотни циклов
- **Виртуальная память** решает проблемы изоляции, защиты и позволяет программам не думать о физических адресах
- **Знание иерархии памяти** позволяет писать значительно более быстрый код, используя cache-friendly паттерны
