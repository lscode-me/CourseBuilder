## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Это фундаментальное физическое ограничение. Быстрая память (SRAM) требует больше транзисторов, занимает больше места и потребляет больше энергии. Невозможно создать память, которая была бы одновременно очень быстрой, очень большой и очень дешёвой. Иерархия памяти — это архитектурное решение этой проблемы. |
| 2 | A | **Temporal locality** — если данные использовались недавно, они вероятно понадобятся снова скоро. **Spatial locality** — если использовались данные по адресу X, вероятно понадобятся данные рядом (X+1, X+2...). Эти принципы наблюдаются в ~90% программ и объясняют, почему кэши с hit rate 95-99% вообще возможны. |
| 3 | C | L1 Cache находится ближе всего к ядру процессора, имеет доступ за 1-4 цикла и размер ~32-128 KB на ядро. L2 больше но медленнее, L3 ещё больше и медленнее, но shared между ядрами. TLB — это специализированный кэш для трансляции адресов, не общий кэш данных. |
| 4 | B | Cache line — это минимальная единица кэша. При cache miss загружается не один байт, а целая cache line (обычно 64 байта). Это использует spatial locality — если программа запросила байт X, вероятно скоро понадобятся X+1, X+2 и т.д. Это также означает, что две переменные в одной cache line могут вызывать false sharing в многопоточном коде. |
| 5 | C | **SRAM** (Static RAM): очень быстрая (~1 ns), дорогая, сложная (6 транзисторов на бит), используется в кэшах. **DRAM** (Dynamic RAM): медленнее (~50 ns), дешёвая, простая (1 транзистор + конденсатор), используется как основная память. Обе теряют данные при отключении питания (обе волатильные), но SRAM не требует refresh, а DRAM требует. |
| 6 | A | Процессор автоматически поддерживает когерентность кэша с помощью протоколов типа MESI (Modified, Exclusive, Shared, Invalid). Эти протоколы отслеживают состояние каждой cache line и синхронизируют изменения между ядрами прозрачно для программ. Это происходит на аппаратном уровне. |
| 7 | C | Виртуальная память решает несколько задач: 1. Изоляция процессов — каждый процесс видит своё адресное пространство. 2. Защита памяти — процессы не могут обращаться к чужой памяти. 3. Абстракция — программы работают с виртуальными адресами, не думая о физическом размещении. 4. Возможность использовать disk как расширение RAM (swap). Виртуальная память не ускоряет доступ (наоборот, добавляет overhead трансляции), но критична для безопасности и удобства разработки. |
| 8 | B | Page Fault происходит, когда программа обращается к виртуальной странице, которая в данный момент не загружена в физическую память. Операционная система: 1. Находит страницу на диске (swap). 2. Загружает её в RAM. 3. Обновляет Page Table. 4. Возобновляет выполнение программы. Это нормальное явление, прозрачное для программы, но медленное (~10 ms). |
| 9 | B | Без TLB каждый доступ к памяти требовал бы чтения Page Table (тоже в памяти), удваивая число обращений к памяти. TLB — это специализированный кэш для недавних трансляций адресов. С типичным hit rate ~99%, TLB делает виртуальную память приемлемо быстрой. При TLB miss процессор обращается к Page Table. |
| 10 | B | DDR (Double Data Rate) означает, что передача данных происходит и по переднему, и по заднему фронту тактового сигнала — два transfer на такт вместо одного (как в SDR — Single Data Rate). Это позволило удвоить пропускную способность без увеличения тактовой частоты. DDR2, DDR3, DDR4, DDR5 — это последующие поколения с дальнейшими улучшениями. |
| 11 | B | При cache miss в L1, процессор автоматически проверяет следующий уровень иерархии: L2 кэш → L3 кэш → RAM → (при необходимости) swap на диске. Это называется "cache hierarchy walk". Каждый уровень медленнее предыдущего, но всё происходит автоматически и прозрачно для программы. |
| 12 | D | Большие страницы (2 MB или 1 GB вместо стандартных 4 KB) означают: 1. Меньше записей в Page Table → меньше overhead. 2. Меньше записей нужно в TLB для покрытия того же объёма памяти → меньше TLB misses. 3. Меньше Page Faults. Используются для баз данных, виртуализации, HPC — приложений с большим working set'ом. Trade-off: больше внутренней фрагментации. |
| 13 | B | NAND Flash память неволатильна (сохраняет данные без питания), но имеет ограниченное число циклов записи/стирания — от ~3,000 (QLC) до ~100,000 (SLC) циклов на ячейку. После этого ячейка изнашивается. Контроллеры SSD используют wear leveling для равномерного распределения записей. Это не критично для большинства пользователей, но важно для write-intensive приложений. |
| 14 | C | В C массивы хранятся row-major (последовательно по строкам). `array[i][j]` означает последовательный доступ к памяти — высокая spatial locality, cache lines используются эффективно. `array[j][i]` прыгает по памяти — каждый доступ может быть в новой cache line, множество cache misses. Разница в производительности может быть 5-10x! |
| 15 | C | False Sharing происходит, когда два потока на разных ядрах модифицируют разные переменные, но эти переменные находятся в одной cache line (64 байта). Каждое изменение вызывает инвалидацию cache line на другом ядре, хотя потоки логически не разделяют данные. Решение — cache line padding (отступы), чтобы переменные оказались в разных cache lines. |
| 16 | A | "Memory Wall" — это проблема, впервые описанная в 1995 году: процессоры становятся быстрее намного быстрее, чем память. Современный процессор за время одного доступа к RAM может выполнить сотни инструкций. Это делает кэши критически важными и означает, что многие программы ограничены не скоростью вычислений, а скоростью доступа к памяти (memory-bound). |
| 17 | B | SSD latency: ~50-100 μs (микросекунды). HDD latency: ~5-10 ms (миллисекунды) = 5000-10000 μs. HDD медленнее примерно в 100 раз из-за механических движений (вращение дисков, позиционирование головок). Для sequential throughput разница меньше (~30x), но для random I/O SSD выигрывают радикально. |
| 18 | A | **ROM**: записывается при производстве, нельзя изменить. **PROM**: программируется один раз специальным устройством. **EPROM**: стирается ультрафиолетовым светом (нужно извлечь). **EEPROM**: стирается и перезаписывается электрически, можно обновлять на месте. Flash память — это разновидность EEPROM, оптимизированная для больших объёмов. |
| 19 | C | L3 Cache — это общий (shared) кэш для всех ядер процессора, в отличие от L1 и L2, которые private (отдельные для каждого ядра). Это позволяет ядрам обмениваться данными через L3 быстрее, чем через RAM. Размер L3: ~4-32 MB на весь чип. Latency: ~40-75 циклов. |
| 20 | A | Процессоры предпочитают (а некоторые требуют), чтобы данные были выровнены по своему размеру: 4-byte int → адрес кратен 4, 8-byte double → адрес кратен 8. Невыровненный доступ может: 1. Требовать два обращения к памяти вместо одного. 2. Пересекать границы cache line. 3. На некоторых архитектурах (RISC) вызывать hardware exception. Компиляторы автоматически выравнивают, добавляя padding. |

## Scoring Guide

- **18-20 правильных ответов:** Отлично! Вы глубоко понимаете организацию памяти в компьютерах.

- **15-17 правильных ответов:** Хорошо! Основные концепции усвоены, стоит повторить детали.

- **12-14 правильных ответов:** Удовлетворительно. Рекомендуется перечитать лекцию, особенно разделы про кэши и виртуальную память.

- **Менее 12 правильных ответов:** Необходимо вернуться к материалу лекции и изучить его более тщательно.
