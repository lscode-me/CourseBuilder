## 1. Эмуляция vs виртуализация

### 1.1 Эмуляция

**Эмуляция** — полное воспроизведение поведения одной системы на другой.

**Характеристики:**

- Медленная работа (интерпретация каждой команды)
- Полная совместимость
- Используется для несовместимых систем

**Примеры:**

**Эмуляция игровых консолей:**
```python
# Упрощённый пример эмулятора
class GameBoyEmulator:
    def __init__(self):
        self.cpu = CPU()
        self.memory = Memory()
        self.display = Display()
    
    def load_rom(self, rom_data):
        self.memory.load(rom_data)
    
    def run(self):
        while True:
            # Интерпретация каждой команды
            instruction = self.memory.read(self.cpu.pc)
            self.cpu.execute(instruction)  # Медленно!
            self.display.update()
```

**Эмуляция архитектуры:**

- QEMU в режиме эмуляции (full emulation)
- Эмуляция ARM на x86
- Эмуляция старых систем

**Характеристики:**

- Медленная работа (интерпретация каждой команды)
- Полная совместимость (может эмулировать любую архитектуру)
- Используется для несовместимых систем

### 1.2 Виртуализация

**Виртуализация** — создание виртуальной версии ресурса (ОС, сервера, сети).

**Характеристики:**

- Более быстрая работа (прямое выполнение на процессоре)
- Изоляция виртуальных машин
- Эффективное использование ресурсов

**Типы:**

**Виртуализация на уровне ОС:**

- Контейнеры (Docker, LXC)
- Изоляция процессов
- Общее ядро ОС

**Виртуализация оборудования:**

- Полная виртуализация (KVM, VMware, Hyper-V)
- Паравиртуализация (Xen)
- Аппаратная виртуализация (Intel VT-x, AMD-V)

**Виртуализация приложений:**

- JVM, .NET CLR
- Изоляция на уровне приложений

**Пример: Виртуализация vs Эмуляция**

```

Эмуляция:
  Guest Instruction → Интерпретация → Host Instruction
  (медленно, каждая команда интерпретируется)

Виртуализация:
  Guest Instruction → Прямое выполнение на CPU
  (быстро, CPU выполняет напрямую)
```

## 2. JVM

### 2.1 Архитектура JVM

**JVM (Java Virtual Machine)** — виртуальная машина для выполнения Java байткода.

**Компоненты:**

- **Class Loader** — загрузка классов

- **Execution Engine** — выполнение байткода

- **Memory Area** — управление памятью

- **Native Method Interface** — интерфейс с нативным кодом

### 2.2 JIT компиляция

**JIT (Just-In-Time)** — компиляция байткода в машинный код во время выполнения.

**Преимущества:**

- Оптимизация на основе реального использования
- Быстрое выполнение после компиляции
- Адаптация к конкретной платформе

**Пример: JIT процесс**

```java

// Java код
public int hotMethod(int x) {
    return x * 2;
}

// Первые N вызовов: интерпретация байткода
// После N вызовов: JIT компилирует в нативный код
// Дальнейшие вызовы: выполнение нативного кода (быстро!)
```

**JIT оптимизации:**

- Inlining (встраивание методов)
- Dead code elimination
- Loop optimization
- Profile-guided optimization

## 3. Hypervisor

### 3.1 Концепция hypervisor

**Hypervisor (виртуальный монитор)** — программное обеспечение, создающее и управляющее виртуальными машинами.

**Типы:**

- **Type 1 (bare-metal)** — работает напрямую на железе

- **Type 2 (hosted)** — работает поверх ОС

### 3.2 Преимущества виртуализации

**Изоляция:**

- Виртуальные машины изолированы друг от друга
- Сбой одной VM не влияет на другие

**Пример: Изоляция VM**

```

Physical Server
├── VM 1 (Linux)     - изолирована
├── VM 2 (Windows)   - изолирована
└── VM 3 (BSD)       - изолирована

Каждая VM имеет:

- Собственное адресное пространство
- Собственные ресурсы
- Собственную ОС
```

**Эффективность:**

- Лучшее использование ресурсов
- Консолидация серверов

**Пример: Консолидация**

```

Без виртуализации:
  Server 1: 10% использования
  Server 2: 15% использования
  Server 3: 20% использования
  (45% общее использование, много простоя)

С виртуализацией:
  Один физический сервер с 3 VM
  (лучшее использование ресурсов)
```

**Гибкость:**

- Легкое создание и удаление VM
- Миграция между физическими серверами

**Пример: Live Migration**

```bash
# Миграция VM без остановки

virsh migrate --live vm1 qemu+ssh://otherhost/system

# VM продолжает работать во время миграции
```

### 3.3 Type 1 vs Type 2 Hypervisor

**Type 1 (Bare-metal):**
```

Hardware
    ↓
Hypervisor (KVM, VMware ESXi, Hyper-V)
    ↓
VM 1    VM 2    VM 3
```

**Преимущества:**

- Меньше overhead
- Лучшая производительность
- Используется в дата-центрах

**Type 2 (Hosted):**
```

Hardware
    ↓
Host OS (Linux, Windows, macOS)
    ↓
Hypervisor (VirtualBox, VMware Workstation)
    ↓
VM 1    VM 2
```

**Преимущества:**

- Проще установка
- Удобно для разработки
- Меньше производительность

## 4. Контейнеры

### 4.1 Концепция контейнеров

**Контейнеры** — изоляция приложений на уровне ОС.

**Отличия от виртуализации:**

- Нет отдельной ОС для каждого контейнера
- Используют ядро хоста
- Легче и быстрее VM

**Преимущества:**

- Меньше накладных расходов
- Быстрый запуск
- Эффективное использование ресурсов

### 4.2 Docker и контейнеризация

**Docker** — платформа для контейнеризации.

**Особенности:**

- Легкое создание и распространение контейнеров
- Изоляция приложений
- Портативность

### 4.3 Unikernels и специализированные абстракции

**Unikernels:**

- Минимальные образы, содержащие только необходимое для приложения
- Нет полноценной ОС — только библиотеки и приложение
- Меньший размер, быстрый запуск, повышенная безопасность
- Компромисс между контейнерами и виртуализацией

**WebAssembly (WASM):**

- Портативный байткод для веб и не только
- Безопасное выполнение кода
- Работа в браузере и вне его
- Новый уровень абстракции для веб-приложений

**Пример: WASM использование**

```rust

// Rust → WASM
#[no_mangle]
pub extern "C" fn add(a: i32, b: i32) -> i32 {
    a + b
}

// Компиляция
// wasm-pack build

// Использование в браузере
// <script type="module">
//   import init, { add } from './pkg/my_module.js';
//   await init();
//   console.log(add(2, 3)); // 5
// </script>
```

**WASM как абстракция:**

- Безопасное выполнение кода (sandbox)
- Близко к нативной производительности
- Портативность (один WASM везде)

## 5. Абстракции как инструмент масштабирования

### 5.1 Уровни абстракции

**Иерархия:**
```

Приложения
    ↓
Контейнеры / VM
    ↓
Операционная система
    ↓
Hypervisor (для VM)
    ↓
Аппаратура
```

### 5.2 Масштабирование через абстракции

**Горизонтальное масштабирование:**

- Легкое создание новых экземпляров
- Распределение нагрузки
- Высокая доступность

**Вертикальное масштабирование:**

- Изменение ресурсов VM/контейнера
- Без изменения приложения

## 6. Сравнение подходов

### 6.1 VM vs Контейнеры vs Unikernels

| Аспект | VM | Контейнеры | Unikernels |
|--------|----|-----------|------------|
| Изоляция | Полная (отдельная ОС) | Процессная (namespaces) | Полная |
| Overhead | Высокий | Низкий | Очень низкий |
| Размер | Большой (GB) | Средний (MB) | Маленький (MB) |
| Запуск | Медленный (секунды) | Быстрый (миллисекунды) | Очень быстрый |
| Безопасность | Высокая | Средняя | Высокая |
| Использование | Полная виртуализация | Разработка, микросервисы | Специализированные задачи |

### 6.2 Выбор подхода

**VM когда:**

- Нужна полная изоляция
- Разные ОС на одном железе
- Критичная безопасность

**Контейнеры когда:**

- Микросервисы
- Быстрое развёртывание
- Эффективное использование ресурсов

**Unikernels когда:**

- Специализированные задачи
- Минимальный размер
- Максимальная производительность

## 💡 Key Takeaways

- **Эмуляция и виртуализация** — разные подходы: эмуляция (полное воспроизведение, медленно), виртуализация (прямое выполнение, быстро)

- **JVM** обеспечивает переносимость (один байткод везде) и производительность через JIT компиляцию (оптимизация на основе runtime данных)

- **Hypervisor** (Type 1/Type 2) позволяет эффективно использовать ресурсы через виртуализацию, изоляцию VM, консолидацию серверов

- **Контейнеры** обеспечивают изоляцию с меньшими накладными расходами (используют ядро хоста, namespaces, cgroups), быстрый запуск, эффективное использование ресурсов

- **Unikernels и WASM** представляют новые уровни абстракции для специализированных сценариев (минимальный размер, безопасность, производительность)

- **Абстракции** критически важны для масштабирования систем (легкое создание экземпляров, распределение нагрузки, горизонтальное масштабирование)
