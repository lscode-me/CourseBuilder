## 1. Solaris и SPARC

### 1.1 Создание Solaris

К концу 1980-х годов стало очевидно, что корпоративному рынку нужна операционная система, способная обрабатывать критически важные задачи с максимальной надёжностью. UNIX был хорош, но требовал доработок для работы на крупных серверах с сотнями пользователей и терабайтами данных. Sun Microsystems решила создать систему, которая объединит стабильность UNIX с инновационными технологиями для корпоративного мира.

**Solaris** — операционная система от Sun Microsystems (теперь Oracle), основанная на UNIX System V. Это была не просто ещё одна версия UNIX, а комплексное решение, спроектированное для работы на серверах следующего поколения.

**История и причины создания:**

- **Разработана для процессоров SPARC** — это было революционным подходом. Вместо того чтобы адаптировать систему под разные архитектуры, Sun создала интегрированное решение "железо + программное обеспечение", где каждый компонент оптимизирован для другого.

- **Оптимизирована для серверных задач** — в отличие от настольных систем, серверы должны работать годами без перезагрузки, обслуживать тысячи одновременных соединений и обрабатывать критически важные данные. Solaris проектировалась именно для этого.

- **Высокая надёжность и масштабируемость** — система могла работать на серверах с десятками процессоров и сотнями гигабайт памяти, что было фантастикой для того времени. Это означало, что крупные компании могли консолидировать свою инфраструктуру на меньшем количестве машин.

**Особенности, изменившие индустрию:**

**ZFS** — продвинутая файловая система

**Пример: ZFS команды**

```bash
# Создание ZFS pool
zpool create tank mirror /dev/sda /dev/sdb

# Создание файловой системы
zfs create tank/documents

# Создание snapshot
zfs snapshot tank/documents@backup1

# Клонирование snapshot
zfs clone tank/documents@backup1 tank/documents-clone

# Проверка целостности
zfs scrub tank

# Информация о pool
zpool status tank
zfs list
```

**DTrace** — инструмент динамической трассировки

**Пример: DTrace скрипт**

```dtrace
#!/usr/sbin/dtrace -s

syscall:::entry
{
    @[execname] = count();
}

END
{
    printa("System calls by process: %s = %@d\n", @);
}
```

**Контейнеры** — ранняя реализация контейнеризации (zones)

**Пример: Solaris Zones**

```bash
# Создание zone
zonecfg -z myzone
zonecfg:myzone> create
zonecfg:myzone> set zonepath=/zones/myzone
zonecfg:myzone> set autoboot=true
zonecfg:myzone> commit
zonecfg:myzone> exit

# Установка zone
zoneadm -z myzone install

# Запуск zone
zoneadm -z myzone boot
```

**Масштабируемость** — поддержка больших систем

### 1.2 Связь с SPARC

Одной из ключевых причин успеха Solaris была её глубокая интеграция с архитектурой SPARC. Это был пример software-hardware co-design — когда операционная система и процессор проектируются вместе, учитывая возможности друг друга. Такой подход позволял достичь производительности, недоступной системам общего назначения.

**Интеграция на глубоком уровне:**

- **Solaris оптимизирована для архитектуры SPARC** — это означало, что каждая системная операция, от переключения контекста до управления памятью, использовала уникальные возможности SPARC. Код ядра писался с учётом особенностей процессора, что было критически важно для достижения максимальной производительности.

- **Использование особенностей SPARC (регистровые окна)** — SPARC имел уникальную систему регистровых окон, которая делала вызовы функций невероятно быстрыми. Solaris использовала это для минимизации накладных расходов на системные вызовы, что давало огромное преимущество при обработке тысяч запросов в секунду.

- **Высокая производительность на SPARC системах** — комбинация оптимизированной ОС и специализированного железа давала производительность, которую невозможно было достичь на системах x86 того времени. Это было революционным преимуществом для корпоративных клиентов.

**Результат:**
Создание интегрированных решений "железо + ОС" для серверов. Это означало, что компании покупали не просто сервер, а комплексную экосистему, где каждый компонент был оптимизирован для работы с другими. Такой подход доминировал в серверном мире до появления дешёвых x86 серверов.

### 1.3 Современное состояние

**OpenSolaris → illumos:**

- Solaris стала открытой (OpenSolaris)
- Развитие продолжается в проекте illumos
- Используется в специализированных системах

## 2. BSD-системы

### 2.1 Происхождение BSD

В то время как AT&T развивала коммерческий UNIX, в академической среде происходила параллельная революция. Калифорнийский университет в Беркли получил исходный код UNIX и начал его улучшать, добавляя функции, которые были нужны исследователям и студентам. Это было фундаментально важно: впервые операционная система развивалась не корпорацией, а академическим сообществом, что определило её открытый характер.

**BSD (Berkeley Software Distribution)** — вариант UNIX, разработанный в Калифорнийском университете в Беркли. Название отражает суть: это была "дистрибуция" — набор улучшений и дополнений к оригинальному UNIX, которые распространялись бесплатно среди университетов.

**История и эволюция:**

- **Начало в 1970-х годах** — студенты и преподаватели Беркли начали добавлять функции в UNIX, которых не хватало для их исследований. Это была эпоха, когда исходный код был доступен, и люди могли свободно экспериментировать. Такая открытость была критически важна для инноваций.

- **Добавления к оригинальному UNIX** — BSD не просто копировала UNIX, она добавляла революционные возможности. Многие улучшения были настолько значительными, что позже вошли в коммерческие версии UNIX. Это было доказательством того, что академическая среда может создавать технологии уровня индустрии.

- **Развитие сетевых возможностей** — это было самым важным вкладом BSD. В конце 1970-х годов сети только зарождались, и BSD стала лабораторией для экспериментов с сетевыми протоколами. Здесь родились идеи, которые позже легли в основу всего интернета.

**Вклад, изменивший мир:**

**TCP/IP стек:**
```c

// BSD sockets API (стал стандартом)
#include <sys/socket.h>
#include <netinet/in.h>

// Создание TCP socket
int sockfd = socket(AF_INET, SOCK_STREAM, 0);

struct sockaddr_in addr;
addr.sin_family = AF_INET;
addr.sin_port = htons(80);
inet_aton("192.168.1.1", &addr.sin_addr);

connect(sockfd, (struct sockaddr*)&addr, sizeof(addr));
```

**Виртуальная память:**

- Demand paging
- Memory mapping
- Swap space

**Файловая система FFS (Fast File System):**

- Улучшения над оригинальной файловой системой UNIX
- Цилиндрические группы
- Лучшая производительность

**Множество утилит:**

- vi, csh, tcsh
- Сетевые утилиты (ping, traceroute)
- Системные утилиты

### 2.2 Варианты BSD

**FreeBSD:**

- Фокус на производительности
- Широкое использование в серверах
- Основа для многих систем

**Пример: FreeBSD особенности**

```bash
# Ports system для установки ПО
cd /usr/ports/www/nginx
make install clean

# Jail (контейнеры)
jail -c name=myjail path=/jails/myjail \
     command=/bin/sh

# ZFS поддержка

zpool create tank /dev/ada0
```

**OpenBSD:**

- Фокус на безопасности
- Аудит безопасности кода
- Используется в критичных системах

**Пример: OpenBSD security features**

```bash
# W^X (Write XOR Execute) - страницы либо writable, либо executable
# ASLR (Address Space Layout Randomization)
# Stack canaries
# Privilege separation

# Проверка безопасности

auditd  # Security audit daemon
```

**NetBSD:**

- Фокус на переносимости
- Работает на множестве платформ
- Встроенные системы

**Поддерживаемые платформы:**

- x86, ARM, MIPS, PowerPC, SPARC, Alpha
- Embedded systems
- Рекордное количество платформ

**macOS:**

- Основан на BSD (Darwin)
- Показывает успех BSD в настольных системах

**Пример: macOS BSD команды**

```bash
# macOS использует BSD версии утилит

ps aux    # BSD формат (не System V)
ls -l     # BSD ls
```

### 2.3 BSD vs Linux

**Различия:**
| Аспект | BSD | Linux |
|--------|-----|-------|
| Лицензия | BSD (свободная) | GPL (copyleft) |
| Kernel + Userland | Единая система | Kernel + разные дистрибутивы |
| Происхождение | Прямой потомок UNIX | Клон UNIX |
| Инициализация | BSD init | systemd/sysvinit |
| Производительность | Высокая | Высокая |

### 2.3 Лицензия BSD

**Особенности:**

- Более свободная, чем GPL
- Позволяет использование в проприетарном ПО
- Способствовала распространению

## 3. Надёжность и масштабируемость

### 3.1 Требования корпоративных систем

**Надёжность:**

- Минимальное время простоя
- Отказоустойчивость
- Восстановление после сбоев

**Масштабируемость:**

- Поддержка большого количества пользователей
- Обработка больших объёмов данных
- Горизонтальное и вертикальное масштабирование

**Производительность:**

- Высокая пропускная способность
- Низкая задержка
- Эффективное использование ресурсов

### 3.2 Технологии надёжности

**RAID:**

- Избыточное хранение данных
- Защита от отказов дисков

**Пример: RAID в Solaris**

```bash
# Solaris Volume Manager
metainit d10 1 1 c0t0d0s0
metainit d20 1 1 c0t1d0s0
metainit d0 -m d10
metattach d0 d20  # Mirror
```

**Кластеризация:**

- Несколько серверов работают вместе
- Высокая доступность

**Пример: Solaris Cluster**

```bash
# Высокая доступность через кластеризацию
# Автоматический failover при отказе узла
# Shared storage между узлами

```

**Резервное копирование:**

- Регулярные бэкапы
- Восстановление данных

**Пример: ZFS snapshots для backup**

```bash
# Автоматические snapshots
zfs set snapdir=visible tank/documents
zfs snapshot -r tank/documents@$(date +%Y%m%d)

# Отправка snapshots на удалённый сервер

zfs send tank/documents@snapshot1 | \
    ssh remote zfs receive tank/backup
```

### 3.3 Мониторинг и обслуживание

**Пример: Мониторинг системы**

```bash
# Solaris prstat (аналог top)
prstat -a

# iostat для I/O статистики
iostat -xn 1

# DTrace для детального анализа

dtrace -n 'syscall:::entry { @[execname] = count(); }'
```

- Больше процессоров, памяти

**Горизонтальное масштабирование:**

## 4. Серверный мир 90-х и 2000-х

### 4.1 Доминирование UNIX

**1990-е:**

- UNIX доминировал в серверном мире
- Различные варианты: Solaris, AIX, HP-UX, BSD
- Высокая стоимость, но необходимая надёжность

**Применение:**

- Корпоративные серверы
- Базы данных
- Веб-серверы (ранний интернет)
- Файловые серверы

### 4.2 Конкуренция

**Linux:**

- Появление Linux в 1990-х
- Бесплатная альтернатива
- Рост популярности

**Windows NT Server:**

- Конкуренция от Microsoft
- Упрощённое администрирование
- Интеграция с Windows клиентами

**Результат:**
Трёхсторонняя конкуренция: проприетарный UNIX, Linux, Windows Server.

### 4.3 Изменения в 2000-х

**Консолидация:**

- Меньше вариантов проприетарного UNIX
- Доминирование Linux и Windows Server
- Облачные вычисления

**Наследие:**
Идеи и технологии из корпоративного UNIX перешли в Linux и современные системы.

## 5. Современное состояние

### 5.1 illumos и OpenSolaris наследие

**illumos:**

- Форк OpenSolaris после закрытия Oracle
- Развитие ZFS, DTrace
- Используется в специализированных системах

**Примеры использования:**

- OmniOS, SmartOS
- Joyent Triton (cloud platform)
- Nexenta (storage systems)

### 5.2 BSD в современности

**FreeBSD:**

- Используется в Netflix (CDN)
- PlayStation 4 (основана на FreeBSD)
- Множество серверов

**OpenBSD:**

- OpenSSH (используется везде)
- pf firewall (портирован в другие системы)
- Критичные системы безопасности

**NetBSD:**

- Embedded systems
- Портативные устройства
- Специализированные платформы

## 💡 Key Takeaways

- **Solaris** показала важность интеграции ОС и аппаратуры (SPARC) для серверных систем, создала технологии (ZFS, DTrace, zones), которые повлияли на современные системы

- **BSD** внесла огромный вклад в развитие UNIX (TCP/IP, виртуальная память, FFS) и сетевых технологий, более свободная лицензия способствовала распространению

- **Надёжность и масштабируемость** — ключевые требования корпоративных систем (RAID, кластеризация, резервное копирование, вертикальное и горизонтальное масштабирование)

- **Серверный мир 90-2000-х** был эпохой доминирования UNIX (Solaris, AIX, HP-UX, BSD), которая сформировала современные подходы, многие идеи перешли в Linux и современные системы
