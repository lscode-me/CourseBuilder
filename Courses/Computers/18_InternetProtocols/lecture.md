## 1. TCP/IP

### 1.1 Стек протоколов TCP/IP

Когда ARPANET начала расти, стало ясно, что нужна единая система правил для общения компьютеров разных типов. В 1970-х Винтон Серф и Роберт Кан разработали TCP/IP — набор протоколов, который стал языком интернета. Это было революционное решение, основанное на принципе многоуровневой абстракции: разделить сложную задачу сетевого взаимодействия на независимые слои, каждый из которых решает свою чётко определённую задачу.

**TCP/IP** — это набор протоколов, лежащих в основе интернета и определяющих, как данные упаковываются, адресуются, передаются, маршрутизируются и принимаются. Без TCP/IP не было бы современного интернета — эти протоколы являются его фундаментом, критически важным для работы всех сетевых приложений.

**Уровни:**

- **Application** — приложения (HTTP, FTP, SMTP). На этом уровне работают программы, с которыми взаимодействуют пользователи: браузеры, почтовые клиенты, мессенджеры. Каждое приложение использует свой протокол, но все они опираются на нижележащие уровни. Это разделение было революционным: разработчики приложений могут не думать о деталях передачи данных.

- **Transport** — TCP, UDP. Этот уровень отвечает за надёжность и порядок доставки данных. TCP гарантирует, что данные придут полностью и в правильном порядке, что критически важно для веб-страниц и электронной почты. UDP жертвует надёжностью ради скорости, что необходимо для видеозвонков и онлайн-игр.

- **Internet** — IP. Этот уровень решает задачу маршрутизации: как доставить пакет данных через множество промежуточных узлов от отправителя к получателю. IP-адреса уникально идентифицируют каждое устройство в интернете, что было критически важно для создания глобальной сети.

- **Link** — Ethernet, Wi-Fi. Самый нижний уровень отвечает за физическую передачу данных по конкретной среде (медный кабель, оптоволокно, радиоволны). Верхние уровни не знают и не должны знать, используется ли Ethernet или Wi-Fi.

**Принцип:**
Каждый уровень решает свои задачи, не зная деталей других уровней. Это инкапсуляция — фундаментальный принцип, который делает систему модульной и гибкой. Можно заменить Wi-Fi на Ethernet, и всё продолжит работать. Можно изменить протокол приложения с HTTP на HTTP/2, и нижележащие уровни этого не заметят. Эта абстракция была революционной идеей, позволившей интернету эволюционировать и масштабироваться.

### 1.2 IP (Internet Protocol)

Представьте мир, где у каждого дома нет адреса — только название. Как бы работала почта? Именно эту проблему решает IP для компьютеров. Когда интернет только зарождался, было несколько десятков компьютеров, и их можно было идентифицировать по именам. Но для создания глобальной сети нужна была универсальная система адресации, которая работала бы для миллионов устройств.

**IP адресация:**

- **Уникальный адрес для каждого устройства** — это фундаментальное требование. IP-адрес — это числовой идентификатор, который должен быть уникален в пределах сети (или всего интернета для публичных адресов). Без уникальности невозможно было бы доставить пакет данных нужному получателю. Это было критически важно для масштабирования сети.

- **IPv4: 32 бита (4 миллиарда адресов)** — казалось, что 4 миллиарда адресов — это более чем достаточно. В 1980-х никто не мог представить, что у каждого человека будет несколько подключённых к интернету устройств. Сегодня мы исчерпали адресное пространство IPv4, что привело к необходимости технологий NAT (трансляция сетевых адресов) и перехода на IPv6.

- **IPv6: 128 бит (практически неограниченное количество)** — это было революционное решение проблемы исчерпания адресов. 2^128 адресов — это примерно 340 ундециллионов (число с 36 нулями). Этого хватит, чтобы дать уникальный адрес каждому атому на поверхности Земли и ещё останется. IPv6 также улучшил безопасность и упростил конфигурацию сети.

**Маршрутизация:**

- **Пакеты направляются от источника к получателю** — в отличие от телефонных сетей, где устанавливается выделенное соединение на всё время разговора, IP работает по принципу коммутации пакетов. Каждый пакет независимо находит путь к получателю, что делает сеть устойчивой к сбоям отдельных узлов. Это было критически важно для военного применения ARPANET.

- **Каждый узел решает, куда направить пакет дальше** — маршрутизаторы анализируют IP-адрес получателя и таблицы маршрутизации, чтобы определить следующий "прыжок" (hop) на пути к цели. Эта децентрализованная система принятия решений позволяет интернету работать без единого центра управления, что было революционным архитектурным решением.

### 1.3 TCP (Transmission Control Protocol)

**Особенности:**

- Надёжная доставка данных
- Установление соединения
- Контроль потока
- Упорядочивание пакетов

**UDP (User Datagram Protocol):**

- Ненадёжная доставка
- Быстрее TCP
- Для приложений, где скорость важнее надёжности

**Пример: TCP vs UDP**

```c

// TCP — надёжная доставка
int tcp_socket = socket(AF_INET, SOCK_STREAM, 0);
// Установление соединения (3-way handshake)
connect(tcp_socket, ...);
// Гарантированная доставка, порядок пакетов
send(tcp_socket, data, len, 0);

// UDP — быстрая доставка
int udp_socket = socket(AF_INET, SOCK_DGRAM, 0);
// Нет установления соединения
// Нет гарантии доставки, порядок не гарантирован
sendto(udp_socket, data, len, 0, ...);
```

**TCP 3-way handshake:**
```

Client                    Server
  |                         |
  |---- SYN ---------------->|
  |                         |
  |<--- SYN-ACK ------------|
  |                         |
  |---- ACK ---------------->|
  |                         |
  |    Соединение установлено
```

**Применение:**

- TCP: веб (HTTP), почта (SMTP), файлы (FTP)
- UDP: DNS запросы, видео стриминг, игры (низкая latency)

## 2. DNS

### 2.1 Система доменных имён

**DNS (Domain Name System)** — система преобразования доменных имён в IP адреса.

**Проблема:**
Людям легче запомнить `google.com`, чем `142.250.185.14`.

**Решение:**
DNS преобразует доменные имена в IP адреса.

### 2.2 Иерархия DNS

**Структура:**
```

. (корень)
├── com
│   └── google
│       └── www
├── org
└── ru
```

**Процесс запроса:**

1. Запрос к локальному DNS серверу
2. Если нет — запрос к корневому серверу
3. Направление к соответствующему домену
4. Получение IP адреса

### 2.3 Важность DNS

**Критичность:**

- Без DNS интернет практически не работает
- Атаки на DNS могут парализовать сеть
- Распределённая система для надёжности

## 3. HTTP

### 3.1 Протокол HTTP

**HTTP (HyperText Transfer Protocol)** — протокол для передачи веб-страниц.

**Принцип:**

- Клиент отправляет запрос
- Сервер отправляет ответ
- Статус-коды (200 OK, 404 Not Found, etc.)

### 3.2 Эволюция HTTP

**HTTP/1.0:**

- Одно соединение на запрос
- Медленно для современных сайтов

**HTTP/1.1:**

- Постоянные соединения
- Кеширование
- Сжатие

**HTTP/2:**

- Мультиплексирование
- Приоритизация
- Сжатие заголовков

**HTTP/3:**

- На основе UDP (QUIC)
- Быстрое установление соединения
- Лучшая работа при потере пакетов

**Пример: HTTP запрос**

```http

GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html

(пустая строка)
```

**Пример: HTTP ответ**

```http

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234

<html>...</html>
```

**Пример: HTTP клиент (Python)**

```python

import requests

# HTTP/1.1 запрос
response = requests.get('https://example.com')
print(response.status_code)  # 200
print(response.text)         # HTML содержимое
```

**HTTP/2 мультиплексирование:**
```

HTTP/1.1: Один запрос на соединение
  Request 1 ──┐
  Request 2 ──┤── Connection ── Server
  Request 3 ──┘  (последовательно)

HTTP/2: Множество запросов параллельно
  Request 1 ──┐
  Request 2 ──┼── Connection ── Server
  Request 3 ──┘  (параллельно, мультиплексирование)
```

**QUIC преимущества:**

- Быстрое установление соединения (0-RTT для повторных соединений)
- Встроенное шифрование (TLS 1.3)
- Лучшая работа при потере пакетов (не блокирует другие потоки)

## 5. Как сети изменили вычисления

### 5.1 Распределённые вычисления

**Возможности:**

- Вычисления на удалённых серверах
- Доступ к данным из любого места
- Совместная работа

### 5.2 Облачные вычисления

**Модели:**

- **IaaS** — инфраструктура как услуга

- **PaaS** — платформа как услуга

- **SaaS** — программное обеспечение как услуга

**Преимущества:**

- Масштабируемость
- Гибкость
- Снижение затрат

### 5.3 Новые парадигмы

**Изменения:**

- От локальных приложений к веб-приложениям
- От покупки ПО к подписке
- От локального хранения к облачному

**Пример: Веб-приложение**

```javascript

// Современное веб-приложение (SPA)
// Работает в браузере, данные с сервера
fetch('/api/data')
  .then(response => response.json())
  .then(data => {
    // Обновление UI без перезагрузки страницы
    updateUI(data);
  });
```

**Пример: Облачное хранилище**

```python
# Загрузка в облако
import boto3

s3 = boto3.client('s3')
s3.upload_file('local_file.txt', 'my-bucket', 'remote_file.txt')

# Доступ из любого места

s3.download_file('my-bucket', 'remote_file.txt', 'local_file.txt')
```

## 6. Безопасность в интернете

### 6.1 HTTPS и TLS

**HTTPS (HTTP Secure):**

- Шифрование данных
- Аутентификация сервера
- Защита от перехвата

**TLS (Transport Layer Security):**
```

HTTP (незашифрованный)
    ↓
TLS Handshake (установление безопасного соединения)
    ↓
HTTPS (зашифрованный HTTP)
```

**Пример: HTTPS**

```python

import requests

# HTTPS автоматически использует TLS

response = requests.get('https://example.com')
# Данные зашифрованы при передаче

```

### 6.2 Сетевая безопасность

**Угрозы:**

- Перехват пакетов (sniffing)
- Man-in-the-Middle атаки
- DDoS атаки

**Защита:**

- Шифрование (TLS/SSL)
- Firewall
- IDS/IPS (Intrusion Detection/Prevention Systems)

## 💡 Key Takeaways

- **TCP/IP** обеспечивает надёжную передачу данных в интернете через многоуровневую архитектуру (Application, Transport, Internet, Link), каждый уровень решает свои задачи

- **DNS** критически важен для работы интернета, преобразуя доменные имена в IP адреса через иерархическую систему, без DNS интернет практически не работает

- **HTTP** эволюционировал от простого протокола (HTTP/1.0) к сложной системе (HTTP/1.1 persistent connections, HTTP/2 multiplexing, HTTP/3 QUIC), оптимизированной для современных веб-приложений

- **Интернет стал платформой** для вычислений, изменив способ разработки (веб-приложения) и использования приложений (облачные сервисы, SaaS)

- **Сети изменили вычисления** — от локальных к распределённым, от покупки ПО к подписке (SaaS), от локального хранения к облачному, от standalone к постоянно подключённым устройствам
