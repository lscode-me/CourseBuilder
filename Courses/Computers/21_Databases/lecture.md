## 1. Реляционные БД

### 1.1 Концепция реляционной модели

**Реляционная база данных:**

- Данные организованы в таблицы (отношения)
- Связи между таблицами через ключи
- Структурированные данные

**Основные понятия:**

- **Таблица (Relation)** — набор строк и столбцов

- **Строка (Tuple)** — запись в таблице

- **Столбец (Attribute)** — поле данных

- **Ключ (Key)** — уникальный идентификатор

**Пример:**
```

Таблица Users:
id | name  | email
1  | Alice | alice@example.com
2  | Bob   | bob@example.com
```

### 1.2 SQL

**SQL (Structured Query Language)** — язык для работы с реляционными БД.

**Операции:**

- SELECT — выборка данных
- INSERT — вставка данных
- UPDATE — обновление данных
- DELETE — удаление данных

**Преимущества:**

- Стандартизированный язык
- Мощные возможности запросов
- Оптимизация запросов

## 2. ACID

### 2.1 Свойства транзакций

**ACID** — четыре свойства транзакций:

- **Atomicity (Атомарность)** — транзакция выполняется полностью или не выполняется вообще

- **Consistency (Согласованность)** — база данных остаётся в согласованном состоянии

- **Isolation (Изоляция)** — транзакции не мешают друг другу

- **Durability (Долговечность)** — изменения сохраняются после завершения транзакции

### 2.2 Важность ACID

**Гарантии:**

- Надёжность данных
- Предсказуемое поведение
- Защита от ошибок

**Пример:**
Перевод денег должен быть атомарным — либо оба счёта обновляются, либо ни один.

## 3. NoSQL

### 3.1 Ограничения реляционных БД

**Проблемы:**

- Сложность масштабирования
- Жёсткая схема
- Сложность для неструктурированных данных

### 3.2 Типы NoSQL

**Документные БД:**

- Хранение документов (JSON, XML)
- Гибкая схема
- Примеры: MongoDB, CouchDB

**Ключ-значение:**

- Простая структура
- Быстрый доступ
- Примеры: Redis, DynamoDB

**Колоночные:**

- Оптимизация для аналитики
- Примеры: Cassandra, HBase

**Графовые:**

- Хранение связей
- Примеры: Neo4j

---

## 4. OLTP vs OLAP

### 4.1 OLTP

**OLTP (Online Transaction Processing):**

- Обработка транзакций в реальном времени
- Много коротких транзакций
- Оптимизация для записи
- Примеры: банковские системы, интернет-магазины

**Характеристики:**

- Высокая доступность
- Быстрый отклик
- ACID гарантии

### 4.2 OLAP

**OLAP (Online Analytical Processing):**

- Аналитическая обработка данных
- Сложные запросы
- Оптимизация для чтения
- Примеры: системы бизнес-аналитики, хранилища данных

**Характеристики:**

- Агрегация данных
- Исторические данные
- Оптимизация для анализа

---

## 5. Почему БД — отдельный мир

### 5.1 Специализация

**Базы данных:**

- Специализированные системы
- Собственные алгоритмы и структуры данных
- Оптимизация для конкретных задач

**Отличия от файловых систем:**

- Транзакции
- Индексы
- Оптимизация запросов
- Управление конкурентным доступом

### 5.2 Важность

**Критичность:**

- Данные — основа приложений
- Потеря данных критична
- Производительность важна

**Результат:**
Базы данных развиваются как отдельная область со своими специалистами и технологиями.

## 💡 Key Takeaways

- **Реляционные БД** обеспечивают структурированное хранение данных через таблицы и связи

- **ACID свойства** гарантируют надёжность и предсказуемость транзакций

- **NoSQL** решает проблемы масштабирования и гибкости схемы для различных типов данных

- **OLTP и OLAP** — разные оптимизации для транзакций и аналитики

- **Базы данных — отдельный мир** со специализированными системами, алгоритмами и экспертизой
