## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Механика дисков (головки HDD) и структура SSD делают последовательную запись намного эффективнее |
| 2 | B | B-tree часто обновляет страницы целиком при изменении данных, вызывая Random I/O |
| 3 | A | Log-Structured Merge-tree |
| 4 | B | Данные всегда дописываются в конец (Append-only), избегая перезаписи |
| 5 | C | Memtable накапливает данные в RAM и сортирует их перед сбросом в SSTable |
| 6 | A | SSTable пишутся один раз и никогда не меняются, что упрощает конкурентный доступ |
| 7 | A | Compaction наводит порядок: сливает файлы, выбрасывает мусор и дубликаты |
| 8 | A | Вероятностная структура, позволяющая не читать файл с диска, если ключа там нет |
| 9 | A | Приходится проверять несколько уровней данных (Memtable + L0..Ln SSTables) |
| 10 | C | Данные в RAM ненадежны. WAL — это страховка на диске |
| 11 | C | Compaction многократно переписывает одни и те же данные при слиянии уровней |
| 12 | D | LSM идеально подходит для Write-Intensive нагрузок (Ingestion) |
| 13 | B | B-tree обеспечивает стабильное и быстрое чтение без накладных расходов на проверку уровней |
| 14 | C | До compaction на диске могут лежать запись "X=1" и "X=2" (старая). Это тратит место |
| 15 | B | Нужна структура, которая держит порядок и эффективна для вставки в памяти |
| 16 | D | Tombstone — это маркер "удалено". Физически данные исчезнут позже |
| 17 | C | Да, это Sorted String Table. Сортировка позволяет эффективно искать и сливать файлы |
| 18 | A | B-tree более предсказуемо для точечного чтения |
| 19 | D | Хотя SSD быстрее HDD на random write, write amplification SSD и износ ячеек делают последовательную запись предпочтительной |
