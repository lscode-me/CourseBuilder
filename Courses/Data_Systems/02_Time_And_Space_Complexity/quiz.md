## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | O(g(n)) означает, что f(n) ограничена сверху функцией g(n) с точностью до константы |
| 2 | C | При упрощении отбрасываем константы и младшие члены, оставляя доминирующий n² |
| 3 | A | Бинарный поиск делит массив пополам на каждом шаге — log n итераций |
| 4 | C | Вложенные циклы перемножаются: n × n = n² |
| 5 | A | Последовательные операции складываются: O(n) + O(n) = O(2n) = O(n) |
| 6 | C | Big-Ω описывает минимальную сложность — алгоритм работает не быстрее |
| 7 | B | Θ(g(n)) означает, что f(n) растёт точно как g(n) (верх и низ совпадают) |
| 8 | B | Худший случай даёт верхнюю границу — гарантию, что не будет медленнее |
| 9 | D | При плохом выборе pivot (уже отсортированный массив) — n² сравнений |
| 10 | B | Амортизация "размазывает" стоимость дорогих операций по всей последовательности |
| 11 | A | Расширение массива (O(n)) происходит логарифмически редко при удвоении |
| 12 | C | Входные данные обычно не считаются — анализируется дополнительная память |
| 13 | B | Каждый вызов добавляет кадр в стек — глубина n |
| 14 | C | Классический выбор: использовать больше памяти для ускорения |
| 15 | D | Хеширование даёт прямой доступ — O(1) в среднем |
| 16 | B | Merge sort делит на 2 (log n уровней) и сливает (n на уровень) |
| 17 | C | При n=10000 получаем 100M операций — заметная задержка |
| 18 | C | При n → ∞ константы становятся несущественными по сравнению с порядком роста |
| 19 | B | 2^30 ≈ 1 миллиард операций — на грани практичности |
| 20 | A | Теория даёт порядок роста, но реальная производительность зависит от констант и hardware |
