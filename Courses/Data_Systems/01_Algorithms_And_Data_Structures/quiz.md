| # | Answer | Explanation |
|---|--------|-------------|
| 1 | C | Оптимальность не обязательна — алгоритм может быть корректным, но не оптимальным |

| 3 | C | Эффективность алгоритма зависит от структуры данных, и выбор DS определяет доступные алгоритмы |
| 4 | A | set использует хеширование для O(1) поиска, list требует O(n) линейного обхода |
| 5 | C | Бинарный поиск делит массив пополам, что работает только для отсортированных данных |
| 6 | D | Инвариант — условие, сохраняющееся на всех итерациях цикла |
| 7 | A | Инварианты позволяют формально доказать, что алгоритм работает правильно |
| 8 | B | Это определяющее свойство BST, обеспечивающее эффективный поиск |
| 9 | A | Полная корректность = частичная корректность + гарантия завершения |
| 10 | A | Алгоритм рассчитывает на выполнение предусловия; при его нарушении результат не гарантирован |
| 11 | B | deque реализован как двусвязный список с O(1) операциями с обоих концов |
| 12 | C | При вставке в начало все элементы сдвигаются на одну позицию вправо |

| 18 | C | Реальные узкие места часто не там, где ожидает разработчик |
