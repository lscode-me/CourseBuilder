## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Интерактив vs Аналитика — фундаментальное разделение |
| 2 | C | Снижает I/O нагрузку на порядки при агрегациях |
| 3 | B | Redis идеален для быстрых, некритичных данных в памяти |
| 4 | A | Schema-less подход хорош для итеративной разработки |
| 5 | D | LSM-tree архитектура заточена под поглощение записи |
| 6 | C | Поиск подстроки требует сканирования, а обратный индекс — точечного доступа |
| 7 | D | Данные приходят потоком во времени, старые становятся неактуальными |
| 8 | B | Самая универсальная RDBMS с богатым функционалом |
| 9 | B | Не существует "серебряной пули", комбинируем инструменты |
| 10 | A | Графовые проходы эффективнее JOINs для глубоких связей |
| 11 | A | LSM-tree (Log Structured Merge Tree) не требует Random I/O при записи |
| 12 | A | Основа любого поискового движка |
| 13 | B | В распределенных системах "Read Local" быстрее, чем сборка данных по сети |
| 14 | C | Компромисс CAP теоремы и производительности |
| 15 | A | БД плохо переваривают большие бинарные файлы, S3 дешевле и масштабируемее |
| 16 | C | AP системы приоритезируют доступность (Shopping Cart не должна падать) |
| 17 | A | Quadtree делит карту на квадранты для быстрого поиска соседей |
| 18 | A | Resource contention. Аналитику лучше гонять на Read Replica или в DWH |
| 19 | B | Простой и надежный паттерн, загружающий в кеш только то, что реально нужно |
| 20 | D | Justification is key. "It depends" — правильный ответ, если за ним следует "depends on..." |

## Scoring Guide

- **18-20 правильных (90-100%)**: Отлично! Вы готовы к System Design интервью.

- **14-17 правильных (70-89%)**: Хорошо. Повторите типы NoSQL.

- **10-13 правильных (50-69%)**: Удовлетворительно. Разберитесь с OLTP vs OLAP.

- **Менее 10 правильных (< 50%)**: Нужно перечитать лекцию.
