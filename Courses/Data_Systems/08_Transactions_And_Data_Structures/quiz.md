## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Стандартный набор требований к транзакционным системам |
| 2 | C | WAL (Redo Log) позволяет восстановить данные после сбоя, гарантируя Durability |
| 3 | D | Write-Ahead Logging: сначала журнал, потом данные. Основа надежности |
| 4 | C | Undo Log хранит старые значения для отката изменений (Atomicity) |
| 5 | C | Изоляция предотвращает влияние промежуточных состояний транзакций друг на друга |
| 6 | D | Последовательная запись (Append) на порядки быстрее случайной |
| 7 | D | Lock Manager управляет очередями доступа к ресурсам (строкам, страницам) |
| 8 | D | Shared Lock позволяет многим читать, но никому писать |
| 9 | B | Exclusive Lock дает монопольное право на изменение |
| 10 | D | Классическая проблема блокировок: A ждет B, B ждет A |
| 11 | D | Главное преимущество MVCC — читатели не ждут писателей и наоборот |
| 12 | A | Версионность позволяет видеть состояние БД в прошлом (Consistent Snapshot) |
| 13 | D | MVCC порождает мусор (старые версии), который нужно собирать освобождать место |
| 14 | D | LSN упорядочивает события и позволяет определить, актуальна страница или нет |
| 15 | A | Механизм Redo (накат) логов восстанавливает консистентность |
| 16 | D | Flush лога на диск — это момент истины для Durability |
| 17 | A | Это гарантирует сериализуемость транзакций (strict 2PL) |
| 18 | A | Аномалия изоляции, связанная с добавлением/удалением строк другими транзакциями |
| 19 | B | Откат — это выполнение действий наоборот (INSERT -> DELETE, etc) |
| 20 | A | Надежность и изоляция требуют ресурсов CPU, Disk I/O и памяти |

## Scoring Guide

- **18-20 правильных (90-100%)**: Отлично! Вы понимаете механику транзакций.

- **14-17 правильных (70-89%)**: Хорошо. Повторите MVCC и типы блокировок.

- **10-13 правильных (50-69%)**: Удовлетворительно. Разберитесь с WAL и Undo Log.

- **Менее 10 правильных (< 50%)**: Нужно перечитать лекцию.
