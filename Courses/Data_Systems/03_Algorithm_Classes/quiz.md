## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Бинарный поиск полагается на упорядоченность для деления массива пополам |
| 2 | B | На каждом шаге массив делится пополам — log n шагов |
| 3 | A | Стабильность означает сохранение относительного порядка равных элементов |
| 4 | B | При неудачном pivot одна часть пустая, другая содержит n-1 элемент |
| 5 | D | Merge Sort требует дополнительный массив размера n для слияния |
| 6 | C | Жадный алгоритм выбирает лучший вариант на текущем шаге |
| 7 | D | Для некоторых наборов монет жадный выбор не даёт минимум монет |
| 8 | A | Divide (разделить), Conquer (решить), Combine (объединить) |
| 9 | D | Master Theorem даёт формулу для T(n) = aT(n/b) + f(n) |
| 10 | C | Эти два свойства — ключевые условия применимости DP |
| 11 | B | Мемоизация кэширует результаты рекурсии, табуляция заполняет таблицу итеративно |
| 12 | D | fib(n) вызывает fib(n-1) и fib(n-2), которые снова вычисляют те же значения |
| 13 | C | Таблица DP имеет размер n × capacity |
| 14 | B | LCS = Longest Common Subsequence (подпоследовательность, не подстрока) |
| 15 | C | На почти отсортированных данных мало сдвигов — близко к O(n) |
| 16 | D | Хаффман жадно выбирает два узла с минимальной частотой |
| 17 | C | Сортировка по концу и жадный выбор даёт максимум непересечений |
| 18 | C | x^n = (x^(n/2))² — уменьшаем n вдвое на каждом шаге |
| 19 | D | DP эффективно кэширует и переиспользует результаты подзадач |
| 20 | C | Доказано, что сравнительные сортировки не могут быть быстрее O(n log n) |
