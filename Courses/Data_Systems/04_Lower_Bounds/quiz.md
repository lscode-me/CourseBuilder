## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | C | Lower bound — это доказанный минимум сложности для любого решения задачи |
| 2 | A | Оптимальный алгоритм достигает теоретического предела — нельзя сделать лучше |
| 3 | A | Доказано через дерево решений: log(n!) ≈ n log n |
| 4 | B | n! возможных перестановок требуют дерево высотой минимум log(n!) |
| 5 | C | Counting Sort не использует сравнения и работает за O(n + k) |
| 6 | D | Элемент может быть в любой позиции — нужно проверить все |
| 7 | C | Каждый элемент, кроме минимума, должен "проиграть" хотя бы одно сравнение |
| 8 | A | Сравниваем пары между собой, затем каждый с текущим min/max |
| 9 | D | При достигнутой нижней границе оптимизируем константы, кэш, параллелизм |
| 10 | B | Алгоритм, минимизирующий cache miss для лучшей производительности |
| 11 | D | P = NP означало бы, что проверка и решение имеют одинаковую сложность |
| 12 | C | Сортировка решается за O(n log n) — это в классе P |
| 13 | B | Приближённые алгоритмы дают "достаточно хорошее" решение за разумное время |
| 14 | C | Nearest neighbor — жадный алгоритм, не гарантирующий оптимум |
| 15 | D | Quickselect находит k-й элемент за O(n) в среднем |
| 16 | B | Алгоритм "median of medians" гарантирует O(n) |
| 17 | D | Индексы позволяют искать за O(log n) или O(1) вместо O(n) |
| 18 | B | Повторные запросы обслуживаются за O(1) вместо пересчёта |
| 19 | B | При малых n константные факторы важнее асимптотики |
| 20 | D | Нижняя граница Ω(n²), лучший известный алгоритм O(n^2.37) |

## Scoring Guide

- **18-20 правильных (90-100%)**: Отлично! Вы понимаете теоретические пределы.

- **14-17 правильных (70-89%)**: Хорошо. Повторите NP-полноту и приближённые алгоритмы.

- **10-13 правильных (50-69%)**: Удовлетворительно. Рекомендуется перечитать лекцию.

- **Менее 10 правильных (< 50%)**: Необходимо внимательно изучить материал заново.
