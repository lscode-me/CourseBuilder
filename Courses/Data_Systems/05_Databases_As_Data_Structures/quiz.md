## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | БД — это B-trees, hash tables, logs и другие структуры данных |
| 2 | C | Storage Engine управляет всеми аспектами физического хранения |
| 3 | B | Логическая модель — абстракция для разработчика |
| 4 | A | Физическая модель — реальное устройство хранения |
| 5 | C | Страница — атомарная единица I/O, обычно 4-16KB |
| 6 | D | Buffer Pool кэширует горячие страницы в RAM |
| 7 | B | Least Recently Used — удаляем то, что давно не использовалось |
| 8 | B | B-tree — основная структура для индексов в реляционных БД |
| 9 | D | Row Store хранит записи целиком |
| 10 | A | Column Store эффективен для SELECT SUM, AVG по колонкам |
| 11 | D | OLTP = много INSERT/UPDATE/DELETE целых записей |
| 12 | C | LSM-tree оптимизирует запись через append-only log |
| 13 | C | B-tree отсортировано → эффективные range queries |
| 14 | B | Индекс — доп. структура, ускоряющая поиск за счёт места |
| 15 | A | Без индекса приходится читать все страницы таблицы |
| 16 | C | Heap — простейшее хранилище без упорядочения |
| 17 | D | Одинаковые значения рядом лучше сжимаются |
| 18 | A | RAM: ~100ns, SSD: ~100μs, HDD: ~10ms |
| 19 | B | Оптимизация чтения часто ухудшает запись и наоборот |
| 20 | C | EXPLAIN показывает, какие индексы и операции использует запрос |

## Scoring Guide

- **18-20 правильных (90-100%)**: Отлично! Вы понимаете внутреннее устройство БД.

- **14-17 правильных (70-89%)**: Хорошо. Повторите storage engines и индексы.

- **10-13 правильных (50-69%)**: Удовлетворительно. Рекомендуется перечитать лекцию.

- **Менее 10 правильных (< 50%)**: Необходимо внимательно изучить материал заново.
