## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | Брокеры сообщений реализуют интерфейс FIFO очереди с гарантией доставки |
| 2 | D | KVS — это распределенная хеш-таблица |
| 3 | C | DNS иерархична по своей природе, как и DOM дерево |
| 4 | D | Графовые БД оптимизированы для хранения связей (ребер) и обхода соседей |
| 5 | A | Стек хранит историю переходов. Back = Pop() |
| 6 | C | Очередь разрывает синхронную связь, позволяя компонентам жить своей жизнью |
| 7 | A | Паттерн обработки сбоев. Аналог catch block, но для сообщений |
| 8 | B | Redis выносит состояние (State) за пределы процесса приложения |
| 9 | D | Классическая архитектура Twitter. Эффективно для чтения (O(1)), дорого для записи |
| 10 | C | Роутеры ищут обработчик по префиксу URL (`/api/user/get` -> `/api` -> `user`...) |
| 11 | A | Вероятностная стурктура для быстрой проверки принадлежности элемента множеству |
| 12 | D | Лог — основа надежности (Durability) и упорядочивания событий |
| 13 | D | БД дает гарантии ACID, которых нет у обычной переменной |
| 14 | C | System Design не требует сакральных знаний, это CS fundamentals at scale |
| 15 | D | "Numbers everyone should know". Network call намного дороже memory access |
| 16 | C | Шардинг — это Partitioning, который часто делается через `hash(key) % N` |
| 17 | A | Кеш не бесконечен, нужно выбирать жертву (Least Recently Used и т.д.) |
| 18 | A | При нажатии Back URL перекладывается из стека Back в стек Forward |
| 19 | D | VIP клиенты или критические баги обрабатываются вне очереди |
| 20 | B | Понимание этого принципа упрощает изучение архитектуры |

## Scoring Guide

- **18-20 правильных (90-100%)**: Отлично! Вы видите матрицу архитектуры.

- **14-17 правильных (70-89%)**: Хорошо. Повторите аналогии Queue и Map.

- **10-13 правильных (50-69%)**: Удовлетворительно. Разберитесь с базовыми структурами.

- **Менее 10 правильных (< 50%)**: Нужно перечитать лекцию.
