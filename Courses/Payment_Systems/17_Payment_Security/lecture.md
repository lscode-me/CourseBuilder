## 1. PCI DSS

### 1.1 Что это

**PCI DSS (Payment Card Industry Data Security Standard)** — стандарт безопасности данных платёжных карт.

### 1.2 Кто должен соответствовать

Все, кто хранит, обрабатывает или передаёт данные карт:
- Торговцы
- Процессоры
- Платёжные шлюзы
- Банки

### 1.3 12 требований

| # | Требование |
|---|------------|
| 1 | Firewall для защиты данных |
| 2 | Не использовать дефолтные пароли |
| 3 | Защита хранимых данных |
| 4 | Шифрование при передаче |
| 5 | Антивирус |
| 6 | Безопасная разработка |
| 7 | Ограничение доступа |
| 8 | Уникальные ID пользователей |
| 9 | Физическая безопасность |
| 10 | Логирование и мониторинг |
| 11 | Тестирование безопасности |
| 12 | Политики безопасности |

### 1.4 Уровни соответствия

| Уровень | Объём | Требования |
|---------|-------|------------|
| 1 | > 6 млн транз/год | QSA аудит |
| 2 | 1-6 млн | SAQ + сканирование |
| 3 | 20К-1 млн | SAQ |
| 4 | < 20К | SAQ |

## 2. 3-D Secure

### 2.1 Принцип работы

```
1. Покупатель вводит карту
2. Merchant → Эквайер → ПС → Эмитент
3. Эмитент оценивает риск
4. При необходимости → Challenge (SMS, push)
5. Держатель подтверждает
6. Liability shift к эмитенту
```

### 2.2 Версии

| Версия | Особенности |
|--------|-------------|
| 1.0 | Pop-up, статические пароли, плохой UX |
| 2.0 | Frictionless, биометрия, лучший UX |
| 2.1+ | SCA для ЕС, улучшения |

### 2.3 Frictionless vs Challenge

**Frictionless:**
- Риск низкий
- Нет дополнительной верификации
- Лучше конверсия

**Challenge:**
- Риск высокий
- Требует подтверждения (SMS, push, биометрия)

### 2.4 Liability Shift

При успешной 3DS ответственность за fraud переходит к эмитенту.

## 3. Fraud Detection

### 3.1 Типы мошенничества

| Тип | Описание |
|-----|----------|
| Card theft | Украденные данные карты |
| Account takeover | Взлом аккаунта |
| Friendly fraud | Ложные заявления держателя |
| Identity theft | Кража личности |

### 3.2 Сигналы риска

| Сигнал | Риск |
|--------|------|
| Новый клиент, крупный заказ | Высокий |
| Разные billing/shipping | Средний |
| Много попыток оплаты | Высокий |
| Подозрительный IP | Высокий |
| Необычное время | Низкий |

### 3.3 Инструменты

- **Device fingerprinting** — идентификация устройства
- **Velocity checks** — частота транзакций
- **Geolocation** — проверка местоположения
- **ML models** — машинное обучение

### 3.4 Действия

| Риск | Действие |
|------|----------|
| Низкий | Пропустить |
| Средний | 3DS / Review |
| Высокий | Отклонить |

## 4. Шифрование

### 4.1 В покое (At Rest)

- AES-256 для хранимых данных
- HSM для ключей
- Токенизация вместо хранения

### 4.2 При передаче (In Transit)

- TLS 1.2+ для всех соединений
- Сертификаты от CA
- HTTPS обязательно

---

## 5. Токенизация

### 5.1 Для хранения

Вместо хранения PAN → хранение токена.

```
Database:
├── customer_id: 123
├── card_token: tok_xxx (безопасно)
└── last4: 9012
```

### 5.2 Преимущества

- Снижение PCI scope
- Токен бесполезен без vault
- Проще compliance

---

## 6. Best Practices

### 6.1 Для разработчиков

1. Никогда не логировать PAN, CVV
2. Использовать токенизацию
3. HTTPS везде
4. Валидация на стороне сервера
5. Rate limiting

### 6.2 Для бизнеса

1. Регулярные аудиты
2. Обучение персонала
3. Incident response plan
4. Мониторинг 24/7
5. Страхование киберрисков

---

## 💡 Key Takeaways

- **PCI DSS обязателен** для всех, кто работает с картами
- **3-D Secure** — liability shift + защита от fraud
- **Fraud detection** использует ML и множество сигналов
- **Токенизация** снижает PCI scope
- **TLS + AES** — стандарты шифрования
