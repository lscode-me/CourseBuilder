## 1. Процессинговый центр

### 1.1 Что это

**Процессинговый центр** — технологическая платформа для обработки карточных транзакций.

**Функции:**
- Маршрутизация транзакций
- Авторизация (если эмитент)
- Управление картами
- Fraud-мониторинг
- Клиринг и reconciliation
- Генерация отчётов

### 1.2 Типы

| Тип | Описание |
|-----|----------|
| **In-house** | Собственный процессинг банка |
| **Outsourced** | Внешний провайдер |
| **Hybrid** | Комбинация |

### 1.3 Примеры процессоров

**Россия:**
- НСПК (Мир)
- Сбербанк-процессинг
- ВТБ-процессинг
- Первый процессинговый

**Международные:**
- First Data (Fiserv)
- Worldpay
- TSYS
- Global Payments

## 2. Банк-эмитент

### 2.1 Функции эмитента

```
┌─────────────────────────────────────────────────────────────┐
│                   ФУНКЦИИ ЭМИТЕНТА                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  • Выпуск карт                                              │
│  • Ведение счетов клиентов                                  │
│  • Авторизация транзакций                                   │
│  • Управление лимитами                                      │
│  • Fraud-мониторинг                                         │
│  • Обслуживание клиентов                                    │
│  • Начисление бонусов/кэшбэка                               │
│  • Кредитование (для кредитных карт)                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 Доходы эмитента

| Источник | Описание |
|----------|----------|
| Interchange | От каждой транзакции |
| Проценты | По кредитным картам |
| Комиссии | Годовое обслуживание, снятие наличных |
| Cross-sell | Другие банковские продукты |

### 2.3 Риски эмитента

- **Кредитный риск** — невозврат кредита
- **Fraud** — мошеннические транзакции
- **Операционный** — сбои систем

## 3. Банк-эквайер

### 3.1 Функции эквайера

```
┌─────────────────────────────────────────────────────────────┐
│                   ФУНКЦИИ ЭКВАЙЕРА                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  • Подключение торговцев                                    │
│  • Предоставление терминалов                                │
│  • Обработка транзакций                                     │
│  • Перевод денег торговцам                                  │
│  • Поддержка торговцев                                      │
│  • Управление chargebacks                                   │
│  • Risk management                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 Доходы эквайера

| Источник | Описание |
|----------|----------|
| Acquirer margin | MDR − Interchange − Scheme fee |
| Аренда терминалов | Ежемесячная плата |
| Дополнительные услуги | DCC, рассрочка, аналитика |

### 3.3 Риски эквайера

- **Chargeback** — торговец не может вернуть
- **Мошенничество** — fake merchants
- **Операционный** — сбои терминалов

## 4. Один банк — две роли

### 4.1 On-us транзакции

Когда эмитент и эквайер — **один банк**:

```
Держатель (Сбербанк) → Торговец (Сбербанк)
        │                      │
        └──────────────────────┘
                  │
           ┌──────▼──────┐
           │  Сбербанк   │
           │(Issuer +    │
           │ Acquirer)   │
           └─────────────┘
```

**Преимущества:**
- Нет внешнего interchange
- Быстрее расчёты
- Полный контроль

### 4.2 Крупные игроки

**В России:**
- Сбербанк — крупнейший эмитент и эквайер
- ВТБ — оба направления
- Тинькофф — преимущественно эмитент, развивает эквайринг

## 5. Взаимодействие с платёжными системами

### 5.1 Членство в ПС

**Требования для членства:**
- Лицензия ЦБ
- Финансовая устойчивость
- Техническая готовность
- Соответствие правилам ПС

### 5.2 Типы членов

| Тип | Права |
|-----|-------|
| Principal | Полные права эмиссии и эквайринга |
| Associate | Через спонсора |
| Participant | Ограниченные права |

## 7. Требования к процессингу

### 7.1 SLA

| Метрика | Требование |
|---------|------------|
| Uptime | 99.99%+ |
| Latency | <500 мс |
| TPS | Тысячи транзакций в секунду |
| Recovery | <1 час |

### 7.2 Безопасность

- **PCI DSS** — обязательная сертификация
- **HSM** — аппаратное хранение ключей
- **Шифрование** — все данные карт
- **Мониторинг** — 24/7

## 8. Тренды

### 8.1 Cloud processing

Переход на облачные платформы:
- Масштабируемость
- Гибкость
- Снижение CAPEX

### 8.2 Real-time

Мгновенные платежи требуют:
- Новые архитектуры
- 24/7 операции
- Быстрый settlement

### 8.3 Открытые API

Open Banking меняет процессинг:
- Интеграция с fintech
- Новые сервисы
- Конкуренция

---

## 💡 Key Takeaways

- **Процессинг — технологическая основа** платежей
- **Эмитент отвечает за карты и клиентов** — авторизация, лимиты, fraud
- **Эквайер обслуживает торговцев** — терминалы, выплаты, chargebacks
- **On-us выгоднее** — когда банк и эмитент, и эквайер
- **PCI DSS обязателен** для всех участников процессинга
