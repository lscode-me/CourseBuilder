## 1. Введение

Вы прикладываете карту к терминалу. Через 2-3 секунды на экране появляется "Approved" или "Declined". За эти секунды происходит сложнейшее взаимодействие между несколькими организациями.

Понимание этого процесса поможет:
- Разбираться в причинах отказов
- Оптимизировать платёжные интеграции
- Понимать задержки и риски

## 2. Обзор процесса

### 2.1 Временная шкала

```
┌─────────────────────────────────────────────────────────────┐
│                    КАРТОЧНЫЙ ПЛАТЁЖ                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    Секунды              Часы/Дни            Дни             │
│        │                    │                │              │
│        ▼                    ▼                ▼              │
│   ┌─────────┐         ┌─────────┐       ┌─────────┐         │
│   │Авториза-│ ──────► │ Клиринг │ ────► │Расчёты  │         │
│   │   ция   │         │         │       │         │         │
│   └─────────┘         └─────────┘       └─────────┘         │
│                                                             │
│   Можно ли          Подготовка        Перевод               │
│   платить?          данных            денег                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 Этапы в деталях

| Этап | Что происходит | Время | Результат |
|------|----------------|-------|-----------|
| **1. Инициация** | Карта предъявляется | <1 сек | Данные считаны |
| **2. Авторизация** | Проверка и одобрение | 1-3 сек | Approved/Declined |
| **3. Capture** | Подтверждение транзакции | 0-24 часа | Batch сформирован |
| **4. Клиринг** | Обмен данными между банками | 1-2 дня | Позиции рассчитаны |
| **5. Settlement** | Фактический перевод денег | 1-3 дня | Деньги переведены |

## 3. Шаг 1: Инициация платежа

### 3.1 Считывание данных карты

**Способы считывания:**

| Способ | Данные | Безопасность |
|--------|--------|--------------|
| Магнитная полоса | Track 1/2 | Низкая |
| Контактный чип | EMV + криптограмма | Высокая |
| Бесконтактный (NFC) | EMV + криптограмма | Высокая |
| Ручной ввод | PAN, Expiry, CVV | Средняя |

### 3.2 Что считывается

**При чипе/NFC:**
```
Данные от карты:
├── PAN (номер карты)
├── Expiry date
├── Cardholder name
├── Application cryptogram (ARQC)
├── ATC (счётчик транзакций)
├── CVR (Card Verification Results)
└── Terminal capabilities
```

### 3.3 Формирование запроса

Терминал формирует запрос авторизации:

```
┌─────────────────────────────────────────────────────────────┐
│              AUTHORIZATION REQUEST                          │
├─────────────────────────────────────────────────────────────┤
│  Message Type:     0100 (Authorization Request)             │
│  PAN:              4276****9012                             │
│  Amount:           1 500.00 RUB                             │
│  Currency:         643 (RUB)                                │
│  MCC:              5411 (Grocery)                           │
│  Merchant ID:      123456789012345                          │
│  Terminal ID:      87654321                                 │
│  Entry Mode:       051 (Chip)                               │
│  Cryptogram:       A1B2C3D4E5F67890                         │
│  Timestamp:        2024-03-15 14:32:17                      │
└─────────────────────────────────────────────────────────────┘
```

## 4. Шаг 2: Маршрутизация запроса

### 4.1 Путь запроса

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ Терминал │───►│ Эквайер  │───►│   ПС     │───►│ Эмитент  │
│          │    │          │    │(Visa/MC) │    │          │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
     │               │               │               │
     │    Запрос     │    Запрос     │    Запрос     │
     │───────────────►───────────────►───────────────►
     │               │               │               │
     │◄───────────────◄───────────────◄───────────────│
     │    Ответ      │    Ответ      │    Ответ      │
```

### 4.2 Определение маршрута

**Как платёжная система определяет эмитента:**

1. Анализ BIN (первые 6-8 цифр)
2. Поиск в BIN-таблице
3. Определение банка-эмитента
4. Маршрутизация на нужный хост

**Пример:**
```
PAN: 4276 1234 5678 9012
BIN: 427614
Lookup: BIN 427614 → Сбербанк, Россия
Route: → Сбербанк процессинг центр
```

### 4.3 Протокол ISO 8583

Все сообщения передаются по стандарту ISO 8583:

| Поле | Название | Пример |
|------|----------|--------|
| MTI | Message Type | 0100 (auth request) |
| DE2 | PAN | 4276123456789012 |
| DE3 | Processing Code | 000000 (purchase) |
| DE4 | Amount | 000000150000 |
| DE49 | Currency Code | 643 |
| DE41 | Terminal ID | 87654321 |
| DE42 | Merchant ID | 123456789012345 |

## 5. Шаг 3: Авторизация у эмитента

### 5.1 Что проверяет эмитент

```
┌─────────────────────────────────────────────────────────────┐
│              ПРОВЕРКИ ЭМИТЕНТА                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ✓ Карта существует и активна                               │
│  ✓ Срок действия не истёк                                   │
│  ✓ Карта не заблокирована                                   │
│  ✓ PIN/криптограмма верны                                   │
│  ✓ Достаточно средств/лимита                                │
│  ✓ Не превышены лимиты (дневные, месячные)                  │
│  ✓ Транзакция не подозрительная (fraud)                     │
│  ✓ Географические ограничения                               │
│  ✓ Категория торговца разрешена                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 Проверка криптограммы (EMV)

Для чиповых транзакций эмитент проверяет ARQC:

```
Входные данные криптограммы:
├── PAN
├── ATC (счётчик транзакций)
├── Amount
├── Terminal Country
├── Terminal Type
├── Transaction Date
└── Unpredictable Number

Эмитент:
1. Воссоздаёт криптограмму с теми же данными
2. Использует свой мастер-ключ
3. Сравнивает с полученной
4. Если совпадает → карта подлинная
```

### 5.3 Fraud-анализ

Современные эмитенты используют ML-модели:

| Сигнал | Что проверяется |
|--------|-----------------|
| Геолокация | Покупка в другой стране через час? |
| Паттерны | Нетипичная категория или сумма? |
| Скорость | Много транзакций за короткое время? |
| Устройство | Новый терминал или IP? |
| Время | Покупка в 3 часа ночи? |

### 5.4 Принятие решения

```
IF карта валидна
   AND достаточно средств
   AND fraud_score < threshold
   AND лимиты не превышены
THEN
   Approve (код 00)
ELSE
   Decline (код XX)
```

## 6. Шаг 4: Ответ авторизации

### 6.1 Структура ответа

```
┌─────────────────────────────────────────────────────────────┐
│              AUTHORIZATION RESPONSE                         │
├─────────────────────────────────────────────────────────────┤
│  Message Type:     0110 (Authorization Response)            │
│  Response Code:    00 (Approved)                            │
│  Authorization ID: A12B3C                                   │
│  Available Balance: 47 500.00 RUB (опционально)             │
│  Timestamp:        2024-03-15 14:32:18                      │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 Коды ответов

| Код | Значение | Описание |
|-----|----------|----------|
| 00 | Approved | Транзакция одобрена |
| 01 | Refer to issuer | Требуется звонок в банк |
| 05 | Do not honor | Отказ без объяснения |
| 12 | Invalid transaction | Неверный тип транзакции |
| 14 | Invalid card | Неверный номер карты |
| 41 | Lost card | Карта утеряна |
| 43 | Stolen card | Карта украдена |
| 51 | Insufficient funds | Недостаточно средств |
| 54 | Expired card | Карта просрочена |
| 55 | Invalid PIN | Неверный PIN |
| 61 | Exceeds limit | Превышен лимит |
| 65 | Activity limit | Превышен лимит активности |

### 6.3 Authorization Code

При одобрении эмитент генерирует **Authorization Code** — уникальный код транзакции.

**Формат:** 6 буквенно-цифровых символов (A12B3C)

**Назначение:**
- Идентификация транзакции
- Связь авторизации с клирингом
- Документ для споров

## 7. Шаг 5: Холдирование средств

### 7.1 Что происходит после Approved

```
ДО ТРАНЗАКЦИИ:
┌─────────────────────────────────────────────────────────────┐
│  Баланс: 50 000 ₽                                           │
│  Доступно: 50 000 ₽                                         │
│  Холд: 0 ₽                                                  │
└─────────────────────────────────────────────────────────────┘

ПОСЛЕ АВТОРИЗАЦИИ (до Settlement):
┌─────────────────────────────────────────────────────────────┐
│  Баланс: 50 000 ₽         ← Деньги ещё на счёте!            │
│  Доступно: 48 500 ₽       ← Минус сумма холда               │
│  Холд: 1 500 ₽            ← Заблокировано                   │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 Срок жизни холда

| Тип транзакции | Срок холда |
|----------------|------------|
| Обычная покупка | 1-7 дней |
| Отель | До 30 дней |
| Аренда авто | До 30 дней |
| АЗС (pre-auth) | 1-3 дня |

### 7.3 Сценарии

**Сценарий 1: Нормальная покупка**
```
День 1: Авторизация 1 500 ₽ → Холд 1 500 ₽
День 2: Клиринг → Холд снимается → Списание 1 500 ₽
```

**Сценарий 2: Отмена (Void)**
```
День 1: Авторизация 1 500 ₽ → Холд 1 500 ₽
День 1: Void → Холд снимается → Списание 0 ₽
```

**Сценарий 3: Частичное списание (отель)**
```
День 1: Pre-auth 10 000 ₽ → Холд 10 000 ₽
День 5: Capture 7 500 ₽ → Списание 7 500 ₽
        Освобождение 2 500 ₽
```

## 8. Pre-authorization и Capture

### 8.1 Двухстадийная транзакция

Некоторые бизнесы используют двухстадийную схему:

```
┌─────────────────────────────────────────────────────────────┐
│              ДВУХСТАДИЙНАЯ ТРАНЗАКЦИЯ                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Pre-auth                          Capture                 │
│   (Резервирование)                  (Списание)              │
│                                                             │
│   ┌─────────┐                       ┌─────────┐             │
│   │ Можно   │    ───────────────►   │ Списать │             │
│   │ списать │        Дни            │ сумму   │             │
│   │ до 10K? │                       │ 8K      │             │
│   └─────────┘                       └─────────┘             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 Когда используется

| Сценарий | Почему |
|----------|--------|
| Отели | Финальная сумма неизвестна (минибар) |
| Аренда авто | Возможные штрафы |
| АЗС | Сумма известна после заправки |
| Рестораны | Добавление чаевых |
| e-commerce | Отложенная доставка |

### 8.3 Правила

- **Срок capture**: Обычно 7-30 дней
- **Сумма capture**: ≤ сумма pre-auth (обычно)
- **Incremental auth**: Можно увеличить (для отелей)

## 9. Offline-транзакции

### 9.1 Когда возникают

**Offline-авторизация** — когда терминал не может связаться с эмитентом.

**Сценарии:**
- Нет связи (самолёт, круизный лайнер)
- Offline floor limit
- Chip offline approval

### 9.2 Как работает

```
Терминал:
1. Не может связаться с эмитентом
2. Проверяет правила на чипе карты
3. Чип может одобрить offline (для малых сумм)
4. Транзакция сохраняется
5. Отправляется при появлении связи
```

### 9.3 Риски

- Эмитент может отклонить при клиринге
- Нет реального подтверждения средств
- Выше риск мошенничества

## 10. Скорость и SLA

### 10.1 Требования к времени

| Этап | Целевое время |
|------|---------------|
| Терминал → Эквайер | <500 мс |
| Эквайер → ПС | <200 мс |
| ПС → Эмитент | <500 мс |
| Эмитент processing | <500 мс |
| **Общее время** | **<2-3 сек** |

### 10.2 Timeout

Если ответ не получен за timeout:
1. Терминал показывает "Ошибка связи"
2. Может быть reversal
3. Статус транзакции неизвестен

### 10.3 Stand-in processing

При недоступности эмитента платёжная система может:
- Одобрить от имени эмитента (для надёжных транзакций)
- Отклонить
- Использовать STIP (Stand-In Processing)

---

## 💡 Key Takeaways

- **2-3 секунды = много шагов**: Терминал → Эквайер → ПС → Эмитент и обратно
- **Авторизация ≠ списание**: После Approved деньги только заблокированы
- **Криптограмма защищает**: EMV-транзакции верифицируются криптографически
- **Код 05 — загадка**: Эмитент не объясняет причину из соображений безопасности
- **Pre-auth для неизвестных сумм**: Отели, аренда, рестораны
