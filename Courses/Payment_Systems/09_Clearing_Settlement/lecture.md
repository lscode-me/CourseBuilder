## 1. Введение

После успешной авторизации деньги не переходят мгновенно. Между "Approved" на терминале и поступлением денег на счёт торговца проходит 1-3 дня. В это время происходят клиринг и расчёты.

**Клиринг** — подготовка данных для расчётов.
**Settlement** — фактический перевод денег.

---

## 2. Обзор процесса

### 2.1 Временная шкала

```
День 0           День 1              День 2
   │                │                   │
   ▼                ▼                   ▼
┌──────┐        ┌──────┐           ┌──────┐
│Покупка│ ────► │Клиринг│ ───────► │Settlement│
│Auth   │       │Batch  │          │Деньги    │
└──────┘        └──────┘           └──────┘
   │                │                   │
Авторизация    Обмен файлами      Перевод денег
2-3 сек        Ночью              Утром
```

### 2.2 Этапы

| Этап | Что происходит | Когда |
|------|----------------|-------|
| Capture | Торговец подтверждает транзакцию | День 0 (вечер) |
| Batching | Сбор транзакций в пакет | День 0 (ночь) |
| Clearing | Обмен данными между банками | День 0-1 |
| Settlement | Фактический перевод денег | День 1-2 |

---

## 3. Capture и Batching

### 3.1 Capture

**Capture** — подтверждение торговцем, что транзакция должна быть проведена.

**Для большинства покупок:** Capture происходит автоматически после авторизации.

**Для pre-auth:** Capture отправляется отдельно, когда известна финальная сумма.

### 3.2 Batch (пакет)

Торговец или его эквайер собирает транзакции в **batch**:

```
┌─────────────────────────────────────────────────────────────┐
│                    BATCH ТОРГОВЦА                           │
│                    Дата: 2024-03-15                         │
├─────────────────────────────────────────────────────────────┤
│ Trans ID  │ Amount   │ Card      │ Auth Code │ Time        │
├───────────┼──────────┼───────────┼───────────┼─────────────┤
│ 001       │ 1,500 ₽  │ 4276****  │ A12B3C    │ 09:15:22    │
│ 002       │ 3,200 ₽  │ 5213****  │ D45E6F    │ 10:32:45    │
│ 003       │ 890 ₽    │ 2202****  │ G78H9I    │ 11:48:03    │
│ ...       │ ...      │ ...       │ ...       │ ...         │
├───────────┼──────────┼───────────┼───────────┼─────────────┤
│ ИТОГО:    │ 125,340₽ │ 47 trans  │           │             │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 Settlement file

Эквайер формирует **settlement file** и отправляет в платёжную систему:

- Формат: ISO 8583 или проприетарный
- Содержит: все транзакции за период
- Отправляется: обычно раз в день (ночью)

## 4. Клиринг (Clearing)

### 4.1 Что происходит

```
┌─────────────────────────────────────────────────────────────┐
│                    ПРОЦЕСС КЛИРИНГА                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Эквайер A ─────────► ┌──────────────┐ ◄───────── Эмитент 1 │
│                       │              │                      │
│  Эквайер B ─────────► │  ПЛАТЁЖНАЯ   │ ◄───────── Эмитент 2 │
│                       │   СИСТЕМА    │                      │
│  Эквайер C ─────────► │  (Visa/MC)   │ ◄───────── Эмитент 3 │
│                       │              │                      │
│                       │   Клиринг:   │                      │
│                       │ • Сопоставление│                    │
│                       │ • Расчёт нетто│                     │
│                       │ • Распределение│                    │
│                       └──────────────┘                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Функции клиринга

1. **Matching** — сопоставление авторизаций и capture
2. **Netting** — взаимозачёт между банками
3. **Calculation** — расчёт interchange и fees
4. **Reporting** — формирование отчётов

### 4.3 Netting (взаимозачёт)

**Без netting:**
```
Банк А → Банк Б: 1 000 000 ₽
Банк Б → Банк А: 800 000 ₽
Итого переводов: 1 800 000 ₽
```

**С netting:**
```
Банк А → Банк Б: 1 000 000 ₽
Банк Б → Банк А: 800 000 ₽
Нетто: Банк А → Банк Б: 200 000 ₽
Итого переводов: 200 000 ₽ (экономия!)
```

## 5. Settlement (Расчёты)

### 5.1 Что происходит

После клиринга платёжная система инициирует **фактический перевод денег**:

```
┌─────────────────────────────────────────────────────────────┐
│                    SETTLEMENT                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Эмитент ────────────────────────────────────────► Эквайер  │
│           Сумма транзакций − Interchange                    │
│                                                             │
│  Эквайер ────────────────────────────────────────► Торговец │
│           Сумма транзакций − MDR                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 Settlement Bank

Расчёты проводятся через **settlement bank** платёжной системы:

- Visa: через JPMorgan Chase, другие
- Mastercard: через Mastercard Settlement Bank
- Мир: через Банк России, расчётные банки

### 5.3 Расчётные циклы

| Обозначение | Значение | Пример |
|-------------|----------|--------|
| T+0 | В тот же день | Некоторые fast payments |
| T+1 | На следующий рабочий день | Стандарт для многих рынков |
| T+2 | Через два рабочих дня | Международные транзакции |
| T+3 | Через три дня | Редко, для сложных случаев |

**Пример T+1:**
```
Понедельник: Покупка, авторизация
Вторник утро: Settlement, деньги у торговца
```

## 6. Когда торговец получает деньги

### 6.1 Стандартные сроки

| Регион/Тип | Срок получения |
|------------|----------------|
| Россия, крупные сети | T+1 |
| Россия, малый бизнес | T+1 — T+3 |
| США | T+1 — T+2 |
| Европа | T+1 — T+2 |
| Международные | T+2 — T+5 |

### 6.2 Факторы, влияющие на сроки

| Фактор | Влияние |
|--------|---------|
| Размер бизнеса | Крупные получают быстрее |
| История | Новые торговцы ждут дольше |
| Риск | High-risk ждут дольше |
| Праздники | Увеличивают срок |
| Rolling reserve | Часть суммы удерживается |

### 6.3 Rolling Reserve

**Rolling reserve** — часть суммы, которую эквайер удерживает на случай chargebacks:

```
Транзакции за день: 100 000 ₽
Rolling reserve: 10%
Торговец получает: 90 000 ₽
Удержано: 10 000 ₽ (возвращается через 90-180 дней)
```

## 7. Мультивалютный settlement

### 7.1 Валюта расчётов

Visa и Mastercard ведут расчёты преимущественно в **USD**:

```
Транзакция в магазине (EUR):
  EUR → USD (курс ПС) → Settlement в USD
  
Получение торговцем:
  USD → EUR (курс банка) → На счёт в EUR
```

### 7.2 DCC при settlement

При DCC конвертация уже произошла:
```
С DCC:
  Держатель заплатил в RUB
  Торговец получает в EUR
  Settlement: напрямую, без дополнительной конвертации
```

### 7.3 Курсовые риски

**Между авторизацией и settlement:**
```
День 0: Авторизация €100, курс 98 ₽
День 2: Settlement, курс изменился на 102 ₽
Разница: 400 ₽ (курсовой риск)
```

## 8. Проблемы при клиринге

### 8.1 Mismatches

**Когда capture не совпадает с авторизацией:**
- Сумма отличается (partial capture OK, over-capture — проблема)
- Authorization code не найден
- Транзакция expired

### 8.2 Duplicate transactions

**Дубликаты:**
- Одна транзакция отправлена дважды
- Технические ошибки
- Нужна reconciliation

### 8.3 Late presentment

**Поздняя отправка:**
- Capture отправлен слишком поздно
- Может быть отклонён
- Типичный срок: 7-30 дней

### 8.4 Chargebacks в settlement

**При chargeback:**
```
Оригинальный settlement: +1 000 ₽ торговцу
Chargeback: −1 000 ₽ от торговца
Итого: 0 ₽ (или минус, с комиссиями)
```

---

## 9. Reconciliation

### 9.1 Что это

**Reconciliation (сверка)** — сопоставление данных между участниками:

```
Торговец:                    Эквайер:
├── Транзакция 001: 1500 ₽   ├── Транзакция 001: 1500 ₽ ✓
├── Транзакция 002: 3200 ₽   ├── Транзакция 002: 3200 ₽ ✓
├── Транзакция 003: 890 ₽    ├── Транзакция 003: ???   ✗
└── ИТОГО: 5590 ₽            └── ИТОГО: 4700 ₽
                             
                             РАСХОЖДЕНИЕ: 890 ₽
```

### 9.2 Что сверяется

- Количество транзакций
- Суммы
- Комиссии
- Chargebacks и refunds

### 9.3 Автоматизация

Современные системы автоматизируют reconciliation:
- Ежедневные отчёты
- Автоматическое выявление расхождений
- Alerts при проблемах

## 10. Real-time settlement

### 10.1 Тренд

Рынок движется к **real-time settlement**:

| Система | Страна | Скорость |
|---------|--------|----------|
| Faster Payments | UK | Секунды |
| СБП | Россия | Секунды |
| SEPA Instant | ЕС | <10 секунд |
| RTP | США | Секунды |

### 10.2 Карты и real-time

Для карточных платежей real-time settlement пока редкость:
- Visa Direct — быстрые push-платежи
- Mastercard Send — аналогично
- Но стандартный retail — всё ещё T+1

### 10.3 Преимущества быстрого settlement

- Торговец получает деньги сразу
- Лучший cash flow
- Меньше рисков
- Конкурентное преимущество

---

## 💡 Key Takeaways

- **Клиринг ≠ Settlement**: Клиринг — подготовка, Settlement — перевод денег
- **Netting экономит**: Взаимозачёт снижает объём переводов
- **T+1 — стандарт**: Торговец получает деньги на следующий день
- **Rolling reserve**: Часть денег может удерживаться на случай споров
- **Real-time приходит**: Но для карт пока медленнее, чем для A2A
