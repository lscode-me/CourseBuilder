## 1. Введение: Почему нужен клиринг

После успешной авторизации деньги не переходят мгновенно. Между "Approved" на терминале и поступлением денег на счёт торговца проходит 1-3 дня. В это время происходят клиринг и расчёты.

### 1.1 Основные понятия

| Термин | Определение | Аналогия |
|--------|-------------|----------|
| **Авторизация** | Проверка и блокировка средств | "Да, деньги есть, зарезервированы" |
| **Capture** | Подтверждение транзакции к списанию | "Подтверждаю, списывайте" |
| **Клиринг (Clearing)** | Подготовка и обмен данными для расчётов | "Считаем, кто кому сколько должен" |
| **Settlement** | Фактический перевод денег | "Переводим деньги" |

### 1.2 Почему не мгновенно?

**Причины задержки:**

1. **Объём транзакций:**
   - Миллионы транзакций в день
   - Тысячи банков-участников
   - Невозможно переводить по каждой транзакции отдельно

2. **Эффективность:**
   - Netting (взаимозачёт) снижает объём переводов на 90%+
   - Меньше комиссий за переводы
   - Меньше ликвидности требуется

3. **Проверки:**
   - Сопоставление авторизаций и capture
   - Выявление ошибок и дубликатов
   - Расчёт комиссий

4. **Историческое наследие:**
   - Системы проектировались в эпоху batch-обработки
   - Модернизация требует времени и инвестиций

### 1.3 Временная шкала типичной транзакции

## 2. Capture и Batching

### 2.1 Capture: Подтверждение транзакции

**Capture** — запрос торговца на фактическое списание средств, зарезервированных при авторизации.

**Типы capture:**

| Тип | Описание | Пример |
|-----|----------|--------|
| Auto-capture | Автоматически после авторизации | Супермаркет, ресторан |
| Delayed capture | Capture отдельно от авторизации | Отель, аренда авто |
| Partial capture | Capture на сумму меньше авторизованной | Частичная отмена заказа |
| Multiple capture | Несколько capture на одну авторизацию | Split shipment |

**Сценарий delayed capture:**

```
┌─────────────────────────────────────────────────────────────────────┐
│                    DELAYED CAPTURE: ОТЕЛЬ                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  День 1: Бронирование                                               │
│  ─────────────────────                                               │
│  Авторизация: 50,000 ₽ (полная стоимость + депозит)                 │
│  Capture: НЕТ (только резерв)                                       │
│                                                                     │
│  День 3: Заезд                                                      │
│  ─────────────                                                       │
│  Проверка резерва: OK                                               │
│  Дополнительные услуги могут добавляться                            │
│                                                                     │
│  День 6: Выезд                                                      │
│  ─────────────                                                       │
│  Финальный счёт: 52,500 ₽ (+ мини-бар, ресторан)                   │
│                                                                     │
│  Вариант A: 52,500 ≤ 50,000 × 1.15 (допустимо)                     │
│  → Capture на 52,500 ₽ (incremental)                                │
│                                                                     │
│  Вариант B: Финальная сумма значительно больше                      │
│  → Отдельная авторизация + capture на разницу                       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 Batch Close

**Batch close** — момент, когда пакет закрывается и отправляется на обработку.

**Варианты batch close:**

| Вариант | Описание | Кто использует |
|---------|----------|----------------|
| End of day | Закрытие в конце рабочего дня | Большинство магазинов |
| Scheduled | В определённое время (напр. 23:00) | Крупные сети |
| Threshold | По достижению суммы/количества | High-volume торговцы |
| Manual | Ручное закрытие кассиром | Редко |

**Важно:** До batch close транзакции можно отменить (void) без комиссий. После — только через refund.

### 3.2 Функции клиринга

**1. Matching (Сопоставление):**

Система сопоставляет capture с оригинальной авторизацией:

| Поле | Авторизация | Capture | Результат |
|------|-------------|---------|-----------|
| Auth Code | A12B3C | A12B3C | ✓ Match |
| Amount | 1,500 ₽ | 1,500 ₽ | ✓ Match |
| Card | 4276****1234 | 4276****1234 | ✓ Match |
| Merchant | Shop123 | Shop123 | ✓ Match |
| Date | 2024-03-15 | 2024-03-15 | ✓ Match |

**2. Netting (Взаимозачёт):**

```
┌─────────────────────────────────────────────────────────────────────┐
│                         NETTING                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  БЕЗ NETTING (Gross Settlement):                                    │
│  ─────────────────────────────────                                   │
│                                                                     │
│  Банк А → Банк Б: 10,000,000 ₽                                      │
│  Банк Б → Банк А:  8,500,000 ₽                                      │
│  Банк А → Банк В:  3,000,000 ₽                                      │
│  Банк В → Банк А:  4,200,000 ₽                                      │
│  Банк Б → Банк В:  2,500,000 ₽                                      │
│  Банк В → Банк Б:  1,800,000 ₽                                      │
│  ─────────────────────────────────                                   │
│  Итого переводов: 30,000,000 ₽                                      │
│                                                                     │
│  С NETTING (Net Settlement):                                        │
│  ─────────────────────────────                                       │
│                                                                     │
│  Нетто-позиции:                                                     │
│  Банк А: -10М + 8.5М - 3М + 4.2М = -0.3М (должен)                  │
│  Банк Б: +10М - 8.5М - 2.5М + 1.8М = +0.8М (получает)              │
│  Банк В: +3М - 4.2М + 2.5М - 1.8М = -0.5М (должен)                 │
│                                                                     │
│  Реальные переводы:                                                 │
│  Банк А → Settlement Bank: 300,000 ₽                                │
│  Банк В → Settlement Bank: 500,000 ₽                                │
│  Settlement Bank → Банк Б: 800,000 ₽                                │
│  ─────────────────────────────────                                   │
│  Итого переводов: 1,600,000 ₽                                       │
│                                                                     │
│  ЭФФЕКТИВНОСТЬ: сокращение на 95%!                                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**3. Calculation (Расчёт комиссий):**

Для каждой транзакции рассчитываются:
- Interchange fee (эмитенту)
- Scheme fee (платёжной системе)
- Assessment fee (если применимо)

**4. Reporting (Отчётность):**

Формируются отчёты для всех участников:
- Settlement reports для банков
- Billing statements для торговцев
- Regulatory reports

### 3.3 Clearing Files

**Форматы clearing files:**

| Формат | Описание | Использование |
|--------|----------|---------------|
| ISO 8583 | Классический формат сообщений | Традиционные системы |
| ISO 20022 | Современный XML/JSON формат | Новые системы, SWIFT gpi |
| Проприетарный | Форматы Visa/Mastercard | Внутри систем |

**Типичный цикл обмена:**

```
23:00 — Эквайер формирует clearing file
23:30 — Файл загружен в платёжную систему
00:00-04:00 — Обработка, matching, netting
04:00 — Результаты отправлены эмитентам
06:00 — Settlement instructions в settlement bank
```

## 4. Settlement: Фактический перевод денег

### 4.1 Как происходит settlement

```
┌─────────────────────────────────────────────────────────────────────┐
│                        SETTLEMENT FLOW                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Шаг 1: Settlement Instructions                                     │
│  ───────────────────────────────                                     │
│  Платёжная система → Settlement Bank                                │
│  "Списать X с Банка А, зачислить Y Банку Б"                        │
│                                                                     │
│  Шаг 2: Фондирование                                                │
│  ────────────────────                                                │
│  Банки с отрицательным балансом переводят средства                  │
│  на счёт в Settlement Bank                                          │
│                                                                     │
│  Шаг 3: Распределение                                               │
│  ─────────────────────                                               │
│  Settlement Bank переводит средства                                 │
│  банкам с положительным балансом                                    │
│                                                                     │
│  Шаг 4: Внутренние расчёты                                          │
│  ──────────────────────────                                          │
│  Эквайер → Торговец: сумма минус MDR                                │
│  Эмитент: списание со счёта держателя                               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 Settlement Banks

**Settlement bank** — банк, через который проводятся финальные расчёты.

| Платёжная система | Settlement Banks | Валюты |
|-------------------|------------------|--------|
| Visa | JPMorgan Chase, Standard Chartered, др. | USD, EUR, др. |
| Mastercard | Mastercard Settlement Bank | USD, EUR, GBP, др. |
| МИР | Банк России, расчётные банки | RUB |
| UnionPay | Bank of China, ICBC, др. | CNY, USD |

**Требования к settlement bank:**
- Высокий кредитный рейтинг
- Достаточная ликвидность
- Регуляторное одобрение
- Операционная надёжность (99.99%+ uptime)

### 4.3 Расчётные циклы

| Обозначение | Значение | Когда применяется |
|-------------|----------|-------------------|
| T+0 | В тот же день | Real-time payments (СБП, Faster Payments) |
| T+1 | Следующий рабочий день | Стандарт для карт в большинстве рынков |
| T+2 | Через 2 рабочих дня | Международные транзакции |
| T+3 и более | 3+ дней | Сложные случаи, high-risk |

**Пример T+1:**

```
Понедельник 15:30 — Покупка, авторизация
Понедельник 23:00 — Batch close
Вторник 04:00 — Клиринг завершён
Вторник 06:00 — Settlement
Вторник 09:00 — Деньги на счёте эквайера
Вторник 12:00 — Деньги на счёте торговца
```

### 5.3 Rolling Reserve

**Rolling Reserve** — часть средств, удерживаемая эквайером для покрытия возможных chargebacks и refunds.

```
┌─────────────────────────────────────────────────────────────────────┐
│                      ROLLING RESERVE                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Параметры:                                                         │
│  ───────────                                                         │
│  • Размер: 5-15% от оборота                                         │
│  • Срок удержания: 90-180 дней                                      │
│  • Применяется к: new merchants, high-risk, проблемные              │
│                                                                     │
│  Пример:                                                            │
│  ────────                                                            │
│  Транзакции за день: 100,000 ₽                                      │
│  Rolling reserve: 10%                                               │
│  ────────────────────────────────                                    │
│  Торговец получает сразу: 90,000 ₽                                  │
│  Удержано на reserve: 10,000 ₽                                      │
│                                                                     │
│  Через 180 дней:                                                    │
│  ──────────────────                                                  │
│  Reserve возвращается (если нет chargebacks)                        │
│  Reserve используется для погашения CB (если есть)                  │
│                                                                     │
│  Rolling effect:                                                    │
│  ─────────────────                                                   │
│  День 1: удержано 10K                                               │
│  День 2: удержано 10K, итого 20K                                    │
│  ...                                                                │
│  День 180: удержано 10K, возврат первых 10K → баланс 10K×180       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.4 Другие виды резервов

| Тип | Описание | Размер |
|-----|----------|--------|
| Rolling reserve | Процент от каждой выплаты | 5-15% |
| Capped reserve | Фиксированная сумма | $10K-100K |
| Up-front reserve | Предоплата до начала работы | Месячный оборот |
| Minimum balance | Минимальный остаток на счёте | $1K-10K |

## 6. Мультивалютный settlement

### 6.1 Валюта расчётов

Visa и Mastercard проводят расчёты преимущественно в **USD и EUR**:

```
┌─────────────────────────────────────────────────────────────────────┐
│              МУЛЬТИВАЛЮТНЫЙ SETTLEMENT                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Сценарий: Российский турист покупает в Италии                      │
│                                                                     │
│  1. Покупка: €100 в магазине                                        │
│     ─────────────────────────                                        │
│     Авторизация: €100 → RUB 11,500 (курс эмитента)                  │
│                                                                     │
│  2. Клиринг:                                                        │
│     ──────────                                                       │
│     Итальянский эквайер → Visa: €100                                │
│     Visa: EUR → USD (settlement currency)                           │
│     Visa → Российский эмитент: $108 (курс Visa)                     │
│                                                                     │
│  3. Settlement:                                                     │
│     ────────────                                                     │
│     Эмитент списывает: 11,500 ₽ (по курсу на день покупки)         │
│     Эквайер получает: €100 - interchange                            │
│     Торговец получает: €100 - MDR                                   │
│                                                                     │
│  Курсовые конвертации:                                              │
│  ──────────────────────                                              │
│  1. EUR → USD (Visa rate) — при settlement                          │
│  2. USD → RUB (эмитент) — при списании с карты                     │
│     ИЛИ RUB → USD (если оплата в рублях на DCC)                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.2 Курсовые риски

**Между авторизацией и settlement курс может измениться:**

| День | Событие | Курс EUR/RUB | Сумма |
|------|---------|--------------|-------|
| День 0 | Авторизация | 115.00 | 11,500 ₽ |
| День 1 | Settlement | 117.50 | 11,750 ₽ (был бы) |

**Кто несёт риск:**
- **Эмитент** — если курс вырос (теряет 250 ₽)
- **Держатель** — обычно списывается по курсу на день авторизации

### 6.3 Multi-Currency Pricing (MCP)

Visa и Mastercard предлагают MCP — возможность получать settlement в разных валютах:

**Преимущества MCP:**
- Меньше конвертаций
- Меньше курсовые потери
- Гибкость для мультивалютных торговцев

## 7. Проблемы при клиринге

### 7.1 Mismatches (Несоответствия)

**Когда capture не совпадает с авторизацией:**

| Проблема | Описание | Решение |
|----------|----------|---------|
| Amount mismatch | Сумма capture ≠ сумме auth | Partial OK, over — reject |
| Auth code not found | Код авторизации не найден | Reject или ручная проверка |
| Expired auth | Авторизация просрочена | Новая авторизация |
| Card mismatch | Номер карты не совпадает | Reject |
| Merchant mismatch | Другой торговец | Reject |

### 7.2 Duplicate Transactions

**Причины дубликатов:**
- Технический сбой (повторная отправка)
- Ошибка POS-терминала
- Человеческая ошибка

**Выявление:**
```
Дубликат если совпадают:
• Merchant ID
• Card Number
• Amount
• Date
• Time (±N минут)
```

### 7.3 Late Presentment

**Late presentment** — представление транзакции к клирингу позже разрешённого срока.

| Платёжная система | Срок представления | Последствия |
|-------------------|-------------------|-------------|
| Visa | 7 дней (domestic), 14 дней (international) | Reject или chargeback right |
| Mastercard | 7-14 дней | Reject |
| МИР | 7-14 дней | Reject |

**Исключения:**
- Delayed delivery merchants (круизы, авиа) — до 120 дней
- Subscription services — срок от последнего billing

### 7.4 Chargebacks в settlement

```
┌─────────────────────────────────────────────────────────────────────┐
│                   CHARGEBACK В SETTLEMENT                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Исходная транзакция (День 1):                                      │
│  ──────────────────────────────                                      │
│  Settlement: +10,000 ₽ → Торговец                                   │
│                                                                     │
│  Chargeback (День 45):                                              │
│  ─────────────────────                                               │
│  Эмитент инициирует chargeback                                      │
│  Settlement adjustment: -10,000 ₽ ← Торговец                        │
│  Chargeback fee: -500 ₽ ← Торговец                                  │
│  ──────────────────────────────                                      │
│  Итого с торговца: -10,500 ₽                                        │
│                                                                     │
│  Если торговец выиграл representment (День 75):                     │
│  ───────────────────────────────────────────────                     │
│  Settlement: +10,000 ₽ → Торговец                                   │
│  (fee обычно не возвращается)                                       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 8. Reconciliation (Сверка)

### 8.1 Зачем нужна сверка

**Reconciliation** — сопоставление данных между участниками для выявления расхождений.

**Уровни сверки:**

| Уровень | Участники | Что сверяется |
|---------|-----------|---------------|
| Терминал-Эквайер | POS ↔ Acquirer | Транзакции, суммы |
| Торговец-Эквайер | Merchant ↔ Acquirer | Payouts, fees |
| Эквайер-ПС | Acquirer ↔ Visa/MC | Clearing totals |
| ПС-Эмитент | Visa/MC ↔ Issuer | Settlement amounts |

### 8.2 Процесс сверки

```
┌─────────────────────────────────────────────────────────────────────┐
│                     RECONCILIATION PROCESS                           │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Данные торговца:              Данные эквайера:                     │
│  ──────────────────            ───────────────────                   │
│  ├── Trans 001: 1,500 ₽        ├── Trans 001: 1,500 ₽ ✓            │
│  ├── Trans 002: 3,200 ₽        ├── Trans 002: 3,200 ₽ ✓            │
│  ├── Trans 003: 890 ₽          ├── Trans 003: ???     ✗            │
│  ├── Trans 004: 2,100 ₽        ├── Trans 004: 2,100 ₽ ✓            │
│  └── Trans 005: 1,800 ₽        ├── Trans 005: 1,800 ₽ ✓            │
│                                └── Trans 006: 750 ₽   ✗            │
│  ─────────────────────         ─────────────────────                │
│  ИТОГО: 9,490 ₽                ИТОГО: 9,350 ₽                       │
│                                                                     │
│  Расхождения:                                                       │
│  ─────────────                                                       │
│  • Trans 003: есть у торговца, нет у эквайера (потеряна?)          │
│  • Trans 006: есть у эквайера, нет у торговца (дубликат?)          │
│                                                                     │
│  Действия:                                                          │
│  ──────────                                                          │
│  1. Проверить логи терминалов                                       │
│  2. Сверить с batch files                                           │
│  3. Открыть тикет на расследование                                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 8.3 Типы расхождений

| Тип | Причина | Действие |
|-----|---------|----------|
| Missing transaction | Потеря в передаче, отмена | Повторная отправка или списание |
| Amount difference | Partial capture, ошибка | Корректировка |
| Duplicate | Повторная отправка | Удаление дубликата, возврат |
| Fee discrepancy | Неверный расчёт комиссий | Перерасчёт |
| FX difference | Курсовая разница | Обычно в пределах нормы |

### 8.4 Автоматизация reconciliation

**Современные системы обеспечивают:**
- Ежедневную автоматическую сверку
- Real-time alerts при расхождениях
- Автоматическое разрешение типовых проблем
- Dashboard с метриками качества

**Ключевые метрики:**
- Match rate: >99.9%
- Exception rate: <0.1%
- Resolution time: <24 часов

## 9. Real-time Settlement

### 9.1 Тренд к мгновенным расчётам

Рынок движется от T+1-T+2 к **real-time settlement**:

```
┌─────────────────────────────────────────────────────────────────────┐
│                  ЭВОЛЮЦИЯ SETTLEMENT                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Прошлое:       Настоящее:        Будущее:                         │
│  ──────────     ────────────      ────────                          │
│  T+3 — T+7      T+1 — T+2         T+0 / Real-time                   │
│                                                                     │
│  Batch weekly   Batch daily       Continuous                        │
│  Manual         Automated         AI-driven                         │
│  ISO 8583       ISO 8583+20022    ISO 20022                         │
│                                                                     │
│  ────────────────────────────────────────────────────────────►     │
│                         TIME                                        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 9.2 Системы быстрых платежей

| Система | Страна | Время settlement | Объём |
|---------|--------|------------------|-------|
| Faster Payments | UK | < 2 часа (часто секунды) | £8 трлн/год |
| СБП | Россия | Секунды | Быстрорастущий |
| SEPA Instant | ЕС | < 10 секунд | €50+ млрд/мес |
| RTP | США | Секунды | Растущий |
| TIPS | ЕС (Eurosystem) | < 10 секунд | Растущий |
| UPI | Индия | Секунды | $2+ трлн/год |
| PIX | Бразилия | Секунды | Доминирует |

### 9.3 Карты и real-time settlement

Для карточных платежей real-time settlement пока редкость, но развивается:

**Push-to-card сервисы:**
- **Visa Direct** — мгновенные переводы на карты
- **Mastercard Send** — аналогичный сервис

**Ограничения:**
- Сложившаяся инфраструктура (batch-ориентированная)
- Необходимость netting для эффективности
- Риски (fraud, liquidity)

### 9.4 Преимущества быстрого settlement

| Преимущество | Описание |
|--------------|----------|
| Cash flow | Торговец получает деньги сразу |
| Ликвидность | Меньше денег "в пути" |
| Снижение риска | Меньше exposure к контрагентам |
| Customer experience | Мгновенные refunds |
| Конкуренция | Преимущество над "медленными" |

## 10. Технологии и стандарты

### 10.1 ISO 8583 vs ISO 20022

| Аспект | ISO 8583 | ISO 20022 |
|--------|----------|-----------|
| Формат | Бинарный, bitmap | XML/JSON |
| Поля | Фиксированные номера | Семантические имена |
| Читаемость | Машинная | Человек + машина |
| Расширяемость | Ограниченная | Высокая |
| Использование | Карточные ПС | SWIFT, новые системы |

### 10.2 Миграция на ISO 20022

**SWIFT ISO 20022 migration:**
- Начало: 2022
- Завершение: 2025
- Цель: унифицированный формат для всех платежей

**Влияние на клиринг:**
- Больше данных в сообщениях
- Лучше автоматизация
- Улучшенный compliance
- End-to-end transparency

## 💡 Key Takeaways

1. **Клиринг ≠ Settlement:** Клиринг — подготовка данных, Settlement — фактический перевод денег
2. **Netting экономит:** Взаимозачёт снижает объём переводов на 90-95%
3. **T+1 — стандарт:** Большинство торговцев получают деньги на следующий рабочий день
4. **Rolling reserve:** Часть денег может удерживаться для покрытия рисков
5. **Reconciliation критична:** Ежедневная сверка предотвращает финансовые потери
6. **Real-time приходит:** Но для карт пока медленнее, чем для A2A платежей
7. **Курсовые риски:** При международных транзакциях курс может измениться
8. **ISO 20022:** Новый стандарт улучшит прозрачность и автоматизацию
