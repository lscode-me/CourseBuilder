## 1. Что такое Chargeback

### 1.1 Определение и сущность

**Chargeback** (чарджбек, возвратный платёж) — механизм принудительного возврата средств держателю карты, инициированный банком-эмитентом в соответствии с правилами платёжной системы.

**Ключевые характеристики:**

| Характеристика | Описание |
|----------------|----------|
| Инициатор | Банк-эмитент (по заявлению держателя карты) |
| Механизм | Принудительное списание с торговца |
| Право ответа | Торговец может оспорить (representment) |
| Регулирование | Правила платёжных систем (Visa, Mastercard, МИР) |
| Арбитраж | Платёжная система выступает финальным арбитром |

**Отличие от возврата (refund):**

```
┌─────────────────────────────────────────────────────────────────┐
│                    REFUND vs CHARGEBACK                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  REFUND (Возврат)                 CHARGEBACK (Чарджбек)         │
│  ─────────────────                ──────────────────────         │
│  • Инициирует торговец            • Инициирует эмитент          │
│  • Добровольный                   • Принудительный              │
│  • Нет дополнительных комиссий    • Комиссия $15-100            │
│  • Не влияет на ratio             • Влияет на chargeback ratio  │
│  • Быстрый процесс                • Длительный процесс          │
│  • Без последствий                • Может привести к санкциям   │
│                                                                  │
│  Рекомендация: Всегда предпочитайте refund вместо chargeback!   │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 История и цель механизма

Chargeback был введён в США в 1974 году как часть **Fair Credit Billing Act** для защиты потребителей от мошенничества и недобросовестных торговцев.

**Цели механизма:**

1. **Защита потребителя:**
   - От несанкционированных транзакций
   - От мошенничества
   - От недобросовестных торговцев
   - От ошибок обработки

2. **Доверие к карточным платежам:**
   - Гарантия безопасности для держателей карт
   - Стимул использовать карты вместо наличных
   - Рост карточной экономики

3. **Баланс интересов:**
   - Держатель защищён от потерь
   - Торговец имеет право на ответ
   - Платёжная система обеспечивает справедливость

## 2. Причины Chargeback

### 2.1 Классификация причин

Платёжные системы классифицируют chargebacks по категориям. Каждой причине присвоен уникальный **Reason Code**.

**Основные категории:**

| Категория | Visa Codes | Mastercard Codes | Доля |
|-----------|------------|------------------|------|
| Мошенничество (Fraud) | 10.x | 48xx | ~35% |
| Товар/услуга (Consumer Disputes) | 13.x | 48xx | ~30% |
| Авторизация (Authorization) | 11.x | 48xx | ~20% |
| Обработка (Processing Errors) | 12.x | 48xx | ~15% |

### 2.2 Мошенничество (Fraud)

**Типы мошенничества:**

1. **True Fraud (Истинное мошенничество):**
   - Украденная карта
   - Скомпрометированные данные
   - Phishing/Скимминг
   - Подделка карты

2. **Friendly Fraud (Дружественное мошенничество):**
   - Покупатель заявляет о мошенничестве
   - На самом деле сам совершил покупку
   - Получил товар/услугу
   - Хочет не платить или получить товар бесплатно

3. **Family Fraud (Семейное мошенничество):**
   - Покупку совершил член семьи
   - Ребёнок без разрешения родителей
   - Держатель не признаёт транзакцию

**Reason Codes для мошенничества:**

### 2.3 Споры потребителей (Consumer Disputes)

**Товар не получен:**
- Посылка не доставлена
- Доставка на неверный адрес
- Виртуальный товар не активирован

**Товар не соответствует описанию:**
- Качество ниже ожидаемого
- Неверный размер/цвет
- Дефекты или повреждения
- Контрафактный товар

**Услуга не оказана:**
- Бронирование отменено
- Услуга не предоставлена
- Качество услуги неприемлемо

**Reason Codes для споров:**

| Платёжная система | Code | Описание |
|-------------------|------|----------|
| Visa | 13.1 | Merchandise/Services Not Received |
| Visa | 13.2 | Cancelled Recurring Transaction |
| Visa | 13.3 | Not as Described or Defective |
| Visa | 13.4 | Counterfeit Merchandise |
| Visa | 13.5 | Misrepresentation |
| Visa | 13.6 | Credit Not Processed |
| Visa | 13.7 | Cancelled Merchandise/Services |
| Mastercard | 4853 | Cardholder Dispute |
| Mastercard | 4855 | Goods or Services Not Provided |

### 2.4 Ошибки авторизации (Authorization)

**Типичные причины:**
- Транзакция без авторизации
- Просроченная авторизация
- Авторизация на другую сумму
- Declined транзакция всё равно проведена

**Reason Codes:**

| Code | Описание |
|------|----------|
| Visa 11.1 | Card Recovery Bulletin |
| Visa 11.2 | Declined Authorization |
| Visa 11.3 | No Authorization |
| MC 4808 | Authorization-Related Chargeback |

### 3.2 Этапы детально

**Этап 1: Претензия держателя карты**

Держатель обращается в банк-эмитент:
- Через мобильное приложение
- По телефону горячей линии
- В отделении банка
- Через интернет-банк

Эмитент собирает информацию:
- Дата и сумма транзакции
- Причина претензии
- Попытки решить вопрос с торговцем
- Документы (если есть)

**Этап 2: First Chargeback**

Эмитент принимает решение и создаёт chargeback:
- Присваивает reason code
- Формирует сообщение для платёжной системы
- Списывает средства со своего счёта
- Кредитует счёт держателя (provisional credit)

**Этап 3: Уведомление торговца**

Эквайер получает chargeback и:
- Списывает средства со счёта торговца
- Взимает комиссию за chargeback
- Уведомляет торговца
- Предоставляет срок для ответа

**Этап 4: Representment (оспаривание)**

Торговец может:

| Действие | Когда выбрать |
|----------|---------------|
| Принять CB | Нет доказательств, ошибка торговца, мелкая сумма |
| Оспорить | Есть доказательства, значительная сумма, явный fraud |

**Этап 5: Решение эмитента**

Эмитент рассматривает доказательства:
- Принимает representment → CB отменён
- Отклоняет → Second Chargeback (Pre-Arbitration)

**Этап 6: Арбитраж**

Если стороны не согласны:
- Дело передаётся платёжной системе
- Комиссия за арбитраж $300-500
- Решение финальное и обязательное

## 4. Сроки и дедлайны

### 4.1 Сроки подачи chargeback

| Платёжная система | Стандартный срок | Особые случаи |
|-------------------|------------------|---------------|
| Visa | 120 дней от транзакции | До 540 дней для некоторых fraud |
| Mastercard | 120 дней | Зависит от reason code |
| American Express | 120 дней | 365 дней для некоторых |
| МИР | 60-120 дней | Зависит от категории |

### 4.2 Исключения из стандартных сроков

**Отложенная доставка:**
- Срок отсчитывается от ожидаемой даты доставки
- Не от даты транзакции

**Подписки и рекурренты:**
- Срок от последнего списания
- Или от даты обнаружения проблемы

**Предоплаченные услуги:**
- Срок от даты оказания услуги
- Например, бронирование отеля на будущее

### 4.3 Сроки для ответа торговца

| Этап | Visa | Mastercard | МИР |
|------|------|------------|-----|
| First Chargeback → Representment | 30 дней | 45 дней | 30 дней |
| Second CB → Pre-Arb response | 30 дней | 30 дней | — |
| Pre-Arb → Arbitration | 10 дней | 45 дней | — |

**Важно:** Пропуск дедлайна означает автоматический проигрыш!

### 4.4 Календарные vs рабочие дни

**Visa:** Обычно календарные дни
**Mastercard:** Часто рабочие дни (исключая выходные и праздники)
**МИР:** Преимущественно рабочие дни

│  Сумма транзакции возвращена:          -10,000 ₽                │
│  Комиссия за chargeback:               -500 ₽                   │
│  Товар не возвращён (fraud):           -6,000 ₽ (себестоимость) │
│  Время менеджера на обработку:         -500 ₽ (условно)         │
│  ─────────────────────────────────────────────                   │
│  Убыток от одного CB:                  -17,000 ₽                │
│                                                                  │
│  Реальные потери = Прибыль + Убыток = 3,800 + 17,000 = 20,800 ₽ │
│                                                                  │
│  💡 Один chargeback "съедает" прибыль от ~5-7 успешных продаж!  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 Комиссии за chargeback

| Тип | Visa | Mastercard | МИР |
|-----|------|------------|-----|
| Стандартная | $15-25 | $15-25 | 500-1000 ₽ |
| High-risk MCC | $25-50 | $25-50 | 1000-2000 ₽ |
| Повторный CB | $50-75 | $50-75 | — |
| Pre-Arbitration | $50-100 | $50 | — |
| Arbitration | $500 | $300-400 | — |

### 5.3 Chargeback Ratio

**Chargeback Ratio** — ключевая метрика здоровья мерчанта:

```
Chargeback Ratio = (Количество chargebacks / Количество транзакций) × 100%

Альтернативный расчёт (Visa):
Chargeback Ratio = Chargebacks / Sales Volume
```

**Пороговые значения:**

| Уровень | Ratio | Или абс. кол-во | Последствия |
|---------|-------|-----------------|-------------|
| Норма | < 0.65% | < 75 CB/мес | Нет санкций |
| Early Warning | 0.65-0.9% | 75-100 CB | Уведомление |
| Standard | 0.9-1.8% | > 100 CB | Мониторинг, штрафы |
| Excessive | > 1.8% | > 300 CB | Высокие штрафы, риск отключения |

### 5.4 Мониторинговые программы

**Visa Dispute Monitoring Program (VDMP):**

```

│  Уровень Standard:                                              │

### 5.5 Reserve и удержания

При высоком chargeback ratio эквайер может:

| Capped Reserve | Фиксированный депозит (напр. $50,000) |
| Up-front Reserve | Предоплата до начала работы |
| Delayed Settlement | Задержка выплат на 7-30 дней |

## 6. Friendly Fraud

### 6.1 Определение и масштаб

**Friendly Fraud** (дружественное мошенничество) — ситуация, когда держатель карты:
- Сам совершил покупку
- Получил товар или услугу
- Но заявляет chargeback как "мошенничество"

**Статистика:**
- 60-80% всех chargebacks — friendly fraud
- Ежегодный рост: 15-20%
- Особенно распространён в e-commerce

### 6.2 Типы friendly fraud

```
┌─────────────────────────────────────────────────────────────────┐
│                   ТИПЫ FRIENDLY FRAUD                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. "Раскаяние покупателя" (Buyer's Remorse)                    │
│     ──────────────────────────────────────────                   │
│     Клиент передумал, но не хочет возвращать товар              │
│     Проще заявить "не я платил"                                 │
│                                                                  │
│  2. "Забывчивость"                                              │
│     ───────────────                                              │
│     Клиент не узнаёт название торговца в выписке                │
│     Billing descriptor: "ACME CORP 8005551234"                  │
│     Клиент: "Я не знаю эту компанию!"                           │
│                                                                  │
│  3. "Семейный fraud"                                            │
│     ──────────────────                                           │
│     Покупку совершил член семьи (ребёнок, супруг)               │
│     Держатель карты не в курсе                                  │
│                                                                  │
│  4. "Cyber-shoplifting"                                         │
│     ─────────────────────                                        │
│     Умышленное получение товара бесплатно                       │
│     Заказ → Получение → Chargeback                              │
│                                                                  │
│  5. "Subscription trap"                                         │
│     ───────────────────                                          │
│     Клиент забыл отменить trial → платная подписка              │
│     Вместо отмены — chargeback                                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 6.3 Признаки friendly fraud

| Признак | Описание |
|---------|----------|
| Доставка подтверждена | Трекинг показывает "Доставлено" |
| IP совпадает | Авторизация с обычного IP клиента |
| Device fingerprint | Тот же device, что и предыдущие покупки |
| История покупок | Клиент делал покупки раньше |
| Контакт с поддержкой | Клиент обращался по поводу заказа |
| Частичное использование | Цифровой товар активирован/использован |

### 6.4 Борьба с friendly fraud

**Технические меры:**
- Обязательная регистрация с email и телефоном
- Device fingerprinting
- Behavioral analytics
- 3-D Secure для всех транзакций

**Процессные меры:**
- Чёткий billing descriptor
- Подтверждение доставки с подписью
- Сохранение всех коммуникаций
- Качественная служба поддержки

**Юридические меры:**
- Чёткая политика возврата
- Согласие с условиями при покупке
- Предупреждение о последствиях fraud

## 7. Representment: защита торговца

### 7.1 Когда оспаривать

**Стоит оспаривать (Win Rate > 50%):**
- Есть подтверждение доставки с подписью
- 3-D Secure успешно пройден
- Клиент использовал товар/услугу
- Переписка подтверждает получение
- Явные признаки friendly fraud

**Не стоит оспаривать:**
- Нет доказательств
- Действительно ошибка торговца
- Сумма меньше стоимости процесса ($50-100)
- Предыдущие representments отклонены

### 7.2 Compelling Evidence

**Что собрать для representment:**

```
┌─────────────────────────────────────────────────────────────────┐
│                   COMPELLING EVIDENCE                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Для "Товар не получен" (13.1):                                 │
│  ─────────────────────────────────                               │
│  ✓ Tracking number и статус доставки                            │
│  ✓ Подпись получателя (если есть)                               │
│  ✓ Фото доставки (Amazon-style)                                 │
│  ✓ GPS-координаты доставки                                      │
│  ✓ Переписка с клиентом о получении                             │
│                                                                  │
│  Для "Fraud" (10.4):                                            │
│  ──────────────────                                              │
│  ✓ 3-D Secure authentication                                    │
│  ✓ AVS match (Address Verification)                             │
│  ✓ CVV match                                                    │
│  ✓ Device fingerprint (тот же device)                           │
│  ✓ IP геолокация (совпадает с billing)                          │
│  ✓ История предыдущих покупок с этого аккаунта                  │
│  ✓ Email/SMS подтверждения, открытые клиентом                   │

│  ✓ Terms & Conditions с подписью/галочкой                       │

```

### 7.3 Формат представления

**Структура ответа:**

1. **Cover Letter:**
   - Номер chargeback и reason code
   - Краткое описание ситуации
   - Почему chargeback необоснован

2. **Timeline событий:**
   - Дата заказа
   - Дата отправки
   - Дата доставки
   - Дата chargeback

3. **Документы:**
   - Копия заказа
   - Подтверждение оплаты
   - Proof of delivery
   - Переписка

4. **Заключение:**
   - Требование отмены chargeback
   - Ссылки на правила ПС

### 7.4 Win Rate по категориям

| Reason Code | Средний Win Rate | Ключевой фактор |
|-------------|------------------|-----------------|
| Fraud (10.4) CNP | 20-30% | 3-D Secure, Device ID |
| Fraud (10.4) с 3DS | 60-80% | Liability shift |
| Not Received (13.1) | 40-60% | Tracking + подпись |
| Not as Described (13.3) | 30-40% | Переписка, фото |
| Cancelled Recurring (13.2) | 50-70% | Terms & logs |

### 8.2 Billing Descriptor

**Проблема:**

Клиент видит в выписке: `ACME CORP LLC 8005551234`
Клиент думает: "Что это? Я не покупал у ACME CORP!"
Результат: Chargeback

**Решение:**

| Плохо | Хорошо |
|-------|--------|
| ACME CORP LLC | MYSHOP.RU*Заказ 12345 |
| PSP GATEWAY | COFFEESHOP Москва |
| 8005551234 | STREAMING*Premium Sub |

### 8.3 Сервисы раннего предупреждения

**Ethoca Alerts (Mastercard):**
- Уведомление о споре до chargeback
- Возможность сделать refund
- Предотвращает 40-70% chargebacks

**Verifi CDRN (Visa Cardholder Dispute Resolution Network):**
- Аналогичный сервис для Visa
- Real-time уведомления
- Автоматический или ручной refund

**Verifi RDR (Rapid Dispute Resolution):**
- Автоматическое разрешение споров
- На основе заданных правил
- Минимизация ручной работы

### 8.4 3-D Secure и Liability Shift

**Как работает Liability Shift:**

```
БЕЗ 3-D Secure:
  Fraud → Chargeback → Торговец платит

С 3-D Secure (успешная аутентификация):
  Fraud → Chargeback → Эмитент платит (Liability Shift)

С 3-D Secure (неуспешная аутентификация):
  Эмитент отклонил 3DS → Торговец сам решает → Принимает риск
```

**Важно:** Liability shift работает только для fraud chargebacks (10.x), но не для споров о товаре (13.x).

## 💡 Key Takeaways

1. **Chargeback — принудительный возврат** по инициативе эмитента, не торговца
2. **120 дней** — стандартный срок для подачи chargeback (Visa/Mastercard)
3. **Friendly fraud составляет до 70%** всех chargebacks
4. **Chargeback ratio > 1%** приводит к штрафам и риску отключения
5. **Один CB "съедает" прибыль** от 5-7 успешных продаж
6. **Торговец имеет право на representment** с доказательствами
7. **3-D Secure обеспечивает liability shift** для fraud chargebacks
8. **Сервисы раннего предупреждения** (Ethoca, Verifi) предотвращают до 70% CB
9. **Чёткий billing descriptor** снижает "дружественное мошенничество"
10. **Документирование всего** — ключ к успешному оспариванию
