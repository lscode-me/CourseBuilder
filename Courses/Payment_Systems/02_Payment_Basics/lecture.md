## 1. Введение

Когда вы оплачиваете покупку картой, за секунды происходит сложное взаимодействие нескольких организаций. Каждая из них выполняет свою роль, и понимание этих ролей — ключ к пониманию всей платёжной индустрии.

В этой лекции мы разберём:

## 2. Что такое платёж

### 2.1 Определение

**Платёж** — передача денежных средств от плательщика к получателю в обмен на товары, услуги или в погашение обязательств.

**Ключевые характеристики платежа:**
- **Плательщик** — кто платит
- **Получатель** — кто получает
- **Сумма** — сколько
- **Валюта** — в чём измерена сумма
- **Основание** — за что платёж
- **Время** — когда совершён

### 2.2 Типы платежей

| Тип | Описание | Примеры |
|-----|----------|---------|
| Наличный | Физическая передача денег | Оплата в магазине купюрами |
| Безналичный | Перевод между счетами | Карточный платёж, перевод |
| Электронный | Через цифровые каналы | Онлайн-покупка, мобильный платёж |

### 2.3 Карточный платёж

**Карточный платёж** — безналичный платёж с использованием банковской карты как инструмента инициации.

**Карта — это не деньги.** Карта — это:
- Инструмент идентификации держателя
- Способ доступа к счёту
- Носитель платёжных данных

## 3. Участники платёжной системы

### 3.1 Четырёхсторонняя модель (Four-Party Model)

Большинство карточных платежей работают по четырёхсторонней модели:

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│    ┌─────────────┐                    ┌─────────────┐        │
│    │  Держатель  │                    │   Торговец  │        │
│    │   карты     │  ────────────────► │  (Merchant) │        │
│    │ (Cardholder)│      Покупка       │             │        │
│    └──────┬──────┘                    └──────┬──────┘        │
│           │                                  │               │
│           │ Карта                     Терминал               │
│           │                                  │               │
│    ┌──────▼──────┐                    ┌──────▼──────┐        │
│    │    Банк-    │                    │    Банк-    │        │
│    │   эмитент   │ ◄────────────────► │   эквайер   │        │
│    │  (Issuer)   │  Платёжная сеть    │  (Acquirer) │        │
│    └─────────────┘                    └─────────────┘        │
│                                                              │
│              ┌─────────────────────────┐                     │
│              │    Платёжная система    │                     │
│              │   (Visa, Mastercard)    │                     │
│              └─────────────────────────┘                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 Держатель карты (Cardholder)

**Кто это:** Физическое лицо, которому банк выдал карту.

**Роль в платеже:**
- Инициирует платёж
- Предоставляет данные карты
- Подтверждает транзакцию (PIN, подпись, биометрия)

**Права:**
- Использовать карту для оплаты
- Оспаривать транзакции
- Получать выписки

**Обязанности:**
- Хранить карту в безопасности
- Не передавать данные третьим лицам
- Сообщать о потере/краже

### 3.3 Торговец (Merchant)

**Кто это:** Юридическое или физическое лицо, принимающее оплату картой.

**Роль в платеже:**
- Предоставляет товары/услуги
- Принимает платёж через терминал
- Отправляет данные эквайеру

**Также называется:**
- Торговая точка
- Мерчант
- Точка продаж (POS — Point of Sale)

**Обязательства:**
- Соблюдать правила платёжных систем
- Обеспечивать безопасность данных (PCI DSS)
- Принимать возвраты по правилам

### 3.4 Банк-эмитент (Issuer)

**Кто это:** Банк, выпустивший карту держателю.

**Роль в платеже:**
- Выпускает карты
- Ведёт счёт держателя
- Авторизует или отклоняет транзакции
- Переводит средства эквайеру

**Примеры:** Сбербанк, Тинькофф, ВТБ (как эмитенты карт).

**За что отвечает:**
- Проверка доступных средств/лимита
- Аутентификация держателя
- Управление рисками (fraud detection)

### 3.5 Банк-эквайер (Acquirer)

**Кто это:** Банк, обслуживающий торговца.

**Роль в платеже:**
- Предоставляет терминалы
- Принимает транзакции от торговца
- Передаёт их в платёжную систему
- Переводит деньги торговцу

**Примеры:** Сбербанк, ВТБ, Русский Стандарт (как эквайеры).

**За что отвечает:**
- Подключение торговых точек
- Техническая поддержка терминалов
- Расчёты с торговцем

> **💡 Важно:**  
> Один банк может быть одновременно эмитентом и эквайером. Например, Сбербанк выпускает карты (эмитент) и обслуживает магазины (эквайер).

### 3.6 Платёжная система (Payment Network)

**Кто это:** Организация, устанавливающая правила и обеспечивающая инфраструктуру.

**Роль:**
- Устанавливает стандарты и правила
- Маршрутизирует транзакции между банками
- Проводит клиринг и расчёты
- Арбитраж споров

**Международные:**
- Visa
- Mastercard
- American Express (трёхсторонняя модель)
- UnionPay
- JCB

**Национальные:**
- МИР (Россия)
- Bancontact (Бельгия)
- iDEAL (Нидерланды)

## 4. Трёхсторонняя модель

### 4.1 Как устроена

В трёхсторонней модели платёжная система сама является эмитентом и эквайером:

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  ┌─────────────┐           ┌─────────────┐      │
│  │  Держатель  │ ────────► │   Торговец  │      │
│  │   карты     │           │             │      │
│  └──────┬──────┘           └──────┬──────┘      │
│         │                        │              │
│         │                        │              │
│         ▼                        ▼              │
│  ┌──────────────────────────────────────┐       │
│  │         Платёжная система            │       │
│  │   (эмитент + эквайер + сеть)         │       │
│  │       American Express, Diners       │       │
│  └──────────────────────────────────────┘       │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 4.2 Примеры

- **American Express** — сама выпускает карты и работает с торговцами
- **Diners Club** — аналогично
- **Discover** — в США

**Преимущества:**
- Больший контроль над процессом
- Единые стандарты
- Прямые отношения с клиентами

**Недостатки:**
- Меньший охват (нужно самим подключать торговцев)
- Более высокие комиссии

## 5. Основные этапы платежа

### 5.1 Обзор этапов

Карточный платёж проходит три основных этапа:

```
   Авторизация          Клиринг             Расчёты
       │                   │                   │
       ▼                   ▼                   ▼
   ┌───────┐           ┌───────┐           ┌───────┐
   │ Можно │           │ Данные│           │ Деньги│
   │платить│    ───►   │собраны│    ───►   │перешли│
   │   ?   │           │       │           │       │
   └───────┘           └───────┘           └───────┘
   
  Секунды           Часы/Дни            Дни
```

### 5.2 Авторизация (Authorization)

**Что это:** Проверка возможности совершить платёж.

**Что происходит:**
1. Держатель предъявляет карту
2. Терминал считывает данные
3. Запрос идёт через эквайера в платёжную сеть
4. Платёжная сеть направляет запрос эмитенту
5. Эмитент проверяет:
   - Карта действительна?
   - Достаточно средств/лимита?
   - Нет ли подозрений на мошенничество?
6. Эмитент отвечает: Approved или Declined
7. Ответ возвращается на терминал

**Время:** Обычно 1-3 секунды.

**Результат авторизации:**
- **Approved** — платёж одобрен
- **Declined** — платёж отклонён (с кодом причины)
- **Referral** — требуется звонок в банк (редко)

### 5.3 Холдирование (Hold)

**Что это:** Блокировка средств на счёте держателя.

После успешной авторизации:
- Деньги ещё не списаны
- Но заблокированы для других транзакций
- Сумма недоступна держателю

**Пример:**
- На счёте: 10 000 ₽
- Авторизация: 3 000 ₽
- Доступно: 7 000 ₽
- Баланс: 10 000 ₽ (деньги ещё на счёте)

### 5.4 Клиринг (Clearing)

**Что это:** Сбор и обработка данных о транзакциях.

**Что происходит:**
1. Торговец отправляет данные о транзакциях эквайеру
2. Эквайер передаёт в платёжную систему
3. Платёжная система агрегирует транзакции
4. Рассчитывает нетто-позиции банков

**Batch processing:**
- Транзакции обычно обрабатываются пакетами
- Раз в день (или несколько раз)
- Не в реальном времени

### 5.5 Расчёты (Settlement)

**Что это:** Фактический перевод денег между банками.

**Что происходит:**
1. Платёжная система определяет, кто кому должен
2. Деньги переводятся от эмитента к эквайеру
3. Эквайер переводит деньги торговцу (за вычетом комиссии)
4. Эмитент списывает деньги со счёта держателя

**Сроки:**
- T+1 — расчёты на следующий рабочий день
- T+2 — через два рабочих дня
- T+3 — через три дня (реже)

## 6. Ключевые термины

### 6.1 Идентификаторы

| Термин | Расшифровка | Описание |
|--------|-------------|----------|
| **PAN** | Primary Account Number | Номер карты (16 цифр) |
| **BIN/IIN** | Bank Identification Number | Первые 6-8 цифр, идентификатор банка |
| **CVV/CVC** | Card Verification Value/Code | Код безопасности (3 цифры на обороте) |
| **MID** | Merchant ID | Идентификатор торговца |
| **TID** | Terminal ID | Идентификатор терминала |

### 6.2 Типы транзакций

| Термин | Описание |
|--------|----------|
| **Purchase** | Покупка — стандартный платёж |
| **Refund** | Возврат — деньги возвращаются держателю |
| **Void** | Отмена — транзакция отменена до расчётов |
| **Reversal** | Реверсал — техническая отмена |
| **Pre-auth** | Преавторизация — резервирование суммы |
| **Capture** | Capture — подтверждение преавторизации |

### 6.3 Коды ответов

**Основные коды авторизации:**

| Код | Значение |
|-----|----------|
| 00 | Approved (одобрено) |
| 05 | Do not honor (отказ без объяснения) |
| 14 | Invalid card number |
| 41 | Lost card |
| 43 | Stolen card |
| 51 | Insufficient funds |
| 54 | Expired card |
| 61 | Exceeds limit |

> **⚠️ Важно:**  
> Код "05" — самый частый код отказа. Банк не объясняет причину из соображений безопасности.

## 7. Типы карточных транзакций

### 7.1 По присутствию карты

**Card Present (CP):**
- Карта физически присутствует
- Магазины, рестораны, АЗС
- Более низкий риск мошенничества
- Меньшие комиссии

**Card Not Present (CNP):**
- Карта не предъявляется физически
- Интернет-покупки, телефонные заказы
- Более высокий риск
- Выше комиссии

### 7.2 По способу ввода

| Способ | Описание | Безопасность |
|--------|----------|--------------|
| Магнитная полоса | Считывание магнитной полосы | Низкая |
| Чип (EMV) | Чтение чипа + PIN | Высокая |
| Бесконтактный | NFC, без PIN до лимита | Средняя |
| Ручной ввод | Ввод номера вручную | Низкая |
| Токен | Использование токена | Высокая |

### 7.3 Специальные типы

**Recurring (подписка):**
- Регулярные автоматические списания
- Netflix, Spotify, абонементы
- Требует согласия держателя

**Installment (рассрочка):**
- Разбиение суммы на части
- BNPL (Buy Now Pay Later)

**MOTO (Mail Order/Telephone Order):**
- Заказы по почте или телефону
- Высокий риск, особые требования

## 8. Потоки данных и денег

### 8.1 Поток данных (при авторизации)

```
Держатель ──► Терминал ──► Эквайер ──► Платёжная ──► Эмитент
                                         сеть
                                         
                          ◄────────────────────────────────
                                    Ответ
```

### 8.2 Поток денег (при расчётах)

```
                    Interchange
Эмитент ──────────────────────────────────► Эквайер
    │                                          │
    │                                          │
    ▼                                          ▼
Списание                                   Зачисление
со счёта                                   торговцу
держателя                                  (минус MDR)
```

**Interchange** — комиссия, которую эквайер платит эмитенту за каждую транзакцию.

## 9. Роль технологий

### 9.1 POS-терминал

**Что делает:**
- Считывает данные карты
- Передаёт данные эквайеру
- Получает ответ
- Печатает чек

**Типы:**
- Стационарный (провод)
- Мобильный (GPRS, Wi-Fi)
- mPOS (подключается к смартфону)
- Soft POS (смартфон как терминал)

### 9.2 Платёжный шлюз (для онлайна)

**Что делает:**
- Принимает данные карты от сайта
- Шифрует и передаёт эквайеру
- Возвращает результат

**Примеры:** Stripe, PayPal, CloudPayments, ЮKassa

### 9.3 Процессинговый центр

**Что делает:**
- Маршрутизация транзакций
- Хранение данных
- Генерация отчётов
- Fraud-мониторинг

## 10. Безопасность базовых процессов

### 10.1 Защита данных карты

**Что защищается:**
- PAN (номер карты)
- CVV/CVC
- PIN
- Данные магнитной полосы

**Стандарт PCI DSS:**
- Требования к хранению данных
- Требования к передаче
- Требования к обработке

### 10.2 Аутентификация держателя

| Метод | Описание | Когда используется |
|-------|----------|-------------------|
| PIN | Секретный код | Чиповые транзакции |
| Подпись | На чеке | Устаревший метод |
| 3-D Secure | Код из SMS/приложения | Онлайн-покупки |
| Биометрия | Отпечаток, Face ID | Мобильные платежи |

## 💡 Key Takeaways

- **Четыре участника**: Держатель, торговец, эмитент, эквайер — каждый со своей ролью
- **Три этапа**: Авторизация (секунды) → Клиринг (часы) → Расчёты (дни)
- **Платёжная система** — связующее звено, устанавливающее правила
- **Карта — не деньги**: Это инструмент доступа к счёту
- **Знание терминологии**: PAN, CVV, interchange, settlement — базовый словарь индустрии
