## 2. 3-D Secure

### 2.1 Как работает

1. Покупатель вводит данные карты
2. Эмитент анализирует риск
3. При необходимости — дополнительная верификация
4. Успешная проверка → liability shift

### 2.2 Liability Shift

**При успешной 3DS:**
- Ответственность за fraud переходит к эмитенту
- Торговец защищён от fraud chargebacks

### 2.3 Версии

| Версия | Особенности |
|--------|-------------|
| 3DS 1.0 | Pop-up, статические пароли, высокий отказ |
| 3DS 2.0 | Frictionless, риск-анализ, биометрия |

### 2.4 Frictionless Flow

При низком риске — без дополнительной верификации:
- Лучший UX
- Выше конверсия
- Сохраняется liability shift

## 3. Fraud Detection

### 3.1 Сигналы риска

| Сигнал | Риск |
|--------|------|
| Разные billing/shipping | Средний |
| Новый клиент, крупный заказ | Высокий |
| Множество попыток | Высокий |
| Подозрительный IP/device | Высокий |
| Необычное время | Низкий |

### 3.2 Инструменты

- **Device fingerprinting** — идентификация устройства
- **IP geolocation** — проверка местоположения
- **Velocity checks** — скорость транзакций
- **ML models** — машинное обучение

### 3.3 Действия

| Риск | Действие |
|------|----------|
| Низкий | Пропустить |
| Средний | 3DS / Ручная проверка |
| Высокий | Отклонить |

## 4. Верификация клиента

### 4.1 AVS (Address Verification)

Проверка billing address:
- Полное совпадение → низкий риск
- Частичное → средний риск
- Нет совпадения → высокий риск

### 4.2 CVV

Обязательная проверка CVV:
- Подтверждает физическое наличие карты
- Снижает fraud

### 4.3 Email/Phone verification

- Подтверждение email
- SMS-верификация
- Звонок для крупных заказов

## 5. Сервисы раннего предупреждения

### 5.1 Alerts

**Ethoca (Mastercard):**
- Уведомление о pretension до chargeback
- Возможность вернуть деньги проактивно

**Verifi CDRN (Visa):**
- Аналогичный сервис
- Предотвращение регистрации chargeback

### 5.2 Как работают

```
Держатель → Эмитент → Alert → Торговец → Refund → Нет chargeback
```

### 5.3 Преимущества

- Нет комиссии за chargeback
- Не влияет на ratio
- Быстрое решение
- Лучший customer experience

## 6. Операционные практики

### 6.1 Billing Descriptor

**Плохо:** ACME CORP LLC
**Хорошо:** MYSHOP.RU*Заказ 12345

Клиент узнаёт покупку в выписке.

### 6.2 Подтверждения

- Email после покупки
- SMS о списании
- Tracking номер
- Уведомление о доставке

### 6.3 Политика возвратов

- Чёткие условия
- Простой процесс
- Быстрое выполнение

## 7. Клиентская поддержка

### 7.1 Важность

Многие chargebacks — результат:
- Невозможности связаться
- Медленной реакции
- Неясной политики

### 7.2 Best Practices

- Быстрый ответ (< 24 часов)
- Несколько каналов (email, chat, phone)
- Готовность к возвратам
- Эскалация для сложных случаев

## 8. Мониторинг

### 8.1 Ключевые метрики

| Метрика | Цель |
|---------|------|
| Chargeback ratio | < 0.9% |
| Fraud rate | < 1% |
| Refund rate | Зависит от бизнеса |
| Win rate | > 30% |

### 8.2 Dashboards

- Ежедневный мониторинг
- Алерты при превышении
- Анализ трендов
- Сегментация по каналам

### 8.3 Root Cause Analysis

При каждом chargeback:
- Причина
- Можно ли было предотвратить
- Изменения в процессе

## 9. Для подписок

### 9.1 Особые риски

- Забытые подписки
- Сложная отмена
- Неожиданные списания

### 9.2 Best Practices

- Напоминание перед списанием
- Простая отмена (1 click)
- Trial с явным переходом
- Прозрачные условия

---

## 10. Документирование

### 10.1 Что сохранять

- Terms of Service (с датой согласия)
- Order confirmation
- Shipping confirmation + tracking
- Delivery confirmation
- Все коммуникации с клиентом
- IP, device fingerprint
- 3DS результат

### 10.2 Сроки хранения

Минимум **540 дней** (120 дней + арбитраж + запас)

## 💡 Key Takeaways

- **3-D Secure — главная защита** от fraud chargebacks
- **Alerts предотвращают** регистрацию chargeback
- **Понятный descriptor** снижает "не узнаю покупку"
- **Быстрая поддержка** решает проблемы до диспута
- **Документирование** — основа для representment
