## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | D | IaaS предоставляет виртуальные машины, клиент отвечает за ОС. В PaaS и FaaS ОС управляет провайдер. В SaaS клиент вообще не касается инфраструктуры. |
| 2 | D | AWS Lambda имеет максимальный timeout 15 минут (900 секунд). Для более длительных задач нужны ECS/EC2 или Step Functions. |
| 3 | D | При использовании RDS (PaaS), AWS отвечает за патчинг ОС и движка БД. Клиент отвечает за данные и настройки БД. |
| 4 | C | Elastic Beanstalk — PaaS для развёртывания web-приложений. EC2 — IaaS, VPC — сетевой сервис, IAM — сервис идентификации. |
| 5 | A | Lambda тарифицируется по количеству запросов ($0.20/1M) и по времени выполнения (GB-seconds). |
| 6 | A | Cold Start — задержка при первом вызове функции, когда AWS создаёт новое execution environment. Последующие вызовы быстрее (warm start). |
| 7 | D | Fargate — serverless compute для контейнеров, не требует управления EC2. ECS/EKS — оркестраторы, ECR — registry. |
| 8 | D | SaaS не даёт контроля над инфраструктурой — это главная характеристика модели. Пользователь только потребляет сервис. |
| 9 | C | FaaS (Lambda) идеален для MVP: минимум ops, pay-per-use, масштабируется от 0. При низкой нагрузке почти бесплатно. |
| 10 | B | Multi-tenant означает, что один инстанс приложения (один deployment) обслуживает множество клиентов с логической изоляцией данных. |
| 11 | D | При использовании EC2 клиент отвечает за Security Groups, IAM, патчинг ОС, настройку firewall. AWS — за физическую безопасность и гипервизор. |
| 12 | D | При постоянной высокой нагрузке 24/7 EC2 дешевле Lambda. Lambda выгодна при переменной/низкой нагрузке. |
| 13 | A | Главное преимущество RDS — автоматические backup, patching, Multi-AZ failover. Это экономит время ops команды. |
| 14 | A | Beanstalk автоматически создаёт EC2 инстансы, настраивает ELB, Auto Scaling, мониторинг. Вы деплоите код — остальное делает AWS. |
| 15 | D | Lambda не поддерживает прямые TCP соединения. Для TCP нужен EC2 или ECS. Lambda работает через API Gateway, S3, SQS и другие AWS события. |
| 16 | D | BaaS = Backend as a Service — готовый backend для мобильных/web приложений (Firebase, AWS Amplify). |
| 17 | B | Serverless НЕ всегда дешевле. При высокой постоянной нагрузке традиционные серверы могут быть экономичнее. |
| 18 | C | EKS — managed Kubernetes (стандарт индустрии). ECS — AWS-native оркестратор с собственным API. Оба работают с Docker и Fargate. |
| 19 | A | PaaS ограничивает выбор языков, фреймворков, версий runtime. За удобство платите гибкостью. |
| 20 | D | Тренд — движение к managed services и более высоким абстракциям: IaaS → PaaS → FaaS → AI-assisted development. |
