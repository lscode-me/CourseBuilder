## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Хэш преобразует вход любого размера в фиксированную строку (fingerprint). |
| 2 | C | MD5 = 128 бит = 32 hex символа. |
| 3 | D | SHA-256 = 256 бит = 64 hex символа. |
| 4 | C | Для MD5 найдены практические коллизии, алгоритм криптографически ненадёжен. |
| 5 | B | `sha256sum` — стандартная команда в Linux. |
| 6 | C | `-c` (check) проверяет файлы по списку хэшей. |
| 7 | D | Хэш — односторонняя функция, восстановить вход невозможно. |
| 8 | D | Изменение одного бита входа меняет ~50% бит хэша. |
| 9 | B | Коллизия — когда разные входы дают одинаковый хэш. |
| 10 | A | Нужно `.encode()` для преобразования str в bytes. |
| 11 | C | Блочное чтение позволяет хэшировать файлы больше RAM. |
| 12 | D | Git использует SHA-1 (переход на SHA-256 планируется). |
| 13 | C | bcrypt/argon2 специально разработаны для паролей (медленные, с солью). |
| 14 | D | На macOS используется `shasum -a 256`. |
| 15 | D | Без `-n` echo добавляет `\n`, изменяя хэш. |
| 16 | A | SHA-512 = 512 бит = 128 hex символов. |
| 17 | C | BLAKE3 очень быстрый и при этом криптографически стойкий. |
| 18 | D | Одинаковый хэш = идентичное содержимое файлов. |
| 19 | A | Хэш необратим и не использует ключ; шифрование обратимо с ключом. |
| 20 | D | `hashlib.new('algorithm')` создаёт объект для любого алгоритма. |
