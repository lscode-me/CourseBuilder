## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Байт всегда состоит из 8 бит. Это стандартная единица данных. |
| 2 | D | 8 бит = 2^8 = 256 возможных значений (от 0 до 255). |
| 3 | B | 101010 = 32 + 8 + 2 = 42 (позиции: 1×32 + 0×16 + 1×8 + 0×4 + 1×2 + 0×1). |
| 4 | D | 15 = 8 + 4 + 2 + 1 = 1111 в двоичной системе. |
| 5 | B | Hex использует 0-9 и A-F (всего 16 символов для основания 16). |
| 6 | D | 0xFF = 15×16 + 15 = 240 + 15 = 255. |
| 7 | A | Nibble — это 4 бита, половина байта, один hex-символ. |
| 8 | A | 7=rwx, 5=r-x, 5=r-x. Владелец всё, группа и остальные — чтение и выполнение. |
| 9 | D | Восьмеричная система имеет основание 8, использует цифры 0-7. |
| 10 | D | Big-Endian хранит старший байт первым: 12 34 56 78. |
| 11 | C | x86-64 (Intel/AMD) использует Little-Endian. |
| 12 | B | TCP/IP всегда использует Big-Endian (Network Byte Order). |
| 13 | A | `xxd` — стандартная утилита для hex dump в Linux. |
| 14 | C | `hex(42)` возвращает строку `'0x2a'` (42 в hex = 2a). |
| 15 | A | `bin(42)` возвращает `'0b101010'`. |
| 16 | B | Signed 8-bit: -128 до 127. Unsigned: 0 до 255. |
| 17 | C | -5 в two's complement: инвертировать 00000101 = 11111010, добавить 1 = 11111011. |
| 18 | A | IEEE 754 floating point имеет ограниченную точность, 0.1 — бесконечная дробь в binary. |
| 19 | D | 1 KiB (кибибайт по IEC) = 1024 байт. Производители часто используют 1000. |
| 20 | A | `xxd -r -p` — reverse plain hex dump, конвертирует hex в binary. |
