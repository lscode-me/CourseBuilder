## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Секции в INI обозначаются `[section_name]`. |
| 2 | B | В INI комментарии начинаются с `;` или `#`. |
| 3 | C | Tom's Obvious Minimal Language — по имени создателя Tom Preston-Werner. |
| 4 | D | TOML поддерживает integer, float, boolean, datetime как отдельные типы. |
| 5 | A | pyproject.toml — стандартный файл конфигурации Python проектов (PEP 518, 621). |
| 6 | B | .env содержит секреты (пароли, ключи), которые не должны быть в репозитории. |
| 7 | C | Стандартный формат .env: `KEY=value` (без пробелов вокруг `=`). |
| 8 | D | `load_dotenv()` из библиотеки python-dotenv загружает .env в os.environ. |
| 9 | A | В TOML массивы: `key = [1, 2, 3]`. |
| 10 | B | `[server]` создаёт таблицу (эквивалент объекта/словаря). |
| 11 | C | `configparser` — стандартный модуль Python для работы с INI. |
| 12 | D | `tomllib` встроен в Python 3.11+ (только чтение). |
| 13 | A | .env.example — шаблон со списком переменных без реальных значений, коммитится в Git. |
| 14 | B | `env_file: .env` или `env_file: [.env]` в docker-compose.yml. |
| 15 | C | TOML поддерживает даты без кавычек: `date = 2024-01-15`. |
| 16 | D | Cargo.toml — файл конфигурации пакетов Rust. |
| 17 | A | В INI все значения — строки, нужно вручную преобразовывать типы. |
| 18 | B | `os.getenv(key, default)` возвращает значение переменной или default. |
| 19 | C | pydantic-settings загружает и валидирует конфигурацию с типизацией. |
| 20 | D | Секреты хранятся в .env и исключаются из Git через .gitignore. |
| 21 | A | `/etc/passwd` использует двоеточие `:` как разделитель полей (colon-separated values). |
| 22 | B | Каждая запись содержит 7 полей: username, password, UID, GID, GECOS, home, shell. |
| 23 | C | `/etc/shadow` хранит хеши паролей и информацию о политиках паролей (срок действия и т.д.). |
| 24 | D | `sshd_config` использует keyword-value формат: директива и значение через пробел. |
| 25 | A | `Match` применяет условные настройки к определённым пользователям, группам или хостам. |
| 26 | B | `visudo` проверяет синтаксис перед сохранением, предотвращая блокировку системы. |
| 27 | C | `/etc/fstab` содержит устройство, точку монтирования, тип ФС, опции, dump и pass. Не права! |
| 28 | B | `/etc/hosts` описывает статическое соответствие IP-адресов и DNS-имён. |
| 29 | A | Стандартные секции systemd service: `[Unit]`, `[Service]`, `[Install]`. |
| 30 | B | `ExecStart` определяет команду, которая запускается при старте сервиса. |
| 31 | C | `Restart=on-failure` перезапускает сервис только если он завершился с ошибкой (код != 0). |
| 32 | D | nginx использует фигурные скобки: `server { ... }`, `location { ... }`. |
| 33 | A | `location` определяет правила обработки запросов по URL путям. |
| 34 | B | `/etc/environment` использует shell-style переменные: `KEY=value`. |
| 35 | A | Crontab имеет 5 полей времени: минута, час, день месяца, месяц, день недели. |
| 36 | B | `*/15` означает "каждые 15 единиц" — каждые 15 минут в поле минут. |
| 37 | C | `@daily` — специальная строка, эквивалент `0 0 * * *` (каждый день в полночь). |
| 38 | B | Модуль `pwd` предоставляет доступ к базе пользователей (password database). |
| 39 | C | Префикс `-` означает "не падать если файл не существует", загружает переменные из файла. |
| 40 | D | Секция 5 man описывает форматы файлов и конвенции (file formats and conventions). |
