## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | A | Секции в INI обозначаются `[section_name]`. |
| 2 | B | В INI комментарии начинаются с `;` или `#`. |
| 3 | B | Tom's Obvious Minimal Language — по имени создателя Tom Preston-Werner. |
| 4 | B | TOML поддерживает integer, float, boolean, datetime как отдельные типы. |
| 5 | C | pyproject.toml — стандартный файл конфигурации Python проектов (PEP 518, 621). |
| 6 | D | .env содержит секреты (пароли, ключи), которые не должны быть в репозитории. |
| 7 | A | Стандартный формат .env: `KEY=value` (без пробелов вокруг `=`). |
| 8 | C | `load_dotenv()` из библиотеки python-dotenv загружает .env в os.environ. |
| 9 | C | В TOML массивы: `key = [1, 2, 3]`. |
| 10 | C | `[server]` создаёт таблицу (эквивалент объекта/словаря). |
| 11 | D | `configparser` — стандартный модуль Python для работы с INI. |
| 12 | C | `tomllib` встроен в Python 3.11+ (только чтение). |
| 13 | D | .env.example — шаблон со списком переменных без реальных значений, коммитится в Git. |
| 14 | D | `env_file: .env` или `env_file: [.env]` в docker-compose.yml. |
| 15 | B | TOML поддерживает даты без кавычек: `date = 2024-01-15`. |
| 16 | D | Cargo.toml — файл конфигурации пакетов Rust. |
| 17 | D | В INI все значения — строки, нужно вручную преобразовывать типы. |
| 18 | D | `os.getenv(key, default)` возвращает значение переменной или default. |
| 19 | A | pydantic-settings загружает и валидирует конфигурацию с типизацией. |
| 20 | C | Секреты хранятся в .env и исключаются из Git через .gitignore. |
| 21 | D | `/etc/passwd` использует двоеточие `:` как разделитель полей (colon-separated values). |
| 22 | B | Каждая запись содержит 7 полей: username, password, UID, GID, GECOS, home, shell. |
| 23 | A | `/etc/shadow` хранит хеши паролей и информацию о политиках паролей (срок действия и т.д.). |
| 24 | A | `sshd_config` использует keyword-value формат: директива и значение через пробел. |
| 25 | D | `Match` применяет условные настройки к определённым пользователям, группам или хостам. |
| 26 | D | `visudo` проверяет синтаксис перед сохранением, предотвращая блокировку системы. |
| 27 | D | `/etc/fstab` содержит устройство, точку монтирования, тип ФС, опции, dump и pass. Не права! |
| 28 | A | `/etc/hosts` описывает статическое соответствие IP-адресов и DNS-имён. |
| 29 | B | Стандартные секции systemd service: `[Unit]`, `[Service]`, `[Install]`. |
| 30 | A | `ExecStart` определяет команду, которая запускается при старте сервиса. |
| 31 | A | `Restart=on-failure` перезапускает сервис только если он завершился с ошибкой (код != 0). |
| 32 | D | nginx использует фигурные скобки: `server { ... }`, `location { ... }`. |
| 33 | C | `location` определяет правила обработки запросов по URL путям. |
| 34 | C | `/etc/environment` использует shell-style переменные: `KEY=value`. |
| 35 | D | Crontab имеет 5 полей времени: минута, час, день месяца, месяц, день недели. |
| 36 | B | `*/15` означает "каждые 15 единиц" — каждые 15 минут в поле минут. |
| 37 | A | `@daily` — специальная строка, эквивалент `0 0 * * *` (каждый день в полночь). |
| 38 | A | Модуль `pwd` предоставляет доступ к базе пользователей (password database). |
| 39 | C | Префикс `-` означает "не падать если файл не существует", загружает переменные из файла. |
| 40 | B | Секция 5 man описывает форматы файлов и конвенции (file formats and conventions). |
