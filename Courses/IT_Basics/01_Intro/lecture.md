## 1. Что такое данные

### 1.1 Данные vs Информация

**Данные** — это сырые факты, числа, символы без контекста. Сами по себе данные не несут смысла.

**Информация** — это данные, обработанные и представленные в контексте, который делает их понятными и полезными.

**Пример:**

```
Данные:    42, 37.5, "Иванов", 2024-12-08
```

Эти числа и строки ничего не значат без контекста.

```
Информация:
  Пациент: Иванов
  Дата приёма: 2024-12-08
  Возраст: 42 года
  Температура: 37.5°C
```

Теперь данные обрели смысл — это медицинская карта пациента.

### 1.2 Жизненный цикл данных

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   Создание  │───►│  Хранение   │───►│  Обработка  │───►│Использование│
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       ▲                                                        │
       └────────────────────────────────────────────────────────┘
```

На каждом этапе важно понимать:

- **Как** данные представлены (формат)

- **Где** данные находятся (хранилище)

- **Как** с ними работать (инструменты)

## 2. Уровни абстракции

### 2.1 От битов до приложений

Компьютер работает только с двоичными данными — нулями и единицами. Но мы видим текст, картинки, слышим музыку. Как это работает?

```
┌────────────────────────────────────────────────────────────────┐
│                        Уровни абстракции                       │
├────────────────────────────────────────────────────────────────┤
│  7. Приложение      │  Текстовый редактор, браузер, плеер      │
├─────────────────────┼──────────────────────────────────────────┤
│  6. Формат данных   │  JSON, YAML, Markdown, MP3, JPEG         │
├─────────────────────┼──────────────────────────────────────────┤
│  5. Кодировка       │  UTF-8, ASCII, Base64                    │
├─────────────────────┼──────────────────────────────────────────┤
│  4. Байты           │  8-битные блоки: 01001000 = 0x48 = 72    │
├─────────────────────┼──────────────────────────────────────────┤
│  3. Биты            │  0 и 1                                   │
├─────────────────────┼──────────────────────────────────────────┤
│  2. Электроника     │  Высокое/низкое напряжение               │
├─────────────────────┼──────────────────────────────────────────┤
│  1. Физика          │  Электроны, магнитные домены             │
└─────────────────────┴──────────────────────────────────────────┘
```

**Пример: буква "H"**

```
Уровень приложения:    H (буква на экране)
         ↓
Уровень формата:       Часть HTML-тега <H1> или JSON-строки
         ↓
Уровень кодировки:     UTF-8 кодирует как 0x48
         ↓
Уровень байтов:        01001000
         ↓
Уровень битов:         0, 1, 0, 0, 1, 0, 0, 0
```

### 2.2 Почему это важно

Когда что-то не работает, проблема может быть на любом уровне:

| Уровень | Типичная проблема |
|---------|-------------------|
| Формат | "Invalid JSON" — синтаксическая ошибка |
| Кодировка | "Кракозябры" — неправильная кодировка |
| Байты | Повреждённый файл |
| Биты | Ошибка чтения диска |

Понимание уровней помогает локализовать и исправлять проблемы.

## 3. Классификация данных

### 3.1 По степени структурированности

Данные делятся на три категории по тому, насколько они организованы:

**Структурированные данные (Structured)**

Данные с чёткой, заранее определённой схемой.

```
┌────────┬─────────────┬───────┐
│ ID     │ Name        │ Age   │
├────────┼─────────────┼───────┤
│ 1      │ Alice       │ 30    │
│ 2      │ Bob         │ 25    │
│ 3      │ Charlie     │ 35    │
└────────┴─────────────┴───────┘
```

Примеры:

- Реляционные базы данных (PostgreSQL, MySQL)
- Таблицы Excel с фиксированными колонками
- CSV с заголовками

Преимущества:

- Легко запрашивать (SQL)
- Легко валидировать
- Эффективное хранение

**Полуструктурированные данные (Semi-structured)**

Данные с гибкой схемой, встроенной в сами данные.

```json
{
  "id": 1,
  "name": "Alice",
  "age": 30,
  "skills": ["Python", "SQL"],
  "address": {
    "city": "Moscow",
    "zip": "101000"
  }
}
```

Примеры:

- JSON
- YAML
- XML

Преимущества:

- Гибкость схемы
- Самоописывающиеся
- Легко расширяемые

**Неструктурированные данные (Unstructured)**

Данные без предопределённой модели.

```
Привет! Это обычный текст. Здесь нет никакой структуры,
просто последовательность символов. Это может быть email,
статья, комментарий или любой другой свободный текст.
```

Примеры:

- Свободный текст (emails, статьи)
- Изображения
- Аудио и видео
- Логи без структуры

Сложности:

- Трудно анализировать автоматически
- Нет единого способа запросов
- Требуют NLP/ML для извлечения информации

### 3.2 Сравнение типов данных

| Характеристика | Structured | Semi-structured | Unstructured |
|----------------|------------|-----------------|--------------|
| Схема | Строгая, внешняя | Гибкая, встроенная | Отсутствует |
| Запросы | SQL, простые | JSONPath, XPath | Полнотекстовый поиск |
| Примеры | RDBMS, CSV | JSON, YAML, XML | Текст, медиа |
| Объём в мире | ~20% | ~10% | ~70% |
| Анализ | Простой | Средний | Сложный |

## 4. Форматы данных

### 4.1 Зачем нужны форматы

**Формат** — это соглашение о том, как данные представлены и интерпретируются.

Без форматов компьютеры не могли бы:

- Понимать друг друга
- Открывать файлы созданные другими программами
- Передавать данные по сети

**Пример проблемы без стандарта:**

```
Программа А сохраняет дату как: 2024-12-08
Программа Б ожидает дату как:   08/12/2024
Программа В ожидает дату как:   12/08/2024

Результат: хаос и ошибки
```

### 4.2 Текстовые vs Бинарные форматы

**Текстовые форматы:**

```json
{"name": "Alice", "age": 30}
```

- Читаемы человеком
- Легко редактировать в текстовом редакторе
- Больший размер
- Примеры: JSON, YAML, XML, CSV, Markdown

**Бинарные форматы:**

```
00000000: 7b22 6e61 6d65 223a 2022 416c 6963 6522  {"name": "Alice"
00000010: 2c20 2261 6765 223a 2033 307d            , "age": 30}
```

(это hex-представление, реально хранятся байты)

- Компактные
- Быстрее парсятся
- Не читаемы без специальных инструментов
- Примеры: Protocol Buffers, MessagePack, JPEG, MP3

### 4.3 Выбор формата

| Сценарий | Рекомендуемый формат | Почему |
|----------|---------------------|--------|
| Конфигурация | YAML, TOML | Читаемость, комментарии |
| API ответы | JSON | Стандарт, широкая поддержка |
| Документация | Markdown | Простота, конвертация |
| Обмен таблицами | CSV | Универсальность |
| Высокая производительность | Protocol Buffers | Компактность, скорость |
| Веб-страницы | HTML | Стандарт браузеров |

## 5. Текстовые и бинарные файлы

### 5.1 Что такое текстовый файл

**Текстовый файл** — это последовательность символов (букв, цифр, знаков), закодированных в определённой кодировке.

```bash
# Просмотр текстового файла

cat hello.txt
```

```
Hello, World!
Привет, мир!
```

Характеристики:

- Состоит из печатаемых символов
- Имеет переносы строк (`\n` или `\r\n`)
- Читаем в любом текстовом редакторе
- Кодировка важна для правильного отображения

### 5.2 Что такое бинарный файл

**Бинарный файл** — это последовательность байтов, не предназначенная для прямого чтения человеком.

```bash
# Просмотр бинарного файла как текста (бессмысленно)

cat image.png
```

```
�PNG
▒
IHDR...(мусор)...
```

```bash
# Просмотр в hex-режиме (имеет смысл)

xxd image.png | head -3
```

```
00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR
00000010: 0000 0100 0000 0100 0802 0000 00d3 1025  ...............%
00000020: 0000 0006 624b 4744 0000 ff00 00ff 00ff  ....bKGD........
```

Характеристики:

- Может содержать любые байты (0-255)
- Требует специальных программ для интерпретации
- Часто имеет магические числа в начале
- Примеры: изображения, исполняемые файлы, архивы

### 5.3 Как определить тип файла

```bash
# Команда file анализирует содержимое

file document.txt
# document.txt: UTF-8 Unicode text

file image.png
# image.png: PNG image data, 256 x 256, 8-bit/color RGB

file archive.zip
# archive.zip: Zip archive data
```

Команда `file` смотрит на:

1. Магические числа (сигнатуры) в начале файла
2. Структуру данных
3. Эвристики для текстовых файлов

## 6. Магические числа

### 6.1 Что такое магические числа

**Магические числа (Magic numbers)** — это специальные байты в начале файла, идентифицирующие его формат.

| Формат | Magic bytes (hex) | ASCII представление |
|--------|-------------------|---------------------|
| PNG | 89 50 4E 47 | `.PNG` |
| JPEG | FF D8 FF | (не печатаемые) |
| PDF | 25 50 44 46 | `%PDF` |
| ZIP | 50 4B 03 04 | `PK..` |
| GIF | 47 49 46 38 | `GIF8` |
| ELF (Linux exe) | 7F 45 4C 46 | `.ELF` |
| Gzip | 1F 8B | (не печатаемые) |

### 6.2 Зачем нужны магические числа

1. **Идентификация формата** — программа может определить тип файла независимо от расширения

2. **Валидация** — если магические числа неправильные, файл повреждён или подменён

3. **Безопасность** — помогает предотвратить подмену файлов

```bash
# Пример: переименуем PNG в .txt

mv image.png fake.txt

# file всё равно определит правильно

file fake.txt
# fake.txt: PNG image data, 256 x 256, 8-bit/color RGB
```

### 6.3 Просмотр магических чисел

```bash
# Первые 16 байт PNG файла

xxd -l 16 image.png
```

```
00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR
```

Разбор:

- `89 50 4E 47` — магическое число PNG
- `0D 0A 1A 0A` — специальные байты для детекции повреждений
- `00 00 00 0D` — длина следующего чанка
- `49 48 44 52` — "IHDR" (заголовок изображения)

## 7. Кодировки: превью

### 7.1 Зачем нужны кодировки

**Кодировка** — это таблица соответствия между символами и числами (байтами).

Компьютер понимает только числа. Чтобы хранить текст, каждому символу присваивается число:

```
A → 65
B → 66
C → 67
...
```

Проблема: разные страны создавали свои таблицы:

- США: ASCII (латиница)
- Россия: KOI8-R, Windows-1251, CP866
- Япония: Shift-JIS, EUC-JP
- И сотни других...

### 7.2 "Кракозябры" — типичная проблема

```
Ожидалось:  Привет, мир!
Получилось: ÐŸÑ€Ð¸Ð²ÐµÑ‚, Ð¼Ð¸Ñ€!
```

Это происходит, когда:

1. Файл сохранён в одной кодировке (UTF-8)
2. Открыт в другой (Windows-1251)

### 7.3 Решение: Unicode и UTF-8

**Unicode** — это единая таблица всех символов всех языков мира.

**UTF-8** — это способ кодирования Unicode, который:

- Совместим с ASCII
- Поддерживает все символы
- Является стандартом в интернете

Подробно разберём в модуле [03_Encodings](../03_Encodings/).

## 9. Инструменты работы с данными

### 9.1 Командная строка

```bash
# Просмотр файлов

cat file.txt          # Весь файл
head -n 10 file.txt   # Первые 10 строк
tail -n 10 file.txt   # Последние 10 строк
less file.txt         # Постраничный просмотр

# Определение типа и кодировки

file document.txt
file -i document.txt  # С MIME-типом и кодировкой

# Hex-просмотр

xxd file.bin | head
hexdump -C file.bin | head

# Конвертация кодировок

iconv -f WINDOWS-1251 -t UTF-8 input.txt > output.txt
```

### 9.2 Специализированные инструменты

```bash
# JSON

jq '.' file.json      # Форматирование
jq '.name' file.json  # Извлечение поля

# YAML

yq '.' file.yaml      # Форматирование

# CSV

csvtool col 1,3 file.csv    # Выбор колонок
csvstat file.csv            # Статистика

# Сжатие

gzip file.txt         # Сжатие
gunzip file.txt.gz    # Распаковка

# Хэши

md5sum file.txt
sha256sum file.txt
```

### 9.3 Редакторы

| Редактор | Для чего |
|----------|----------|
| VS Code | Универсальный, JSON/YAML подсветка |
| Vim/Neovim | Быстрое редактирование в терминале |
| Sublime Text | Работа с большими файлами |

## 10. Common Pitfalls

### 10.1 Игнорирование кодировок

❌ **Ошибка:** Открывать файлы без проверки кодировки

```bash
# Файл в Windows-1251, открытый как UTF-8

cat russian.txt
# Результат: ÐŸÑ€Ð¸Ð²ÐµÑ‚!
```

✅ **Решение:** Всегда проверять кодировку

```bash
file -i russian.txt
# russian.txt: text/plain; charset=iso-8859-1

# Конвертировать если нужно

iconv -f WINDOWS-1251 -t UTF-8 russian.txt
```

### 10.2 Путаница с расширениями файлов

❌ **Ошибка:** Верить расширению файла

```bash
# Кто-то переименовал virus.exe в picture.jpg

file picture.jpg
# picture.jpg: PE32 executable (GUI) Intel 80386
```

✅ **Решение:** Использовать `file` для проверки

### 10.3 Редактирование бинарных файлов

❌ **Ошибка:** Открыть бинарный файл в текстовом редакторе и сохранить

```bash
# Это повредит файл!

nano database.db
```

✅ **Решение:** Использовать специализированные инструменты

```bash
# Hex-редактор для бинарных файлов

hexedit file.bin
```

### 10.4 Смешивание line endings

❌ **Ошибка:** Смешивать Windows (`\r\n`) и Unix (`\n`) переносы строк

```bash
# Файл с смешанными окончаниями

file mixed.txt
# mixed.txt: ASCII text, with CRLF, LF line terminators
```

✅ **Решение:** Конвертировать в один формат

```bash
# Windows → Unix

sed -i 's/\r$//' file.txt

# Или использовать dos2unix

dos2unix file.txt
```

## 💡 Key Takeaways

- **Данные ≠ Информация**: Данные становятся информацией только в контексте. Формат и представление критически важны.

- **Уровни абстракции**: От битов до приложений — понимание уровней помогает диагностировать проблемы.

- **Три типа данных**: Структурированные (SQL), полуструктурированные (JSON/YAML), неструктурированные (текст/медиа) — каждый требует своего подхода.

- **Текстовые vs Бинарные**: Текстовые файлы читаемы человеком, бинарные требуют специальных инструментов. Используйте `file` для определения типа.

- **Кодировки важны**: "Кракозябры" — это несовпадение кодировок. UTF-8 — современный стандарт.
