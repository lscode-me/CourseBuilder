## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | Данные — сырые факты (42, "Иванов"), информация — данные с контекстом ("Пациент Иванов, 42 года"). |
| 2 | B | Реляционные таблицы с фиксированной схемой — структурированные данные. JSON — полуструктурированные. |
| 3 | A | JSON имеет гибкую схему, встроенную в сами данные — это полуструктурированный формат. |
| 4 | C | Текстовый файл — последовательность печатаемых символов в определённой кодировке, не зависит от расширения. |
| 5 | A | PNG — бинарный формат изображений. YAML, HTML, Markdown — текстовые форматы. |
| 6 | C | Magic numbers идентифицируют формат файла по первым байтам, независимо от расширения. |
| 7 | D | PNG начинается с `89 50 4E 47` (`.PNG` в ASCII). `FF D8 FF` — JPEG, `50 4B` — ZIP, `25 50 44 46` — PDF. |
| 8 | C | Команда `file` анализирует содержимое файла и определяет его тип. |
| 9 | D | `file -i` показывает MIME-тип и кодировку файла. |
| 10 | A | "Кракозябры" появляются при несовпадении кодировки записи и чтения файла. |
| 11 | D | Уровни: биты → байты → кодировка → формат данных → приложение. |
| 12 | C | Расширение — просто часть имени файла, его можно изменить, не меняя содержимое. |
| 13 | B | `xxd` выводит hex-дамп файла с ASCII представлением. |
| 14 | D | `iconv` — стандартная утилита для конвертации кодировок с флагами `-f` (from) и `-t` (to). |
| 15 | C | `\r\n` (CRLF) — Windows-стиль переноса строки. Unix использует `\n` (LF). |
| 16 | A | JSON поддерживает вложенные объекты и массивы, CSV — только плоские таблицы. |
| 17 | A | YAML поддерживает комментарии (#), JSON — нет. |
| 18 | C | По оценкам, ~70% мировых данных неструктурированные (текст, медиа). |
| 19 | D | `xxd -l 8` выводит первые 8 байт файла в hex-формате. |
| 20 | D | Protocol Buffers — бинарный формат сериализации от Google. |
