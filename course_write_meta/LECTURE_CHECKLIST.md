### Обязательные секции (в порядке)
- [ ] 📋 Prerequisites (что нужно знать)
- [ ] 🎯 Learning Objectives (3-5 целей)
- [ ] 📁 Sample Data (если применимо)
- [ ] 5-12 пронумерованных основных секций
- [ ] 💡 Key Takeaways (3-5 пунктов)
- [ ] 🚀 Next Steps (что дальше изучать)
- [ ] 📚 Additional Resources (опционально)

### Нумерация
- [ ] Основные секции: `## 1.`, `## 2.`, etc.
- [ ] Подсекции: `### 1.1`, `### 1.2`, etc.
- [ ] Нумерация последовательна (нет пропусков)

## 3️⃣ КАЧЕСТВО КОНТЕНТА

### Learning Objectives
- [ ] Есть 3-5 целей обучения
- [ ] Каждая цель начинается с глагола действия
- [ ] Цели измеримы/проверяемы
- [ ] НЕТ абстрактных глаголов ("понимать", "знать")

**Примеры целей:**
- ✅ "Создавать классы с наследованием"
- ❌ "Понимать ООП"

### Прогрессия сложности
- [ ] Начинается с простых концепций
- [ ] Постепенно переходит к сложным
- [ ] Новое строится на изученном
- [ ] Есть logical flow между секциями

### Полнота объяснений
Для каждой основной концепции есть:
- [ ] **Что** это такое (определение)
- [ ] **Зачем** нужно (мотивация)
- [ ] **Как** использовать (синтаксис/API)
- [ ] **Когда** применять (сценарии)
- [ ] **Pitfalls** (частые ошибки)

### Key Takeaways
- [ ] 3-5 ключевых выводов
- [ ] Формат: **Концепция**: объяснение
- [ ] Это действительно главное из модуля
- [ ] Выводы запоминаемы и применимы

---

## 4️⃣ ПРИМЕРЫ КОДА

### Формат блоков кода
Каждый блок имеет:
- [ ] Заголовок (### Example: название)
- [ ] Введение (1-2 предложения о примере)
- [ ] Код с правильным синтаксисом
- [ ] Output (результат выполнения)
- [ ] Объяснение результата

### Качество кода
- [ ] Весь код **исполняемый** (можно скопировать и запустить)
- [ ] Код **современный** (f-strings, type hints, etc.)
- [ ] Код **идиоматичный** (Pythonic/Unix-way)
- [ ] Переменные с **понятными именами**
- [ ] Нет **устаревших практик** (%, old-style, etc.)

### Комментарии в коде
- [ ] Комментируется неочевидное (не очевидное)
- [ ] Язык комментариев единообразен
- [ ] Нет избыточных комментариев

**Примеры:**
```python
❌ x = 5  # Set x to 5 (избыточно)
✅ # Binary search for O(log n) performance
```

### Разнообразие примеров
- [ ] Есть минимальные примеры (концепции)
- [ ] Есть практические примеры (применение)
- [ ] Есть production примеры (с error handling)
- [ ] Пропорция примерно: 40% / 40% / 20%

### Output для примеров
- [ ] Показан output для ВСЕХ примеров
- [ ] Output реалистичный (не выдуманный)
- [ ] Формат: блок ```Output:``` после кода

## 5️⃣ ФОРМАТИРОВАНИЕ

### Эмодзи
- [ ] Используются **стандартные** эмодзи:
  - 📋 Prerequisites
  - 🎯 Goals/Objectives  
  - 📁 Files/Data
  - 💡 Tips/Takeaways
  - 🚀 Next Steps
  - ⚠️ Warnings
  - ✅ Good practices
  - ❌ Bad practices

- [ ] Эмодзи только в **началах секций** (не в тексте)
- [ ] Используются **умеренно** (не overuse)

### Форматирование текста

**Жирный текст:**
- [ ] Используется для **ключевых терминов**
- [ ] Используется для **важных концепций**
- [ ] НЕ используется избыточно

**Курсив:**
- [ ] Используется для *акцентов*
- [ ] Используется для *названий* (на англ. в рус. тексте)

**Код-форматирование:**
- [ ] Все имена функций/классов/переменных в `code`
- [ ] Все команды оболочки в `code`
- [ ] Все пути к файлам в `code`

### Списки
- [ ] Маркированные для неупорядоченных элементов
- [ ] Нумерованные для последовательностей/шагов
- [ ] Максимум 2 уровня вложенности
- [ ] Форматирование списков единообразно

### Таблицы
- [ ] Используются для сравнений/справочников
- [ ] Заголовки выровнены
- [ ] Колонки выровнены корректно
- [ ] Не перегружены информацией

### Разделители
- [ ] `---` после header
- [ ] `---` перед Key Takeaways
- [ ] `---` перед Next Steps
- [ ] НЕ используются избыточно

## 6️⃣ ЯЗЫКОВЫЕ ТРЕБОВАНИЯ

### Терминология
- [ ] Термины **единообразны** по всему модулю
- [ ] Термины **согласованы** с другими модулями
- [ ] Английские термины в **коде**: `map()`, не map
- [ ] Устоявшиеся переводы использованы правильно

### Предложения
- [ ] Среднее: **15-20 слов**
- [ ] Максимум: **30 слов** 
- [ ] Нет слишком длинных предложений
- [ ] Сложные мысли разбиты на пункты

### Абзацы
- [ ] **3-5 предложений** на абзац
- [ ] Одна идея на абзац
- [ ] Пустая строка между абзацами
- [ ] Абзацы логически связаны

### Тон
- [ ] Дружелюбный но профессиональный
- [ ] Единообразное обращение (ты/вы)
- [ ] Мотивирующий но не развлекательный
- [ ] Баланс теории и практики

## 🔟 QUIZ.MD ФАЙЛ

### Наличие и структура
- [ ] Файл `quiz.md` **существует** в папке модуля
- [ ] Есть заголовок с названием модуля
- [ ] Есть краткое описание квиза

### Количество вопросов
- [ ] Минимум **10 вопросов**
- [ ] Максимум **30 вопросов**
  - Текущее количество: _______ вопросов

### Формат вопросов
- [ ] Каждый вопрос имеет **4 варианта ответа** (A, B, C, D)
- [ ] Только **один правильный ответ** на вопрос
- [ ] Вопросы **пронумерованы** последовательно
- [ ] Каждый вопрос имеет **тему/название**
- [ ] Неправильные ответы **правдоподобны**

### Покрытие материала
- [ ] Вопросы **покрывают** Learning Objectives из лекции
- [ ] Есть вопросы на **понимание концепций** (~40%)
- [ ] Есть вопросы на **практическое применение** (~40%)
- [ ] Есть вопросы на **edge cases и pitfalls** (~20%)
- [ ] НЕТ вопросов о материале, **отсутствующем** в лекции

### Answer Key
- [ ] Есть секция **Answer Key** с ответами
- [ ] Для каждого ответа указана **буква** правильного варианта
- [ ] Для каждого ответа есть **пояснение** почему это правильно
- [ ] Пояснения **понятны** и **обучающи**

### Scoring Guide
- [ ] Есть секция **Scoring Guide**
- [ ] Разделена на **4 категории** по процентам
- [ ] Даны **рекомендации** для каждой категории
- [ ] Мотивирует на изучение/повторение

### Качество вопросов
- [ ] Вопросы **разного уровня сложности**
- [ ] Нет **очевидно** неправильных вариантов
- [ ] Формулировки **ясные и однозначные**
- [ ] Код в вопросах **корректен** и **форматирован**
