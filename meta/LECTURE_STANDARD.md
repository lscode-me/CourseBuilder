# Стандарт лекций CourseBuilder

## 📋 Назначение документа

Этот документ определяет единые требования к структуре, содержанию и оформлению всех лекций во всех курсах CourseBuilder.

**Цель:** обеспечить согласованность, качество и удобство обучения независимо от тематики курса.

**Применяется к:** всем курсам в `Courses/` (Git, Python, DevOps, Linux, Leadership, и др.)

---

## 🎯 Общие принципы

### 1. Философия курса
- **Практичность**: Теория подкреплена работающими примерами
- **Ясность**: Сложное объясняем простым языком
- **Прогрессия**: От базового к продвинутому
- **Релевантность**: Актуальные технологии и best practices
- **Применимость**: Навыки для реальных задач

### 2. Тон и стиль
- **Дружелюбный, но профессиональный**
- Обращение на "ты" / "вы" (выбрать одно и использовать везде)
- Избегать излишней формальности
- Мотивировать, но не развлекать
- Баланс между теорией и практикой

### 3. Целевая аудитория
- Студенты с базовыми знаниями в области курса
- Практики, желающие углубить навыки
- Те, кто ценит понимание "как это работает"

**Примечание:** Конкретная аудитория уточняется в `course.txt` каждого курса.

## 📐 Структура лекции

### Обязательные секции (в указанном порядке)

```markdown
# [Название модуля]
## [Подзаголовок: что конкретно изучаем]

---

## 📋 Prerequisites
Что нужно знать перед началом

## 🎯 Learning Objectives
Что вы изучите в этом модуле

## 📁 Sample Data
Ссылка на данные для практики (если применимо)

---

## 1. [Основная секция 1]
### 1.1 [Подсекция]
### 1.2 [Подсекция]

## 2. [Основная секция 2]
...

---

## 💡 Key Takeaways
Главные выводы (3-5 пунктов)

## 🚀 Next Steps
Что изучить дальше, связанные темы

## 📚 Additional Resources
Дополнительные материалы (опционально)

---
```

### Требования к секциям

#### Header (первые 3 строки)
```markdown
# [Название]
## [Конкретная тема]

---
```

- H1: Название модуля (напр. "Object-Oriented Programming")
- H2: Конкретизация (напр. "Classes, Inheritance, Polymorphism")
- Разделитель `---`

#### Prerequisites
```markdown
## 📋 Prerequisites

Перед началом этого модуля вы должны:
- Знать базовый синтаксис Python / понимать командную строку
- Быть знакомы с [концепция из предыдущего модуля]
- [Опционально] Иметь опыт с [инструмент]
```

**Правила:**
- 2-4 пункта
- Конкретные, проверяемые требования
- Ссылки на предыдущие модули, если применимо

#### Learning Objectives
```markdown
## 🎯 Learning Objectives

После завершения этого модуля вы сможете:
- [Глагол действия] + [конкретный навык]
- [Глагол действия] + [конкретный навык]
- [Глагол действия] + [конкретный навык]
```

**Правила:**
- 3-5 целей
- Использовать активные глаголы: создавать, применять, анализировать, разрабатывать
- Измеримые результаты обучения
- НЕ использовать: понимать, знать (слишком абстрактно)

**Примеры хороших objectives:**
- ✅ "Создавать ветки и выполнять merge в Git"
- ✅ "Применять декораторы для модификации функций"
- ✅ "Разрабатывать эффективные pipeline'ы с grep, sed, awk"
- ✅ "Настраивать CI/CD pipeline в GitHub Actions"
- ❌ "Понимать Git" (плохо - неизмеримо)
- ❌ "Знать декораторы" (плохо - неконкретно)

#### Sample Data (для модулей с практикой)
```markdown
## 📁 Sample Data

**[Название датасета](../data/DataSamples.md)** — описание данных для практики

Датасеты для этого модуля:
- `data/file1.csv` — описание
- `data/file2.json` — описание
```

#### Key Takeaways
```markdown
## 💡 Key Takeaways

- **Ключевая концепция 1**: Краткое объяснение почему важно
- **Ключевая концепция 2**: Краткое объяснение почему важно
- **Ключевая концепция 3**: Краткое объяснение почему важно
```

**Правила:**
- 3-5 пунктов
- Формат: **Концепция**: объяснение
- Это должны быть самые важные идеи модуля
- То, что останется в памяти через месяц

#### Next Steps
```markdown
## 🚀 Next Steps

**Related Modules:**
- [Module X](../XX_Module/) — как связано
- [Module Y](../YY_Module/) — как связано

**Practice Ideas:**
- Задача для самостоятельной практики
- Проект для применения знаний

**Going Deeper:**
- Дополнительная тема для углубления
- Продвинутая концепция
```

## 📝 Требования к содержанию

### 1. Основные секции (H2)

**Нумерация:**
```markdown
## 1. Название секции
## 2. Название секции
## 3. Название секции
```

**Правила:**
- Нумеруются арабскими цифрами
- 5-12 основных секций на лекцию
- Логическая последовательность: от простого к сложному
- Каждая секция = законченная мысль

### 2. Подсекции (H3)

```markdown
### 1.1 Подсекция
### 1.2 Подсекция
```

**Правила:**
- Нумерация через точку: `1.1`, `1.2`, `2.1`, etc.
- 0-4 подсекций на основную секцию
- Если подсекций больше 4 — возможно, нужно разбить основную секцию

### 3. Структура секции

**Стандартная структура:**
```markdown
## N. [Название темы]

[1-2 абзаца введения: что это и зачем]

### N.1 [Подтема]

[Объяснение концепции]

**Пример:**
```[язык]
[код]
```

**Output:**
```
[результат выполнения]
```

[Объяснение что произошло]

### N.2 [Другая подтема]
...
```

### 4. Длина лекции

**Целевые метрики:**
- **Строк:** 600-1000 строк
- **Время чтения:** 30-45 минут
- **Основных секций:** 5-12
- **Примеров кода:** см. раздел "Типы курсов" ниже

**Если лекция слишком длинная (>1200 строк):**
- Разбить на два модуля
- Вынести advanced topics в отдельный модуль
- Убрать дублирование

**Если лекция слишком короткая (<400 строк):**
- Добавить больше примеров
- Углубить объяснения
- Добавить edge cases и best practices
- Добавить real-world scenarios

## 🎯 Типы курсов и требования к коду

Курсы делятся на категории по отношению к программированию. Требования к количеству блоков кода зависят от типа курса.

### 1. Программистские курсы (Programming Courses)

Курсы, непосредственно связанные с написанием кода.

**Примеры:** Python, JavaScript, Go, SQL, DevOps, алгоритмы, frameworks

**Требования:**
- **Примеров кода:** 15-30 блоков
- **Процент кода к тексту:** 30-40%
- Код должен быть исполняемым
- Показывать output для примеров

### 2. Технические курсы (Technical Courses)

Курсы на техническую тему, но не требующие написания кода как основной навык.

**Примеры:** Платёжные системы, Сети, Криптография, Архитектура систем

**Требования:**
- **Примеров кода/диаграмм:** 5-15 блоков
- **Тип блоков:** ASCII-диаграммы, схемы, примеры API, конфигурации
- Код необязателен, можно заменить на:
  - Текстовые диаграммы и схемы (ASCII art)
  - Таблицы с данными
  - Примеры форматов (JSON, XML)
  - Pseudocode

### 3. Гуманитарные курсы (Non-Technical Courses)

Курсы без технической составляющей.

**Примеры:** История, Менеджмент, Маркетинг, Soft Skills, Языки

**Требования:**
- **Примеров кода:** 0-5 блоков (опционально)
- Блоки кода не требуются
- Можно использовать:
  - Цитаты
  - Примеры документов
  - Форматированные списки

### 4. Определение типа курса

Тип курса определяется по его тематике и указывается в `description.md` курса.

**Ключевые слова для автоопределения:**

| Тип | Ключевые слова в названии/описании |
|-----|-----------------------------------|
| Programming | Python, JavaScript, Go, Rust, Java, SQL, код, программирование, разработка, framework, library, API (разработка) |
| Technical | система, архитектура, сеть, безопасность, платёж, инфраструктура, DevOps, данные |
| Non-Technical | история, менеджмент, маркетинг, продажи, коммуникация, психология |

## 💻 Требования к примерам кода

> **Примечание:** Этот раздел применяется в полной мере для **программистских курсов**. 
> Для технических и гуманитарных курсов требования к коду снижены — см. раздел "Типы курсов".

### 1. Формат блока кода

**Полный блок:**
```markdown
### Example: [Описательное название]

[1-2 предложения: что делает пример и зачем он нужен]

```python
# Комментарий: что делает этот блок
def example_function(param):
    """Docstring если это функция/класс"""
    result = param * 2
    return result

# Демонстрация использования
value = example_function(5)
print(value)
```

**Output:**
```
10
```

**Объяснение:**
Функция `example_function()` умножает параметр на 2. Обратите внимание на [важная деталь].
```

### 2. Правила комментирования

**В коде:**
- Комментарии на английском (если код на Python) ИЛИ на русском (если это демонстрация)
- Выбрать ОДИН подход и использовать везде
- Комментировать неочевидное, а не очевидное

**Плохо:**
```python
# Set x to 5
x = 5  # Очевидно и бесполезно
```

**Хорошо:**
```python
# Use binary search for O(log n) performance
result = binary_search(arr, target)
```

### 3. Типы примеров

**Минимальный пример (концепция):**
```python
# Демонстрирует только концепцию
x = [1, 2, 3]
y = [n * 2 for n in x]
```

**Практический пример (применение):**
```python
# Реальная задача: фильтрация логов
def filter_errors(log_file):
    with open(log_file) as f:
        errors = [line for line in f if 'ERROR' in line]
    return errors
```

**Полный пример (production-ready):**
```python
# Production-ready код с обработкой ошибок
def safe_divide(a: float, b: float) -> float | None:
    """
    Safely divide two numbers.
    Returns None if division by zero.
    """
    try:
        return a / b
    except ZeroDivisionError:
        return None
```

**Правило:** Включать все три типа в пропорции 40% / 40% / 20%

### 4. Код должен быть:

- ✅ **Исполняемым**: Можно скопировать и запустить
- ✅ **Современным**: Актуальные практики и синтаксис
- ✅ **Идиоматичным**: Соответствует best practices языка/инструмента
- ✅ **Понятным**: Переменные с понятными именами
- ✅ **Безопасным**: Обработка ошибок где нужно

❌ **Избегать:**
- Устаревших конструкций и deprecated API
- Слишком clever code (читаемость важнее краткости)
- Примеров без контекста ("просто код")
- Незакрытых ресурсов, утечек памяти

### 5. Показывать вывод

**Всегда показывать результат выполнения:**

```markdown
```python
print([x**2 for x in range(5)])
```

**Output:**
```
[0, 1, 4, 9, 16]
```
```

**Для интерактивных сессий:**
```python
>>> x = 5
>>> x * 2
10
>>> x + 3
8
```

## 🎨 Стилистические требования

### 1. Эмодзи

**Использовать умеренно для:**
- Маркировки секций: 📋 📁 🎯 💡 🚀
- Важных замечаний: ⚠️ ✅ ❌ 💡
- Типов контента: 📚 💻 🔧

**Стандартные эмодзи:**
- 📋 Prerequisites
- 🎯 Learning Objectives / Goals
- 📁 Sample Data / Files
- 💡 Key Takeaways / Pro Tips
- 🚀 Next Steps / Advanced
- ⚠️ Warning / Caution
- ✅ Good practice / Correct
- ❌ Bad practice / Incorrect
- 📚 Theory / Concepts
- 💻 Practical / Code Examples
- 🔧 Tools / Commands
- 📊 Data / Results
- 🎓 Exercise / Practice

**НЕ использовать:**
- Много эмодзи подряд: ❌ 🚀🔥💯✨
- Эмодзи внутри предложений (только в началах секций)
- Случайные эмодзи без значения

### 2. Форматирование текста

**Жирный текст (`**text**`):**
- Ключевые термины при первом упоминании
- Важные концепции
- Заголовки в списках

**Курсив (`*text*`):**
- Акценты в предложениях
- Названия на английском в русском тексте
- Метапеременные (напр. *filename*, *pattern*)

**Код (`code`):**
- Имена функций, классов, переменных
- Команды оболочки
- Пути к файлам
- Короткие фрагменты кода (до 1 строки)

**Примеры:**

```markdown
**Правильно:**
The `map()` function applies a transformation to each element.
Use **list comprehensions** when you need a list result.

**Неправильно:**
The map() function applies a **transformation** to **each element**.
Use list comprehensions when you need a list result.
```

### 3. Списки

**Маркированные списки:**
```markdown
Используются для:
- Неупорядоченных элементов
- Преимуществ / недостатков
- Ключевых пунктов
```

**Нумерованные списки:**
```markdown
Используются для:
1. Последовательных шагов
2. Алгоритмов
3. Иерархических структур
```

**Вложенные списки (максимум 2 уровня):**
```markdown
- Level 1
  - Level 2
    - Avoid Level 3 (рефакторить)
```

### 4. Таблицы

**Использовать для:**
- Сравнений
- Справочников
- Спецификаций

**Формат:**
```markdown
| Column 1 | Column 2 | Column 3 |
|----------|----------|----------|
| Value    | Value    | Value    |
| Value    | Value    | Value    |
```

**Выравнивание:**
- Текст: по левому краю
- Числа: по правому краю
- Заголовки: по центру (опционально)

### 5. Цитаты и врезки

**Для важных замечаний:**
```markdown
> **💡 Pro Tip:**  
> Полезный совет или инсайт

> **⚠️ Warning:**  
> Важное предупреждение или частая ошибка

> **📝 Note:**  
> Дополнительная информация
```

### 6. Разделители

**Использовать `---` для:**
- Отделения header от контента
- Между крупными секциями (перед Key Takeaways, Next Steps)

**Не использовать:**
- Между каждой секцией (слишком много)
- Внутри секций

## ✍️ Языковые требования

### 1. Терминология

**Единообразие:**
- Выбрать ОДИН термин и использовать везде
- Создать глоссарий часто используемых терминов

**Примеры:**
- ✅ Используем: "функция" (не "метод" для standalone functions)
- ✅ Используем: "аргумент" (не "параметр" для вызова)
- ✅ Используем: "параметр" (для определения функции)

### 2. Перевод vs транслитерация

**Правило:** Использовать устоявшиеся переводы, НО оставлять английские термины в `code`

**Примеры:**
```markdown
✅ Хорошо:
Функция `map()` применяет трансформацию к каждому элементу.
Декоратор `@property` создает getter для атрибута.

❌ Плохо:
Функция map применяет трансформацию к каждому элементу. (без код-форматирования)
Декоратор эт-property создает геттер для атрибута. (транслитерация)
```

### 3. Длина предложений

**Целевые метрики:**
- Среднее: 15-20 слов
- Максимум: 30 слов
- Если длиннее — разбить на два

**Сложные предложения:**
- Разбивать на пункты списка
- Использовать короткие абзацы

### 4. Абзацы

**Правила:**
- 3-5 предложений на абзац
- Одна идея на абзац
- Пустая строка между абзацами

## 🔍 Требования к качеству

### 1. Технические требования

**Точность:**
- ✅ Технически корректная информация
- ✅ Работающие примеры кода
- ✅ Актуальные версии инструментов
- ❌ Устаревшие практики
- ❌ Неработающий код

**Проверяемость:**
```markdown
Плохо: "Этот код быстрее"
Хорошо: "Этот код в 2 раза быстрее (O(log n) vs O(n))"
```

### 2. Педагогические требования

**Прогрессия:**
- От простого к сложному
- От конкретного к абстрактному
- Новые концепции строятся на известных

**Примеры:**
```markdown
✅ Хорошая прогрессия:
1. Basic list comprehension: [x*2 for x in range(10)]
2. With condition: [x*2 for x in range(10) if x % 2 == 0]
3. Nested: [[y*x for y in range(3)] for x in range(3)]

❌ Плохая прогрессия:
1. Nested comprehension (сразу сложное)
2. Basic comprehension (проще после сложного)
```

**Объяснение:**
- Сначала ЧТО делает код
- Потом КАК он работает
- Наконец ПОЧЕМУ именно так

### 3. Полнота

**Каждая концепция должна включать:**
- Определение
- Зачем нужно (мотивация)
- Как использовать (примеры)
- Когда использовать (сценарии)
- Частые ошибки (pitfalls)

## 🎓 Примеры

### Пример хорошей секции

```markdown
## 3. List Comprehensions

List comprehensions provide a concise way to create lists based on existing iterables. They're more readable and often faster than traditional loops.

### 3.1 Basic Syntax

**Format:**
```python
[expression for item in iterable]
```

**Example: Square numbers**
```python
# Traditional loop
squares = []
for x in range(10):
    squares.append(x ** 2)

# List comprehension (Pythonic)
squares = [x**2 for x in range(10)]
print(squares)
```

**Output:**
```
[0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
```

Both produce the same result, but comprehension is more concise and expressive.

### 3.2 With Filtering

Add an `if` clause to filter elements:

```python
# Only even squares
even_squares = [x**2 for x in range(10) if x % 2 == 0]
print(even_squares)
```

**Output:**
```
[0, 4, 16, 36, 64]
```

> **💡 Pro Tip:**  
> Use comprehensions when the logic is simple. For complex operations, stick with regular loops for clarity.

### 3.3 Common Pitfalls

❌ **Don't overuse nested comprehensions:**
```python
# Hard to read
result = [[y*x for y in range(3)] for x in range(3)]
```

✅ **Use regular loops for complex nesting:**
```python
# More readable
result = []
for x in range(3):
    row = []
    for y in range(3):
        row.append(y * x)
    result.append(row)
```
```

**Количество вопросов:**
- Минимум: 20 вопросов
