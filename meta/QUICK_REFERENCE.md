# ⚡ Quick Reference: Lecture Standards

Краткая памятка для авторов курса. Полная версия: [LECTURE_STANDARD.md](LECTURE_STANDARD.md)

---

## 🎯 Обязательная структура

```markdown
# [Название модуля]
## [Конкретная тема]

---

## 📋 Prerequisites
- [Что нужно знать]

## 🎯 Learning Objectives (3-5)
- [Глагол действия] + [навык]

## 📁 Sample Data (если применимо)

## 1-12. [Основные секции с примерами]

## 💡 Key Takeaways (3-5)

## 🚀 Next Steps

---
```

## 📊 Целевые метрики

| Метрика | Значение |
|---------|----------|
| **Длина** | 600-1000 строк |
| **Секций** | 5-12 |
| **Примеров кода** | 15-30 |
| **Время чтения** | 30-45 мин |

## ✅ Must-Have в каждом блоке кода

```markdown
### Example: [Описание]

[Что делает пример]

```python
# Комментарии к неочевидному
code_here()
```

**Output:**
```
результат
```

[Объяснение]
```

## 🎨 Стандартные эмодзи

- 📋 Prerequisites
- 🎯 Objectives/Goals
- 📁 Files/Data
- 💡 Tips/Takeaways
- 🚀 Next Steps
- ⚠️ Warnings
- ✅ Good / ❌ Bad

## 🔑 Критические правила

1. ✅ **Весь код работает** (протестирован)
2. ✅ **Output показан** для всех примеров
3. ✅ **От простого к сложному** (прогрессия)
4. ✅ **Prerequisites корректны**
5. ✅ **Нет broken links**
6. ✅ **Нет устаревших практик**

## 🚫 Чего избегать

- ❌ Код без output
- ❌ Неработающие примеры
- ❌ Слишком длинные секции (>200 строк)
- ❌ Устаревший синтаксис (%, old-style)
- ❌ Объяснение только "как", без "зачем"
- ❌ Больше 2 уровней вложенности списков

## ⚡ Quick Checklist

Перед отправкой на review:

- [ ] Есть все обязательные секции
- [ ] 3-5 Learning Objectives
- [ ] 3-5 Key Takeaways
- [ ] Весь код работает
- [ ] Output для всех примеров
- [ ] 600-1000 строк
- [ ] Нет broken links
- [ ] Прогрессия от простого к сложному
- [ ] Единообразная терминология
- [ ] **Quiz.md создан** (20-40 вопросов)
- [ ] **Вопросы покрывают Learning Objectives**

**Полная проверка:** [LECTURE_CHECKLIST.md](LECTURE_CHECKLIST.md) (155 пунктов)

## 🎓 Глаголы для Learning Objectives

✅ Используй:
- Создавать, разрабатывать, реализовывать
- Применять, использовать
- Анализировать, оценивать
- Оптимизировать, улучшать

❌ Избегай:
- Понимать, знать (неизмеримо)
- Ознакомиться, узнать (слишком абстрактно)

## 💻 Типы примеров (пропорции)

- 40% — **Минимальные** (концепция)
- 40% — **Практические** (применение)
- 20% — **Production** (с error handling)

## 📝 Форматирование

**Жирный:** ключевые термины, важные концепции  
*Курсив:* акценты, названия  
`Код:` функции, команды, переменные, пути

## 📝 Quiz.md (обязательно!)

```markdown
# [Module Name] - Quiz

## Question 1: [Тема]
[Вопрос]
A) ... B) ... C) ... D) ...

---

## Answer Key
1. B - [Ответ] - [Пояснение]

## Scoring Guide
- 90-100%: Отлично
- 70-89%: Хорошо
- 50-69%: Удовлетворительно
- <50%: Нужно повторить
```

**Требования:** 20-40 вопросов, 4 варианта (ABCD), покрытие Learning Objectives

## 🔄 Workflow

```
Создать/Скопировать из TEMPLATE
   ↓
Заполнить контент лекции
   ↓
Создать quiz.md (20-40 вопросов)
   ↓
Самопроверка (Quick Checklist)
   ↓
Полная проверка (LECTURE_CHECKLIST.md)
   ↓
Review → Правки → Публикация
```
