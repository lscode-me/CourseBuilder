## Answer Key

| # | Answer | Explanation |
|---|--------|-------------|
| 1 | B | `chroot` появился в Unix Version 7 в 1979 году |
| 2 | B | `chroot` меняет корневую директорию для текущего процесса на указанную |
| 3 | B | chroot НЕ изолирует процессы — все процессы системы остаются видимыми |
| 4 | B | Классический escape: открыть дескриптор, chroot в поддиректорию, fchdir обратно |
| 5 | B | FreeBSD Jails добавили изоляцию процессов и сети, чего не было в chroot |
| 6 | C | Global Zone — основная ОС, которая имеет доступ ко всему оборудованию и управляет non-global zones |
| 7 | B | Namespaces отвечают за изоляцию видимости ресурсов (PID, NET, MNT и др.) |
| 8 | B | Cgroups (Control Groups) управляют и ограничивают потребление ресурсов (CPU, память, I/O) |
| 9 | C | chroot (1979) → LXC (2008) → Docker (2013) → Kubernetes (2014) |
| 10 | B | LXC — первая полноценная система контейнеризации для Linux, объединившая namespaces и cgroups |
| 11 | C | Docker принёс удобный workflow: Dockerfile, слои образов, Docker Hub |
| 12 | B | OCI — организация, разрабатывающая открытые стандарты для контейнеров (runtime, image, distribution) |
| 13 | C | runc — референсная реализация low-level OCI runtime |
| 14 | B | Для работы bash нужен сам исполняемый файл и все динамические библиотеки (libc, libtinfo и др.) |
| 15 | C | UTS namespace изолирует hostname и domain name |
| 16 | B | Открытость (open source), модульность механизмов и доминирование в облачной инфраструктуре |
| 17 | B | `lxc.cgroup.memory.limit_in_bytes` — параметр для ограничения памяти через cgroups |
| 18 | C | Docker Daemon через runc (ранее libcontainer) взаимодействует с ядром для создания контейнеров |
| 19 | B | Слои позволяют переиспользовать общие части образов, экономя дисковое пространство |
| 20 | B | chroot изолирует только файловую систему, и даже это можно обойти с root-правами |
